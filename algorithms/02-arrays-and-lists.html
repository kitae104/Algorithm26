    05핵심 개념

    배열 — 같은 자료형을 줄지어 담는 고정 크기의 그릇

    배열(array)은 같은 자료형의 값들을 메모리에 연속으로 줄지어 담는 구조. int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};처럼 만들면 8칸짜리 그릇이 생기고, 각 칸에 인덱스(index) 번호가 붙습니다.

    배열 scores의 인덱스와 값
    인덱스01234567
    값7285906678935581
    • 인덱스는 0부터 시작합니다. 인덱스는 "몇 번째"가 아니라 "시작 지점에서 몇 칸 떨어져 있는가"입니다. 첫 칸은 0칸 떨어져 있으므로 0입니다.
    • 첫 원소는 scores[0], 마지막 원소는 scores[scores.length - 1]입니다. 길이가 8이면 유효한 인덱스는 0부터 7까지 — 8은 없습니다!
    • 인덱스 접근(scores[i])은 위치 계산 한 번으로 끝나는 O(1) 연산입니다. 1강 응용 예제의 "직접 접근"이 빨랐던 이유가 바로 이것입니다.
    • 한 번 만든 배열의 크기는 바꿀 수 없습니다. 9번째 값을 넣으려면 더 큰 배열을 새로 만들어 값을 옮겨야 합니다.

    데이터 순회 — 처음부터 끝까지 하나씩 방문하기

    배열의 모든 원소를 한 번씩 방문하는 것을 순회(traversal)라고 합니다. 오늘 나오는 모든 코드가 이 뼈대 위에 서 있습니다.

    for (int i = 0; i < scores.length; i++) {
    // scores[i]를 가지고 할 일
}
    • 조건이 i <= scores.length가 아니라 i < scores.length인 것에 주의 — 마지막 유효 인덱스가 length - 1이기 때문
    • 순회 뼈대 안의 "할 일"만 바꾸면 합계, 최댓값, 검색, 빈도가 전부 만들어짐
    패턴기억 칸(변수)순회 안에서 할 일
    합계 (누적)sum = 0sum = sum + scores[i] — 1강의 누적 패턴 그대로
    최댓값 (후보 비교)max = scores[0]if (scores[i] > max) max = scores[i]
    최솟값 (후보 비교)min = scores[0]if (scores[i] < min) min = scores[i]
    조건 검색count = 0 또는 결과 리스트if (조건) count++ 또는 결과에 추가
    빈도 계산카운팅 배열 int[] bandsbands[scores[i] / 10]++

    리스트(ArrayList) — 필요할 때마다 자라는 그릇

    ArrayList는 배열을 감싸서 "크기 관리"를 대신해 주는 클래스 — 추가하면 스스로 커지고, 삭제하면 빈틈을 스스로 메웁니다.

    import java.util.ArrayList;

ArrayList<String> names = new ArrayList<>();   // 빈 리스트 생성
names.add("김하늘");          // 끝에 추가
names.add("이준호");
names.get(0);                 // 읽기: "김하늘" (배열의 names[0]에 해당)
names.set(1, "이준서");       // 바꾸기 (배열의 names[1] = ... 에 해당)
names.remove(0);              // 0번 삭제 — 뒤 원소들이 한 칸씩 앞으로 밀려온다
names.size();                 // 현재 크기 (배열의 length에 해당)
    • 꺾쇠 안의 <String>은 "이 리스트에는 String만 담는다"는 제네릭 선언입니다.
    • 제네릭에는 기본형을 쓸 수 없습니다. ArrayList<int>는 오류이고, 래퍼 클래스를 써서 ArrayList<Integer>로 선언합니다.
    • 끝에 추가(add)는 평균 O(1)이지만, 중간 삭제(remove)는 O(n)입니다 — 삭제된 칸을 메우기 위해 뒤의 모든 원소가 한 칸씩 이동하기 때문입니다. 이 "밀림"이 오류 카드 2번의 주인공입니다.

    배열 복사 — 이름 복사와 진짜 복사

    • 배열 변수에는 값이 아니라 배열이 있는 곳의 주소(참조)가 담김
    • 그래서 int[] b = a;는 그릇을 하나 더 만드는 것이 아니라 같은 그릇에 이름표를 하나 더 붙이는 것 — b[0]을 바꾸면 a[0]도 바뀜!
    • 진짜 복사는 새 배열을 만들고 순회하며 값을 옮겨야 함
    int[] a = {1, 2, 3};

int[] b = a;                       // 이름 복사(참조 복사): 같은 배열을 가리킨다
b[0] = 99;                         // a[0]도 99가 된다!

int[] c = new int[a.length];       // 진짜 복사: 새 배열을 만들고
for (int i = 0; i < a.length; i++) {
    c[i] = a[i];                   // 값을 한 칸씩 옮긴다 — O(n)
}
c[0] = 7;                          // a에는 아무 영향이 없다
    라이브러리 한 줄 메모

    실무에서는 java.util.Arrays.copyOf(a, a.length) 한 줄로 복사 — 다만 그 안에서도 결국 같은 O(n) 순회가 일어납니다. 원리를 알고 쓰는 것과 모르고 쓰는 것은 다릅니다.

    06단계별 동작 과정

    학생 8명의 점수 배열 [72, 85, 90, 66, 78, 93, 55, 81]을 한 번 순회하며 누적 합(sum = 0에서 시작)과 최댓값 후보(max = 첫 번째 점수 72에서 시작)를 동시에 갱신하는 과정을 단계별로 확인합니다. 다음 단계 ▶로 한 단계씩, 또는 자동 실행. 비교 중 = 앰버색, 확정/완료 = 초록색. 새 데이터 버튼으로 랜덤 점수 배열을 다시 실행할 수 있습니다.

    카운터를 보면 원소를 하나 지날 때마다 누적 연산 1번 + 최댓값 비교 1번이 정확히 일어남 — 원소가 n개면 비교도 n번, 순회의 시간 복잡도가 O(n)이라는 사실을 1강의 연산 카운터 기법으로 다시 확인.

    07의사코드

    코드를 쓰기 전에, 방금 본 절차를 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", scores[i]는 "배열의 i번 칸", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)
    • ÷는 몫만 남기는 나눗셈 — Java의 정수 나눗셈 /와 같음 (72 ÷ 10 = 7)
    Pseudo 한 번의 순회로 합계·최댓값·최솟값 구하기 
    알고리즘 SumMaxMin(scores)
    sum ← 0                       // 누적 합 (1강의 누적 패턴)
    max ← scores[0]               // 최댓값 후보: 데이터 안의 실제 값에서 시작
    min ← scores[0]               // 최솟값 후보
    i를 0부터 scores의 길이 - 1까지 반복:
        sum ← sum + scores[i]     // 핵심 연산 1: 누적 (n번 실행)
        만약 scores[i] > max 이면: max ← scores[i]   // 핵심 연산 2: 후보 비교
        만약 scores[i] < min 이면: min ← scores[i]
    sum, max, min을 반환한다

    코드 설명 — 한 번의 순회로 합계·최댓값·최솟값 구하기

    • sum ← 0 — 누적 합을 담을 기억 칸. "아직 아무것도 안 더한 상태"가 정확히 0이므로 0에서 시작
    • max ← scores[0], min ← scores[0] — 최댓값·최솟값 후보는 첫 번째 점수에서 시작
      • 0에서 시작하면 안 되는 이유: 데이터가 영하의 온도(-5, -3, -9)라면 max = 0이 끝까지 남아, 데이터에 없는 값이 "최댓값"이 됨
      • 데이터 안에 실제로 있는 값에서 시작해야 어떤 데이터에도 안전
    • i를 0부터 scores의 길이 - 1까지 반복 — 배열을 처음부터 끝까지 한 칸씩 방문하는 순회. 마지막 칸 번호는 길이 - 1
    • sum ← sum + scores[i] — 지금 칸의 점수를 누적 합에 더함 (1강의 누적 패턴)
      • 예: [72, 85, 90] → sum은 72 → 157 → 247
    • 만약 scores[i] > max 이면: max ← scores[i] — 지금 점수가 후보보다 크면 후보를 교체, 아니면 그대로 둠
      • 예: max = 72에서 85를 만나면 85로, 90을 만나면 90으로 교체, 66을 만나면 90 유지
    • 만약 scores[i] < min 이면: min ← scores[i] — 최댓값과 같은 구조에서 부등호 방향만 반대
    • sum, max, min을 반환한다 — 순회를 한 번만 했는데 세 가지 답을 모두 얻음. 평균은 sum ÷ 개수로 바로 계산
    Pseudo 조건 검색과 빈도 계산 
    알고리즘 CountAtLeast(scores, threshold)
    count ← 0
    i를 0부터 scores의 길이 - 1까지 반복:
        만약 scores[i] ≥ threshold 이면: count ← count + 1
    count를 반환한다

알고리즘 BandFrequency(scores)
    bands ← 크기 10의 새 배열 (모두 0)      // 점수대별 칸을 미리 만든다
    i를 0부터 scores의 길이 - 1까지 반복:
        bands[scores[i] ÷ 10] ← bands[scores[i] ÷ 10] + 1   // 값 → 인덱스 변환
    bands를 반환한다

    코드 설명 — 조건 검색과 빈도 계산

    • CountAtLeast — 기준 점수 이상인 원소가 몇 개인지 셈
      • count ← 0 — 조건에 맞는 개수를 셀 기억 칸, 0에서 시작
      • i를 0부터 scores의 길이 - 1까지 반복 — 모든 점수를 한 번씩 확인하는 순회
      • 만약 scores[i] ≥ threshold 이면: count ← count + 1 — 조건에 맞을 때만 개수를 1 늘림, 맞지 않으면 그냥 지나감
      • 예: threshold = 80이면 [72, 85, 90, 66, 78, 93, 55, 81]에서 85, 90, 93, 81 → count = 4
      • count를 반환한다 — 결과가 몇 개일지는 끝까지 보기 전에는 알 수 없음 (그래서 결과를 모을 때는 스스로 자라는 ArrayList가 편함)
    • BandFrequency — 점수대(50점대, 60점대, …)별로 몇 명인지 셈
      • bands ← 크기 10의 새 배열 (모두 0) — 0점대~90점대를 셀 칸 10개를 미리 만들어 둠 (종이에 칸을 그려 두고 바를 정(正)자를 긋는 것과 같음)
      • i를 0부터 scores의 길이 - 1까지 반복 — 점수를 하나씩 확인
      • bands[scores[i] ÷ 10] ← bands[scores[i] ÷ 10] + 1 — 점수를 10으로 나눈 몫이 곧 칸 번호, 그 칸을 1 늘림
        • 예: 72 ÷ 10 = 7 → 7번 칸(70점대) +1, 85 ÷ 10 = 8 → 8번 칸(80점대) +1
        • 칸을 찾으려고 비교를 반복할 필요 없이 값 자체가 인덱스가 되므로 한 번에 해당 칸으로 감
      • bands를 반환한다 — 칸마다 해당 점수대의 인원이 담긴 배열

    • 특히 BandFrequency의 "값을 인덱스로 바꿔서 센다"는 발상은 3강의 해시, 4강의 계수 정렬로 확장됨

    08실습 코드

    의사코드(07)를 실제 Java 프로그램으로 옮깁니다. 성적 배열 하나를 받아 통계 기능별로 메서드를 나눠 정리했습니다 — main에 모든 코드를 쏟아붓는 대신 기능 하나에 메서드 하나씩을 대응시켜, 각 기능을 따로 테스트하고 최종 문제에서도 재사용할 수 있게 합니다.

    • sum·average는 누적 패턴(05 핵심 개념), max·min은 후보 비교 패턴을 그대로 메서드로 옮긴 것
    • countAtLeast는 조건 검색, bandCounts는 빈도 계산(값 → 인덱스) 패턴
    • collectBelow는 "조건 검색 + 새 배열 복사"를 함께 보여줌 — 배열은 크기가 고정이라 개수를 먼저 세고, 그 크기로 만들어, 다시 채우는 2단계 순회가 필요
    Java ScoreStatsComplete.java 
    public class ScoreStatsComplete {

    /** 합계: 1강의 누적 패턴. 원소가 n개면 누적 연산도 n번 — O(n) */
    static int sum(int[] data) {
        int total = 0;
        for (int i = 0; i < data.length; i++) {
            total = total + data[i];
        }
        return total;
    }

    /** 평균: 합계를 개수로 나눈다. (double) 캐스팅으로 소수점을 지킨다 */
    static double average(int[] data) {
        return (double) sum(data) / data.length;
    }

    /** 최댓값: 첫 원소를 후보로 두고, 더 큰 값을 만나면 후보를 교체한다 — O(n) */
    static int max(int[] data) {
        int candidate = data[0];
        for (int i = 1; i < data.length; i++) {
            if (data[i] > candidate) {
                candidate = data[i];
            }
        }
        return candidate;
    }

    /** 최솟값: 최댓값과 같은 구조에서 부등호 방향만 다르다 — O(n) */
    static int min(int[] data) {
        int candidate = data[0];
        for (int i = 1; i < data.length; i++) {
            if (data[i] < candidate) {
                candidate = data[i];
            }
        }
        return candidate;
    }

    /** 조건 검색: threshold점 이상인 원소의 개수 — O(n) */
    static int countAtLeast(int[] data, int threshold) {
        int count = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] >= threshold) {
                count++;
            }
        }
        return count;
    }

    /**
     * 조건 검색 + 배열 복사: limit 미만인 원소만 모아 "새 배열"로 반환한다.
     * 배열은 크기가 고정이므로 (1) 개수를 먼저 세고 (2) 그 크기로 만들어 (3) 채운다.
     */
    static int[] collectBelow(int[] data, double limit) {
        int count = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] < limit) count++;            // 1차 순회: 개수 세기
        }
        int[] result = new int[count];               // 정확한 크기의 새 배열
        int pos = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] < limit) {
                result[pos] = data[i];               // 2차 순회: 값 채우기
                pos++;
            }
        }
        return result;
    }

    /** 빈도 계산: 점수대별 인원을 카운팅 배열로 센다 — O(n) */
    static int[] bandCounts(int[] data) {
        int[] bands = new int[10];
        for (int i = 0; i < data.length; i++) {
            bands[data[i] / 10]++;
        }
        return bands;
    }

    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};
        double avg = average(scores);

        System.out.println("== 성적 통계 리포트 ==");
        System.out.println("학생 수   : " + scores.length + "명");
        System.out.println("합계      : " + sum(scores) + "점");
        System.out.printf("평균      : %.1f점%n", avg);
        System.out.println("최고점    : " + max(scores) + "점");
        System.out.println("최저점    : " + min(scores) + "점");
        System.out.println("80점 이상 : " + countAtLeast(scores, 80) + "명");

        int[] belowAvg = collectBelow(scores, avg);
        StringBuilder line = new StringBuilder();
        for (int i = 0; i < belowAvg.length; i++) {
            if (i > 0) line.append(", ");
            line.append(belowAvg[i]);
        }
        System.out.println("평균 미만 : " + belowAvg.length + "명 [" + line + "]");

        int[] bands = bandCounts(scores);
        System.out.print("점수대 분포: ");
        for (int band = 5; band <= 9; band++) {
            System.out.print(band * 10 + "점대 " + bands[band] + "명");
            if (band < 9) System.out.print(" | ");
        }
        System.out.println();
    }
}

    09잘못된 코드와 오류 찾기

    배열과 리스트에서 초보자가 가장 자주 만나는 오류 두 가지. 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 배열 범위 초과 (ArrayIndexOutOfBoundsException)

    Java BuggyIndexRange.java (오류 있음) 
    public class BuggyIndexRange {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};
        int sum = 0;

        // 모든 점수의 합계를 구하고 싶다
        for (int i = 0; i <= scores.length; i++) {
            sum = sum + scores[i];
        }

        System.out.println("합계 = " + sum);
    }
}
    발생하는 문제와 수정 방법 확인
    • 발생하는 문제: 합계가 출력되기 전에 프로그램이 예외로 죽음
    Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 8 out of bounds for length 8
	at BuggyIndexRange.main(BuggyIndexRange.java:8)
    • 오류가 나타나는 입력: 배열 길이와 무관하게 항상 발생 (길이 8이면 i = 8에서, 길이 100이면 i = 100에서 터짐)
    • 원인: 반복 조건이 i <= scores.length라서 마지막 회차에 i = 8이 되는데, 길이 8인 배열의 유효 인덱스는 0부터 7까지. 존재하지 않는 scores[8]에 접근하는 순간 Java가 ArrayIndexOutOfBoundsException을 던짐 — 1강의 off-by-one 오류가 배열에서는 "값이 틀리는" 정도가 아니라 "프로그램이 죽는" 사고가 됨
    • 수정 방법: 조건을 i < scores.length로 바꿈
    for (int i = 0; i < scores.length; i++) {
    sum = sum + scores[i];
}

    수정 후 출력: 합계 = 620. "0부터 시작하면 <, 1부터 시작하면 <="를 기계적으로 외우기보다, 마지막 유효 인덱스가 length - 1이라는 사실에서 조건을 끌어내는 습관을 들이세요.

    오류 2 — 순회 중 삭제로 인한 인덱스 밀림 (원소 건너뜀)

    import java.util.ArrayList;

public class BuggyRemoveWhileLoop {
    public static void main(String[] args) {
        ArrayList<Integer> scores = new ArrayList<>();
        scores.add(55);
        scores.add(58);
        scores.add(90);
        scores.add(45);
        scores.add(47);

            }

    발생하는 문제와 수정 방법 확인
    • 발생하는 문제: 60점 미만을 전부 지웠다고 생각했는데, 출력이 남은 점수: [58, 90, 47] — 58과 47이 살아남음 (기대: [90])
    • 오류가 나타나는 입력: 삭제 대상이 연달아 붙어 있을 때. [55, 58]처럼 지울 값이 이웃해 있으면 뒤의 것을 건너뜀 — 삭제 대상이 띄엄띄엄 있으면 우연히 맞아서, 테스트를 통과한 것처럼 보이는 것이 함정
    • 원인: remove(i)를 하면 뒤의 원소들이 한 칸씩 앞으로 밀려옴. i = 0에서 55를 지우는 순간 58이 0번 칸으로 이동하는데, 반복문은 다음 회차에 i = 1로 넘어가므로 0번 칸에 새로 온 58은 한 번도 검사받지 않음 — 45와 47에서도 같은 일이 반복
    • 수정 방법 1: 삭제한 회차에는 인덱스를 그대로 두어(i--) 밀려온 원소를 다시 검사
    for (int i = 0; i < scores.size(); i++) {
    if (scores.get(i) < 60) {
        scores.remove(i);
        i--;   // 밀려온 원소를 건너뛰지 않도록 한 칸 되돌린다
    }
}
    • 수정 방법 2 (더 안전): 뒤에서 앞으로 순회하면 삭제로 밀리는 것은 이미 검사를 끝낸 뒤쪽 원소들뿐이므로 건너뜀이 아예 생기지 않음
    for (int i = scores.size() - 1; i >= 0; i--) {
    if (scores.get(i) < 60) {
        scores.remove(i);
    }
}

    수정 후 출력: 남은 점수: [90]. "순회하면서 그 대상을 삭제"하는 코드는 항상 인덱스 밀림을 의심하세요. 같은 이유로 for-each 순회 중의 remove는 아예 예외(ConcurrentModificationException)를 던집니다.

    10복잡도 및 특성 분석

    복잡도 분석 = "데이터가 많아지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 어려운 수식 대신 "원소를 몇 번 건드리는가"만 세어 봅니다.

    입력 크기 — 무엇이 많아지는가?

    • 원소 수 n — 배열이나 리스트에 담긴 값의 개수 (예: 학생 수 8명)
    • 학생이 8명에서 200명, 100만 명으로 늘어날수록 일이 늘어남
    • 빈도 계산에서는 하나 더: 카운팅 배열의 칸 수 k (점수대 10칸이면 k = 10)

    주요 연산 — 무엇을 세는가?

    • 프로그램에서 가장 많이 반복되는 한 동작만 세면 충분
    • 합계: 더하기 sum = sum + scores[i] 한 번
    • 최댓값·최솟값: 후보와 비교 scores[i] > max 한 번
    • 조건 검색: 조건 검사 scores[i] >= 80 한 번
    • 어느 것이든 순회 한 바퀴에 원소 하나당 한 번 실행됨

    시간 복잡도 — 얼마나 오래 걸리는가?

    연산하는 일원소 8개일 때원소 100만 개일 때배열ArrayList
    인덱스로 읽기·쓰기위치 계산 한 번으로 바로 접근1번1번O(1)O(1)
    순회 (합계·평균·최대·최소·빈도)모든 원소를 한 번씩 방문8번100만 번O(n)O(n)
    조건 검색 (전체)원소마다 조건 검사8번100만 번O(n)O(n)
    끝에 추가배열: 더 큰 새 배열에 전부 옮김 / 리스트: 남는 칸에 넣음배열 8번 옮김 / 리스트 대개 1번배열 100만 번 옮김 / 리스트 대개 1번불가 (새 배열 복사 O(n))평균 O(1)
    맨 앞(중간) 삭제뒤의 원소를 한 칸씩 당김최대 7번 이동최대 약 100만 번 이동직접 밀어야 함 O(n)O(n)
    배열 복사원소를 한 칸씩 옮김8번100만 번O(n)O(n)
    • O(1)을 쉽게 말하면: 데이터가 아무리 많아도 일은 늘 한 번 — 사물함 번호만 알면 몇 개가 있든 바로 그 칸을 여는 것과 같음
    • O(n)을 쉽게 말하면: 데이터가 10배 늘면 일도 10배 — 출석부를 위에서부터 한 번 읽어 내려가는 것과 같음
    • ArrayList의 끝 추가가 "평균" O(1)인 이유: 리스트는 여유 칸을 미리 확보해 둠
      • 빈 칸이 있으면 넣기만 하면 끝 (1번)
      • 가득 차면 가끔 한 번 더 큰 곳으로 "이사"(전체 복사)하지만, 드물게 일어나므로 평균하면 한 번꼴
    • 중간 삭제가 O(n)인 이유: 줄 선 사람 중 맨 앞사람이 빠지면 뒤의 모든 사람이 한 걸음씩 앞으로 — 이 "밀림"이 오류 카드 2번의 원인

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 합계·평균·최댓값·최솟값·개수 세기: 기억 칸(sum, max, count) 몇 개뿐 — 학생이 늘어도 추가 메모리는 그대로, O(1)
    • 조건에 맞는 원소를 새 배열·리스트에 모으기: 최악의 경우 전부 조건에 맞으면 n개를 모두 담음, O(n)
    • 빈도 계산: 칸 수 k만큼의 카운팅 배열이 필요, O(k) — 점수대 10칸이면 학생이 100만 명이어도 10칸 그대로
    한 줄 정리 — 한 번 훑으면 O(n), 기억 칸은 몇 개면 충분
    • 오늘 배운 통계·검색·빈도는 모두 배열을 한 번 훑는 O(n), 추가 메모리는 기억 칸 몇 개(O(1)) 또는 칸 수 k(O(k))

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 통계 순회는 항상 n번: 합계·최댓값은 운이 좋아도 나빠도 끝까지 다 봐야 함 → 입력이 무엇이든 같은 횟수
      • 반면 "첫 번째로 80점 이상인 학생 찾기"처럼 1강의 조기 중단을 쓰면 빠르면 1번, 늦으면 n번
    • 한 번 훑을 때 여러 일을 같이: 합계·최대·최소를 한 바퀴에 처리하면 순회 3번이 1번 — Big-O는 똑같이 O(n)이지만 실제 시간은 줄어드는 실전 요령
    • 그릇 고르기가 곧 설계: 개수가 정해져 있으면 배열, 늘었다 줄었다 하면 ArrayList — 빈도 계산처럼 "값 → 칸 번호"로 세는 일에는 크기가 정해진 카운팅 배열이 딱 맞음
    • 다음 강의와 연결: 순회 + 조건 검사는 3강의 완전 탐색으로, 카운팅 배열의 "값 → 칸 번호" 발상은 3강의 해시로 이어짐

    import java.util.Arrays;
import java.util.IntSummaryStatistics;
import java.util.stream.Collectors;
import java.util.stream.IntStream;

/**
 * 2강 「람다·스트림 변경」.
 *
 * ScoreStatsComplete.java(실습 코드)를 같은 결과가 나오도록 람다와 스트림으로 다시 쓴 것이다.
 */
public class ModernizeSolution {

    /** 조건 검색: threshold점 이상인 원소의 개수 */
    static long countAtLeast(int[] data, int threshold) {
        return Arrays.stream(data)
                .filter(s -> s >= threshold)
                .count();
    }

    /** 조건 검색 + 배열 복사: limit 미만인 원소만 모아 새 배열로 반환한다. */
    static int[] collectBelow(int[] data, double limit) {
        return Arrays.stream(data)
                .filter(s -> s < limit)
                .toArray();
    }

    /** 빈도 계산: 점수대별 인원을 카운팅 배열로 센다. */
    static int[] bandCounts(int[] data) {
        int[] bands = new int[10];
        Arrays.stream(data).forEach(s -> bands[s / 10]++);
        return bands;
    }

    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};

        // 개수·합계·평균·최댓값·최솟값을 한 번의 순회로 구한다
        IntSummaryStatistics stat = Arrays.stream(scores).summaryStatistics();
        double avg = stat.getAverage();

        System.out.println("== 성적 통계 리포트 ==");
        System.out.println("학생 수   : " + stat.getCount() + "명");
        System.out.println("합계      : " + stat.getSum() + "점");
        System.out.printf("평균      : %.1f점%n", avg);
        System.out.println("최고점    : " + stat.getMax() + "점");
        System.out.println("최저점    : " + stat.getMin() + "점");
        System.out.println("80점 이상 : " + countAtLeast(scores, 80) + "명");

        int[] belowAvg = collectBelow(scores, avg);
        String line = Arrays.stream(belowAvg)
                .boxed()
                .map(String::valueOf)
                .collect(Collectors.joining(", "));
        System.out.println("평균 미만 : " + belowAvg.length + "명 [" + line + "]");

        int[] bands = bandCounts(scores);
        String distribution = IntStream.rangeClosed(5, 9)
                .boxed()
                .map(band -> band * 10 + "점대 " + bands[band] + "명")
                .collect(Collectors.joining(" | "));
        System.out.println("점수대 분포: " + distribution);
    }
}

    import java.util.ArrayList;

public class BookLoanApplication {

    /** 특정 회원의 대출 기록을 모두 찾아 출력한다 — 조건 검색, O(n) */
    static int printLoansOf(ArrayList<String> loans, String member) {
        int found = 0;
        for (int i = 0; i < loans.size(); i++) {
            String record = loans.get(i);              // 기록 형식: "회원:책제목"
            if (record.startsWith(member + ":")) {
                System.out.println("  " + i + "번 기록: " + record);
                found++;
            }
        }
        if (found == 0) {
            System.out.println("  (대출 기록 없음)");
        }
        return found;
    }

    /**
     * 반납 처리: record와 일치하는 기록 하나를 찾아 삭제한다.
     * ArrayList.remove(Object)가 내부에서 정확히 같은 일(선형탐색 + 첫 일치 삭제)을 한다 — O(n).
     */
    static boolean returnBook(ArrayList<String> loans, String record) {
        return loans.remove(record);
    }

    과제 안내

    이 문제는 수업 시간이 아니라 수업 후 과제로 진행합니다. 수업에서는 문제 배경과 시작 코드만 짚고 넘어가고, 나머지는 직접 완성해 오세요.

    문제 제목 — 성적 분석 프로그램 "GradeAnalyzer"

    문제 배경

    4번 섹션의 조교 이야기가 현실이 되었습니다. 교수님이 학생 8명의 이름과 점수를 넘기며 분석 리포트를 요청했습니다. 필요한 것은 합계, 평균, 최고점 학생, 최저점 학생, 그리고 조건별 명단 두 가지 — 80점 이상(우수)과 평균 미만(면담 대상) — 입니다. 점수만 다루면 되던 지금까지와 달리, 이번에는 이름과 점수가 한 몸이어야 합니다. "최고점은 93점"이 아니라 "최고점은 강지훈 93점"이라고 말해야 하니까요. 그래서 이름과 점수를 묶는 Student 클래스를 사용하고, 몇 명이 될지 모르는 조건별 명단은 ArrayList에 모읍니다. 오늘 배운 다섯 가지 순회 패턴을 전부 사용하는 종합 문제입니다.

    프로그램 목표

    Student 배열을 순회하며 합계·평균·최고점·최저점을 계산하고, 조건에 맞는 학생 명단을 ArrayList로 수집하여 분석 리포트를 출력하는 콘솔 프로그램을 완성합니다.

    필수 요구사항

    1. totalScore(Student[]) — 누적 패턴으로 전체 점수 합계를 반환한다.
    2. average(Student[]) — 평균을 double로 반환한다. (정수 나눗셈 함정 주의)
    3. findTop(Student[]) — 후보 비교 패턴으로 최고점 학생 객체를 반환한다.
    4. findBottom(Student[]) — 최저점 학생 객체를 반환한다.
    5. filterAtLeast(Student[], int) — 기준 점수 이상인 학생들을 ArrayList<Student>로 모아 반환한다.
    6. filterBelow(Student[], double) — 기준 미만인 학생들을 모아 반환한다. (평균 미만 명단에 사용)
    7. main에서 리포트를 예상 출력과 동일한 형식으로 출력한다.

    제한 조건

    • 학생 수는 1명 이상 100명 이하, 점수는 0 이상 100 이하의 정수.
    • 합계·최댓값·최솟값·검색은 반복문으로 직접 구현한다 — Arrays.sort(), Collections.max(), stream() 등 라이브러리 대체 금지.
    • 조건별 명단은 반드시 ArrayList<Student>에 모은다. (몇 명일지 미리 알 수 없으므로)
    • 동점이 있으면 먼저 나온 학생을 최고점/최저점으로 선택한다.
    • 평균 "미만"은 <이다 — 평균과 같은 점수는 명단에 넣지 않는다.

    구현 단계 안내

    1. Student 클래스(이름 + 점수)와 시작 코드의 구조를 먼저 읽고 이해한다.
    2. totalScore부터 완성한다 — 실습 코드의 sum 메서드와 같은 누적 패턴이며, data[i] 대신 students[i].score를 더한다.
    3. average를 완성하고 77.5가 나오는지 확인한다. 77.0이 나오면 정수 나눗셈 함정이다.

    Java GradeAnalyzerSolution.java 
    import java.util.ArrayList;

public class GradeAnalyzerSolution {

    /** 학생 한 명의 데이터: 이름 + 점수 */
    static class Student {
        String name;
        int score;

        Student(String name, int score) {
            this.name = name;
            this.score = score;
        }
    }

    /** 1) 전체 점수 합계 — 1강의 누적 패턴, O(n) */
    static int totalScore(Student[] students) {
        int sum = 0;
        for (int i = 0; i < students.length; i++) {
            sum = sum + students[i].score;
        }
        return sum;
    }

    /** 2) 평균 점수 — (double) 캐스팅으로 소수점을 지킨다 */
    static double average(Student[] students) {
        return (double) totalScore(students) / students.length;
    }

    /** 3) 최고점 학생 — 후보 비교 패턴, O(n) */
    static Student findTop(Student[] students) {
        Student top = students[0];
        for (int i = 1; i < students.length; i++) {
            if (students[i].score > top.score) {
                top = students[i];
            }
        }
        return top;
    }

    /** 4) 최저점 학생 — 부등호 방향만 반대, O(n) */
    static Student findBottom(Student[] students) {
        Student bottom = students[0];
        for (int i = 1; i < students.length; i++) {
            if (students[i].score < bottom.score) {
                bottom = students[i];
            }
        }
        return bottom;
    }

    /** 5) threshold점 이상인 학생 명단 — 조건 검색 + ArrayList에 수집, O(n) */
    static ArrayList<Student> filterAtLeast(Student[] students, int threshold) {
        ArrayList<Student> result = new ArrayList<>();
        for (int i = 0; i < students.length; i++) {
            if (students[i].score >= threshold) {
                result.add(students[i]);   // 몇 명이 될지 몰라도 리스트는 스스로 자란다
            }
        }
        return result;
    }

    /** 6) limit점 미만인 학생 명단 — 같은 구조, 조건만 다름, O(n) */
    static ArrayList<Student> filterBelow(Student[] students, double limit) {
        ArrayList<Student> result = new ArrayList<>();
        for (int i = 0; i < students.length; i++) {
            if (students[i].score < limit) {
                result.add(students[i]);
            }
        }
        return result;
    }

        for (int i = 0; i < list.size(); i++) {
            if (i > 0) line.append(", ");
            Student s = list.get(i);

        }
        System.out.println(title + " (" + list.size() + "명): " + line);
    }

            new Student("정다은", 78), new Student("강지훈", 93),

        printStudents("평균 미만", filterBelow(students, avg));

    구현 순서와 핵심 알고리즘 적용 부분

    1. totalScore는 실습 코드의 sum 메서드가 쓰던 누적 패턴에서 더하는 대상만 scores[i] → students[i].score로 바뀌었습니다. 패턴은 데이터의 모양이 바뀌어도 그대로라는 것이 이 문제의 핵심 교훈입니다.
    2. findTop의 후보 변수가 int가 아니라 Student인 것에 주목하세요. 점수로 비교하되 객체 전체를 기억해야 "강지훈 93점"이라고 말할 수 있습니다.
    3. 동점 처리: 조건이 >(초과)이므로 같은 점수에서는 후보가 바뀌지 않아 자연스럽게 "먼저 나온 학생"이 유지됩니다. >=로 쓰면 뒤 학생이 선택되어 요구사항 위반입니다.
    4. 조건별 명단은 "몇 명일지 모른다" → ArrayList, 반면 학생 원본 데이터는 "8명으로 확정" → 배열. 그릇 선택의 기준이 코드에 그대로 드러납니다.

    복잡도 분석

    • 여섯 메서드 모두 순회 1번씩 — 각각 O(n), 전체도 O(n)입니다. (상수 배만 다릅니다)
    • 공간: 통계 계산은 O(1), 조건별 명단은 최악(전원 해당)일 때 O(n)입니다.
    • average가 내부에서 totalScore를 다시 부르므로 합계 순회가 2번 일어납니다. main에서 합계를 한 번만 구해 재사용하면 순회 1번을 아낄 수 있습니다 — Big-O는 같지만 좋은 습관입니다.

    자주 발생하는 오류

    • 평균이 77.0으로 나오는 경우 — (double) 캐스팅 누락 (정수 나눗셈).
    • findTop에서 top.score가 아니라 top과 비교하려다 컴파일 오류 — 객체끼리는 >로 비교할 수 없고, 비교 기준 필드(score)를 명시해야 합니다.

    16오늘의 핵심 정리

    • 배열은 같은 자료형을 연속으로 담는 고정 크기 그릇이다. 인덱스는 0부터, 마지막은 length - 1, 접근은 O(1)이다.
    • ArrayList는 크기 관리를 대신해 주는 가변 그릇이다. 끝 추가는 평균 O(1), 중간 삭제는 밀림 때문에 O(n)이며, 기본형은 래퍼(Integer)로 담는다.
    • 모든 데이터 처리의 뼈대는 순회다: for (int i = 0; i < length; i++) 안의 "할 일"만 바꾸면 누적(합계·평균), 후보 비교(최대·최소), 조건 검색, 빈도 계산이 전부 만들어진다 — 모두 O(n).
    • 빈도 계산은 값을 인덱스로 바꿔 카운팅 배열에 세는 기법이다 — 3강 해시, 4강 계수 정렬의 씨앗.
    • 배열 변수의 대입(b = a)은 참조 복사다. 진짜 복사는 새 배열을 만들어 O(n) 순회로 옮겨야 한다.
    • 두 가지 대표 사고: 범위 초과(i <= length → 예외)와 순회 중 삭제(인덱스 밀림 → 원소 건너뜀). 각각 < length와 역방향 순회(또는 i--)로 예방한다.

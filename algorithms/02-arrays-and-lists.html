Data Processing with Arrays and Lists

데이터가 한두 개일 때는 변수로 충분하지만, 학생 8명·회원 800명의 데이터를 다루려면 값들을 한 줄로 모아 두는 그릇이 필요합니다. 이번 강의에서는 그 그릇인 배열과 리스트(ArrayList)를 배우고, 순회 한 번으로 합계·평균·최댓값·최솟값·조건 검색·빈도 계산까지 해내는 데이터 처리의 기본기를 익힙니다.

이 강의의 목차

    01강의 소개

    1강에서 우리는 "1부터 n까지의 합"을 구했습니다. 그때의 데이터는 규칙이 있는 연속된 수였습니다. 하지만 현실의 데이터 — 학생들의 시험 점수, 도서관의 대출 기록, 쇼핑몰의 주문 내역 — 에는 그런 공식이 없습니다. 임의의 데이터를 다루려면 데이터를 담을 그릇과, 그릇을 처음부터 끝까지 훑는 순회가 필요합니다.

    이번 강의에서는 Java의 두 가지 대표 그릇을 배웁니다. 크기가 고정된 배열(array)과, 필요할 때마다 자라는 리스트(ArrayList)입니다. 그리고 이 그릇 위에서 프로그래밍 전체를 통틀어 가장 자주 쓰이는 다섯 가지 순회 패턴 — 누적(합계·평균), 후보 비교(최댓값·최솟값), 조건 검색, 빈도 계산, 배열 복사 — 를 하나씩 구현합니다. 마지막에는 학생 이름과 점수를 함께 다루는 성적 분석 프로그램을 직접 완성합니다.

    04실제 문제 상황

    여러분이 학과 조교가 되어 알고리즘 과목의 중간고사 성적 처리를 맡았다고 상상해 봅시다. 교수님이 말합니다. "8명 점수인데, 합계랑 평균, 최고점·최저점, 그리고 80점 이상인 학생이 몇 명인지 알려줘요." 처음에는 int score1, score2, score3, ...처럼 변수 8개를 만들었는데, 합계 한 줄에 변수 이름을 8번 쓰다 보니 벌써 손이 아픕니다. 그런데 다음 주에 교수님이 다시 말합니다. "수강 정정 기간이라 학생이 3명 더 들어왔어요. 아, 그리고 다른 분반 200명 것도 부탁해요." 변수 200개를 만들 수는 없습니다. 값이 몇 개든 하나의 이름으로 묶고, 반복문 하나로 전부 처리하는 방법이 필요합니다. 그것이 오늘 배우는 배열과 리스트입니다.

    오늘의 핵심 질문

    데이터가 몇 개가 되든 같은 코드로 합계·평균·최대·최소·검색·빈도를 처리하려면 데이터를 어떻게 저장하고, 어떻게 훑어야 할까?

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 작은 데이터로 손으로 풀어 봅니다. 점수 5개만 사용합시다: 72, 85, 90, 66, 78. 목표는 종이 한 장으로 합계와 최고점을 동시에 구하는 것입니다.

    합계와 최고점을 한 번에 구하기

    STEP 1

    종이에 기억 칸 두 개를 만듭니다. 누적 합 sum = 0, 그리고 최고점 후보 max = 72 (첫 번째 점수)로 시작합니다.

    질문: 최고점 후보는 왜 0이 아니라 첫 번째 점수로 시작할까요?

    점수가 0~100이라면 0으로 시작해도 우연히 맞습니다. 하지만 데이터가 영하의 온도(-5, -3, -9)라면 max = 0은 실제로 존재하지도 않는 값이 "최댓값"으로 남습니다. 데이터 안에 실제로 있는 값(첫 원소)에서 시작해야 어떤 데이터에도 안전합니다. 반면 누적 합은 "아직 아무것도 안 더한 상태"가 정확히 0이므로 0에서 시작합니다.

    STEP 2

    점수를 앞에서부터 하나씩 봅니다. 볼 때마다 두 가지 일을 합니다: ① sum에 더한다 ② max와 비교해 더 크면 후보를 바꾼다.
    1번째(72): sum = 72, max는 72 그대로. 2번째(85): sum = 157, 85 > 72이므로 max = 85. 3번째(90): sum = 247, 90 > 85이므로 max = 90.

    질문: 4번째(66)와 5번째(78)까지 마치면 sum과 max는 각각 얼마인가요?

    4번째(66): sum = 247 + 66 = 313, 66 ≤ 90이므로 max는 90 유지. 5번째(78): sum = 313 + 78 = 391, 78 ≤ 90이므로 max는 90으로 확정. 평균은 391 ÷ 5 = 78.2입니다. 순회를 한 번만 했는데 합계·평균·최고점을 모두 얻었습니다.

    STEP 3

    이번에는 조건 검색입니다. 같은 점수를 다시 앞에서부터 보며 "80점 이상인가?"만 묻고, 맞으면 따로 적습니다.

    질문: 80점 이상은 몇 개이고, "몇 개가 나올지"를 보기 전에 미리 알 수 있었나요?

    85와 90, 2개입니다. 그리고 끝까지 보기 전에는 몇 개인지 미리 알 수 없습니다. 이것이 뒤에서 배울 중요한 차이로 이어집니다 — 결과가 몇 개일지 모를 때는 크기 고정인 배열보다 스스로 자라는 ArrayList에 모으는 것이 편합니다.

    STEP 4

    마지막으로 빈도 계산입니다. "점수대별로 몇 명인가?"를 세기 위해 종이에 50점대~90점대 칸을 미리 그려 두고, 점수를 하나 볼 때마다 해당 칸에 바를 정(正)자를 긋습니다. 72 → 70점대 칸, 85 → 80점대 칸, 90 → 90점대 칸, 66 → 60점대 칸, 78 → 70점대 칸.

    질문: 이 "칸을 미리 그려 두고 긋기" 방식을 프로그램으로 옮기면 무엇이 될까요?

    칸들이 곧 카운팅 배열 int[] bandCount = new int[10]이고, "해당 칸에 긋기"가 bandCount[점수 / 10]++입니다. 점수 72는 72 / 10 = 7이므로 7번 칸(70점대)이 1 늘어납니다. 값 자체를 인덱스로 바꿔서 세는 이 기법은 3강의 해시, 4강의 계수 정렬로 확장됩니다.

    지금 손으로 한 이 과정 — 기억 칸을 두고, 앞에서부터 하나씩 보며, 칸을 갱신하는 것 — 이 오늘 배울 모든 코드의 전부입니다. 이제 이 "기억 칸"과 "하나씩 보기"를 Java의 언어로 옮겨 봅시다.

    06핵심 개념

    배열 — 같은 자료형을 줄지어 담는 고정 크기의 그릇

    배열(array)은 같은 자료형의 값들을 메모리에 연속으로 줄지어 담는 구조입니다. int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};처럼 만들면 8칸짜리 그릇이 생기고, 각 칸에는 인덱스(index)라는 번호가 붙습니다.

    배열 scores의 인덱스와 값
    인덱스01234567
    값7285906678935581
    • 인덱스는 0부터 시작합니다. 인덱스는 "몇 번째"가 아니라 "시작 지점에서 몇 칸 떨어져 있는가"입니다. 첫 칸은 0칸 떨어져 있으므로 0입니다.
    • 첫 원소는 scores[0], 마지막 원소는 scores[scores.length - 1]입니다. 길이가 8이면 유효한 인덱스는 0부터 7까지 — 8은 없습니다!
    • 인덱스 접근(scores[i])은 위치 계산 한 번으로 끝나는 O(1) 연산입니다. 1강 응용 예제의 "직접 접근"이 빨랐던 이유가 바로 이것입니다.
    • 한 번 만든 배열의 크기는 바꿀 수 없습니다. 9번째 값을 넣으려면 더 큰 배열을 새로 만들어 값을 옮겨야 합니다.

    데이터 순회 — 처음부터 끝까지 하나씩 방문하기

    배열의 모든 원소를 한 번씩 방문하는 것을 순회(traversal)라고 합니다. 순회의 표준 형태는 다음 한 줄이며, 오늘 나오는 모든 코드가 이 뼈대 위에 서 있습니다. 

    for (int i = 0; i < scores.length; i++) {
    // scores[i]를 가지고 할 일
}

    조건이 i <= scores.length가 아니라 i < scores.length인 것에 주의하세요. 마지막 유효 인덱스가 length - 1이기 때문입니다. 순회 뼈대 안의 "할 일"만 바꾸면 합계, 최댓값, 검색, 빈도가 전부 만들어집니다.

    패턴기억 칸(변수)순회 안에서 할 일

    최댓값 (후보 비교)max = scores[0]if (scores[i] > max) max = scores[i]
    최솟값 (후보 비교)min = scores[0]if (scores[i] < min) min = scores[i]

    리스트(ArrayList) — 필요할 때마다 자라는 그릇

    ArrayList는 배열을 감싸서 "크기 관리"를 대신해 주는 클래스입니다. 원소를 추가하면 스스로 커지고, 삭제하면 빈틈을 스스로 메웁니다. 

    import java.util.ArrayList;

ArrayList<String> names = new ArrayList<>();   // 빈 리스트 생성
names.add("김하늘");          // 끝에 추가
names.add("이준호");
names.get(0);                 // 읽기: "김하늘" (배열의 names[0]에 해당)
names.set(1, "이준서");       // 바꾸기 (배열의 names[1] = ... 에 해당)
names.remove(0);              // 0번 삭제 — 뒤 원소들이 한 칸씩 앞으로 밀려온다
names.size();                 // 현재 크기 (배열의 length에 해당)
    • 꺾쇠 안의 <String>은 "이 리스트에는 String만 담는다"는 제네릭 선언입니다.
    • 제네릭에는 기본형을 쓸 수 없습니다. ArrayList<int>는 오류이고, 래퍼 클래스를 써서 ArrayList<Integer>로 선언합니다.
    • 끝에 추가(add)는 평균 O(1)이지만, 중간 삭제(remove)는 O(n)입니다 — 삭제된 칸을 메우기 위해 뒤의 모든 원소가 한 칸씩 이동하기 때문입니다. 이 "밀림"이 오류 카드 2번의 주인공입니다.

    배열 복사 — 이름 복사와 진짜 복사

    배열 변수에는 값이 아니라 배열이 있는 곳의 주소(참조)가 담깁니다. 그래서 int[] b = a;는 그릇을 하나 더 만드는 것이 아니라 같은 그릇에 이름표를 하나 더 붙이는 것입니다. b[0]을 바꾸면 a[0]도 바뀝니다! 진짜 복사는 새 배열을 만들고 순회하며 값을 옮겨야 합니다. 

    int[] a = {1, 2, 3};

int[] b = a;                       // 이름 복사(참조 복사): 같은 배열을 가리킨다
b[0] = 99;                         // a[0]도 99가 된다!

int[] c = new int[a.length];       // 진짜 복사: 새 배열을 만들고
for (int i = 0; i < a.length; i++) {
    c[i] = a[i];                   // 값을 한 칸씩 옮긴다 — O(n)
}
c[0] = 7;                          // a에는 아무 영향이 없다
    라이브러리 한 줄 메모

    실무에서는 java.util.Arrays.copyOf(a, a.length) 한 줄로 복사할 수 있습니다. 다만 그 한 줄의 안에서도 결국 위와 같은 O(n) 순회가 일어납니다 — 원리를 알고 쓰는 것과 모르고 쓰는 것은 다릅니다.

    07단계별 동작 과정

    배열을 한 번 순회하며 누적 합과 최댓값을 동시에 갱신하는 과정을 단계별로 확인해 봅시다. 다음 단계 ▶ 버튼으로 한 단계씩 진행하거나 자동 실행을 사용하세요. 지금 보고 있는 칸은 앰버색(비교 중), 이미 지나간 칸은 초록색(확정/완료)으로 표시됩니다. 새 데이터 버튼을 누르면 랜덤 점수 배열로 다시 실행할 수 있습니다.

    카운터를 보세요. 원소를 하나 지날 때마다 누적 연산 1번 + 최댓값 비교 1번이 정확히 일어납니다. 원소가 n개면 비교도 n번 — 순회의 시간 복잡도가 O(n)이라는 사실을 1강의 연산 카운터 기법으로 다시 확인한 것입니다.

    sum ← 0                       // 누적 합 (1강의 누적 패턴)
    max ← scores[0]               // 최댓값 후보: 데이터 안의 실제 값에서 시작
    min ← scores[0]               // 최솟값 후보
    i를 0부터 scores의 길이 - 1까지 반복:
        sum ← sum + scores[i]     // 핵심 연산 1: 누적 (n번 실행)
        만약 scores[i] > max 이면: max ← scores[i]   // 핵심 연산 2: 후보 비교
        만약 scores[i] < min 이면: min ← scores[i]
    sum, max, min을 반환한다
    Pseudo 조건 검색과 빈도 계산 
    알고리즘 CountAtLeast(scores, threshold)
    count ← 0
    i를 0부터 scores의 길이 - 1까지 반복:
        만약 scores[i] ≥ threshold 이면: count ← count + 1
    count를 반환한다

알고리즘 BandFrequency(scores)
    bands ← 크기 10의 새 배열 (모두 0)      // 점수대별 칸을 미리 만든다
    i를 0부터 scores의 길이 - 1까지 반복:
        bands[scores[i] ÷ 10] ← bands[scores[i] ÷ 10] + 1   // 값 → 인덱스 변환
    bands를 반환한다

    두 의사코드 모두 뼈대는 같은 순회이고, 순회 안의 "할 일"만 다릅니다. 특히 BandFrequency의 "값을 인덱스로 바꿔서 센다"는 발상은 손 풀이 STEP 4의 바를 정(正)자 칸과 정확히 같은 절차입니다.

    구현 3단계 — 순회로 합계와 평균 구하기

    핵심 연산을 순회 뼈대로 감쌉니다. 1강의 누적 패턴 sum = sum + ...과 연산 카운터가 그대로 다시 등장하는 것을 확인하세요. 달라진 것은 더하는 대상이 i(연속된 수)에서 scores[i](임의의 데이터)로 바뀐 것뿐입니다.

    Java Step3SumAverage.java 
    public class Step3SumAverage {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};

        int sum = 0;              // 1강의 누적 패턴: sum = sum + ... 을 그대로 사용한다
        int operationCount = 0;   // 1강의 연산 카운터 기법도 그대로 사용한다

        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];   // 핵심 연산: 원소 하나를 누적
            operationCount++;
        }

        double average = (double) sum / scores.length;   // int / int 함정 주의!

        System.out.println("합계 = " + sum);
        System.out.println("평균 = " + average);
        System.out.println("누적 연산 실행 횟수 = " + operationCount
                + " (데이터 " + scores.length + "개 → 연산 " + operationCount + "번, O(n))");
    }
}

    구현 4단계 — 최댓값·최솟값·조건 검색·빈도 계산으로 확장

    같은 순회 뼈대에 "할 일"을 하나씩 추가합니다. 합계·최댓값·최솟값은 한 번의 순회 안에서 동시에 처리하고, 조건 검색과 빈도 계산은 별도의 순회로 구현합니다.

    Java Step4Statistics.java 
    public class Step4Statistics {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};

        // 1) 합계·최댓값·최솟값을 "한 번의 순회"로 동시에 구한다
        int sum = 0;
        int max = scores[0];   // 첫 원소를 최댓값 후보로 시작
        int min = scores[0];   // 첫 원소를 최솟값 후보로 시작
        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];
            if (scores[i] > max) max = scores[i];   // 후보 비교 (최댓값)
            if (scores[i] < min) min = scores[i];   // 후보 비교 (최솟값)
        }
        System.out.println("합계 = " + sum + ", 최고점 = " + max + ", 최저점 = " + min);

        // 2) 조건 검색: 80점 이상인 점수를 모두 찾는다
        System.out.print("80점 이상: ");
        int passCount = 0;
        for (int i = 0; i < scores.length; i++) {
            if (scores[i] >= 80) {
                System.out.print("scores[" + i + "]=" + scores[i] + " ");
                passCount++;
            }
        }
        System.out.println("→ " + passCount + "명");

        // 3) 빈도 계산: 점수대(50점대~90점대)별 학생 수를 카운팅 배열로 센다
        int[] bandCount = new int[10];        // bandCount[7] = 70점대 학생 수
        for (int i = 0; i < scores.length; i++) {
            bandCount[scores[i] / 10]++;      // 예: 72 / 10 = 7 → 70점대 칸을 1 증가
        }
        for (int band = 5; band <= 9; band++) {
            System.out.println(band * 10 + "점대: " + bandCount[band] + "명");
        }
    }
}

    10완성 Java 코드

    지금까지의 조각을 모아 통계 기능별 메서드로 정리한 완성 프로그램입니다. main에 모든 코드를 쏟아붓는 대신, 기능 하나 = 메서드 하나로 분리하면 각 기능을 따로 테스트할 수 있고 최종 문제에서도 그대로 재사용할 수 있습니다. collectBelow는 "조건 검색 + 새 배열 복사"를 함께 보여 줍니다 — 배열은 크기가 고정이라 개수를 먼저 세고, 그 크기로 만들어, 다시 채우는 2단계 순회가 필요하다는 점에 주목하세요.

    Java ScoreStatsComplete.java 
    public class ScoreStatsComplete {

    /** 합계: 1강의 누적 패턴. 원소가 n개면 누적 연산도 n번 — O(n) */
    static int sum(int[] data) {
        int total = 0;
        for (int i = 0; i < data.length; i++) {
            total = total + data[i];
        }
        return total;
    }

    /** 평균: 합계를 개수로 나눈다. (double) 캐스팅으로 소수점을 지킨다 */
    static double average(int[] data) {
        return (double) sum(data) / data.length;
    }

    /** 최댓값: 첫 원소를 후보로 두고, 더 큰 값을 만나면 후보를 교체한다 — O(n) */
    static int max(int[] data) {
        int candidate = data[0];
        for (int i = 1; i < data.length; i++) {
            if (data[i] > candidate) {
                candidate = data[i];
            }
        }
        return candidate;
    }

    /** 최솟값: 최댓값과 같은 구조에서 부등호 방향만 다르다 — O(n) */
    static int min(int[] data) {
        int candidate = data[0];
        for (int i = 1; i < data.length; i++) {
            if (data[i] < candidate) {
                candidate = data[i];
            }
        }
        return candidate;
    }

    /** 조건 검색: threshold점 이상인 원소의 개수 — O(n) */
    static int countAtLeast(int[] data, int threshold) {
        int count = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] >= threshold) {
                count++;
            }
        }
        return count;
    }

    /**
     * 조건 검색 + 배열 복사: limit 미만인 원소만 모아 "새 배열"로 반환한다.
     * 배열은 크기가 고정이므로 (1) 개수를 먼저 세고 (2) 그 크기로 만들어 (3) 채운다.
     */
    static int[] collectBelow(int[] data, double limit) {
        int count = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] < limit) count++;            // 1차 순회: 개수 세기
        }
        int[] result = new int[count];               // 정확한 크기의 새 배열
        int pos = 0;
        for (int i = 0; i < data.length; i++) {
            if (data[i] < limit) {
                result[pos] = data[i];               // 2차 순회: 값 채우기
                pos++;
            }
        }
        return result;
    }

    /** 빈도 계산: 점수대별 인원을 카운팅 배열로 센다 — O(n) */
    static int[] bandCounts(int[] data) {
        int[] bands = new int[10];
        for (int i = 0; i < data.length; i++) {
            bands[data[i] / 10]++;
        }
        return bands;
    }

    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};
        double avg = average(scores);

        System.out.println("== 성적 통계 리포트 ==");
        System.out.println("학생 수   : " + scores.length + "명");
        System.out.println("합계      : " + sum(scores) + "점");
        System.out.printf("평균      : %.1f점%n", avg);
        System.out.println("최고점    : " + max(scores) + "점");
        System.out.println("최저점    : " + min(scores) + "점");
        System.out.println("80점 이상 : " + countAtLeast(scores, 80) + "명");

        int[] belowAvg = collectBelow(scores, avg);
        StringBuilder line = new StringBuilder();
        for (int i = 0; i < belowAvg.length; i++) {
            if (i > 0) line.append(", ");
            line.append(belowAvg[i]);
        }
        System.out.println("평균 미만 : " + belowAvg.length + "명 [" + line + "]");

        int[] bands = bandCounts(scores);
        System.out.print("점수대 분포: ");
        for (int band = 5; band <= 9; band++) {
            System.out.print(band * 10 + "점대 " + bands[band] + "명");
            if (band < 9) System.out.print(" | ");
        }
        System.out.println();
    }
}

    3회차까지의 값(sum 247, max 90)이 손 풀이 STEP 2와 정확히 일치하고, max가 72 → 85 → 90 → 93으로, min이 72 → 66 → 55로 갱신되는 순간이 시각화의 앰버색 칸과 같은 위치입니다. 손 풀이 = 시각화 = 코드가 같은 절차임을 확인했습니다.

    12잘못된 코드와 오류 찾기

    배열과 리스트에서 초보자가 가장 자주 만나는 오류 두 가지입니다. 먼저 코드를 읽고 무엇이 잘못됐는지 스스로 찾아본 뒤 해설을 여세요.

    오류 1 — 배열 범위 초과 (ArrayIndexOutOfBoundsException)

    Java BuggyIndexRange.java (오류 있음) 
    public class BuggyIndexRange {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81};
        int sum = 0;

        // 모든 점수의 합계를 구하고 싶다
        for (int i = 0; i <= scores.length; i++) {
            sum = sum + scores[i];
        }

        System.out.println("합계 = " + sum);
    }
}
    발생하는 문제와 수정 방법 확인

    발생하는 문제: 합계가 출력되기 전에 프로그램이 예외로 죽습니다.

    Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 8 out of bounds for length 8
	at BuggyIndexRange.main(BuggyIndexRange.java:8)

    오류가 나타나는 입력: 배열 길이와 무관하게 항상 발생합니다. (길이 8이면 i = 8에서, 길이 100이면 i = 100에서 터집니다.)

    원인: 반복 조건이 i <= scores.length라서 마지막 회차에 i = 8이 되는데, 길이 8인 배열의 유효 인덱스는 0부터 7까지입니다. 존재하지 않는 scores[8]에 접근하는 순간 Java가 ArrayIndexOutOfBoundsException을 던집니다. 1강의 off-by-one 오류가 배열에서는 "값이 틀리는" 정도가 아니라 "프로그램이 죽는" 사고가 됩니다.

    수정 방법: 조건을 i < scores.length로 바꿉니다.

    for (int i = 0; i < scores.length; i++) {
    sum = sum + scores[i];
}

    수정 후 출력: 합계 = 620. "0부터 시작하면 <, 1부터 시작하면 <="를 기계적으로 외우기보다, 마지막 유효 인덱스가 length - 1이라는 사실에서 조건을 끌어내는 습관을 들이세요.

    오류 2 — 순회 중 삭제로 인한 인덱스 밀림 (원소 건너뜀)

    Java BuggyRemoveWhileLoop.java (오류 있음) 
    import java.util.ArrayList;

public class BuggyRemoveWhileLoop {
    public static void main(String[] args) {
        ArrayList<Integer> scores = new ArrayList<>();
        scores.add(55);
        scores.add(58);
        scores.add(90);
        scores.add(45);
        scores.add(47);

        // 60점 미만인 점수를 모두 삭제하고 싶다
        for (int i = 0; i < scores.size(); i++) {
            if (scores.get(i) < 60) {
                scores.remove(i);
            }
        }

        System.out.println("남은 점수: " + scores);
    }
}
    발생하는 문제와 수정 방법 확인

    발생하는 문제: 60점 미만을 전부 지웠다고 생각했는데, 출력이 남은 점수: [58, 90, 47] — 58과 47이 살아남았습니다. (기대: [90])

    오류가 나타나는 입력: 삭제 대상이 연달아 붙어 있을 때. [55, 58]처럼 지울 값이 이웃해 있으면 뒤의 것을 건너뜁니다. 삭제 대상이 띄엄띄엄 있으면 우연히 맞아서, 테스트를 통과한 것처럼 보이는 것이 함정입니다.

    원인: remove(i)를 하면 뒤의 원소들이 한 칸씩 앞으로 밀려옵니다. i = 0에서 55를 지우는 순간 58이 0번 칸으로 이동하는데, 반복문은 다음 회차에 i = 1로 넘어가므로 0번 칸에 새로 온 58은 한 번도 검사받지 않습니다. 45와 47에서도 같은 일이 반복됩니다.

    수정 방법 1: 삭제한 회차에는 인덱스를 그대로 두어(i--) 밀려온 원소를 다시 검사합니다.

    for (int i = 0; i < scores.size(); i++) {
    if (scores.get(i) < 60) {
        scores.remove(i);
        i--;   // 밀려온 원소를 건너뛰지 않도록 한 칸 되돌린다
    }
}

    수정 방법 2 (더 안전): 뒤에서 앞으로 순회하면 삭제로 밀리는 것은 이미 검사를 끝낸 뒤쪽 원소들뿐이므로 건너뜀이 아예 생기지 않습니다.

    for (int i = scores.size() - 1; i >= 0; i--) {
    if (scores.get(i) < 60) {
        scores.remove(i);
    }
}

    수정 후 출력: 남은 점수: [90]. "순회하면서 그 대상을 삭제"하는 코드는 항상 인덱스 밀림을 의심하세요. 같은 이유로 for-each 순회 중의 remove는 아예 예외(ConcurrentModificationException)를 던집니다.

    13복잡도 및 특성 분석

    입력 크기

    n은 배열 또는 리스트에 담긴 원소의 개수입니다. (예: 학생 수 8)

    주요 연산

    통계 알고리즘의 핵심 연산은 원소 하나에 대한 처리 — 누적 sum = sum + scores[i], 후보 비교 scores[i] > max, 조건 검사 scores[i] >= 80 — 이고, 어느 것이든 순회 한 바퀴에 원소당 한 번 실행됩니다.

    시간 복잡도

    연산배열ArrayList이유
    인덱스로 읽기·쓰기O(1)O(1)위치 계산 한 번으로 바로 접근
    순회 (합계·평균·최대·최소·빈도)O(n)O(n)모든 원소를 정확히 한 번씩 방문
    조건 검색 (전체)O(n)O(n)조건 검사를 원소마다 수행
    끝에 추가불가 (새 배열 복사 O(n))평균 O(1)리스트는 여유 공간을 미리 확보
    중간 삭제직접 밀어야 함 O(n)O(n)뒤의 원소가 모두 한 칸씩 이동
    배열 복사O(n)O(n)원소를 한 칸씩 옮김

    공간 복잡도

    • 합계·평균·최댓값·최솟값·개수 세기: 기억 칸 몇 개만 쓰므로 O(1).
    • 조건에 맞는 원소를 새 배열/리스트에 모으기: 최악의 경우 전부 모이므로 O(n).
    • 빈도 계산: 값의 범위 크기 k만큼의 카운팅 배열이 필요하므로 O(k). (점수대 10칸이면 k = 10 — n과 무관하게 고정)

    알고리즘 특성

    • 순회는 정확히 n번: 통계 순회는 입력이 무엇이든 항상 n번 일합니다 — 최선과 최악이 같습니다. 반면 조건 검색에 1강의 조기 중단을 결합하면("첫 번째로 80점 이상인 학생 찾기") 최선 1번, 최악 n번이 됩니다.
    • 한 순회에 여러 일: 합계·최대·최소를 한 바퀴에 처리하면 순회 3번이 1번이 됩니다. Big-O는 같아도 상수 배가 줄어드는 실전 최적화입니다.
    • 그릇 선택이 곧 설계: 개수가 고정이면 배열, 변하면 ArrayList. 빈도 계산처럼 "값 → 인덱스" 규칙을 쓸 때는 크기가 확정된 카운팅 배열이 정확히 맞는 도구입니다.
    • 다음 강의와의 연결: 순회 + 조건 검사가 3강의 완전 탐색으로, 카운팅 배열의 "값 → 인덱스" 발상이 3강의 해시로 확장됩니다.

    학과 도서관의 대출 기록을 관리하는 프로그램을 만듭니다. 대출과 반납이 수시로 일어나므로 기록의 개수가 계속 변합니다 — 이 지점에서 배열과 리스트의 차이가 실감 나게 드러납니다. 배열이라면 다섯 칸이 가득 찬 순간 여섯 번째 대출을 받을 수 없어서 더 큰 배열을 만들어 복사하는 코드를 직접 짜야 하지만, ArrayList는 add 한 줄로 끝납니다. 요구 기능은 세 가지입니다: 신규 대출 추가, 특정 회원의 대출 기록 검색, 반납 처리(삭제).

    데이터 모델과 알고리즘 적용 기준

    • 검색: 오늘 배운 조건 검색 — startsWith(회원 + ":")로 원소마다 조건 검사, O(n)
    • 삭제: 1강의 조기 중단 — 일치하는 기록을 찾는 즉시 지우고 반환. 삭제 후 뒤 원소들이 밀려와 인덱스가 바뀐다는 것을 출력으로 직접 확인합니다.
    Java BookLoanApplication.java 
    import java.util.ArrayList;

public class BookLoanApplication {

    /** 특정 회원의 대출 기록을 모두 찾아 출력한다 — 조건 검색, O(n) */
    static int printLoansOf(ArrayList<String> loans, String member) {
        int found = 0;
        for (int i = 0; i < loans.size(); i++) {
            String record = loans.get(i);              // 기록 형식: "회원:책제목"
            if (record.startsWith(member + ":")) {
                System.out.println("  " + i + "번 기록: " + record);
                found++;
            }
        }
        if (found == 0) {
            System.out.println("  (대출 기록 없음)");
        }
        return found;
    }

    /** 반납 처리: record와 일치하는 기록 하나를 찾아 삭제한다 — O(n) */
    static boolean returnBook(ArrayList<String> loans, String record) {
        for (int i = 0; i < loans.size(); i++) {
            if (loans.get(i).equals(record)) {
                loans.remove(i);   // 삭제하면 뒤 원소가 한 칸씩 앞으로 밀려온다
                return true;       // 하나만 지우고 즉시 종료 (1강의 조기 중단!)
            }
        }
        return false;
    }

    public static void main(String[] args) {
        // [배열 방식] 크기가 5로 고정 — 여섯 번째 대출은 받을 수 없다
        String[] loanArray = new String[5];
        loanArray[0] = "김하늘:자바의 정석";
        loanArray[1] = "이준호:알고리즘 도감";
        loanArray[2] = "김하늘:클린 코드";
        loanArray[3] = "박서연:자바의 정석";
        loanArray[4] = "이준호:데이터베이스 첫걸음";
        System.out.println("[배열] 칸 수 " + loanArray.length
                + " — 가득 차면 더 큰 배열을 만들어 직접 복사해야 한다");

        // [리스트 방식] 필요할 때마다 스스로 자란다
        ArrayList<String> loans = new ArrayList<>();
        loans.add("김하늘:자바의 정석");
        loans.add("이준호:알고리즘 도감");
        loans.add("김하늘:클린 코드");
        loans.add("박서연:자바의 정석");
        loans.add("이준호:데이터베이스 첫걸음");
        System.out.println("[리스트] 현재 대출 " + loans.size() + "건");

        // 추가: 크기 걱정 없이 끝에 붙인다
        loans.add("김하늘:이산수학");
        System.out.println("신규 대출 추가 후: " + loans.size() + "건");

        System.out.println();
        System.out.println("김하늘 님의 대출 기록 검색:");
        int count = printLoansOf(loans, "김하늘");
        System.out.println("→ 총 " + count + "건");

        System.out.println();
        System.out.println("반납 처리: \"김하늘:클린 코드\"");
        boolean returned = returnBook(loans, "김하늘:클린 코드");
        System.out.println("반납 성공 = " + returned + ", 남은 대출 " + loans.size() + "건");

        System.out.println();
        System.out.println("반납 후 김하늘 님의 대출 기록:");
        printLoansOf(loans, "김하늘");
    }
}

    Java GradeAnalyzerSolution.java 
    import java.util.ArrayList;

public class GradeAnalyzerSolution {

    /** 학생 한 명의 데이터: 이름 + 점수 */
    static class Student {
        String name;
        int score;

        Student(String name, int score) {
            this.name = name;
            this.score = score;
        }
    }

    /** 1) 전체 점수 합계 — 1강의 누적 패턴, O(n) */
    static int totalScore(Student[] students) {
        int sum = 0;
        for (int i = 0; i < students.length; i++) {
            sum = sum + students[i].score;
        }
        return sum;
    }

    /** 2) 평균 점수 — (double) 캐스팅으로 소수점을 지킨다 */
    static double average(Student[] students) {
        return (double) totalScore(students) / students.length;
    }

    /** 3) 최고점 학생 — 후보 비교 패턴, O(n) */
    static Student findTop(Student[] students) {
        Student top = students[0];
        for (int i = 1; i < students.length; i++) {
            if (students[i].score > top.score) {
                top = students[i];
            }
        }
        return top;
    }

    /** 4) 최저점 학생 — 부등호 방향만 반대, O(n) */
    static Student findBottom(Student[] students) {
        Student bottom = students[0];
        for (int i = 1; i < students.length; i++) {
            if (students[i].score < bottom.score) {
                bottom = students[i];
            }
        }
        return bottom;
    }

    /** 5) threshold점 이상인 학생 명단 — 조건 검색 + ArrayList에 수집, O(n) */
    static ArrayList<Student> filterAtLeast(Student[] students, int threshold) {
        ArrayList<Student> result = new ArrayList<>();
        for (int i = 0; i < students.length; i++) {
            if (students[i].score >= threshold) {
                result.add(students[i]);   // 몇 명이 될지 몰라도 리스트는 스스로 자란다
            }
        }
        return result;
    }

    /** 6) limit점 미만인 학생 명단 — 같은 구조, 조건만 다름, O(n) */
    static ArrayList<Student> filterBelow(Student[] students, double limit) {
        ArrayList<Student> result = new ArrayList<>();
        for (int i = 0; i < students.length; i++) {
            if (students[i].score < limit) {
                result.add(students[i]);
            }
        }
        return result;
    }

    /** 명단을 "이름(점수점)" 형태로 한 줄에 출력하는 보조 메서드 */
    static void printStudents(String title, ArrayList<Student> list) {
        StringBuilder line = new StringBuilder();
        for (int i = 0; i < list.size(); i++) {
            if (i > 0) line.append(", ");
            Student s = list.get(i);
            line.append(s.name).append("(").append(s.score).append("점)");
        }
        System.out.println(title + " (" + list.size() + "명): " + line);
    }

    public static void main(String[] args) {
        Student[] students = {
            new Student("김하늘", 72), new Student("이준호", 85),
            new Student("박서연", 90), new Student("최민재", 66),
            new Student("정다은", 78), new Student("강지훈", 93),
            new Student("윤소미", 55), new Student("한도윤", 81)
        };

        System.out.println("== 성적 분석 리포트 ==");
        System.out.println("학생 수: " + students.length + "명");

        System.out.println("합계: " + sum + "점");
        System.out.printf("평균: %.1f점%n", avg);

        System.out.println("최고점: " + top.name + " " + top.score + "점");
        System.out.println("최저점: " + bottom.name + " " + bottom.score + "점");

        printStudents("80점 이상", filterAtLeast(students, 80));
        printStudents("평균 미만", filterBelow(students, avg));
    }

    구현 순서와 핵심 알고리즘 적용 부분

    1. totalScore는 구현 3단계의 누적 패턴에서 더하는 대상만 scores[i] → students[i].score로 바뀌었습니다. 패턴은 데이터의 모양이 바뀌어도 그대로라는 것이 이 문제의 핵심 교훈입니다.
    2. findTop의 후보 변수가 int가 아니라 Student인 것에 주목하세요. 점수로 비교하되 객체 전체를 기억해야 "강지훈 93점"이라고 말할 수 있습니다.
    3. 동점 처리: 조건이 >(초과)이므로 같은 점수에서는 후보가 바뀌지 않아 자연스럽게 "먼저 나온 학생"이 유지됩니다. >=로 쓰면 뒤 학생이 선택되어 요구사항 위반입니다.
    4. 조건별 명단은 "몇 명일지 모른다" → ArrayList, 반면 학생 원본 데이터는 "8명으로 확정" → 배열. 그릇 선택의 기준이 코드에 그대로 드러납니다.

    복잡도 분석

    • 여섯 메서드 모두 순회 1번씩 — 각각 O(n), 전체도 O(n)입니다. (상수 배만 다릅니다)
    • 공간: 통계 계산은 O(1), 조건별 명단은 최악(전원 해당)일 때 O(n)입니다.
    • average가 내부에서 totalScore를 다시 부르므로 합계 순회가 2번 일어납니다. main에서 합계를 한 번만 구해 재사용하면 순회 1번을 아낄 수 있습니다 — Big-O는 같지만 좋은 습관입니다.

    자주 발생하는 오류

    • 평균이 77.0으로 나오는 경우 — (double) 캐스팅 누락 (정수 나눗셈).
    • findTop에서 top.score가 아니라 top과 비교하려다 컴파일 오류 — 객체끼리는 >로 비교할 수 없고, 비교 기준 필드(score)를 명시해야 합니다.
    • filterBelow의 조건을 <=로 써서 평균과 같은 점수까지 명단에 들어가는 경우 — 이 데이터에서는 결과가 같지만(77.5점인 학생이 없으므로) 요구사항 위반입니다.
    • 반복을 i = 1부터 시작해야 할 이유가 없는 totalScore까지 1부터 시작해 첫 학생이 빠지는 경우 — 후보 비교(이미 students[0]이 후보)와 누적(0부터 모두 더함)의 시작점은 다릅니다.

    다른 해결 방법

    Student를 Java 16+의 record Student(String name, int score)로 선언하면 더 간결합니다. 또 합계·최고·최저를 한 번의 순회로 동시에 구하는 통합 메서드도 가능합니다 (구현 4단계 방식) — 순회 횟수는 줄지만 메서드 하나가 여러 일을 하게 되므로, 지금처럼 기능별로 나눈 구조가 테스트와 재사용에는 더 좋습니다. 데이터가 정렬되어 있다면 최고점·최저점을 O(1)로 얻을 수 있는데, 그 "정렬"을 4강에서 직접 만듭니다.

    18확인 퀴즈

    19오늘의 핵심 정리

    • 배열은 같은 자료형을 연속으로 담는 고정 크기 그릇이다. 인덱스는 0부터, 마지막은 length - 1, 접근은 O(1)이다.
    • ArrayList는 크기 관리를 대신해 주는 가변 그릇이다. 끝 추가는 평균 O(1), 중간 삭제는 밀림 때문에 O(n)이며, 기본형은 래퍼(Integer)로 담는다.
    • 모든 데이터 처리의 뼈대는 순회다: for (int i = 0; i < length; i++) 안의 "할 일"만 바꾸면 누적(합계·평균), 후보 비교(최대·최소), 조건 검색, 빈도 계산이 전부 만들어진다 — 모두 O(n).
    • 빈도 계산은 값을 인덱스로 바꿔 카운팅 배열에 세는 기법이다 — 3강 해시, 4강 계수 정렬의 씨앗.
    • 배열 변수의 대입(b = a)은 참조 복사다. 진짜 복사는 새 배열을 만들어 O(n) 순회로 옮겨야 한다.
    • 두 가지 대표 사고: 범위 초과(i <= length → 예외)와 순회 중 삭제(인덱스 밀림 → 원소 건너뜀). 각각 < length와 역방향 순회(또는 i--)로 예방한다.

    20다음 강의 연결

    다음 강의는 3강. 완전 탐색과 문자열·해시 처리입니다. 오늘 익힌 순회 패턴이 그대로 무기가 됩니다.

    • 오늘의 배열 순회 + 조건 검사가 3강의 완전 탐색(brute force)이 됩니다 — "모든 후보를 순회하며 조건을 검사한다"는 발상 자체가 완전 탐색입니다. 순회를 겹쳐 쓰면(이중 반복문) 모든 쌍을 검사하는 O(n²) 탐색이 됩니다.
    • 오늘의 조건 검색이 문자열 위로 옮겨 갑니다 — 문자열은 문자의 배열이므로, scores[i] 순회가 charAt(i) 순회로 바뀔 뿐입니다.
    • 오늘의 빈도 계산(값 → 인덱스)이 3강의 해시로 확장됩니다 — 점수처럼 작은 정수가 아닌 문자열도 "인덱스로 바꿔서" 빠르게 세고 찾는 방법을 배웁니다.
    • 오늘 "검색은 O(n)이 최선일까?"라는 질문이 남았습니다 — 5강 이진 탐색에서 O(log n)으로 답합니다.

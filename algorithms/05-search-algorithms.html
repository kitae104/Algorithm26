순차 탐색과 이진 탐색

Linear Search and Binary Search

탐색 초급 Java 17+

도서 100,000권 중에서 한 권을 찾는 데 몇 번의 확인이 필요할까요? 앞에서부터 하나씩 보면 최악의 경우 100,000번, 그러나 데이터가 정렬되어 있다면 단 17번이면 충분합니다. 이번 강의에서는 순차 탐색과 이진 탐색을 직접 구현하며, "절반 버리기"가 만들어 내는 O(n)과 O(log n)의 차이를 비교 횟수로 확인합니다.

이 강의의 목차

    01강의 소개

    오늘의 질문: 데이터가 정렬되어 있다면 찾기는 얼마나 빨라질까?

    • 탐색(search)은 프로그램이 가장 자주 하는 일 — 회원 아이디로 회원 정보를, 상품 코드로 재고를, 파일 이름으로 파일을 찾음
    • 2강에서 "조건에 맞는 값 찾기"를 해봤지만 앞에서부터 하나씩 확인하는 방법뿐 — 데이터 10개는 충분해도 100,000개는 다름
    • 오늘의 주인공은 이진 탐색(binary search) — 4강에서 배운 정렬 덕분에 데이터가 오름차순으로 줄 서 있다면 중간 하나만 확인해도 나머지 절반을 통째로 버릴 수 있음
    • 순차 탐색 복습 → "정렬돼 있다면 무엇이 달라지는가?" → low·mid·high 세 포인터로 범위를 절반씩 줄이는 이진 탐색을 단계별로 완성
    • 마지막에는 도서 번호로 재고를 조회하는 도서 검색 프로그램 BookFinder를 직접 제작

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 순차 탐색을 조기 중단과 비교 카운터를 포함하여 구현하고, 최선·평균·최악의 비교 횟수를 설명할 수 있다.
    • 학생은 이진 탐색이 성립하기 위한 전제 조건(정렬된 배열, O(1) 인덱스 접근)을 설명할 수 있다.
    • 학생은 low·mid·high 포인터의 의미와 갱신 규칙(low = mid + 1, high = mid - 1)을 손으로 추적할 수 있다.
    • 학생은 while 반복문 기반 이진 탐색을 직접 작성하고, 없는 값에 대해 -1을 반환하도록 처리할 수 있다.
    • 학생은 데이터 크기 n에 따른 순차 탐색(n번)과 이진 탐색(log₂n번)의 비교 횟수를 표로 비교할 수 있다.
    • 학생은 이진 탐색의 대표적인 오류 — off-by-one 경계 실수, 정렬 전제 위반, mid 계산 오버플로 — 를 찾아 고칠 수 있다.

    04핵심 개념

    탐색과 순차 탐색

    • 탐색 = 데이터 묶음에서 원하는 값의 위치를 찾는 일
    • 순차 탐색(linear search) = 앞에서부터 하나씩 비교하는 가장 기본적인 방법, 정렬 여부와 상관없이 어떤 배열에서든 동작
    • 찾는 즉시 중단(1강)해도 최악의 경우(맨 끝에 있거나 아예 없을 때)는 n번을 모두 비교해야 하므로 O(n)

    비교 한 번이 주는 정보 — 정렬의 힘

    정렬되지 않은 배열에서 arr[5] != target은 "5번 칸에는 없다" 하나만 알려 주지만, 오름차순으로 정렬된 배열이라면 같은 비교 한 번이 세 가지 중 하나를 알려 줍니다.

    • arr[5] == target — 찾았다. 끝.
    • arr[5] < target — target이 있다면 반드시 5번보다 오른쪽. 왼쪽 전부(0~5번)를 버린다.
    • arr[5] > target — target이 있다면 반드시 5번보다 왼쪽. 오른쪽 전부(5~끝)를 버린다.
    • 비교 한 번의 값어치가 "칸 하나 제거"에서 "절반 제거"로 뛰어오름
    • 1강에서 말한 "데이터의 규칙을 알수록 빠른 알고리즘을 선택할 수 있다"의 대표 사례

    이진 탐색과 low · mid · high 포인터

    이진 탐색(binary search)은 "절반 버리기"를 반복하는 알고리즘 — 현재 남아 있는 탐색 범위를 두 개의 인덱스로 관리합니다.

    변수의미시작값갱신 규칙
    low남은 범위의 왼쪽 끝 인덱스0arr[mid] < target이면 low = mid + 1
    high남은 범위의 오른쪽 끝 인덱스arr.length - 1arr[mid] > target이면 high = mid - 1
    mid이번에 확인할 중간 인덱스매 회차 계산mid = (low + high) / 2 (정수 나눗셈)
    • 갱신 규칙의 +1과 -1이 중요 — mid 자리는 방금 비교로 이미 확인했으므로 다음 범위에서 반드시 제외해야 함
    • 이것을 빼먹으면(low = mid) 범위가 줄지 않아 무한 반복에 빠질 수 있음 (12 확인 퀴즈의 오류 찾기 문제에서 직접 확인)
    • 반복은 low <= high인 동안, 즉 범위에 후보가 하나라도 남아 있는 동안 계속하고, low > high가 되는 순간 "없다"(-1)를 확정

    비교 횟수 — n번 vs log₂n번

    후보가 비교마다 절반씩 줄어들므로, n개에서 시작해 1개가 될 때까지의 비교 횟수는 "n을 2로 몇 번 나누면 1이 되는가" 즉 log₂n — 데이터가 2배 커져도 비교는 1번만 늘어남.

    데이터 개수 n순차 탐색 최악 (n번)이진 탐색 최악 (⌊log₂n⌋+1번)
    1212번4번
    1,0001,000번10번
    100,000100,000번17번
    1,000,0001,000,000번20번
    1,000,000,000 (10억)10억 번30번

    10억 개에서도 30번 — 이것이 1강 Big-O 표에서 예고했던 O(log n)의 실체입니다.

    mid 계산의 함정 — 오버플로

    • 교과서적인 중간 계산 mid = (low + high) / 2에는 숨은 함정이 있음
    • low + high가 int 최댓값(약 21억)을 넘으면 오버플로가 일어나 mid가 음수가 되고, arr[mid]에서 프로그램이 죽음
    • 1강의 가우스 공식 오버플로와 정확히 같은 종류의 사고 — 안전한 표기는 다음과 같음
    int mid = low + (high - low) / 2;   // 두 값의 "차이의 절반"을 low에 더한다 — 합을 만들지 않으므로 안전
    • 수학적으로는 같은 값이지만, 덧셈 결과가 항상 high 이하이므로 넘칠 일이 없음
    • 이번 강의의 예제(12권~10만 권)에서는 어느 쪽을 써도 결과가 같지만, 실무에서는 안전한 표기를 습관으로 만드는 것이 좋음 (오류 찾기 섹션에서 실제로 넘치는 값을 확인)

    • 지금 비교 중인 mid 칸은 앰버색(비교 중), 발견된 칸은 초록색(확정)

    • 🎲 새 데이터 버튼은 찾는 번호를 무작위로 바꿈 — 없는 번호가 걸리면 실패 과정도 볼 수 있음

    "남은 후보" 카운터가 12 → 6 → 2처럼 비교 1번마다 절반으로 줄고, 실패할 때는 범위가 완전히 빈 뒤에야(low > high) 멈추는 것을 확인 — 이 움직임을 지금부터 의사코드와 Java 코드로 옮깁니다.

    06의사코드

    코드를 쓰기 전에, 두 탐색의 절차를 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)
    • arr[i]는 "arr의 i번 칸", 반환한다는 "답을 돌려주고 알고리즘을 즉시 끝낸다"는 뜻

    순차 탐색 (Linear Search)

    Pseudo 순차 탐색 
    알고리즘 LinearSearch(arr, target)
    i를 0부터 arr의 끝까지 반복:
        arr[i]와 target을 비교한다          // 핵심 연산 (최악 n번)
        같으면 i를 반환한다                 // 조기 중단
    끝까지 못 찾았으면 -1을 반환한다        // 모든 칸을 봤는데 없다는 뜻

    이진 탐색 (Binary Search)

    Pseudo 이진 탐색 (배열은 오름차순 정렬 전제) 
    알고리즘 BinarySearch(arr, target)
    low ← 0                                  // 후보 범위의 왼쪽 끝
    high ← arr의 길이 - 1                    // 후보 범위의 오른쪽 끝
    // 등호 필요: low = high(후보 1개)도 확인해야 함
    low가 high 이하인 동안 반복:              // 범위에 후보가 남아 있는 동안
        mid ← (low + high) / 2               // 정수 나눗셈 (소수점 버림)
        arr[mid]와 target을 비교한다          // 핵심 연산 (최악 log₂n번)
        같으면 mid를 반환한다
        // ±1: mid는 방금 확인했으므로 범위에서 뺀다
        arr[mid]가 target보다 작으면 low ← mid + 1     // 왼쪽 절반 버리기
        arr[mid]가 target보다 크면 high ← mid - 1      // 오른쪽 절반 버리기
    -1을 반환한다                             // 범위가 비었다 = 없다

    두 의사코드 비교

    • 순차 탐색의 순서도는 "다음 칸으로"라는 한 칸짜리 고리
    • 이진 탐색의 순서도는 "판단(같다/작다/크다) → 범위 절반 축소 → 다시 판단"이라는 세 갈래 고리
    • 고리를 도는 횟수가 각각 n번과 log₂n번 — 이것이 두 알고리즘의 모든 차이

    07실습 코드

    의사코드(06)를 Java로 옮깁니다. 순차 탐색과 이진 탐색을 각각 메서드로 분리하고, 결과와 비교 횟수를 SearchResult로 함께 반환하는 탐색 비교 프로그램입니다.

    • linearSearch의 comparisons++와 return은 04 핵심 개념의 비교 카운터·조기 중단을 그대로 메서드로 옮긴 것
    • binarySearchLoop는 06 의사코드의 중간 비교 → 범위 절반 버리기(low = mid + 1 / high = mid - 1)를 low <= high인 동안 반복하는 while 문으로 그대로 옮긴 것
    • 같은 알고리즘을 재귀로 표현한 binarySearchRecursive(7강에서 심화)와, 중복 값이 있을 때 첫 번째 위치를 보장하는 firstOccurrence도 함께 담음
    • 결과와 비교 횟수를 함께 담는 SearchResult는 1강 AlgoMeter의 Measurement와 같은 패턴이며, 세 방법의 결과가 항상 같은지 정확성 검증도 진행

    /** 탐색 결과: 찾은 위치와 비교 횟수를 함께 담는 기록용 클래스 */
public class SearchResult {
    int index;        // 찾은 위치 (없으면 -1)
    int comparisons;  // 비교 횟수

    SearchResult(int index, int comparisons) {
        this.index = index;
        this.comparisons = comparisons;
    }
}
    Java SearchAlgorithmsComplete.java 
    public class SearchAlgorithmsComplete {

    // SearchResult 클래스는 같은 폴더의 SearchResult.java에 정의되어 있다.

    /** 순차 탐색: 앞에서부터 하나씩 비교. 1강의 findStopEarly와 같은 구조다. */
    static SearchResult linearSearch(int[] arr, int target) {
        int comparisons = 0;
        for (int i = 0; i < arr.length; i++) {
            comparisons++;                       // 핵심 연산: 비교
            if (arr[i] == target) {
                return new SearchResult(i, comparisons);   // 찾는 즉시 중단
            }
        }
        return new SearchResult(-1, comparisons);
    }

    /** 반복문 기반 이진 탐색: 정렬된 배열에서 절반씩 버리며 찾는다. */
    static SearchResult binarySearchLoop(int[] arr, int target) {
        int low = 0;
        int high = arr.length - 1;
        int comparisons = 0;
        while (low <= high) {
            int mid = (low + high) / 2;
            comparisons++;                       // 핵심 연산: 비교
            if (arr[mid] == target) {
                return new SearchResult(mid, comparisons);
            } else if (arr[mid] < target) {
                low = mid + 1;                   // 왼쪽 절반 버리기
            } else {
                high = mid - 1;                  // 오른쪽 절반 버리기
            }
        }
        return new SearchResult(-1, comparisons);
    }

    /** 재귀 기반 이진 탐색: 같은 알고리즘을 "자기 자신 호출"로 표현한다. (7강에서 심화) */
    static SearchResult binarySearchRecursive(int[] arr, int target,
                                              int low, int high, int comparisons) {
        if (low > high) {
            return new SearchResult(-1, comparisons);      // 범위가 비면 실패
        }
        int mid = (low + high) / 2;
        comparisons++;
        if (arr[mid] == target) {
            return new SearchResult(mid, comparisons);
        } else if (arr[mid] < target) {
            return binarySearchRecursive(arr, target, mid + 1, high, comparisons);
        } else {
            return binarySearchRecursive(arr, target, low, mid - 1, comparisons);
        }
    }

    /** 중복이 있을 때 첫 번째 위치를 찾는다 (lower bound의 기초). */
    static SearchResult firstOccurrence(int[] arr, int target) {
        int low = 0;
        int high = arr.length - 1;
        int comparisons = 0;
        int answer = -1;
        while (low <= high) {
            int mid = (low + high) / 2;
            comparisons++;
            if (arr[mid] == target) {
                answer = mid;        // 일단 기록하고,
                high = mid - 1;      // 더 왼쪽에도 있는지 계속 확인한다
            } else if (arr[mid] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return new SearchResult(answer, comparisons);
    }

    public static void main(String[] args) {
        int[] bookNumbers = {1001, 1203, 1450, 2088, 2311, 2754,
                             3106, 3502, 3860, 4213, 4771, 5090};
        int[] targets = {1001, 3106, 5090, 2500};   // 2500은 없는 번호

        System.out.println("찾는 번호 | 순차 위치 | 순차 비교 | 이진 위치 | 이진 비교 | 재귀 비교");
        System.out.println("---------+----------+----------+----------+----------+----------");

        for (int target : targets) {
            SearchResult lin = linearSearch(bookNumbers, target);
            SearchResult bin = binarySearchLoop(bookNumbers, target);
            SearchResult rec = binarySearchRecursive(bookNumbers, target,

    08잘못된 코드와 오류 찾기

    이진 탐색은 "아이디어는 쉽지만 경계에서 틀리기로 악명 높은" 알고리즘입니다. 초보자가 자주 만드는 오류 세 가지를 직접 찾아봅시다 — 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 마지막 한 칸을 못 보는 반복 조건 (off-by-one)

    09복잡도 및 특성 분석

    복잡도 = "데이터가 많아지면 일이 얼마나 늘어나는가?" 초 단위 시간이 아니라 "몇 번 하는가"만 세어 봅니다.

    시간 복잡도 — 얼마나 오래 걸리는가?

    알고리즘최선최악Big-O쉽게 말하면
    순차 탐색1번n번O(n)출석부를 위에서 한 줄씩 읽기 — 10배 늘면 10배
    이진 탐색1번약 log₂n번O(log n)사전 가운데를 펴고 절반 버리기 — 2배 늘어도 1번만 추가
    • 도서 10만 권: 순차 탐색 최악 10만 번 vs 이진 탐색 17번 (10억 권이어도 30번)
    • 단, 이진 탐색은 데이터가 정렬돼 있어야 가능

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 순차 탐색·반복문 이진 탐색: 변수 몇 개뿐 → O(1)
    • 재귀 이진 탐색: 호출 기록이 약 log₂n개 쌓임 → O(log n) (7강)
    한 줄 정리 — 정렬해 두면 찾기가 n번에서 log n번으로
    • 대가는 정렬(4강) 비용 — 한 번 정렬하고 여러 번 검색할수록 이득
    • 데이터가 아주 적거나 정렬돼 있지 않으면 순차 탐색이 합리적인 선택

    10람다·스트림 변경

    도서 번호를 배열 대신 List에 담고, 람다와 스트림으로 순차 탐색을 하고, 자바 기본 API인 Collections.binarySearch로 이진 탐색을 해 봅니다. 문법은 추가 정보의 람다식·자바 스트림 문서를 참고하세요.

    • 스트림 순차 탐색: IntStream.range + filter + findFirst — 찾는 즉시 멈춘다
    • 기본 API 이진 탐색: Collections.binarySearch(list, key) — 정렬된 List 필요, 찾으면 인덱스, 못 찾으면 -(넣을 위치) - 1 반환
    Java ModernizeSolution.java 
    import java.util.Collections;
import java.util.List;
import java.util.stream.IntStream;

/**
 * 5강 「람다·스트림 변경」.
 *
 * 도서 번호를 배열 대신 List에 담고, 람다·스트림(순차 탐색)과
 * Collections.binarySearch(이진 탐색)로 같은 번호를 찾아 본다.
 */
public class ModernizeSolution {

    public static void main(String[] args) {
        List<Integer> bookNumbers = List.of(1001, 1203, 1450, 2088, 2311, 2754,
                                            3106, 3502, 3860, 4213, 4771, 5090);
        List<Integer> targets = List.of(1001, 3106, 5090, 2500);   // 2500은 없는 번호

        System.out.println("도서 " + bookNumbers.size() + "권에서 번호 찾기");
        System.out.println();

        // 1) 람다 + 스트림 순차 탐색: 조건에 맞는 첫 인덱스를 findFirst로 찾는다.
        System.out.println("[1] 스트림 순차 탐색");
        targets.forEach(target -> {
            int index = IntStream.range(0, bookNumbers.size())
                    .filter(i -> bookNumbers.get(i).equals(target))
                    .findFirst()                 // 찾는 즉시 멈춘다 (조기 중단)
                    .orElse(-1);
            System.out.println(target + " -> 인덱스 " + index);
        });

        // 2) 스트림 필터: 목록에 실제로 있는 번호만 골라낸다.
        List<Integer> found = targets.stream()
                .filter(bookNumbers::contains)
                .toList();
        System.out.println("목록에 있는 번호: " + found);
        System.out.println();

        // 3) 기본 API 이진 탐색: Collections.binarySearch (정렬된 List 필요)
        //    찾으면 인덱스, 못 찾으면 -(삽입 위치) - 1 을 돌려준다.
        System.out.println("[2] Collections.binarySearch");
        targets.forEach(target -> {
            int result = Collections.binarySearch(bookNumbers, target);
            if (result >= 0) {
                System.out.println(target + " -> 인덱스 " + result);
            } else {
                int insertionPoint = -(result + 1);
                System.out.println(target + " -> 없음 (반환값 " + result
                        + ", 넣을 위치 " + insertionPoint + ")");
            }
        });
    }
}

    Java BookSearchApplication.java 
    public class BookSearchApplication {

    // Book 클래스는 같은 폴더의 Book.java에 정의되어 있다.

    /** 마지막 탐색의 비교 횟수 */
    static int compareCount = 0;

    /** 도서 번호로 이진 탐색한다. 배열은 번호 오름차순 정렬이 전제다. */
    static int binarySearchByNumber(Book[] books, int targetNumber) {
        compareCount = 0;
        int low = 0;
        int high = books.length - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            compareCount++;
            if (books[mid].number == targetNumber) {
                return mid;
            } else if (books[mid].number < targetNumber) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return -1;
    }

    /** int 배열에서 순차 탐색의 비교 횟수만 센다 (대규모 비교 실험용). */
    static int linearComparisons(int[] arr, int target) {
        int comparisons = 0;
        for (int i = 0; i < arr.length; i++) {
            comparisons++;
            if (arr[i] == target) {
                return comparisons;
            }
        }
        return comparisons;
    }

    /** int 배열에서 이진 탐색의 비교 횟수만 센다 (대규모 비교 실험용). */
    static int binaryComparisons(int[] arr, int target) {
        int low = 0;
        int high = arr.length - 1;
        int comparisons = 0;
        while (low <= high) {
            int mid = (low + high) / 2;
            comparisons++;
            if (arr[mid] == target) {
                return comparisons;
            } else if (arr[mid] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return comparisons;
    }

    public class BookSearchSolution {

    // 도서 번호(오름차순 정렬됨)와 같은 순서의 제목·재고 데이터
    static int[] bookNumbers = {1001, 1203, 1450, 2088, 2311, 2754,
                                3106, 3502, 3860, 4213, 4771, 5090};
    static String[] titles = {
        "알고리즘 첫걸음", "자바 프로그래밍 입문", "자료구조의 이해",
        "데이터베이스 개론", "운영체제 원리", "컴퓨터 네트워크",
        "소프트웨어 공학", "인공지능 기초", "웹 개발 실무",
        "정보 보안의 기초", "클라우드 컴퓨팅", "모바일 앱 개발"
    };
    static int[] stocks = {3, 5, 2, 0, 4, 1, 6, 2, 0, 3, 7, 1};

    /** 마지막 탐색에서 수행한 비교 횟수 */
    static int compareCount = 0;

    /** 요구사항 1: 순차 탐색 — 앞에서부터 비교하며 target의 위치를 찾는다. 없으면 -1 */
    static int linearSearch(int[] numbers, int target) {
        compareCount = 0;
        for (int i = 0; i < numbers.length; i++) {
            compareCount++;                  // 핵심 연산: 비교
            if (numbers[i] == target) {
                return i;                    // 찾는 즉시 중단 (1강의 조기 중단)
            }
        }
        return -1;
    }

    /** 요구사항 2: 이진 탐색 — 절반씩 버리며 target의 위치를 찾는다. 없으면 -1 */
    static int binarySearch(int[] numbers, int target) {
        compareCount = 0;
        int low = 0;
        int high = numbers.length - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            compareCount++;                  // 핵심 연산: 비교
            if (numbers[mid] == target) {
                return mid;
            } else if (numbers[mid] < target) {
                low = mid + 1;               // 왼쪽 절반 버리기
            } else {
                high = mid - 1;              // 오른쪽 절반 버리기
            }
        }
        return -1;                           // low > high → 없는 번호
    }

    public static void main(String[] args) {
        int[] queries = {1001, 3106, 5090, 2500};   // 2500은 없는 번호

        System.out.println("== 도서 검색 프로그램 BookFinder ==");
        System.out.println("등록 도서 " + bookNumbers.length + "권");
        System.out.println();

        for (int number : queries) {
            System.out.println("도서 번호 " + number + " 검색:");

            int linearIndex = linearSearch(bookNumbers, number);
            int linearCount = compareCount;
            int binaryIndex = binarySearch(bookNumbers, number);
            int binaryCount = compareCount;

            System.out.println("  순차 탐색: 위치 " + linearIndex + ", 비교 " + linearCount + "번");
            System.out.println("  이진 탐색: 위치 " + binaryIndex + ", 비교 " + binaryCount + "번");

            if (binaryIndex >= 0) {
                String status = stocks[binaryIndex] > 0
                        ? "대출 가능 (재고 " + stocks[binaryIndex] + "권)"
                        : "재고 없음 (대출 불가)";
                System.out.println("  도서: \"" + titles[binaryIndex] + "\" — " + status);
            } else {
                System.out.println("  등록되지 않은 도서 번호입니다.");
            }

            // 두 탐색의 정확성 검증: 결과가 다르면 알고리즘에 오류가 있다
            if (linearIndex != binaryIndex) {
                System.out.println("  경고: 두 탐색의 결과가 다릅니다!");
            }
            System.out.println();
        }

        System.out.println("정렬된 데이터라면, 비교 몇 번으로 십만 권 중 한 권도 찾을 수 있다.");
    }

    구현 순서와 핵심 알고리즘 적용 부분

    1. linearSearch는 1강에서 배운 for + 조기 중단 패턴 그대로입니다. break 후 변수로 전달하는 대신 return i로 바로 반환해 더 단순해졌습니다.
    2. binarySearch의 핵심은 세 줄입니다: while (low <= high)(범위가 남아 있는 동안), low = mid + 1 / high = mid - 1(확인한 mid는 반드시 제외). 이 세 줄의 등호와 ±1이 이진 탐색 정확성의 전부입니다.
    3. compareCount = 0 초기화를 메서드 맨 앞에서 하므로, 호출한 직후 값을 읽어 두면(linearCount, binaryCount) 다음 호출이 덮어써도 안전합니다.
    4. 재고 상태 문자열은 탐색 결과(binaryIndex)를 사용하는 main 쪽에 두어 탐색 메서드를 순수하게 유지했습니다.

    복잡도 분석

    • 순차 탐색: 최선 1번(1001), 최악 n = 12번(5090, 2500) → O(n). 공간 O(1).
    • 이진 탐색: 이 데이터에서 최대 ⌊log₂12⌋ + 1 = 4번 → O(log n). 공간 O(1).
    • 비교 횟수 합계: 순차 1 + 7 + 12 + 12 = 32번 vs 이진 3 + 3 + 4 + 4 = 14번. 12권에서도 2배 이상, 100,000권이면 수천 배 차이가 납니다.

    자주 발생하는 오류

    • 반복 조건을 low < high로 써서 마지막 한 칸을 못 보는 경우 (오류 1 — 5090이나 4213 같은 값에서 드러남).
    • low = mid / high = mid로 써서 범위가 줄지 않아 무한 반복에 빠지는 경우.
    • compareCount = 0 초기화를 잊어 두 번째 검색부터 횟수가 누적되는 경우.
    • 순차 탐색의 compareCount++를 if 안에 넣어 실패한 비교가 세어지지 않는 경우.

    이진 탐색을 재귀로 쓰는 방법(실습 코드의 binarySearchRecursive)도 있습니다 — 로직은 같고 반복문 대신 자기 호출로 범위를 좁힙니다 (7강에서 자세히). 실무에서는 검증이 끝난 표준 라이브러리 Arrays.binarySearch를 쓰지만, 그 내부가 오늘 우리가 쓴 코드와 같다는 것, 그리고 mid 계산 오버플로 같은 함정(오류 3)까지 처리되어 있다는 것을 이해하고 쓰는 것이 이 강의의 목적입니다. 번호·제목·재고를 배열 3개 대신 Book 클래스로 묶으면(응용 예제 방식) 데이터 정합성 관리가 더 쉬워집니다.

    15오늘의 핵심 정리

    • 순차 탐색은 앞에서부터 하나씩 비교한다 — 정렬 불필요, 최악 n번, O(n).
    • 이진 탐색은 정렬된 배열에서 중간과 비교해 절반을 통째로 버린다 — 최악 ⌊log₂n⌋+1번, O(log n). 10억 개도 30번이면 끝난다.
    • 탐색 범위는 low(왼쪽 끝)·high(오른쪽 끝)로 관리하고, mid는 이미 확인했으므로 low = mid + 1 / high = mid - 1로 반드시 제외한다.
    • 반복은 low <= high인 동안 — 등호를 빼면 마지막 한 칸을 못 보는 off-by-one 오류가 된다. low > high가 되는 순간 "없다"(-1)가 확정된다.
    • 이진 탐색의 전제는 정렬(4강)이다. 전제가 깨지면 예외 없이 조용히 틀린 답을 낸다. 그리고 거대한 배열에서는 (low + high) / 2가 넘칠 수 있으므로 low + (high - low) / 2가 안전하다.
    • 이진 탐색이 항상 이기는 것은 아니다 — 첫 원소는 순차 1번 vs 이진 3번. 데이터 크기·정렬 여부·검색 빈도를 보고 근거를 갖고 선택한다.

    다음 강의는 6강. 스택과 큐를 활용한 작업 처리입니다. 지금까지는 "이미 담겨 있는 데이터를 어떻게 찾는가"를 다뤘다면, 6강부터는 "데이터를 어떤 순서로 넣고 꺼내는가"가 주제가 됩니다.

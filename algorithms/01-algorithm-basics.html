알고리즘 기초 초급 Java 17+

같은 문제라도 "어떻게 푸느냐"에 따라 컴퓨터가 하는 일의 양이 수백, 수만 배 달라집니다. 이번 강의에서는 알고리즘이 무엇인지, 문제를 입력·처리·출력으로 나누는 방법, 그리고 알고리즘의 효율을 숫자로 표현하는 시간 복잡도와 Big-O 표기법을 배웁니다.

이 강의의 목차

    01강의 소개

    프로그래밍 공부를 시작하면 누구나 이런 질문을 만납니다. "내 코드는 돌아가긴 하는데, 잘 만든 걸까?" 이 질문에 답하려면 두 가지 기준이 필요합니다. 첫째, 정확성 — 어떤 입력에도 올바른 답을 내는가. 둘째, 효율성 — 데이터가 많아져도 감당할 수 있는가.

    이번 강의는 13개 강좌 전체의 출발점입니다. 알고리즘이라는 말의 의미부터, 문제를 입력 → 처리 → 출력으로 나누는 습관, 풀이 과정을 코드 이전에 표현하는 의사코드와 순서도, 그리고 알고리즘의 일의 양을 표현하는 시간 복잡도와 Big-O 표기법까지 다룹니다. 마지막에는 같은 문제를 두 가지 방식으로 풀어 실행 횟수를 비교하는 알고리즘 효율성 분석 프로그램을 직접 만듭니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 주어진 문제를 입력, 처리, 출력의 세 부분으로 나누어 설명할 수 있다.
    • 학생은 "1부터 n까지의 합" 문제의 풀이 과정을 의사코드로 작성할 수 있다.
    • 학생은 반복문 방식과 공식 방식의 핵심 연산 실행 횟수를 각각 세어 표로 비교할 수 있다.
    • 학생은 O(1), O(n), O(n²), O(log n)의 의미를 입력 크기와 연결하여 설명할 수 있다.
    • 학생은 연산 횟수를 세는 카운터 변수를 Java 코드에 추가할 수 있다.
    • 학생은 두 알고리즘의 결과가 같은지(정확성) 코드로 검증할 수 있다.

    04실제 문제 상황

    여러분이 한 대학교의 수강 신청 시스템을 관리하는 개발팀에 들어갔다고 상상해 봅시다. 매 학기 초, 시스템은 "1번 학생부터 n번 학생까지 순서대로 처리했을 때의 누적 작업량"을 계산해서 서버 용량을 미리 준비해야 합니다. 작년까지는 학생이 5,000명이라 아무 방법으로 계산해도 순식간이었습니다. 그런데 올해 통합 캠퍼스가 생기면서 학생이 500,000명으로 늘었고, 기존 계산 프로그램이 눈에 띄게 느려졌습니다. 선배 개발자가 말합니다. "코드는 맞게 짰는데, 알고리즘이 느린 거야." 코드가 맞았는데 느리다니, 무슨 뜻일까요? 이번 강의에서 이 말의 의미를 정확히 이해하게 됩니다.

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 작은 데이터로 문제를 손으로 풀어 봅니다. 문제를 단순하게 줄여 봅시다: "1부터 8까지의 합은 얼마인가?"

    방법 A — 하나씩 더하기

    STEP 1

    빈 종이에 0을 적습니다. 그리고 1을 더합니다. → 1

    질문: 지금 우리가 "기억"하고 있는 값은 무엇인가요?

    지금까지의 누적 합(1)과, 다음에 더할 숫자가 2라는 사실입니다. 프로그램으로 옮기면 각각 변수 sum과 반복 변수 i가 됩니다.

    STEP 2

    2를 더합니다 → 3. 3을 더합니다 → 6. 4를 더합니다 → 10. … 8까지 반복합니다.

    질문: 덧셈을 총 몇 번 했나요? 숫자가 1부터 100까지라면 몇 번일까요?

    8번입니다. 1부터 100까지라면 100번입니다. 데이터 개수가 n이면 덧셈도 n번 — 일의 양이 데이터 크기에 비례합니다.

    방법 B — 수학자 가우스의 방법

    STEP 3

    숫자를 앞뒤로 짝지어 봅니다: (1+8), (2+7), (3+6), (4+5). 모든 짝의 합이 9로 같습니다! 짝이 4개이므로 답은 9 × 4 = 36.

    질문: 이 방법을 일반화하면 어떤 공식이 될까요?

    (첫 수 + 끝 수) × 개수 ÷ 2, 즉 n × (n + 1) / 2입니다. 1부터 100까지라면 100 × 101 / 2 = 5050. 계산 한 번으로 끝납니다.

    STEP 4

    두 방법을 비교해 봅시다. 결과는 둘 다 36으로 같습니다. 하지만 일의 양이 다릅니다.

    질문: n이 500,000이라면 두 방법의 일의 양은 각각 얼마일까요?

    방법 A는 덧셈 500,000번, 방법 B는 계산 1번입니다. 결과가 같아도(정확성 동일) 일의 양은 50만 배 차이 — 이것이 효율성의 차이입니다.

    06핵심 개념

    알고리즘이란?

    알고리즘은 문제를 해결하는, 순서가 있는 명확한 절차입니다. "명확한"이 중요합니다 — 누가 따라 해도(사람이든 컴퓨터든) 같은 결과가 나와야 합니다. 방금 손으로 풀었던 "하나씩 더하기"와 "가우스 공식"은 같은 문제를 푸는 서로 다른 두 알고리즘입니다.

    문제를 입력 · 처리 · 출력으로 나누기

    어떤 문제든 프로그램으로 만들기 전에 세 부분으로 나누면 설계가 선명해집니다.

    구분질문1~n 합 문제에서는
    입력무엇이 주어지는가?자연수 n (예: 8)
    처리어떤 절차로 바꾸는가?하나씩 더하기 또는 공식 계산
    출력무엇을 내놓는가?합계 (예: 36)

    복잡한 문제는 문제 분해로 더 작은 입력·처리·출력 덩어리로 쪼갭니다. 예를 들어 "성적 분석 프로그램"은 (1) 점수 읽기 (2) 합계 구하기 (3) 평균 구하기 (4) 결과 출력의 작은 문제 4개로 나눌 수 있습니다. 2강에서 실제로 해 봅니다.

    의사코드와 순서도

    의사코드(pseudocode)는 특정 언어 문법에 매이지 않고 절차를 적는 방법이고, 순서도(flowchart)는 절차를 도형(시작/끝, 처리, 판단)으로 그리는 방법입니다. 코드보다 먼저 절차를 적어 보면 논리 오류를 훨씬 일찍 발견할 수 있습니다. 구체적인 예는 아래 9번 의사코드 섹션에서 다룹니다.

    정확성과 효율성

    • 정확성: 모든 유효한 입력에 대해 올바른 출력을 낸다. (n=1, n=0 같은 경계도 포함!)
    • 효율성: 시간(연산 횟수)과 공간(메모리)을 얼마나 쓰는가.

    정확하지 않은 빠른 코드는 쓸모가 없습니다. 항상 정확성 먼저, 그다음 효율성입니다.

    시간 복잡도와 Big-O 표기법

    시간 복잡도는 입력 크기 n이 커질 때 핵심 연산의 실행 횟수가 어떻게 늘어나는지를 나타냅니다. 정확한 횟수 대신 증가하는 모양만 남긴 것이 Big-O 표기법입니다. 예를 들어 연산 횟수가 3n + 5번이라면, n이 커질수록 중요한 것은 "n에 비례한다"는 사실뿐이므로 O(n)이라고 씁니다.

    Big-O이름n=1,000일 때 대략의 연산이 과정에서 만나는 곳
    O(1)상수 시간1공식 계산, 배열 인덱스 접근
    O(log n)로그 시간약 105강 이진 탐색
    O(n)선형 시간1,000배열 순회, 순차 탐색
    O(n²)이차 시간1,000,0004강 선택·버블 정렬

    공간 복잡도는 같은 질문을 메모리에 대해 묻는 것입니다. 방법 A와 B는 모두 변수 몇 개만 쓰므로 공간 복잡도 O(1)입니다.

    07단계별 동작 과정

    두 알고리즘이 실제로 일하는 모습을 단계별로 확인해 봅시다. 다음 단계 ▶ 버튼을 눌러 한 단계씩 진행하거나 자동 실행을 사용하세요. 비교·누적 중인 칸은 앰버색, 처리 완료된 칸은 초록색으로 표시됩니다.

    시각화 마지막 단계에서 확인할 수 있듯, 반복문 방식은 n번의 누적 연산 후에, 공식 방식은 단 1번의 계산으로 같은 결과 36에 도달합니다.

    08의사코드

    코드를 쓰기 전에, 방금 본 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo 방법 A — 반복문으로 합 구하기 
    알고리즘 SumByLoop(n)
    sum ← 0
    i ← 1
    i가 n 이하인 동안 반복:
        sum ← sum + i        // 핵심 연산 (n번 실행)
        i ← i + 1
    sum을 반환한다
    Pseudo 방법 B — 공식으로 합 구하기 
    알고리즘 SumByFormula(n)
    sum ← n × (n + 1) ÷ 2   // 핵심 연산 (1번 실행)
    sum을 반환한다

    순서도로 그리면 방법 A는 "판단(i ≤ n?) → 처리(누적) → 다시 판단"의 고리(loop)가 생기고, 방법 B는 시작 → 처리 → 끝의 직선이 됩니다. 고리의 유무가 곧 O(n)과 O(1)의 차이입니다.

    09점진적 Java 구현

    이제 의사코드를 Java로 옮깁니다. 완성 코드를 한 번에 쓰지 않고, 데이터 준비 → 핵심 연산 하나 → 반복 구조 → 실행 횟수 세기 순서로 확장합니다. 각 단계의 코드는 모두 독립적으로 복사해서 실행할 수 있습니다.

    구현 1단계 — 입력 데이터 준비

    먼저 처리할 데이터를 준비하고 눈으로 확인합니다. 여기서는 학생 5명의 점수를 사용합니다.

    Java Step1ScoreData.java 
    public class Step1ScoreData {
    public static void main(String[] args) {
        // 학생 5명의 점수 (입력 데이터)
        int[] scores = {72, 85, 90, 66, 78};

        System.out.println("학생 수: " + scores.length);

        // 배열의 내용을 처음부터 끝까지 출력한다
        for (int i = 0; i < scores.length; i++) {
            System.out.println("scores[" + i + "] = " + scores[i]);
        }
    }
}
    출력 실행 결과 
    학생 수: 5
scores[0] = 72
scores[1] = 85
scores[2] = 90
scores[3] = 66
scores[4] = 78

    구현 2단계 — 핵심 연산 하나 구현

    합계 알고리즘의 핵심 연산은 "누적 변수에 값 하나를 더하기"입니다. 반복문 없이 딱 한 번만 수행해 봅니다. 1단계와 달라진 부분은 sum 변수와 누적 한 줄뿐입니다.

    Java Step2AddOnce.java 
    public class Step2AddOnce {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78};

        int sum = 0;              // 누적 변수: 지금까지의 합을 기억한다

        sum = sum + scores[0];    // 핵심 연산: 값 하나를 누적한다

        System.out.println("첫 번째 점수를 더한 뒤 sum = " + sum);
    }
}
    출력 실행 결과 
    첫 번째 점수를 더한 뒤 sum = 72

    구현 3단계 — 반복 구조 추가

    핵심 연산을 배열 길이만큼 반복하도록 for 문으로 감쌉니다. 2단계의 scores[0]이 scores[i]로 바뀐 것에 주목하세요.

    Java Step3SumLoop.java 
    public class Step3SumLoop {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78};

        int sum = 0;

        // 핵심 연산을 배열 길이만큼 반복한다
        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];
        }

        System.out.println("점수 합계 = " + sum);
        System.out.println("평균 = " + (double) sum / scores.length);
    }
}
    출력 실행 결과 
    점수 합계 = 391
평균 = 78.2

    구현 4단계 — 실행 횟수 세기

    이제 이 강의의 핵심 도구를 추가합니다: 연산 카운터. 핵심 연산이 실행될 때마다 operationCount를 1씩 늘리면 알고리즘의 일의 양을 직접 눈으로 확인할 수 있습니다.

    Java Step4CountOperations.java 
    public class Step4CountOperations {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78};

        int sum = 0;
        int operationCount = 0;   // 핵심 연산 실행 횟수

        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];
            operationCount++;     // 누적 연산을 할 때마다 1 증가
        }

        System.out.println("점수 합계 = " + sum);
        System.out.println("데이터 개수 n = " + scores.length);
        System.out.println("누적 연산 실행 횟수 = " + operationCount);
    }
}
    출력 실행 결과 
    점수 합계 = 391
데이터 개수 n = 5
누적 연산 실행 횟수 = 5
    관찰

    데이터가 5개일 때 연산도 5번 — n개면 n번입니다. 이것을 O(n)이라고 부릅니다. 이 "카운터 붙이기" 기법은 4강 정렬의 비교·교환 횟수, 5강 탐색의 비교 횟수를 잴 때 계속 사용합니다.

    10완성 Java 코드

    지금까지의 조각을 모아 "같은 문제, 두 가지 알고리즘" 비교 프로그램을 완성합니다. 방법 A(반복문)와 방법 B(가우스 공식)를 각각 메서드로 분리하고, n을 10배씩 키우며 결과와 연산 횟수를 표로 출력합니다. 결과가 다르면 경고를 출력해 정확성 검증도 함께 합니다.

    Java SumTwoWaysComplete.java 
    public class SumTwoWaysComplete {

    /** 방법 A: 1부터 n까지 반복문으로 더한다. 누적 연산이 n번 실행된다. */
    static long sumByLoop(int n) {
        long sum = 0;
        for (int i = 1; i <= n; i++) {
            sum = sum + i;
        }
        return sum;
    }

    /** 방법 A의 핵심 연산 실행 횟수: 데이터가 n개면 정확히 n번 */
    static long loopOperationCount(int n) {
        return n;
    }

    /** 방법 B: 가우스 공식. n이 아무리 커도 계산은 한 번이다. */
    static long sumByFormula(int n) {
        return (long) n * (n + 1) / 2;
    }

    public static void main(String[] args) {
        int[] sizes = {10, 100, 1000, 10000, 100000};

        System.out.println("n        | 반복문 결과   | 공식 결과     | 반복문 연산 횟수 | 공식 연산 횟수");
        System.out.println("---------+--------------+--------------+-----------------+---------------");

        for (int n : sizes) {
            long loopResult = sumByLoop(n);
            long formulaResult = sumByFormula(n);

            System.out.printf("%-8d | %-12d | %-12d | %-15d | %d%n",
                    n, loopResult, formulaResult, loopOperationCount(n), 1);

            // 두 알고리즘의 "정확성"이 같은지 반드시 확인한다
            if (loopResult != formulaResult) {
                System.out.println("경고: 두 방법의 결과가 다릅니다! 알고리즘에 오류가 있습니다.");
            }
        }

        System.out.println();
        System.out.println("n이 10배 커질 때: 반복문의 일은 10배 늘고, 공식의 일은 그대로 1이다.");
    }
}

    13복잡도 및 특성 분석

    입력 크기

    n은 더할 숫자의 개수(= 마지막 숫자)입니다. 알고리즘의 일의 양은 이 n을 기준으로 표현합니다.

    주요 연산

    방법 A의 핵심 연산은 누적 덧셈 sum = sum + i, 방법 B의 핵심 연산은 공식 계산 한 번입니다.

    시간 복잡도

    알고리즘최선평균최악Big-O
    방법 A — 반복문n번n번n번O(n)
    방법 B — 공식1번1번1번O(1)

    방법 A는 입력이 무엇이든 항상 n번 일합니다 — 최선과 최악이 같습니다. 반면 뒤에서 배울 탐색 알고리즘(5강)은 "어디에 있느냐"에 따라 최선(1번)과 최악(n번)이 달라집니다.

    공간 복잡도

    두 방법 모두 sum, i, 카운터 등 변수 몇 개만 사용합니다. 입력이 커져도 추가 메모리가 늘지 않으므로 공간 복잡도 O(1)입니다.

    알고리즘 특성

    • 결과 동일성: 두 알고리즘은 모든 유효한 n에서 같은 출력을 냅니다. 효율만 다릅니다.
    • 일반성의 차이: 공식(O(1))은 "1부터 n까지 연속된 자연수"라는 규칙이 있을 때만 가능합니다. 임의의 점수 배열 합계에는 공식이 없으므로 O(n) 순회가 필요합니다 — 2강의 주제입니다.
    • 시간과 지식의 교환: 데이터의 규칙(수학적 성질, 정렬 여부 등)을 알수록 더 빠른 알고리즘을 선택할 수 있습니다. 5강 이진 탐색, 11강 동적 계획법이 이 원리의 확장입니다.

    15실제 데이터 응용 예제

    문제 상황

    교수님이 출석부 프로그램을 만들고 있습니다. "출석 번호 k번 학생 이름을 찾아라"라는 요청이 자주 들어옵니다. 이름 배열을 앞에서부터 한 명씩 확인할 수도 있지만, 이 데이터에는 "출석 번호 = 배열 인덱스 + 1"이라는 규칙이 있습니다. 규칙을 이용하면 확인 한 번으로 찾을 수 있습니다.

    데이터 모델과 알고리즘 적용 기준

    • 데이터: 출석 번호 순으로 저장된 학생 이름 배열 String[] names
    • 방법 A (순차 확인): 규칙을 모를 때 — 어떤 배열에도 쓸 수 있는 일반적인 방법, O(n)
    • 방법 B (직접 접근): "번호 = 인덱스 + 1" 규칙을 알 때 — 이 데이터에만 가능한 방법, O(1)
    Java StudentLookupApplication.java 
    public class StudentLookupApplication {

    /** 방법 A: 순서대로 확인. 몇 번 비교했는지 함께 출력한다. */
    static String findBySequentialCheck(String[] names, int attendanceNo) {
        int compareCount = 0;
        for (int i = 0; i < names.length; i++) {
            compareCount++;
            // 이 자리의 출석 번호는 i + 1 이다
            if (i + 1 == attendanceNo) {
                System.out.println("  [방법 A] 비교 " + compareCount + "번 만에 발견");
                return names[i];
            }
        }
        System.out.println("  [방법 A] " + compareCount + "번 비교했지만 없음");
        return null;
    }

    /** 방법 B: 번호 규칙(번호 = 인덱스 + 1)을 이용해 한 번에 접근한다. */
    static String findByDirectAccess(String[] names, int attendanceNo) {
        if (attendanceNo < 1 || attendanceNo > names.length) {
            System.out.println("  [방법 B] 접근 1번 — 범위를 벗어난 번호");
            return null;
        }
        System.out.println("  [방법 B] 접근 1번 만에 발견");
        return names[attendanceNo - 1];
    }

    public static void main(String[] args) {
        // 출석 번호 1번부터 8번까지의 학생 이름
        String[] names = {"김하늘", "이준호", "박서연", "최민재",
                          "정다은", "강지훈", "윤소미", "한도윤"};

        int[] searchTargets = {1, 5, 8, 12};

        for (int no : searchTargets) {
            System.out.println("출석 번호 " + no + "번 학생 찾기:");
            String resultA = findBySequentialCheck(names, no);
            String resultB = findByDirectAccess(names, no);
            System.out.println("  결과: " + (resultA == null ? "없음" : resultA)
                    + " / 두 방법의 결과 일치 = "
                    + java.util.Objects.equals(resultA, resultB));
            System.out.println();
        }

        System.out.println("데이터에 규칙(번호 = 인덱스 + 1)이 있으면 O(n) 확인을 O(1) 접근으로 바꿀 수 있다.");
    }
}

    코드 해설과 복잡도 분석

    • 방법 B는 어떤 번호든 범위 검사 1번 + 접근 1번 → O(1). 단, 존재하지 않는 번호(12번)도 안전하게 처리하도록 입력 검증이 필수입니다.
    • 두 방법의 결과가 항상 일치하는지 Objects.equals로 검증합니다 — 빠른 알고리즘을 도입할 때는 반드시 느리지만 확실한 방법과 결과를 비교하세요.

    문제 제목 — 알고리즘 효율성 분석기 "AlgoMeter"

    문제 배경

    여러분은 개발팀의 신입 개발자입니다. 팀장이 새 기능에 쓸 알고리즘 두 가지를 두고 고민하다가, "감으로 정하지 말고 측정해서 정하자"라며 여러분에게 도구 제작을 맡겼습니다. 이 도구는 같은 문제를 푸는 두 방식의 핵심 연산 실행 횟수를 세어 표로 비교합니다. 측정 대상은 두 과제입니다. 과제 1은 "1부터 n까지의 합"(반복문 vs 공식), 과제 2는 "점수 목록에서 특정 점수 찾기"(전체 확인 vs 조기 중단)입니다. 실행 횟수가 눈에 보이면, 어떤 알고리즘을 선택할지 근거를 갖고 말할 수 있게 됩니다.

    프로그램 목표

    두 과제 각각에 대해 두 가지 방식을 구현하고, 결과와 연산 횟수를 표 형태로 출력하는 콘솔 프로그램을 완성합니다.

    필수 요구사항

    1. sumByLoop(int n) — 반복문으로 1부터 n까지 더하고, 누적 연산 횟수를 함께 기록한다.
    2. sumByFormula(int n) — 가우스 공식으로 계산하고 연산 횟수를 1로 기록한다. (long으로 계산해 오버플로 방지)
    3. findCheckAll(int[] data, int target) — 배열 전체를 끝까지 확인하며 위치를 찾고, 비교 횟수를 기록한다.
    4. findStopEarly(int[] data, int target) — 찾는 즉시 반복을 중단하고, 비교 횟수를 기록한다.
    5. 각 메서드는 결과와 연산 횟수를 담은 Measurement 객체를 반환한다.
    6. n = 10, 100, 1000, 10000에 대해 과제 1의 결과를 표로 출력한다.
    7. 과제 2에서 "있는 값"과 "없는 값" 두 경우의 비교 횟수를 모두 출력한다.

    입력 데이터

    과제 1: n = 10, 100, 1000, 10000
과제 2: scores = {72, 85, 90, 66, 78, 93, 55, 81, 60, 77}
        찾는 값: 78 (있는 값), 100 (없는 값)

    제한 조건

    • n은 1 이상 100,000 이하의 정수, 점수 배열의 길이는 1 이상 1,000 이하.
    • 합계는 반드시 long으로 계산한다 (int 오버플로 방지).
    • java.util.stream 등의 라이브러리 합계 기능은 사용하지 않는다 — 반복문을 직접 작성한다.
    • 찾는 값이 없으면 위치는 -1로 기록한다. 배열에 중복 값은 없다고 가정한다.
    • 4개 메서드와 Measurement 클래스는 반드시 구현한다.

    구현 단계 안내

    1. Measurement 클래스가 결과와 연산 횟수를 담는 구조를 먼저 이해한다.
    2. sumByLoop부터 완성한다 — 구현 4단계(카운터 붙이기)와 같은 구조다.
    3. sumByFormula를 완성하고, 과제 1 표의 두 결과가 항상 같은지 확인한다.
    4. findCheckAll을 완성한다 — 찾아도 멈추지 않고 끝까지 확인한다.
    5. findStopEarly를 완성한다 — return으로 즉시 중단한다.
    6. 없는 값(100)을 찾는 보너스 출력을 추가하고, 두 방식의 비교 횟수가 왜 같아지는지 생각해 본다.

    정답 코드와 해설 확인
    Java EfficiencyAnalyzerSolution.java 
    public class EfficiencyAnalyzerSolution {

    /** 측정 결과를 담는 작은 기록용 클래스 */
    static class Measurement {
        long result;          // 계산 결과 (합계 또는 찾은 위치)
        long operationCount;  // 핵심 연산 실행 횟수

        Measurement(long result, long operationCount) {
            this.result = result;
            this.operationCount = operationCount;
        }
    }

    /** 과제 1-A: 반복문으로 1부터 n까지 더하고, 덧셈 횟수를 센다. */
    static Measurement sumByLoop(int n) {
        long sum = 0;
        long count = 0;
        for (int i = 1; i <= n; i++) {
            sum = sum + i;   // 핵심 연산: 누적
            count++;
        }
        return new Measurement(sum, count);
    }

    /** 과제 1-B: 가우스 공식. long으로 계산해 오버플로를 막는다. */
    static Measurement sumByFormula(int n) {
        long sum = (long) n * (n + 1) / 2;
        return new Measurement(sum, 1);
    }

    /** 과제 2-A: 배열 전체를 끝까지 확인한다. 비교 횟수는 항상 n이다. */
    static Measurement findCheckAll(int[] data, int target) {
        long count = 0;
        long foundIndex = -1;
        for (int i = 0; i < data.length; i++) {
            count++;                 // 핵심 연산: 비교
            if (data[i] == target) {
                foundIndex = i;      // 기록만 하고 계속 확인한다
            }
        }
        return new Measurement(foundIndex, count);
    }

    /** 과제 2-B: 찾는 즉시 중단한다. 최선 1번, 최악 n번 비교. */
    static Measurement findStopEarly(int[] data, int target) {
        long count = 0;
        for (int i = 0; i < data.length; i++) {
            count++;                 // 핵심 연산: 비교
            if (data[i] == target) {
                return new Measurement(i, count);   // 즉시 반환 = 조기 중단
            }
        }
        return new Measurement(-1, count);
    }

    public static void main(String[] args) {
        System.out.println("== 과제 1: 1부터 n까지의 합 ==");
        System.out.println("n      | 반복문 결과 | 공식 결과   | 반복 연산 | 공식 연산");
        int[] sizes = {10, 100, 1000, 10000};
        for (int n : sizes) {
            Measurement loop = sumByLoop(n);
            Measurement formula = sumByFormula(n);
            System.out.printf("%-6d | %-10d | %-10d | %-8d | %d%n",
                    n, loop.result, formula.result, loop.operationCount, formula.operationCount);
        }

        System.out.println();
        System.out.println("== 과제 2: 점수 목록에서 78점 찾기 ==");
        int[] scores = {72, 85, 90, 66, 78, 93, 55, 81, 60, 77};
        Measurement all = findCheckAll(scores, 78);
        Measurement early = findStopEarly(scores, 78);
        System.out.println("전체 확인 방식: 위치 " + all.result + ", 비교 " + all.operationCount + "번");
        System.out.println("조기 중단 방식: 위치 " + early.result + ", 비교 " + early.operationCount + "번");

        System.out.println();
        System.out.println("== 과제 2 보너스: 없는 값(100점) 찾기 ==");
        Measurement allMiss = findCheckAll(scores, 100);
        Measurement earlyMiss = findStopEarly(scores, 100);
        System.out.println("전체 확인 방식: 위치 " + allMiss.result + ", 비교 " + allMiss.operationCount + "번");
        System.out.println("조기 중단 방식: 위치 " + earlyMiss.result + ", 비교 " + earlyMiss.operationCount + "번");
        System.out.println("없는 값을 찾을 때(최악의 경우)는 두 방식 모두 n번 비교한다.");
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. Measurement는 "결과 + 일의 양"을 한 번에 반환하기 위한 작은 기록 클래스입니다. 메서드가 값을 두 개 돌려줘야 할 때 쓰는 기본 패턴입니다.
    2. sumByLoop의 핵심은 누적과 카운트가 같은 반복 안에서 함께 일어나는 것입니다.
    3. sumByFormula의 핵심은 (long) n 캐스팅 — 오류 2에서 본 오버플로 함정을 피합니다.
    4. findCheckAll과 findStopEarly의 유일한 차이는 찾았을 때 return하느냐입니다. 이 한 줄이 평균 비교 횟수를 절반으로 줄입니다.

    복잡도 분석

    • 과제 1: 반복문 O(n) vs 공식 O(1). 공간은 둘 다 O(1).
    • 과제 2: 전체 확인은 항상 n번(최선=최악). 조기 중단은 최선 1번, 평균 약 n/2번, 최악(없는 값) n번. Big-O로는 둘 다 O(n)이지만 평균 실행 횟수는 2배 차이 — Big-O가 전부가 아니라는 것도 배웁니다.

    자주 발생하는 오류

    • i < n으로 써서 합이 n만큼 모자란 경우 (off-by-one).
    • (long) 캐스팅을 빼서 n=100000에서 틀린 값이 나오는 경우.
    • findStopEarly에서 count++를 if 뒤에 두어 비교 횟수가 1 적게 세어지는 경우.

    다른 해결 방법

    Measurement를 Java 16+의 record Measurement(long result, long operationCount)로 선언하면 더 간결합니다. 또한 연산 횟수를 전역 변수로 세는 방법도 있지만, 메서드가 자신의 측정값을 직접 반환하는 지금 구조가 테스트하기 더 좋습니다.

    19오늘의 핵심 정리

    • 알고리즘은 문제를 해결하는 명확한 절차이며, 같은 문제에 여러 알고리즘이 존재할 수 있다.
    • 문제는 입력 → 처리 → 출력으로 나누고, 큰 문제는 작은 문제로 분해한다.
    • 좋은 알고리즘의 기준은 정확성 먼저, 효율성 다음. 정확성은 경계 입력(n=1, 없는 값, 큰 값)까지 확인해야 한다.
    • 시간 복잡도는 입력 크기 n에 따른 핵심 연산 횟수의 증가 모양이며, Big-O로 표기한다: O(1) → O(log n) → O(n) → O(n²) 순으로 느려진다.
    • 연산 횟수는 카운터 변수로 직접 셀 수 있다 — 이 기법은 이후 모든 강의에서 사용된다.
    • 데이터의 규칙(연속된 수, 번호=인덱스 등)을 알면 훨씬 빠른 알고리즘을 선택할 수 있다.

    01강의 소개

    프로그래밍 공부를 시작하면 누구나 이런 질문을 만납니다. "내 코드는 돌아가긴 하는데, 잘 만든 걸까?" 이 질문에 답하려면 두 가지 기준이 필요합니다. 첫째, 정확성 — 어떤 입력에도 올바른 답을 내는가. 둘째, 효율성 — 데이터가 많아져도 감당할 수 있는가.

    이번 강의는 13개 강좌 전체의 출발점입니다. 알고리즘이라는 말의 의미부터, 문제를 입력 → 처리 → 출력으로 나누는 습관, 풀이 과정을 코드 이전에 표현하는 의사코드와 순서도, 그리고 알고리즘의 일의 양을 표현하는 시간 복잡도와 Big-O 표기법까지 다룹니다. 마지막에는 같은 문제를 두 가지 방식으로 풀어 실행 횟수를 비교하는 알고리즘 효율성 분석 프로그램을 직접 만듭니다.

    05실행 빈도수 세어보기

    04번 섹션에서 선배 개발자는 "코드는 맞게 짰는데, 알고리즘이 느린 거야"라고 말했습니다. 이 말을 감이 아니라 숫자로 확인하는 방법은 뜻밖에 단순합니다. 코드의 각 줄이 입력 크기 n에 따라 몇 번 실행되는지 손으로 세어 보는 것입니다. 이렇게 얻은 "실행 빈도수"를 모두 더하면 시간 복잡도 식이 되고, 왜 그 식이 2n + 1이나 3n + 4처럼 딱 떨어지지 않는 모양으로 나오는지도 알 수 있습니다.

    실행 빈도수 — 초 대신 "몇 번"을 센다

    같은 프로그램도 컴퓨터 성능에 따라 실행 시간(초)이 달라집니다. 그래서 시간 복잡도는 초 대신 각 문장이 몇 번 실행되는가(실행 빈도수)를 셉니다. 대입문(sum ← 0), 조건 검사(i ≤ n), 반환문(return)처럼 한 번 실행하는 데 걸리는 시간이 서로 비슷한 문장은 모두 단위 시간 1로 취급합니다.

    예제 1 — 반복문 하나로 "2n + 1" 만들기

    가장 단순한 반복문부터 세어 봅니다.

    i ← 1
i가 n 이하인 동안 반복:     // ① 조건 검사
    (할 일 한 가지)          // ② 반복문 몸체
    i ← i + 1
    질문: ① 조건 검사(i ≤ n)는 총 몇 번 실행될까요?

    n + 1번입니다. i가 1, 2, …, n일 때는 조건이 참이라 몸체로 들어가고(n번), i가 n+1이 되는 순간 조건이 거짓으로 판정되어 반복을 빠져나갑니다(1번). 반복을 끝내기 위한 이 마지막 한 번의 "실패한 검사"가 실행 횟수 식에 붙는 "+1"의 정체입니다.

    질문: ② 반복문 몸체는 총 몇 번 실행될까요? 그리고 전체 실행 횟수는?

    몸체는 조건이 참일 때만 실행되므로 n번입니다. 전체 실행 횟수 = 조건 검사(n+1) + 몸체(n) = 2n + 1입니다. 2장 「소프트웨어와 자료구조」에서 f(n) = 2n + 1이 Big-O 예시로 자주 등장하는 이유가 바로 "조건 검사가 몸체보다 한 번 더 실행된다"는, 반복문이라면 어디서나 나타나는 구조 때문입니다.

    예제 2 — SumByLoop으로 "3n + 4" 만들기

    이번에는 이 강의에서 계속 쓸 "1부터 n까지의 합" 알고리즘 자체를 줄 단위로 세어 봅니다.

    줄문장실행 조건실행 횟수
    ①sum ← 0딱 한 번, 시작할 때만1
    ②i ← 1딱 한 번, 시작할 때만1
    ③i ≤ n (조건 검사)참 n번 + 거짓 1번n + 1
    ④sum ← sum + i조건이 참일 때만n
    ⑤i ← i + 1조건이 참일 때만n
    ⑥sum 반환딱 한 번, 끝날 때만1

    총 실행 횟수 = 1 + 1 + (n+1) + n + n + 1 = 3n + 4. 예제 1과 세는 방식은 완전히 같지만, 초기화문 두 줄(①②)과 반환문 한 줄(⑥)이 "n과 무관하게 1번씩" 더 실행되면서 계수와 상수항이 달라졌습니다. 알고리즘마다 정확한 식이 2n+1, 3n+4, 4n+2처럼 서로 다르게 나오는 것은, 서로 다른 종류의 문장이 각각 다른 횟수만큼 실행되고 그 횟수들을 전부 더하기 때문입니다. (교재의 피보나치 수열 알고리즘도 같은 방식으로 13개 줄을 세어 4n + 2를 얻습니다.)

    그래서 다음 섹션에서는?

    2n+1과 3n+4는 생김새는 달라도 둘 다 "n이 커지면 실행 횟수도 거의 같은 속도로 늘어난다"는 같은 이야기를 하고 있습니다. 이 증가하는 모양만 남기고 계수와 상수항을 정리하는 규칙이 다음 섹션의 Big-O 표기법입니다.

    06핵심 개념

    알고리즘이란?

    알고리즘은 문제를 해결하는, 순서가 있는 명확한 절차입니다. "명확한"이 중요합니다 — 누가 따라 해도(사람이든 컴퓨터든) 같은 결과가 나와야 합니다. 예를 들어 "1부터 n까지의 합을 구하라"는 같은 문제도, 하나씩 더하는 절차와 가우스의 공식을 쓰는 절차처럼 서로 다른 알고리즘으로 풀 수 있습니다. 두 절차는 이 강의 전체에서 계속 비교합니다.

    의사코드와 순서도

    의사코드(pseudocode)는 특정 언어 문법에 매이지 않고 절차를 적는 방법이고, 순서도(flowchart)는 절차를 도형(시작/끝, 처리, 판단)으로 그리는 방법입니다. 코드보다 먼저 절차를 적어 보면 논리 오류를 훨씬 일찍 발견할 수 있습니다. 구체적인 예는 아래 8번 의사코드 섹션에서 다룹니다.

    정확성과 효율성

    • 정확성: 모든 유효한 입력에 대해 올바른 출력을 낸다. (n=1, n=0 같은 경계도 포함!)
    • 효율성: 시간(연산 횟수)과 공간(메모리)을 얼마나 쓰는가.

    시간 복잡도와 Big-O 표기법

    시간 복잡도는 입력 크기 n이 커질 때 핵심 연산의 실행 횟수가 어떻게 늘어나는지를 나타냅니다. 05번 섹션에서 직접 세어 얻은 2n + 1, 3n + 4 같은 식이 바로 이 시간 복잡도 함수입니다. 정확한 식 대신 증가하는 모양만 남긴 것이 Big-O 표기법입니다.

    계수와 낮은 차수 항을 버리는 이유

    2n + 1을 예로 들어 봅시다. n이 100,000이면 2n은 200,000이고 +1은 그 옆에 붙어도 눈에 띄지 않습니다. n이 커질수록 식 전체의 크기를 사실상 결정하는 것은 차수가 가장 높은 항 하나뿐이고, 계수(2)와 낮은 차수의 항(+1)은 상대적으로 무시할 수 있을 만큼 작아집니다.

    숫자로 확인하기 — T(n) = n² + n + 1, n=1,000일 때

    T(1,000) = 1,000,000 + 1,000 + 1 = 1,001,001입니다. 이 중 n² 항(1,000,000)이 전체의 약 99.9%를 차지하고, n 항(1,000)은 0.1%, 상수항(1)은 사실상 0%입니다. 가장 큰 항 하나만 남겨도 전체 값을 거의 그대로 설명할 수 있으므로, Big-O는 그 항만 남기고 계수마저 지워 O(n²)이라고 씁니다.

    Big-O의 정확한 뜻 — 함수의 상한

    Big-O는 "대충 이 정도로 늘어난다"는 감이 아니라 정확히 정의된 상한선입니다. f(n) = O(g(n))이라는 말은, 어떤 기준값 n₀와 상수 c가 있어서 n ≥ n₀인 모든 n에 대해 f(n) ≤ c × g(n)이 항상 성립한다는 뜻입니다. 즉 "입력이 충분히 커지면, 실행 횟수는 많아야 g(n)에 상수를 곱한 만큼까지만 늘어난다"는 약속입니다.

    실행 횟수 함수 f(n)Big-O성립 근거
    5O(1)n₀=1, c=10일 때 n≥1이면 5 ≤ 10 × 1
    2n + 1O(n)n₀=2, c=3일 때 n≥2이면 2n+1 ≤ 3n
    3n² + 100O(n²)n₀=100, c=5일 때 n≥100이면 3n²+100 ≤ 5n²
    5·2ⁿ + 10n² + 100O(2ⁿ)n₀=1,000, c=10일 때 n≥1,000이면 성립

    두 번째 줄이 바로 05번 섹션에서 얻은 2n + 1입니다. n≥2일 때 2n+1 ≤ 3n이 항상 성립하므로 2n + 1 = O(n)이고, 같은 이유로 3n + 4도 O(n)입니다.

    시각화 마지막 단계에서 확인할 수 있듯, 반복문 방식은 n번의 누적 연산 후에, 공식 방식은 단 1번의 계산으로 같은 결과 36에 도달합니다.

    08의사코드

    코드를 쓰기 전에, 방금 본 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo 방법 A — 반복문으로 합 구하기 
    알고리즘 SumByLoop(n)
    sum ← 0
    i ← 1
    i가 n 이하인 동안 반복:
        sum ← sum + i        // 핵심 연산 (n번 실행)
        i ← i + 1
    sum을 반환한다
    Pseudo 방법 B — 공식으로 합 구하기 
    알고리즘 SumByFormula(n)
    sum ← n × (n + 1) ÷ 2   // 핵심 연산 (1번 실행)
    sum을 반환한다

    순서도로 그리면 방법 A는 "판단(i ≤ n?) → 처리(누적) → 다시 판단"의 고리(loop)가 생기고, 방법 B는 시작 → 처리 → 끝의 직선이 됩니다. 고리의 유무가 곧 O(n)과 O(1)의 차이입니다.

    Java Step4CountOperations.java 
    public class Step4CountOperations {
    public static void main(String[] args) {
        int[] scores = {72, 85, 90, 66, 78};

        int sum = 0;
        int operationCount = 0;   // 핵심 연산 실행 횟수

        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];
            operationCount++;     // 누적 연산을 할 때마다 1 증가
        }

        System.out.println("점수 합계 = " + sum);
        System.out.println("데이터 개수 n = " + scores.length);
        System.out.println("누적 연산 실행 횟수 = " + operationCount);
    }
}

    데이터가 5개일 때 연산도 5번 — n개면 n번입니다. 이것을 O(n)이라고 부릅니다. 이 "카운터 붙이기" 기법은 4강 정렬의 비교·교환 횟수, 5강 탐색의 비교 횟수를 잴 때 계속 사용합니다.

    10완성 Java 코드

    지금까지의 조각을 모아 "같은 문제, 두 가지 알고리즘" 비교 프로그램을 완성합니다. 방법 A(반복문)와 방법 B(가우스 공식)를 각각 메서드로 분리하고, n을 10배씩 키우며 결과와 연산 횟수를 표로 출력합니다. 결과가 다르면 경고를 출력해 정확성 검증도 함께 합니다.

    Java SumTwoWaysComplete.java 
    public class SumTwoWaysComplete {

    /** 방법 A: 1부터 n까지 반복문으로 더한다. 누적 연산이 n번 실행된다. */
    static long sumByLoop(int n) {
        long sum = 0;
        for (int i = 1; i <= n; i++) {
            sum = sum + i;
        }
        return sum;
    }

    /** 방법 A의 핵심 연산 실행 횟수: 데이터가 n개면 정확히 n번 */
    static long loopOperationCount(int n) {
        return n;
    }

    /** 방법 B: 가우스 공식. n이 아무리 커도 계산은 한 번이다. */
    static long sumByFormula(int n) {
        return (long) n * (n + 1) / 2;
    }

    public static void main(String[] args) {
        int[] sizes = {10, 100, 1000, 10000, 100000};

        System.out.println("n        | 반복문 결과   | 공식 결과     | 반복문 연산 횟수 | 공식 연산 횟수");
        System.out.println("---------+--------------+--------------+-----------------+---------------");

        for (int n : sizes) {
            long loopResult = sumByLoop(n);
            long formulaResult = sumByFormula(n);

            System.out.printf("%-8d | %-12d | %-12d | %-15d | %d%n",
                    n, loopResult, formulaResult, loopOperationCount(n), 1);

            // 두 알고리즘의 "정확성"이 같은지 반드시 확인한다
            if (loopResult != formulaResult) {
                System.out.println("경고: 두 방법의 결과가 다릅니다! 알고리즘에 오류가 있습니다.");
            }
        }

        System.out.println();
        System.out.println("n이 10배 커질 때: 반복문의 일은 10배 늘고, 공식의 일은 그대로 1이다.");
    }
}

    왜 long을 쓸까?

    (long) n * (n + 1)에서 캐스팅을 빼면 n=100,000일 때 int 곱셈이 넘쳐(오버플로) 틀린 값이 나옵니다. 효율보다 정확성이 먼저라는 원칙이 코드 한 줄에도 적용됩니다.

    12잘못된 코드와 오류 찾기

    초보자가 이 알고리즘에서 자주 만드는 오류 두 가지를 직접 찾아봅시다. 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 반복 범위가 잘못된 합계

    Java BuggySumRange.java (오류 있음) 
    public class BuggySumRange {
    public static void main(String[] args) {
        int n = 8;
        long sum = 0;

        // 1부터 n까지의 합을 구하고 싶다
        for (int i = 1; i < n; i++) {
            sum = sum + i;
        }

        System.out.println("1부터 " + n + "까지의 합 = " + sum);
    }
}
    발생하는 문제와 수정 방법 확인

    발생하는 문제: 출력이 28로, 정답 36보다 작습니다.

    오류가 나타나는 입력: 모든 n ≥ 1. (n=1이면 아예 0이 나옵니다.)

    원인: 조건이 i < n이라 마지막 값 n(여기서는 8)이 더해지지 않습니다. "n번 반복"과 "n까지 반복"을 혼동한, 가장 흔한 off-by-one(하나 차이) 오류입니다.

    수정 방법: 조건을 i <= n으로 바꿉니다.

    for (int i = 1; i <= n; i++) {
    sum = sum + i;
}

    수정 후 출력: 1부터 8까지의 합 = 36. 경계값(첫 값과 끝 값)이 포함되는지 항상 손으로 확인하는 습관을 들이세요.

    오류 2 — int 오버플로로 틀린 공식 결과

    오류가 나타나는 입력: n이 약 65,536 이상일 때. n=10,000까지는 정답이 나와서 테스트를 통과한 것처럼 보이는 것이 함정입니다.

    원인: n * (n + 1)이 int끼리의 곱셈으로 먼저 계산됩니다. 100,000 × 100,001은 int의 최댓값(약 21억)을 넘어 오버플로가 일어난 뒤, 이미 망가진 값이 long 변수에 저장됩니다.

    수정 방법: 곱셈 전에 long으로 캐스팅합니다.

    long sum = (long) n * (n + 1) / 2;

    수정 후 출력: 1부터 100000까지의 합 = 5000050000. "작은 입력에서 통과했다"는 것이 "모든 입력에서 정확하다"를 보장하지 않습니다 — 정확성 검증에는 큰 입력과 경계 입력이 반드시 필요합니다.

    13복잡도 및 특성 분석

    입력 크기

    n은 더할 숫자의 개수(= 마지막 숫자)입니다. 알고리즘의 일의 양은 이 n을 기준으로 표현합니다.

    주요 연산

    방법 A의 핵심 연산은 누적 덧셈 sum = sum + i, 방법 B의 핵심 연산은 공식 계산 한 번입니다.

    시간 복잡도

    알고리즘최선평균최악Big-O
    방법 A — 반복문n번n번n번O(n)
    방법 B — 공식1번1번1번O(1)

    방법 A는 입력이 무엇이든 항상 n번 일합니다 — 최선과 최악이 같습니다. 반면 뒤에서 배울 탐색 알고리즘(5강)은 "어디에 있느냐"에 따라 최선(1번)과 최악(n번)이 달라집니다.

    공간 복잡도

    두 방법 모두 sum, i, 카운터 등 변수 몇 개만 사용합니다. 입력이 커져도 추가 메모리가 늘지 않으므로 공간 복잡도 O(1)입니다.

    알고리즘 특성

    • 결과 동일성: 두 알고리즘은 모든 유효한 n에서 같은 출력을 냅니다. 효율만 다릅니다.
    • 일반성의 차이: 공식(O(1))은 "1부터 n까지 연속된 자연수"라는 규칙이 있을 때만 가능합니다. 임의의 점수 배열 합계에는 공식이 없으므로 O(n) 순회가 필요합니다 — 2강의 주제입니다.
    • 시간과 지식의 교환: 데이터의 규칙(수학적 성질, 정렬 여부 등)을 알수록 더 빠른 알고리즘을 선택할 수 있습니다. 5강 이진 탐색, 11강 동적 계획법이 이 원리의 확장입니다.

    14실제 데이터 응용 예제

    문제 상황

    교수님이 출석부 프로그램을 만들고 있습니다. "출석 번호 k번 학생 이름을 찾아라"라는 요청이 자주 들어옵니다. 이름 배열을 앞에서부터 한 명씩 확인할 수도 있지만, 이 데이터에는 "출석 번호 = 배열 인덱스 + 1"이라는 규칙이 있습니다. 규칙을 이용하면 확인 한 번으로 찾을 수 있습니다.

    데이터 모델과 알고리즘 적용 기준

    • 데이터: 출석 번호 순으로 저장된 학생 이름 배열 String[] names
    • 방법 A (순차 확인): 규칙을 모를 때 — 어떤 배열에도 쓸 수 있는 일반적인 방법, O(n)
    • 방법 B (직접 접근): "번호 = 인덱스 + 1" 규칙을 알 때 — 이 데이터에만 가능한 방법, O(1)
    Java StudentLookupApplication.java 
    public class StudentLookupApplication {

    /** 방법 A: 순서대로 확인. 몇 번 비교했는지 함께 출력한다. */
    static String findBySequentialCheck(String[] names, int attendanceNo) {
        int compareCount = 0;
        for (int i = 0; i < names.length; i++) {
            compareCount++;
            // 이 자리의 출석 번호는 i + 1 이다
            if (i + 1 == attendanceNo) {
                System.out.println("  [방법 A] 비교 " + compareCount + "번 만에 발견");
                return names[i];
            }
        }
        System.out.println("  [방법 A] " + compareCount + "번 비교했지만 없음");
        return null;
    }

        long sum = 0;
        long count = 0;
        for (int i = 1; i <= n; i++) {
            sum = sum + i;   // 핵심 연산: 누적
            count++;
        }
        return new Measurement(sum, count);

        Measurement all = findCheckAll(scores, 78);
        Measurement early = findStopEarly(scores, 78);
        System.out.println("전체 확인 방식: 위치 " + all.result + ", 비교 " + all.operationCount + "번");
        System.out.println("조기 중단 방식: 위치 " + early.result + ", 비교 " + early.operationCount + "번");

        System.out.println();
        System.out.println("== 과제 2 보너스: 없는 값(100점) 찾기 ==");
        Measurement allMiss = findCheckAll(scores, 100);
        Measurement earlyMiss = findStopEarly(scores, 100);
        System.out.println("전체 확인 방식: 위치 " + allMiss.result + ", 비교 " + allMiss.operationCount + "번");
        System.out.println("조기 중단 방식: 위치 " + earlyMiss.result + ", 비교 " + earlyMiss.operationCount + "번");
        System.out.println("없는 값을 찾을 때(최악의 경우)는 두 방식 모두 n번 비교한다.");
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. Measurement는 "결과 + 일의 양"을 한 번에 반환하기 위한 작은 기록 클래스입니다. 메서드가 값을 두 개 돌려줘야 할 때 쓰는 기본 패턴입니다.
    2. sumByLoop의 핵심은 누적과 카운트가 같은 반복 안에서 함께 일어나는 것입니다.
    3. sumByFormula의 핵심은 (long) n 캐스팅 — 오류 2에서 본 오버플로 함정을 피합니다.
    4. findCheckAll과 findStopEarly의 유일한 차이는 찾았을 때 return하느냐입니다. 이 한 줄이 평균 비교 횟수를 절반으로 줄입니다.

    복잡도 분석

    • 과제 1: 반복문 O(n) vs 공식 O(1). 공간은 둘 다 O(1).
    • 과제 2: 전체 확인은 항상 n번(최선=최악). 조기 중단은 최선 1번, 평균 약 n/2번, 최악(없는 값) n번. Big-O로는 둘 다 O(n)이지만 평균 실행 횟수는 2배 차이 — Big-O가 전부가 아니라는 것도 배웁니다.

    자주 발생하는 오류

    • i < n으로 써서 합이 n만큼 모자란 경우 (off-by-one).
    • (long) 캐스팅을 빼서 n=100000에서 틀린 값이 나오는 경우.
    • findStopEarly에서 count++를 if 뒤에 두어 비교 횟수가 1 적게 세어지는 경우.

    다른 해결 방법

    Measurement를 Java 16+의 record Measurement(long result, long operationCount)로 선언하면 더 간결합니다. 또한 연산 횟수를 전역 변수로 세는 방법도 있지만, 메서드가 자신의 측정값을 직접 반환하는 지금 구조가 테스트하기 더 좋습니다.

    18오늘의 핵심 정리

    • 알고리즘은 문제를 해결하는 명확한 절차이며, 같은 문제에 여러 알고리즘이 존재할 수 있다.
    • 문제는 입력 → 처리 → 출력으로 나누고, 큰 문제는 작은 문제로 분해한다.
    • 좋은 알고리즘의 기준은 정확성 먼저, 효율성 다음. 정확성은 경계 입력(n=1, 없는 값, 큰 값)까지 확인해야 한다.
    • 문장별 실행 빈도수를 세어 더하면 2n+1, 3n+4 같은 시간 복잡도 식을 얻는다. 문장의 종류마다 실행 횟수가 다르기 때문에 식의 계수와 상수항이 알고리즘마다 달라진다.
    • 시간 복잡도 식에서 계수와 낮은 차수 항을 지우고 증가 모양만 남긴 것이 Big-O다: O(1) → O(log n) → O(n) → O(n²) 순으로 느려진다.
    • 연산 횟수는 카운터 변수로 직접 셀 수 있다 — 이 기법은 이후 모든 강의에서 사용된다.
    • 데이터의 규칙(연속된 수, 번호=인덱스 등)을 알면 훨씬 빠른 알고리즘을 선택할 수 있다.

동적 계획법

Dynamic Programming

설계 기법 중급 Java 17+

7강의 재귀 피보나치는 n=35에서 약 3천만 번 호출됩니다. 같은 계산을 수백만 번 반복하기 때문입니다. 이번 강의에서는 "한 번 구한 답은 적어 두고 다시 쓴다"는 단순한 아이디어로 이 폭발을 잠재우는 동적 계획법(DP)을 배웁니다. 점화식을 세우는 3단계, 메모이제이션(탑다운)과 테이블(바텀업), 그리고 10강에서 그리디가 실패했던 동전 문제를 DP로 최적 해결하는 것까지 다룹니다.

이 강의의 목차

    01강의 소개

    지금까지 배운 알고리즘은 대부분 "어떤 자료구조를 쓰는가"의 이야기였습니다. 이번 강의부터는 "문제를 어떻게 설계하는가"의 이야기입니다. 동적 계획법(Dynamic Programming, DP)은 특정 자료구조가 아니라 설계 기법입니다. 큰 문제를 작은 문제로 나누고, 작은 문제의 답을 저장해서 다시 쓰는 것이 전부입니다.

    출발점은 7강에서 이미 만난 재귀 피보나치입니다. 이 코드가 왜 느린지 호출 횟수를 실제로 세어 확인하고(n=35에서 29,860,703번!), 답을 저장하는 것만으로 호출이 69번으로 줄어드는 것을 직접 봅니다. 그다음 재귀 없이 표를 채우는 바텀업 테이블로 바꾸고, 같은 요령으로 새 문제(계단 오르기)의 점화식을 스스로 세우는 3단계를 연습합니다. 마지막에는 10강에서 그리디가 틀렸던 동전 문제를 DP로 최적 해결하며 두 기법의 차이를 확인합니다.

    STEP 2

    이번에는 수첩을 하나 준비합니다. fibo(2)를 처음 계산하면 수첩에 "fibo(2)=1"이라고 적고, 다음부터 fibo(2)가 필요하면 계산하지 않고 수첩을 봅니다. 다시 나무를 그려 보세요.

    질문: 수첩을 쓰면 호출이 몇 번으로 줄어드나요?

    STEP 3

    계단 4칸을 1칸/2칸 걸음으로 오르는 방법을 전부 나열해 봅시다. (1+1+1+1), (1+1+2), (1+2+1), (2+1+1), (2+2) — 모두 5가지입니다.

    질문: 5가지를 "마지막 걸음"으로 나누면 어떻게 묶이나요?

    마지막 걸음이 1칸인 경우: (1+1+1+1), (1+2+1), (2+1+1) — 3가지. 앞부분은 정확히 "3칸을 오르는 방법"입니다.
    마지막 걸음이 2칸인 경우: (1+1+2), (2+2) — 2가지. 앞부분은 정확히 "2칸을 오르는 방법"입니다.
    즉 4칸의 답(5) = 3칸의 답(3) + 2칸의 답(2). 큰 문제의 답이 작은 문제의 답으로 조립됩니다!

    06핵심 개념

    동적 계획법(DP)이란?

    동적 계획법은 큰 문제를 작은 부분 문제로 나누고, 각 부분 문제의 답을 한 번만 계산해 저장한 뒤 재사용하는 설계 기법입니다. 이름의 "동적(dynamic)"에 특별한 뜻은 없습니다 — 핵심은 "저장하고 재사용한다"뿐입니다. 정렬이나 스택 같은 특정 알고리즘·자료구조가 아니라, 문제에 접근하는 방법이라는 점에서 10강의 그리디와 같은 "설계 기법" 분류에 속합니다.

    DP가 통하는 두 가지 조건

    조건뜻방금 손 풀이에서
    중복 부분 문제
    (Overlapping Subproblems)    		 같은 작은 문제가 여러 번 다시 등장한다 fibo(5)의 호출 나무에서 fibo(3)이 2번, fibo(2)가 3번 등장
    최적 부분 구조
    (Optimal Substructure)    		 큰 문제의 (최적) 답을 작은 문제의 (최적) 답으로 조립할 수 있다 계단 4칸의 답 = 3칸의 답 + 2칸의 답

    중복이 없다면 저장해 봐야 다시 쓸 일이 없고(그냥 분할 정복), 조립이 안 된다면 작은 답을 모아도 큰 답이 안 됩니다. 두 조건이 모두 성립할 때 DP가 위력을 발휘합니다.

    점화식 — DP의 설계도 (코드보다 먼저!)

    "작은 문제의 답으로 큰 문제의 답을 만드는 규칙"을 식으로 적은 것이 점화식입니다. 피보나치의 정의 자체가 점화식입니다: F(n) = F(n-1) + F(n-2), 그리고 F(0) = 0, F(1) = 1.

    계단 오르기는 정의가 식으로 주어지지 않으므로 우리가 유도해야 합니다. 손 풀이 STEP 3의 논리를 그대로 일반화하면 됩니다. n칸에 도착하는 마지막 걸음은 반드시 1칸 아니면 2칸입니다. 마지막이 1칸이면 그 앞은 "n-1칸을 오르는 모든 방법", 마지막이 2칸이면 "n-2칸을 오르는 모든 방법"이고, 두 묶음은 서로 겹치지 않습니다. 따라서:

    계단 오르기의 점화식

    dp[n] = dp[n-1] + dp[n-2]  (단, dp[1] = 1, dp[2] = 2)

    dp[n]은 "n칸 계단을 오르는 방법의 수". 이 식이 확정되면 구현은 옮겨 적기에 가깝습니다. DP 문제의 승부는 코드가 아니라 점화식에서 납니다.

    점화식을 세우는 3단계

    1. 정의 — dp[i]가 무엇인지 완전한 한국어 문장으로 적는다. (예: "dp[i] = i칸 계단을 오르는 방법의 수") 여기가 모호하면 다음 단계가 전부 무너집니다.
    2. 기저 조건 — 더 쪼갤 수 없는 가장 작은 문제의 답을 직접 적는다. (예: dp[1] = 1, dp[2] = 2) 7강 재귀의 기저 조건과 같은 역할입니다.
    3. 전이(점화식) — dp[i]를 이미 구한 앞의 답들로 만드는 규칙을 적는다. (예: dp[i] = dp[i-1] + dp[i-2]) "마지막 선택이 무엇이었나?"를 나눠 보는 것이 가장 흔한 요령입니다.

    같은 점화식, 두 가지 구현 — 메모이제이션 vs 타뷸레이션

    점화식이 정해지면 구현 방향은 두 가지입니다. 위에서 내려가며 필요할 때 계산하거나, 아래에서 올라가며 미리 다 채우거나.

    구분메모이제이션 (탑다운)타뷸레이션 (바텀업)
    방향큰 문제 → 작은 문제 (필요한 것만)작은 문제 → 큰 문제 (차례로 전부)
    구현 형태재귀 + 저장 배열(memo)반복문 + 테이블(dp)
    계산 범위실제로 필요한 부분 문제만 계산기저부터 목표까지 모든 칸을 계산
    호출 스택재귀 깊이만큼 사용 (아주 큰 n에서는 StackOverflow 위험)사용하지 않음 (반복문)
    코드 느낌점화식 정의를 거의 그대로 옮김 — 직관적채우는 순서를 직접 정해야 함 — 대신 빠르고 안전
    이 강의에서구현 2단계 (Step2)구현 3단계 (Step3) 이후 기본 방식

    그리디(10강)와 DP의 차이

    그리디는 매 순간 하나의 선택을 확정하고 되돌리지 않습니다. DP는 각 부분 문제에서 가능한 모든 선택을 점화식으로 비교한 뒤 가장 좋은 답만 기록합니다. 동전 문제로 말하면 — 그리디는 "일단 100원!"이지만, DP의 점화식 dp[금액] = min(dp[금액 - 동전] + 1)은 모든 동전을 다 넣어 보고 최소를 고릅니다. 그래서 그리디가 실패하는 동전 {1, 60, 100}에서도 DP는 항상 최적입니다. (16번 응용 섹션에서 실측으로 확인합니다.)

    07단계별 동작 과정

    계단 오르기 DP 테이블이 채워지는 과정을 단계별로 봅니다. 다음 단계 ▶ 버튼으로 진행하세요. 지금 계산 중인 칸은 파란색(현재), 점화식이 참조하는 앞의 두 칸은 앰버색(참조), 값이 확정된 칸은 초록색(확정)으로 표시됩니다.

    매 단계에서 하는 일은 단 하나 — 이미 확정된 두 칸을 더해 다음 칸을 채우는 것입니다. 재귀처럼 위에서 내려갔다 올라오는 여행이 없고, 왼쪽에서 오른쪽으로 한 번 지나가면 끝입니다. 이것이 손 풀이 STEP 4의 "표 채우기"이고, 구현 3단계의 코드와 정확히 같은 동작입니다.

    08의사코드

    점화식 3단계를 그대로 의사코드로 옮깁니다. 두 구현 방향을 나란히 봅니다.

    Pseudo 방향 1 — 메모이제이션 (탑다운) 
    알고리즘 Ways(n)                      // dp 정의: n칸을 오르는 방법의 수
    n이 1이면 1을 반환한다             // 기저 조건
    n이 2이면 2를 반환한다
    memo[n]에 답이 있으면 그것을 반환한다   // 저장된 답 재사용 (중복 계산 제거)
    memo[n] ← Ways(n-1) + Ways(n-2)   // 전이(점화식) 결과를 저장
    memo[n]을 반환한다
    Pseudo 방향 2 — 타뷸레이션 (바텀업) 
    알고리즘 WaysByTable(n)
    dp ← 크기 n+1의 표
    dp[1] ← 1                         // 기저 조건을 표에 먼저 적는다
    dp[2] ← 2
    i를 3부터 n까지 반복:
        dp[i] ← dp[i-1] + dp[i-2]     // 전이: 이미 채운 두 칸을 더한다
    dp[n]을 반환한다                   // 표의 마지막 칸이 최종 답

    두 의사코드의 점화식은 완전히 같습니다. 다른 것은 계산 순서뿐입니다. 탑다운은 "필요하면 내려가서 구해 오기", 바텀업은 "아래부터 미리 다 채워 두기"입니다.

    09점진적 Java 구현

    완성 코드를 한 번에 쓰지 않습니다. 문제를 실측 → 저장 추가(메모) → 반복문으로 전환(테이블) → 새 문제에 적용 순서로, 매 단계에서 직전 단계와의 차이를 확인하며 나아갑니다.

    구현 1단계 — 순수 재귀의 호출 횟수 실측

    7강의 재귀 피보나치에 1강의 연산 카운터를 붙입니다. "느리다더라"가 아니라 몇 번 호출되는지 숫자로 확인하는 것이 목적입니다.

    Java Step1FibonacciNaive.java 
    public class Step1FibonacciNaive {

    /** 재귀 호출 횟수 카운터 (1강의 연산 카운터를 재귀에 적용) */
    static long callCount = 0;

    /** 순수 재귀 피보나치: 점화식 F(n) = F(n-1) + F(n-2)를 그대로 옮긴 코드 */
    static long fibo(int n) {
        callCount++;                        // 호출될 때마다 1 증가
        if (n <= 1) {
            return n;                       // 기저 조건: F(0) = 0, F(1) = 1
        }
        return fibo(n - 1) + fibo(n - 2);   // 점화식(전이): 두 작은 문제의 답을 더한다
    }

    public static void main(String[] args) {
        int[] sizes = {10, 20, 30, 35};

        System.out.println("n    | fibo(n)    | 재귀 호출 횟수");
        System.out.println("-----+------------+---------------");

        for (int n : sizes) {
            callCount = 0;                  // 매번 카운터를 초기화한다
            long result = fibo(n);
            System.out.printf("%-4d | %-10d | %,d%n", n, result, callCount);
        }

        System.out.println();
        System.out.println("n이 5 커질 때마다 호출 횟수가 약 11배씩 늘어난다.");
        System.out.println("같은 fibo(k)를 몇 번이고 다시 계산하기 때문이다 — 중복 부분 문제!");
    }
}

    구현 2단계 — 메모이제이션: 저장 배열 추가 (탑다운)

    1단계 코드에 달라지는 것은 배열 memo와 두 줄뿐입니다. 답이 저장돼 있으면 즉시 반환하고, 없으면 계산한 뒤 저장합니다. 손 풀이 STEP 2의 "수첩" 그대로입니다.

    Java Step2FibonacciMemo.java 
    public class Step2FibonacciMemo {

    /** 재귀 호출 횟수 카운터 */
    static long callCount = 0;

    /** memo[k] = 이미 계산한 fibo(k)의 답 (0이면 아직 계산 전) */
    static long[] memo;

    /** 메모이제이션(탑다운): 계산한 답을 저장하고, 두 번째부터는 즉시 꺼내 쓴다 */
    static long fibo(int n) {
        callCount++;
        if (n <= 1) {
            return n;                       // 기저 조건: F(0) = 0, F(1) = 1
        }
        if (memo[n] != 0) {
            return memo[n];                 // 이미 계산한 답 → 다시 계산하지 않는다
        }
        memo[n] = fibo(n - 1) + fibo(n - 2);   // 점화식의 결과를 저장한 뒤
        return memo[n];                        // 반환한다
    }

    /** 순수 재귀였다면 필요한 호출 횟수: 2 x F(n+1) - 1 (Step1의 실측값과 같은 식) */
    static long naiveCallCount(int n) {
        long prev = 0, curr = 1;            // F(0), F(1)
        for (int i = 2; i <= n + 1; i++) {
            long next = prev + curr;
            prev = curr;
            curr = next;
        }
        return 2 * curr - 1;                // curr = F(n+1)
    }

    public static void main(String[] args) {
        int[] sizes = {10, 20, 30, 35, 50};

        System.out.println("n    | fibo(n)        | 메모 호출 횟수 | 순수 재귀라면");
        System.out.println("-----+----------------+---------------+------------------");

        for (int n : sizes) {
            callCount = 0;
            memo = new long[n + 1];         // 답을 저장할 공간 (0번~n번 → 크기 n + 1)
            long result = fibo(n);
            System.out.printf("%-4d | %-14d | %-13d | %,d%n",
                    n, result, callCount, naiveCallCount(n));
        }

        System.out.println();
        System.out.println("호출 횟수가 2n - 1로 줄었다: 각 fibo(k)를 딱 한 번만 계산하기 때문이다.");
        System.out.println("n=50이면 약 407억 번이 99번이 된다 — 저장 공간 O(n)과 바꾼 속도다.");
    }
}

    구현 3단계 — 타뷸레이션: 재귀를 반복문으로 (바텀업)

    메모이제이션은 여전히 재귀입니다. 그런데 잘 보면 fibo(n)에 필요한 것은 fibo(0)부터 fibo(n-1)까지 — 어차피 전부입니다. 그렇다면 처음부터 작은 쪽에서 표를 차례로 채우면 재귀가 필요 없습니다.

    Java Step3FibonacciTable.java 
    public class Step3FibonacciTable {

    /** 타뷸레이션(바텀업): 재귀 없이, 작은 답부터 표를 차례로 채운다 */
    static long fiboByTable(int n) {
        if (n <= 1) {
            return n;
        }
        long[] dp = new long[n + 1];        // dp[0]부터 dp[n]까지 → 크기는 n + 1
        dp[0] = 0;                          // 기저 조건
        dp[1] = 1;
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];  // 점화식: 이미 채운 두 칸을 더한다
        }
        return dp[n];                       // 표의 마지막 칸이 최종 답
    }

    public static void main(String[] args) {
        // 1) n = 10의 테이블이 채워진 최종 모습을 눈으로 확인한다
        int n = 10;
        long[] dp = new long[n + 1];
        dp[0] = 0;
        dp[1] = 1;
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }

        System.out.println("피보나치 DP 테이블 (n = " + n + ")");
        System.out.print("인덱스:");
        for (int i = 0; i <= n; i++) {
            System.out.printf("%6d", i);
        }
        System.out.println();
        System.out.print("dp[i] :");
        for (int i = 0; i <= n; i++) {
            System.out.printf("%6d", dp[i]);
        }
        System.out.println();
        System.out.println();

        // 2) 큰 n에서도 덧셈 n - 1번이면 끝난다
        int[] sizes = {10, 20, 30, 35, 50};
        System.out.println("n    | fiboByTable(n) | 덧셈 횟수 (n - 1)");
        System.out.println("-----+----------------+------------------");
        for (int size : sizes) {
            System.out.printf("%-4d | %-14d | %d%n", size, fiboByTable(size), size - 1);
        }

        System.out.println();
        System.out.println("재귀가 사라졌다: 반복문 한 번으로 끝나므로 호출 스택 걱정도 없다.");
    }
}

    2단계와 3단계는 같은 점화식이다

    메모(59번 호출)와 테이블(29번 덧셈)의 결과는 n=30에서 둘 다 832040으로 같습니다. 바뀐 것은 계산 방향뿐입니다. 테이블 방식은 호출 스택을 쓰지 않으므로 n이 수십만이어도 StackOverflow 걱정이 없습니다. 이후 이 과정에서는 바텀업을 기본으로 씁니다.

    구현 4단계 — 새 문제에 적용: 계단 오르기

    이제 점화식 3단계를 새 문제에 스스로 적용합니다. ① 정의: dp[i] = i칸 계단을 오르는 방법의 수. ② 기저: dp[1] = 1, dp[2] = 2. ③ 전이: dp[i] = dp[i-1] + dp[i-2] (마지막 걸음이 1칸이냐 2칸이냐). 순수 재귀와 테이블을 나란히 구현해 결과가 같은지 검증합니다.

    Java Step4ClimbStairs.java 
    public class Step4ClimbStairs {

    /** 재귀 호출 횟수 카운터 */
    static long callCount = 0;

    /** 순수 재귀: ways(n) = ways(n-1) + ways(n-2) — 마지막 걸음이 1칸이냐 2칸이냐로 나눈다 */
    static long waysByRecursion(int n) {
        callCount++;
        if (n == 1) {
            return 1;                       // 기저 조건: 1칸은 [1] 한 가지
        }
        if (n == 2) {
            return 2;                       // 기저 조건: 2칸은 [1+1], [2] 두 가지
        }
        return waysByRecursion(n - 1) + waysByRecursion(n - 2);   // 점화식
    }

    /** 바텀업 테이블: 같은 점화식을 반복문으로 채운다 */
    static long waysByTable(int n) {
        if (n == 1) {
            return 1;
        }
        long[] dp = new long[n + 1];        // dp[1]부터 dp[n]까지 사용
        dp[1] = 1;                          // 기저 조건
        dp[2] = 2;
        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];  // 점화식(전이)
        }
        return dp[n];
    }

    public static void main(String[] args) {
        int[] sizes = {4, 10, 20, 30};

        System.out.println("계단 오르기: n칸을 1칸/2칸 걸음으로 오르는 방법의 수");
        System.out.println("n    | 재귀 결과  | 테이블 결과 | 재귀 호출 횟수 | 테이블 덧셈 횟수");
        System.out.println("-----+-----------+------------+---------------+-----------------");

        for (int n : sizes) {
            callCount = 0;
            long byRecursion = waysByRecursion(n);
            long byTable = waysByTable(n);
            System.out.printf("%-4d | %-9d | %-10d | %,-13d | %d%n",
                    n, byRecursion, byTable, callCount, Math.max(n - 2, 0));

            if (byRecursion != byTable) {
                System.out.println("경고: 두 방법의 결과가 다릅니다! 점화식 구현에 오류가 있습니다.");
            }
        }

        System.out.println();
        System.out.println("피보나치와 다른 문제인데 점화식 모양은 같다 — 기저 조건만 1, 2로 다르다.");
    }
}

    10완성 Java 코드

    지금까지의 조각을 모아 계단 오르기를 네 가지 방법으로 구현하고 서로 검증하는 프로그램을 완성합니다. 마지막 방법은 새로 등장하는 공간 최적화입니다 — 점화식이 직전 두 칸만 참조하므로, 표 전체 대신 변수 2개만 유지해도 됩니다.

    Java ClimbStairsComplete.java 
    public class ClimbStairsComplete {

    /** 방법별 호출/연산 횟수 카운터 */
    static long recursionCalls = 0;
    static long memoCalls = 0;

    /** 방법 1: 순수 재귀 — 점화식 그대로. 느리다(중복 계산). */
    static long waysByRecursion(int n) {
        recursionCalls++;
        if (n == 1) {
            return 1;
        }
        if (n == 2) {
            return 2;
        }
        return waysByRecursion(n - 1) + waysByRecursion(n - 2);
    }

    /** 방법 2: 메모이제이션(탑다운) — 계산한 답을 저장한다. */
    static long waysByMemo(int n) {
        long[] memo = new long[n + 1];
        return memoHelper(n, memo);
    }

    static long memoHelper(int n, long[] memo) {
        memoCalls++;
        if (n == 1) {
            return 1;
        }
        if (n == 2) {
            return 2;
        }
        if (memo[n] != 0) {
            return memo[n];
        }
        memo[n] = memoHelper(n - 1, memo) + memoHelper(n - 2, memo);
        return memo[n];
    }

    /** 방법 3: 타뷸레이션(바텀업) — 표를 앞에서부터 채운다. */
    static long waysByTable(int n) {
        if (n == 1) {
            return 1;
        }
        long[] dp = new long[n + 1];
        dp[1] = 1;
        dp[2] = 2;
        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }
        return dp[n];
    }

    /** 방법 4: 공간 최적화 — 항상 직전 두 칸만 쓰므로 변수 2개면 충분하다. */
    static long waysByTwoVars(int n) {
        if (n == 1) {
            return 1;
        }
        long prev2 = 1;                     // dp[i - 2] 역할
        long prev1 = 2;                     // dp[i - 1] 역할
        for (int i = 3; i <= n; i++) {
            long current = prev1 + prev2;   // 같은 점화식
            prev2 = prev1;                  // 두 변수를 한 칸씩 밀어 준다
            prev1 = current;
        }
        return prev1;
    }

    public static void main(String[] args) {
        int[] sizes = {10, 20, 30};

        System.out.println("== 계단 오르기: 네 가지 구현 비교 ==");
        System.out.println("n    | 결과      | 재귀 호출    | 메모 호출 | 테이블 덧셈");
        System.out.println("-----+-----------+-------------+----------+------------");

        for (int n : sizes) {
            recursionCalls = 0;
            memoCalls = 0;
            long r1 = waysByRecursion(n);
            long r2 = waysByMemo(n);
            long r3 = waysByTable(n);
            long r4 = waysByTwoVars(n);

            System.out.printf("%-4d | %-9d | %,-11d | %-8d | %d%n",
                    n, r1, recursionCalls, memoCalls, n - 2);

            // 네 방법의 결과가 모두 같은지 정확성을 검증한다 (1강의 원칙)
            if (r1 != r2 || r1 != r3 || r1 != r4) {
                System.out.println("경고: 결과가 서로 다릅니다! 구현에 오류가 있습니다.");
            }
        }

        System.out.println();
        System.out.println("== 큰 입력: n = 50 (순수 재귀는 약 407억 번 호출이라 생략) ==");
        memoCalls = 0;
        System.out.println("메모이제이션 : " + waysByMemo(50) + " (호출 " + memoCalls + "번)");
        System.out.println("타뷸레이션   : " + waysByTable(50) + " (덧셈 48번, 표 51칸)");
        System.out.println("공간 최적화  : " + waysByTwoVars(50) + " (덧셈 48번, 변수 2개)");
        System.out.println();
        System.out.println("시간: O(2^n) → O(n), 공간: 테이블 O(n) → 변수 2개 O(1)");
    }
}

    Java DpTableTrace.java 
    public class DpTableTrace {

    public static void main(String[] args) {
        int n = 8;
        long[] dp = new long[n + 1];

        System.out.println("계단 오르기 DP 테이블 채우기 추적 (n = " + n + ")");
        System.out.println();

        dp[1] = 1;
        System.out.println("기저 dp[1] = 1              | " + tableString(dp, 1, n));
        dp[2] = 2;
        System.out.println("기저 dp[2] = 2              | " + tableString(dp, 2, n));

        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];   // 점화식: 이미 확정된 두 칸을 참조
            System.out.printf("dp[%d] = dp[%d] + dp[%d] = %2d + %2d = %2d | %s%n",
                    i, i - 1, i - 2, dp[i - 1], dp[i - 2], dp[i], tableString(dp, i, n));
        }

        System.out.println();
        System.out.println("최종 답: dp[" + n + "] = " + dp[n]
                + " — " + n + "칸 계단을 오르는 방법은 " + dp[n] + "가지");
    }

    /** 테이블의 현재 상태를 문자열로 만든다. 아직 안 채운 칸은 - 로 표시. */
    static String tableString(long[] dp, int filledUpTo, int n) {
        StringBuilder sb = new StringBuilder("[");
        for (int i = 1; i <= n; i++) {
            if (i > 1) {
                sb.append(", ");
            }
            sb.append(i <= filledUpTo ? String.valueOf(dp[i]) : "-");
        }
        return sb.append("]").toString();
    }
}

    13복잡도 및 특성 분석

    입력 크기

    n은 문제의 크기(피보나치의 n, 계단의 칸 수)입니다. 동전 문제(15번 섹션)에서는 금액과 동전 종류 수, 두 개의 크기가 등장합니다.

    주요 연산

    점화식 한 번의 계산(덧셈 또는 min 비교)과, 저장된 답의 조회입니다. 배열 조회는 O(1)이므로 전체 시간 = 채워야 할 칸 수 × 한 칸을 채우는 비용입니다. 이 공식은 어떤 DP에도 통합니다.

    시간·공간 복잡도

    구현시간공간n=35 실측(호출/덧셈)

    알고리즘 특성

    • 기법이지 알고리즘이 아니다: DP는 "저장하고 재사용"이라는 접근법입니다. 문제마다 점화식이 다르므로, 연습의 핵심은 코드가 아니라 점화식 3단계입니다.
    • 정확성의 근거: 전이가 가능한 모든 선택을 비교하므로, 점화식이 옳다면 답은 항상 최적입니다. 그리디처럼 "운 좋게 맞는" 것이 아닙니다.
    • 시간과 공간의 교환: O(2ⁿ) 시간을 O(n) 메모리와 맞바꿉니다. 1강의 "데이터의 규칙을 알수록 빨라진다"가 "이미 푼 답을 알수록 빨라진다"로 확장된 것입니다.
    • 한계: 상태(테이블 칸)가 너무 많으면 메모리가 먼저 터집니다. 또 부분 문제가 겹치지 않으면 저장의 이득이 없습니다.

    문제 상황 — 그리디가 실패한 그 동전, DP로 다시

    10강의 마지막 장면을 기억하나요? 이상한 나라의 자판기는 동전이 {1, 60, 100}원뿐이었고, 120원을 거슬러 줄 때 그리디(큰 동전부터)는 100원을 덥석 집은 탓에 100 + 1×20 = 21개를 내놓았습니다. 최적은 60×2 = 2개인데 말이죠. 이제 우리에게는 DP가 있습니다. "모든 선택을 비교하고 기록한다"는 방식이 이 문제를 어떻게 구하는지 확인합니다.

    데이터 모델과 점화식 (코드보다 먼저!)

    • 데이터: 동전 종류 {100, 60, 1}, 목표 금액 amount
    • ① 정의: dp[money] = money원을 만드는 최소 동전 개수
    • ② 기저: dp[0] = 0 (0원은 동전 0개로 만든다)
    • ③ 전이: 마지막에 넣은 동전이 coin이었다면 그 전 상태는 money - coin. 따라서 dp[money] = min(dp[money - coin] + 1) — 모든 동전 coin에 대해 비교

    그리디와의 차이가 전이에 그대로 드러납니다. 그리디는 "가장 큰 동전 하나"만 보지만, 이 점화식은 세 동전을 전부 넣어 보고 최소를 고릅니다. 또 하나 — 이 점화식은 dp[money - 100]처럼 먼 칸을 참조하므로 변수 2개 최적화는 불가능하고 표 전체가 필요합니다.

    Java CoinChangeDpApplication.java 
    public class CoinChangeDpApplication {

    /** "도달 불가능"을 나타내는 큰 값 (더해도 넘치지 않도록 절반으로) */
    static final int IMPOSSIBLE = Integer.MAX_VALUE / 2;

    /** 10강의 그리디: 큰 동전부터 최대한 많이 사용한다. */
    static int greedyCount(int amount, int[] coinsDesc) {
        int remaining = amount;
        int totalCount = 0;
        for (int coin : coinsDesc) {
            totalCount += remaining / coin;
            remaining = remaining % coin;
        }
        return totalCount;
    }

    /** DP: dp[money] = money원을 만드는 최소 동전 개수. 0원부터 표를 채운다. */
    static int[] buildDpTable(int amount, int[] coins) {
        int[] dp = new int[amount + 1];
        dp[0] = 0;                          // 기저 조건: 0원은 동전 0개
        for (int money = 1; money <= amount; money++) {
            dp[money] = IMPOSSIBLE;
            for (int coin : coins) {
                // 점화식: dp[money] = min(dp[money - coin] + 1)  (모든 동전을 비교)
                if (coin <= money && dp[money - coin] + 1 < dp[money]) {
                    dp[money] = dp[money - coin] + 1;
                }
            }
        }
        return dp;
    }

    /** 완성된 테이블을 역추적해 실제로 어떤 동전을 몇 개 썼는지 알아낸다. */
    static String reconstruct(int amount, int[] coinsDesc, int[] dp) {
        StringBuilder sb = new StringBuilder();
        int money = amount;
        for (int coin : coinsDesc) {
            int used = 0;
            // dp[money - coin]이 정확히 1 작다면, 이 동전은 최적해의 일부다
            while (coin <= money && dp[money - coin] == dp[money] - 1) {
                money -= coin;
                used++;
            }
            if (used > 0) {
                if (sb.length() > 0) {
                    sb.append(", ");
                }
                sb.append(coin).append("원 x ").append(used).append("개");
            }
        }
        return sb.toString();
    }

    public static void main(String[] args) {
        int[] coinsDesc = {100, 60, 1};     // 10강의 반례 동전: {1, 60, 100}
        int[] amounts = {80, 120, 180, 200};

        System.out.println("동전 {1, 60, 100}으로 거슬러 주기 — 그리디(10강) vs DP(11강)");
        System.out.println("금액   | 그리디 개수 | DP 최소 개수 | DP가 고른 조합");
        System.out.println("-------+------------+-------------+---------------------");

        for (int amount : amounts) {
            int greedy = greedyCount(amount, coinsDesc);
            int[] dp = buildDpTable(amount, coinsDesc);
            String combo = reconstruct(amount, coinsDesc, dp);
            System.out.printf("%-6d | %-10d | %-11d | %s%n",
                    amount, greedy, dp[amount], combo);
        }

        System.out.println();

    정답 코드와 해설 확인
    Java MinCostStairsSolution.java 
    public class MinCostStairsSolution {

    /**
     * dp[i] = "i번 계단을 밟고 서 있기"까지의 최소 비용.
     * 바닥에서 첫 발은 0번 또는 1번 계단에 바로 올릴 수 있다.
     */
    static long[] buildDpTable(int[] cost) {
        int n = cost.length;
        long[] dp = new long[n];

        dp[0] = cost[0];                    // 기저 조건: 바닥에서 바로 밟는다
        dp[1] = cost[1];

        for (int i = 2; i < n; i++) {
            // 점화식: i-1번에서 1칸 오르거나, i-2번에서 2칸 오르거나 — 싼 쪽을 고른다
            dp[i] = cost[i] + Math.min(dp[i - 1], dp[i - 2]);
        }
        return dp;
    }

    /** 꼭대기(마지막 계단 다음)까지의 최소 비용 */
    static long minTotalCost(int[] cost) {
        long[] dp = buildDpTable(cost);
        int n = cost.length;
        // 꼭대기에는 마지막 계단(n-1)에서 1칸, 또는 그 아래(n-2)에서 2칸 올라 도착한다
        return Math.min(dp[n - 1], dp[n - 2]);
    }

    /** 검증용 완전 탐색(3강): i번 계단을 밟은 뒤 꼭대기까지의 모든 경로를 시도한다. */
    static long bruteForceFrom(int[] cost, int i) {
        if (i >= cost.length) {
            return 0;                       // 이미 꼭대기
        }
        long stepOne = bruteForceFrom(cost, i + 1);
        long stepTwo = bruteForceFrom(cost, i + 2);
        return cost[i] + Math.min(stepOne, stepTwo);
    }

    static long bruteForceMin(int[] cost) {
        return Math.min(bruteForceFrom(cost, 0), bruteForceFrom(cost, 1));
    }

    public static void main(String[] args) {
        int[][] tests = {
                {10, 15, 20},
                {1, 100, 1, 1, 1, 100, 1, 1, 100, 1},
                {10, 15}
        };

        for (int[] cost : tests) {
            long[] dp = buildDpTable(cost);
            long dpAnswer = minTotalCost(cost);
            long bruteAnswer = bruteForceMin(cost);

            System.out.println("  DP 테이블   = " + java.util.Arrays.toString(dp));
            System.out.println("  DP 최소 비용 = " + dpAnswer

        }

    구현 순서와 핵심 알고리즘 적용 부분

    1. 정의가 절반입니다. dp[i]를 "i번 계단을 밟고 서 있기까지의 최소 비용"으로 정의했기 때문에 전이가 cost[i] + min(...) 한 줄로 떨어집니다. "i번 계단을 지나가기까지"처럼 모호하게 정의하면 전이를 쓸 수 없습니다.
    2. 기저 조건: 첫 발은 0번 또는 1번에 바로 올릴 수 있으므로 dp[0] = cost[0], dp[1] = cost[1]. dp[1]에 dp[0]을 더하지 않는 것이 포인트입니다.
    3. 전이: i번 계단에 도착하는 직전 상태는 i-1번 아니면 i-2번뿐 — "마지막 걸음으로 나누기"라는 계단 오르기의 논리가 min으로 바뀌었을 뿐입니다.
    4. 답 읽기: 꼭대기는 계단이 아니므로 테이블 밖에 있습니다. 꼭대기 직전 상태(n-1 또는 n-2) 중 싼 쪽이 답입니다.
    5. 검증: 테스트 2에서 완전 탐색은 2^10 수준의 경로를 모두 확인해 6을 내고, DP는 덧셈·비교 몇 번으로 같은 6을 냅니다 — 정확성은 같고 일의 양만 다릅니다.

    복잡도 분석

    • DP: 테이블 n칸 × 칸당 O(1) = 시간 O(n), 공간 O(n) (변수 2개 최적화 시 공간 O(1)).
    • 완전 탐색: 경로 수가 피보나치처럼 늘어나 O(2ⁿ) — n=10,000 제한에서는 DP만 감당할 수 있습니다.

    자주 발생하는 오류

    • dp[1]을 cost[0] + cost[1]로 채우는 실수 — 첫 발은 1번 계단에 바로 올릴 수 있습니다.
    • 답을 dp[n - 1]로만 읽는 실수 — 마지막 계단을 밟지 않고 n-2에서 2칸 올라가는 더 싼 경로를 놓칩니다. (테스트 1이 이 경우: 답은 dp[2]=30이 아니라 dp[1]=15)
    • 반복 범위를 i <= n으로 써서 dp[n]에 접근 — 이 테이블은 크기가 n이므로 오류 2(테이블 크기)와 같은 예외가 납니다.

    다른 해결 방법

    같은 점화식을 탑다운(메모이제이션)으로도 구현할 수 있습니다. minCostFrom(i) = "i번 계단부터 꼭대기까지의 최소 비용"으로 정의하면 bruteForceFrom에 memo 배열만 붙인 형태가 됩니다 — 검증용 완전 탐색과 정답 DP가 사실 같은 식의 두 구현이라는 것을 확인해 보세요.

    19오늘의 핵심 정리

    • 동적 계획법(DP)은 작은 문제의 답을 저장하고 재사용하는 설계 기법이다. 성립 조건은 중복 부분 문제와 최적 부분 구조 두 가지.
    • 순수 재귀 피보나치는 n=35에서 29,860,703번 호출된다(실측). 답을 저장하면 69번 — O(2ⁿ)이 O(n)이 된다.
    • DP의 설계도는 점화식이며, 세우는 순서는 ① 정의(dp[i]를 문장으로) → ② 기저 조건 → ③ 전이다. 코드는 그다음이다.
    • 같은 점화식의 두 구현: 메모이제이션(탑다운, 재귀+저장)과 타뷸레이션(바텀업, 반복문+테이블). 기본은 바텀업.
    • 점화식이 직전 몇 칸만 참조하면 테이블을 변수 몇 개로 압축할 수 있다(공간 O(1)).
    • 그리디는 선택 하나를 확정하지만, DP는 점화식으로 모든 선택을 비교한다 — 그래서 동전 {1, 60, 100}의 120원에서 그리디는 21개, DP는 2개.
    • DP 테이블에는 최적값뿐 아니라 답을 복원할 정보도 들어 있다(역추적).

    20다음 강의 연결

    다음 강의는 12강. 최단 경로 알고리즘입니다. 9강의 그래프, 10강의 그리디, 그리고 오늘의 점화식이 한 문제에서 만납니다.

    • 다익스트라의 거리 갱신 dist[v] = min(dist[v], dist[u] + w)는 — 오늘 동전 문제의 dp[money] = min(dp[money - coin] + 1)과 같은 모양의 점화식입니다. "거리 갱신도 점화식"이라는 눈으로 보면 다익스트라가 훨씬 쉽게 읽힙니다.
    • 다익스트라는 "가장 가까운 정점부터 확정"하는 그리디 선택(10강)과 우선순위 큐(6강)를 함께 씁니다 — 그리디가 이번엔 왜 옳은지도 다룹니다.
    • 오늘 배운 역추적(테이블에서 답 복원)이 최단 경로의 경로 복원으로 확장됩니다.

완전 탐색과 문자열·해시 처리

Brute Force, Strings, and Hashing

알고리즘 기초 초급 Java 17+

"가능한 모든 경우를 다 확인한다" — 가장 단순하지만 가장 확실한 문제 해결 전략, 완전 탐색을 배웁니다. 문자열을 한 글자씩 순회하고, 회문을 판별하고, 단어의 빈도를 세는 과정에서 완전 탐색의 대표 패턴인 중첩 반복문을 익힙니다. 그리고 같은 문제를 HashMap과 HashSet으로 다시 풀어, O(n²)의 완전 탐색이 어떻게 O(n)으로 줄어드는지 직접 확인합니다.

이 강의의 목차

    01강의 소개

    오늘의 질문: "가능한 모든 경우를 하나씩 다 확인하면 어떻게 될까?" — 이것이 완전 탐색(brute force)입니다.

    • 완전 탐색은 느릴 수는 있어도 틀리지 않음 — 모든 알고리즘 설계의 출발점
    • 이번 강의(문자열 데이터에 적용)에서 다루는 것
      • 문자열을 한 글자씩 순회하는 charAt, 올바르게 비교하는 equals
      • 앞뒤가 똑같은 회문(팰린드롬) 판별
      • 완전 탐색의 대표 패턴인 중첩 반복문으로 모든 쌍 비교하기
      • 같은 문제를 HashMap·HashSet으로 다시 풀어, 비교 횟수가 n(n-1)/2번 → n번으로 줄어드는 것을 1강의 연산 카운터로 확인
    • 마지막 실습: 게시글의 단어 빈도·중복 단어·최다 등장 단어를 분석하는 단어 분석 프로그램

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 완전 탐색이 무엇인지 설명하고, 중첩 반복문으로 모든 쌍을 비교하는 코드를 작성할 수 있다.
    • 학생은 charAt과 length()로 문자열을 한 글자씩 순회하고, equals로 문자열을 올바르게 비교할 수 있다.
    • 학생은 left·right 포인터를 이용해 회문(팰린드롬)을 판별하는 메서드를 작성할 수 있다.
    • 학생은 HashMap의 getOrDefault로 문자·단어의 빈도를 세고, entrySet으로 결과를 순회할 수 있다.
    • 학생은 HashSet의 add 반환값을 이용해 중복 데이터를 한 번의 순회로 찾을 수 있다.
    • 학생은 완전 탐색 O(n²)과 해시 O(n)의 비교 횟수를 카운터로 세어 표로 비교할 수 있다.

    03실제 문제 상황

    • 상황: 학과 커뮤니티 게시판 운영. 도배성 게시글이 늘어 같은 단어가 반복 등장하는지, 어떤 단어가 가장 많이 쓰였는지를 자동 분석하고 싶음
    • 처음엔 단어 수십 개라 "모든 단어 쌍을 비교"하는 프로그램으로 충분 → 댓글까지 합쳐 단어가 수만 개가 되자 분석 시간이 눈에 띄게 길어짐
    • 선배 개발자: "모든 쌍을 비교하면 n²이야. 해시를 쓰면 n에 끝나."
    • n²과 n의 차이는 1강에서 배웠습니다 — 이제 그 차이를 만들어 내는 방법을 배울 차례입니다.

    모든 경우를 확인하는 완전 탐색은 언제나 옳다. 그런데 더 적게 확인하고도 같은 답을 얻을 수는 없을까?

    04핵심 개념

    완전 탐색(Brute Force)이란?

    • 완전 탐색 = 가능한 모든 경우를 빠짐없이 확인하는 문제 해결 전략
    • "후보를 하나도 놓치지 않는다" — 구현이 올바르다면 답이 틀릴 수 없음 (2강의 조건 검색도 완전 탐색의 한 형태)
    • 문제는 속도 — "모든 경우"의 수가 크면 그만큼 오래 걸림
    • 알고리즘 설계의 일반적 순서: ① 완전 탐색으로 일단 정확한 답을 얻는다 → ② 더 적게 확인하는 방법을 찾는다 (오늘 강의가 정확히 이 두 단계)

    중첩 반복문 — "모든 쌍"을 만드는 기계

    • 완전 탐색에서 가장 자주 쓰는 도구 = 중첩 반복문(반복문 안의 반복문)
    • 바깥 반복문이 기준 i를 정하면, 안쪽 반복문이 비교 상대 j를 훑음
    • 같은 쌍을 두 번 비교하지 않도록 안쪽을 j = i + 1부터 시작하는 것이 관례
    패턴코드 형태반복 횟수Big-O
    단일 반복문for (i = 0; i < n; i++)n번O(n)
    중첩 반복문 (모든 쌍)for (i...) for (j = i + 1...)n(n-1)/2번O(n²)
    • n=10이면 45번, n=1,000이면 499,500번, n=100,000이면 약 50억 번 — 중첩 반복문은 n이 커질수록 빠르게 무거워짐
    • 참고: 이 "i를 고정하고 j를 훑는" 구조는 4강에서 배울 선택 정렬·버블 정렬의 뼈대이기도 함

    문자열 순회 — length()와 charAt(i)

    문자열은 "문자들이 순서대로 늘어선 데이터"라는 점에서 배열과 매우 닮음 — 순회 패턴은 그대로, 문법만 조금 다릅니다.

    하고 싶은 일배열(int[])문자열(String)
    길이 구하기arr.lengthstr.length() — 메서드라서 괄호 필요
    i번째 요소 꺼내기arr[i]str.charAt(i) — 결과는 char
    단어로 쪼개기-str.split(" ") — 결과는 String[]

    문자열 비교 — 반드시 equals!

    • 문자(char)는 숫자처럼 ==로 비교
    • 문자열(String)은 객체라서 ==는 "내용이 같은가"가 아니라 "같은 객체인가(같은 메모리를 가리키는가)"를 물음 — 내용 비교는 반드시 a.equals(b)
    • split으로 만들어진 단어들은 전부 새 객체이므로, == 비교는 내용이 같아도 false — 오늘 오류 카드(09번 섹션)에서 이 사고를 재현

    회문(팰린드롬) 판별

    • 회문 — 앞으로 읽어도 뒤로 읽어도 같은 문자열: level, noon, 기러기, 토마토
    • 판별 알고리즘 = 양 끝에서 가운데로 좁혀 가는 두 포인터
    • left·right가 가리키는 문자를 비교 — 같으면 한 칸씩 안쪽으로 이동, 다르면 그 즉시 "회문 아님"으로 종료
    • 문자열 길이가 L이면 비교는 최대 L/2번 — "확인해야 할 모든 쌍을 확인하는" 작은 완전 탐색

    빈도 계산과 HashMap

    "apple" 같은 단어는 배열 인덱스가 될 수 없음 — 2강의 count[점수]++ 대신 키(key) → 값(value) 쌍을 저장하는 HashMap을 씁니다.

    • map.put(key, value) — 키에 값을 저장(이미 있으면 덮어쓰기)
    • map.get(key) — 키의 값을 꺼냄. 키가 없으면 null!
    • map.getOrDefault(key, 0) — 키가 없으면 null 대신 기본값 0을 돌려줌
    • map.containsKey(key) — 키가 있는지 확인
    • map.entrySet() — (키, 값) 쌍 전체를 순회할 때 사용

    빈도 계산의 핵심 한 줄: "지금까지의 횟수(없으면 0)에 1을 더해 다시 저장한다."

    freq.put(word, freq.getOrDefault(word, 0) + 1);

    중복 확인과 HashSet

    • HashSet = "값의 집합" — 같은 값을 두 번 담을 수 없음
    • add가 그 사실을 알려 줌: 처음 넣는 값이면 true, 이미 있던 값이면 false
    • "지금까지 본 단어를 명단에 적어 두고, 명단에 있으면 중복"이라는 아이디어가 코드 한 줄로 — seen.add(word)가 false를 돌려주는 순간이 곧 중복 발견

    해시는 왜 빠른가?

    • HashMap·HashSet의 "Hash" = 해시 함수에서 온 이름 — "apple" 같은 값을 받아 저장 위치(번호)를 계산
    • 덕분에 "apple이 있나?"라는 질문에 전체를 뒤지지 않고 계산된 위치만 확인하면 됨
    • 1강 응용 예제의 "번호 = 인덱스 + 1" 규칙으로 O(1) 접근했던 것과 같은 원리를, 해시 함수가 어떤 값에 대해서도 만들어 주는 셈
    • 그래서 추가·확인이 평균 O(1), n개를 순회해도 전체가 평균 O(n)
    비교 항목완전 탐색 (이중 반복문)해시 (HashSet·HashMap)
    중복 확인 방법모든 쌍을 직접 비교"본 것"을 집합에 기억
    확인 횟수 (n=10)45번10번
    확인 횟수 (n=100,000)약 50억 번100,000번
    시간 복잡도O(n²)평균 O(n)
    추가 메모리거의 없음 O(1)집합·맵 저장 공간 O(n)

    05단계별 동작 과정

    단어 카드 5장 [사과, 포도, 사과, 배, 포도]에서 중복된 단어를 찾는 과정을 시각화로 봅니다. 1부는 이중 반복문(모든 쌍 비교), 2부는 같은 데이터를 HashSet으로 처리. 다음 단계 ▶로 한 단계씩 진행하며 비교 횟수 카운터를 관찰하세요 — 기준 단어 i는 파란색(현재), 비교 상대 j는 앰버색(비교 중), 중복 확정은 초록색(확정).

    단어 5개에 대해 이중 반복문은 10번, HashSet은 5번의 확인으로 같은 중복 [사과, 포도]를 찾아냅니다 — 같은 답, 다른 일의 양입니다.

    06의사코드

    코드를 쓰기 전에, 시각화에서 본 절차를 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)

    완전 탐색 중복 찾기 (FindDuplicatesByPairs)

    Pseudo 방법 A — 이중 반복문으로 중복 찾기 
    알고리즘 FindDuplicatesByPairs(words)
    i를 0부터 n-1까지 반복:                    // 기준 단어
        j를 i+1부터 n-1까지 반복:              // i+1부터: 같은 쌍을 두 번 비교하지 않음
            words[i]와 words[j]를 비교한다     // 핵심 연산 (n(n-1)/2번)
            같으면 words[i]를 중복 목록에 기록한다
    중복 목록을 반환한다

    HashSet 중복 찾기 (FindDuplicatesByHashSet)

    Pseudo 방법 B — HashSet으로 중복 찾기 
    알고리즘 FindDuplicatesByHashSet(words)
    seen ← 빈 집합                            // 지금까지 본 단어 명단
    words의 각 단어 word에 대해 반복:
        word가 seen에 이미 있으면:            // 핵심 연산 (n번)
            word를 중복 목록에 기록한다
        아니면:
            word를 seen에 추가한다            // 처음 본 단어는 명단에 기록
    중복 목록을 반환한다

    양 끝 포인터 회문 판별 (IsPalindrome)

    Pseudo 회문 판별 — 양 끝 포인터 
    알고리즘 IsPalindrome(word)
    left ← 0
    right ← word의 길이 - 1
    left가 right보다 작은 동안 반복:         // 만나거나 엇갈리면 종료
        word[left]와 word[right]가 다르면:   // 핵심 연산 (최대 L/2번)
            "회문 아님"을 반환한다           // 한 쌍이라도 다르면 즉시 종료
        left ← left + 1
        right ← right - 1
    "회문"을 반환한다                        // 끝까지 같았으면 회문

    세 의사코드 비교

    • 방법 A의 절차에는 고리(loop) 안에 또 고리가 있음 — 이것이 O(n²)의 모양
    • 방법 B는 고리가 하나뿐이지만, 대신 집합이라는 기억 장치가 추가됨
    • 시간을 줄이는 대가로 공간을 쓰는 이 교환을 코드로 확인

    07실습 코드

    의사코드(06)의 방법 A·방법 B를 그대로 옮긴 "같은 문제, 두 가지 알고리즘" 비교 프로그램입니다 — 이중 반복문(방법 A)과 HashSet(방법 B)으로 각각 중복 단어를 찾아 결과·확인 횟수를 비교하고, 마지막엔 HashMap의 getOrDefault로 모든 단어의 빈도를 단 한 번의 순회로 계산합니다.

    • findDuplicatesByPairs는 06의 방법 A(이중 반복문)를 그대로 옮긴 것 — 바깥 루프 i가 기준 단어를, 안쪽 루프 j가 비교 상대를 맡는 04 핵심 개념의 완전 탐색 구조
    • findDuplicatesByHashSet는 06의 방법 B — seen.add(word) 한 줄로 "본 적 있는지 확인"과 "기록"을 동시에 처리하는 04의 집합 기반 탐색
    • countFrequencies는 04 핵심 개념의 빈도 계산 패턴을 HashMap의 getOrDefault로 옮긴 것 — 처음 보는 단어는 0에서 시작해 안전하게 누적
    Java WordAnalysisComplete.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;

public class WordAnalysisComplete {

    /** 방법 A: 이중 반복문(완전 탐색)으로 중복 단어 목록을 찾는다. 비교는 n(n-1)/2번. */
    static List<String> findDuplicatesByPairs(String[] words) {
        List<String> duplicates = new ArrayList<>();
        int compareCount = 0;

        for (int i = 0; i < words.length; i++) {
            for (int j = i + 1; j < words.length; j++) {
                compareCount++;                       // 핵심 연산: 문자열 비교
                if (words[i].equals(words[j]) && !duplicates.contains(words[i])) {
                    duplicates.add(words[i]);         // 처음 확인된 중복만 기록
                }
            }
        }

        System.out.println("  [방법 A: 이중 반복문] 비교 횟수 = " + compareCount);
        return duplicates;
    }

    /** 방법 B: HashSet으로 중복 단어 목록을 찾는다. 집합 검사는 n번. */
    static List<String> findDuplicatesByHashSet(String[] words) {
        List<String> duplicates = new ArrayList<>();
        HashSet<String> seen = new HashSet<>();       // 지금까지 본 단어들의 집합
        int checkCount = 0;

        for (String word : words) {
            checkCount++;                             // 핵심 연산: 집합 검사(add)
            if (!seen.add(word)) {                    // add가 false = 이미 있던 단어 = 중복!
                if (!duplicates.contains(word)) {
                    duplicates.add(word);
                }
            }
        }

        System.out.println("  [방법 B: HashSet]     검사 횟수 = " + checkCount);
        return duplicates;
    }

    /** 단어 빈도: HashMap으로 각 단어의 등장 횟수를 센다. 순회는 n번. */
    static Map<String, Integer> countFrequencies(String[] words) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            // 처음 보는 단어면 0에서, 이미 본 단어면 지금까지의 횟수에서 1을 더한다
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    public static void main(String[] args) {
        String sentence = "apple banana apple orange banana apple kiwi orange plum kiwi";
        String[] words = sentence.split(" ");
        int n = words.length;

        System.out.println("문장: " + sentence);
        System.out.println("단어 수 n = " + n);
        System.out.println();

        System.out.println("== 1. 중복 단어 찾기: 완전 탐색 vs HashSet ==");
        List<String> dupA = findDuplicatesByPairs(words);
        List<String> dupB = findDuplicatesByHashSet(words);

    09복잡도 및 특성 분석

    복잡도 분석 = "데이터가 많아지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 어려운 수식 대신 "몇 번 확인하는가"만 세어 봅니다.

    입력 크기 — 무엇이 많아지는가?

    • 중복 찾기·빈도 계산: 단어 수 n — 게시글이 길어져 단어가 많아질수록 일이 늘어남
    • 회문 판별: 글자 수 L — 한 단어가 길어질수록 일이 늘어남

    주요 연산 — 무엇을 세는가?

    • 프로그램에서 가장 많이 반복되는 한 동작만 세면 충분
    • 이중 반복문: 두 단어를 비교하는 equals 한 번
    • HashSet·HashMap: 명단에 확인·기록하는 add·put 한 번
    • 회문 판별: 앞 글자와 뒤 글자를 비교하는 한 번

    시간 복잡도 — 얼마나 오래 걸리는가?

    알고리즘확인 횟수단어 10개일 때단어 10만 개일 때Big-O
    중복 찾기 — 이중 반복문모든 쌍: n(n-1)/2번45번약 50억 번O(n²)
    중복 찾기 — HashSet단어마다 1번: n번10번10만 번평균 O(n)
    단어 빈도 — HashMap단어마다 1번: n번10번10만 번평균 O(n)
    • O(n²)을 쉽게 말하면: 데이터가 10배 늘면 일은 100배 늘어남 — 반 친구 모두가 서로 한 번씩 악수하는 것과 같음 (사람이 늘수록 악수 횟수가 폭발적으로 증가)
    • O(n)을 쉽게 말하면: 데이터가 10배 늘면 일도 10배만 늘어남 — 출석부를 위에서부터 한 번 읽어 내려가는 것과 같음
    • 이중 반복문은 중복을 일찍 찾아도 모든 쌍을 끝까지 확인 → 운이 좋아도 나빠도 항상 같은 횟수
    • HashSet·HashMap 앞의 "평균": 아주 드물게 한 번의 확인이 느려질 수 있지만, 실제로는 거의 항상 한 번에 끝난다고 생각해도 충분
    • 회문 판별(글자 수 L): 양 끝에서 한 쌍씩 비교하므로 최대 L/2번, O(L)
      • 첫 글자와 끝 글자부터 다르면 1번 만에 끝남 — 회문이 아닐수록 빨리 끝남
      • 회문일 때 가장 오래 걸림 (모든 쌍을 끝까지 확인해야 하므로)

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 이중 반복문: 변수 i, j, 카운터 몇 개뿐 — 단어가 늘어도 추가 메모리는 그대로, O(1)
    • HashSet·HashMap: 서로 다른 단어를 모두 명단에 적어 둠 — 단어가 늘면 명단도 커짐, O(n)
    한 줄 정리 — 메모리를 내주고 시간을 산다
    • 해시는 명단(메모리)을 조금 더 쓰는 대신 확인 횟수를 n² → n으로 크게 줄임
    • 요즘 컴퓨터는 메모리가 넉넉해 대부분 이득인 교환 — 단, "빠름에는 공짜가 없다"는 사실은 기억

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 완전 탐색은 "정답지" 역할: 느리지만 틀리지 않으므로, 새로 만든 빠른 코드(해시)의 결과와 비교해 버그를 찾는 데 유용 (실습 코드의 dupA.equals(dupB))
    • 데이터가 적으면 완전 탐색도 괜찮음: 단어가 수십~수백 개 정도면 O(n²)도 눈 깜짝할 사이에 끝남 — 코드가 단순한 쪽이 오히려 좋은 선택일 수 있음
    • 해시는 순서를 기억하지 않음: HashMap·HashSet에서 꺼내면 넣은 순서와 다르게 나올 수 있음 — 순서가 필요하면 원본 배열을 다시 순회
    • 이중 반복문은 다시 만남: "i를 고정하고 j를 훑는" 구조는 4강의 선택 정렬·버블 정렬에서 그대로 등장

    Java ModernizeSolution.java 
    import java.util.Arrays;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.stream.Collectors;
import java.util.stream.IntStream;

public class ModernizeSolution {

    /** 방법 A: 모든 쌍 (i, j)를 비교해 중복 단어 목록을 찾는다. */
    static List<String> findDuplicatesByPairs(String[] words) {
        int n = words.length;

        List<String> duplicates = IntStream.range(0, n)
                .boxed()
                .filter(i -> IntStream.range(i + 1, n)
                        .anyMatch(j -> words[i].equals(words[j])))
                .map(i -> words[i])
                .distinct()
                .toList();

        int pairCount = IntStream.range(0, n).map(i -> n - 1 - i).sum();
        System.out.println("  [방법 A: 이중 반복문] 비교 쌍의 수 = " + pairCount);
        return duplicates;
    }

    /** 방법 B: HashSet으로 중복 단어 목록을 찾는다. */
    static List<String> findDuplicatesByHashSet(String[] words) {
        Set<String> seen = new HashSet<>();

        List<String> duplicates = Arrays.stream(words)
                .filter(word -> !seen.add(word))
                .distinct()
                .toList();

        System.out.println("  [방법 B: HashSet]     검사 횟수 = " + words.length);
        return duplicates;
    }

    /** 단어 빈도: 단어 자신을 기준으로 묶어 개수를 센다. */
    static Map<String, Long> countFrequencies(String[] words) {
        return Arrays.stream(words)
                .collect(Collectors.groupingBy(w -> w, Collectors.counting()));
    }

    public static void main(String[] args) {
        String sentence = "apple banana apple orange banana apple kiwi orange plum kiwi";
        String[] words = sentence.split(" ");
        int n = words.length;

        System.out.println("문장: " + sentence);
        System.out.println("단어 수 n = " + n);
        System.out.println();

        System.out.println("== 1. 중복 단어 찾기: 완전 탐색 vs HashSet ==");
        List<String> dupA = findDuplicatesByPairs(words);
        List<String> dupB = findDuplicatesByHashSet(words);
        System.out.println("  방법 A 결과: " + dupA);
        System.out.println("  방법 B 결과: " + dupB);
        System.out.println("  두 방법의 결과 일치 = " + dupA.equals(dupB));
        System.out.println();

        System.out.println("== 2. 단어 빈도 (HashMap) ==");
        Map<String, Long> freq = countFrequencies(words);
        Arrays.stream(words)
                .distinct()
                .forEach(word -> System.out.println("  " + word + " : " + freq.get(word) + "회"));
        System.out.println();

        System.out.println("n = " + n + "일 때: 완전 탐색은 " + (n * (n - 1) / 2)
                + "번, 해시는 " + n + "번. n이 커질수록 차이는 극적으로 벌어진다.");
    }

    • 회문 판별: 04 핵심 개념·06 의사코드의 두 포인터 알고리즘 — 아이디 길이 L에 대해 O(L)
    Java NoticeAnalysisApplication.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class NoticeAnalysisApplication {

    /** 단어 빈도를 세면서, 처음 만난 단어를 등장 순서대로 order 목록에 기록한다. */
    static Map<String, Integer> countFrequencies(String[] words, List<String> order) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            if (!freq.containsKey(word)) {
                order.add(word);   // 처음 보는 단어의 등장 순서를 기억한다
            }
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    /**
     * 빈도 상위 topN 단어: Map.Entry 스트림을 빈도 내림차순(동점이면 사전순)으로 정렬해
     * 앞에서 topN개를 취한다. 정렬 알고리즘의 원리는 4강에서 배우지만, 정렬된 결과 자체는
     * 지금도 라이브러리로 바로 얻을 수 있다.
     */
    static List<String> topWords(Map<String, Integer> freq, int topN) {
        return freq.entrySet().stream()
                .sorted(Map.Entry.<String, Integer>comparingByValue().reversed()
                        .thenComparing(Map.Entry::getKey))
                .limit(topN)
                .map(Map.Entry::getKey)
                .toList();
    }

    /** 회문 판별 (PalindromeTrace와 같은 알고리즘, 추적 출력만 없음) */
    static boolean isPalindrome(String word) {
        int left = 0;
        int right = word.length() - 1;
        while (left < right) {
            if (word.charAt(left) != word.charAt(right)) {
                return false;
            }
            left++;
            right--;
        }
        return true;
    }

    public static void main(String[] args) {
        String notice = "시험 일정 안내 시험 범위 안내 시험 일정 준비 안내 제출 마감 안내";
        String[] words = notice.split(" ");

        System.out.println("공지사항: " + notice);
        System.out.println("단어 수: " + words.length);
        System.out.println();

        List<String> order = new ArrayList<>();
        Map<String, Integer> freq = countFrequencies(words, order);

    문제 배경

    여러분은 커뮤니티 운영팀의 신입 개발자입니다. 운영팀은 도배성 게시글을 걸러 내기 위해 게시글의 단어 사용 패턴을 보고 싶어 합니다. 구체적으로는 게시글에 어떤 단어가 몇 번씩 나오는지, 두 번 이상 반복된 단어는 무엇인지, 그리고 가장 많이 등장한 단어가 무엇인지를 한 번에 보여 주는 도구가 필요합니다. 단어 수만 개짜리 게시글도 분석해야 하므로, 모든 계산은 오늘 배운 HashMap·HashSet 기반의 O(n) 방식으로 구현하기로 했습니다. 이 도구의 이름은 WordLens — 게시글을 단어 단위로 들여다보는 돋보기입니다.

    Java WordFrequencySolution.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class WordFrequencySolution {

    /** 1단계: 문장을 공백 기준으로 잘라 단어 배열을 만든다. */
    static String[] splitWords(String post) {
        return post.split(" ");
    }

    /** 2단계: HashMap으로 각 단어의 등장 횟수를 센다. O(n) */
    static Map<String, Integer> countFrequencies(String[] words) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            // 처음 보는 단어면 0에서, 이미 본 단어면 지금까지의 횟수에서 1을 더한다
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    /** 3단계: 두 번 이상 등장한 단어 목록을 첫 등장 순서대로 만든다. O(n) */
    static List<String> findDuplicates(String[] words) {
        List<String> duplicates = new ArrayList<>();
        Set<String> seen = new HashSet<>();
        for (String word : words) {
            if (!seen.add(word)) {                 // add가 false = 이미 본 단어 = 중복
                if (!duplicates.contains(word)) {  // 같은 단어를 두 번 넣지 않는다
                    duplicates.add(word);
                }
            }
        }
        return duplicates;
    }

    /** 4단계: 가장 많이 등장한 단어를 찾는다. (2강의 최댓값 찾기 패턴) O(n) */
    static String findMostFrequent(String[] words, Map<String, Integer> freq) {
        String best = null;
        for (String word : words) {
            if (best == null || freq.get(word) > freq.get(best)) {
                best = word;   // 더 자주 등장한 단어를 만나면 갈아 끼운다
            }
        }
        return best;
    }

    public static void main(String[] args) {
        String post = "자바 공부 시작 자바 문법 공부 자바 프로젝트 시작";
        String[] words = splitWords(post);

        System.out.println("게시글: " + post);
        System.out.println("단어 수: " + words.length);
        System.out.println();

        Map<String, Integer> freq = countFrequencies(words);

        System.out.println("== 단어 빈도 ==");
        Set<String> printed = new HashSet<>();
        for (String word : words) {
            if (printed.add(word)) {   // 첫 등장 순서대로 한 번씩만 출력
                System.out.println("  " + word + " : " + freq.getOrDefault(word, 0) + "회");
            }
        }
        System.out.println();

        System.out.println("== 두 번 이상 등장한 단어 ==");
        System.out.println("  " + findDuplicates(words));
        System.out.println();

        String most = findMostFrequent(words, freq);
        System.out.println("== 가장 많이 등장한 단어 ==");
        System.out.println("  " + most + " (" + (most == null ? 0 : freq.getOrDefault(most, 0)) + "회)");
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. countFrequencies의 핵심은 freq.put(word, freq.getOrDefault(word, 0) + 1) 한 줄입니다 — "없으면 0에서 시작"이 오류 카드 2의 NullPointerException을 막아 줍니다.
    2. findDuplicates의 핵심은 !seen.add(word)입니다 — add의 반환값 하나로 "확인"과 "기록"이 동시에 끝나므로 순회 한 번이면 충분합니다.
    3. findMostFrequent는 2강의 최댓값 찾기와 같은 구조입니다. 비교 대상이 "값 자체"가 아니라 "맵에서 꺼낸 빈도"라는 점만 다릅니다. best == null 처리 덕분에 단어 1개짜리 경계 조건도 안전합니다.
    4. 출력의 printed.add(word) 패턴은 "한 번만 출력"을 집합으로 구현한 것 — 중복 확인과 같은 아이디어를 출력 제어에 재활용했습니다.

    복잡도 분석

    • 빈도 계산 O(n), 중복 목록 O(n), 최다 단어 O(n), 출력 O(n) — 전체 평균 O(n).
    • 공간은 맵·집합에 서로 다른 단어를 저장하므로 O(n) — 이중 반복문 버전(시간 O(n²), 공간 O(1))과 정확히 반대의 교환입니다.
    • 같은 작업을 이중 반복문으로 하면 n=100,000일 때 약 50억 번의 비교가 필요합니다 — 제한 조건이 "이중 반복문 금지"인 이유입니다.

    자주 발생하는 오류

    • freq.get(word) + 1로 써서 첫 단어에서 NullPointerException이 나는 경우 (오류 카드 2).
    • findDuplicates에서 duplicates.contains 확인을 빼먹어 "자바"가 목록에 두 번 들어가는 경우 (자바는 3번 등장하므로 중복 감지가 2번 일어납니다).
    • findMostFrequent에서 best를 ""로 초기화하고 freq.get(best)를 호출해 NullPointerException이 나는 경우 — null 초기화 + null 검사가 안전합니다.
    • 단어 비교나 동률 처리에서 ==를 사용한 경우 — 항상 equals!

    다른 해결 방법

    중복 목록을 duplicates.contains(리스트 순회) 대신 두 번째 HashSet으로 확인하면 그 부분도 평균 O(1)이 됩니다. 빈도를 유지하면서 순서도 기억하는 LinkedHashMap을 쓰면 출력용 printed 집합이 필요 없어집니다. 또한 실무에서는 freq.merge(word, 1, Integer::sum)이나 stream 집계도 쓰이지만, 내부에서 일어나는 일은 오늘 직접 구현한 "getOrDefault + 1"과 같습니다 — 원리를 알고 쓰는 것이 중요합니다.

    15오늘의 핵심 정리

    • 완전 탐색은 가능한 모든 경우를 확인하는 전략이다 — 느릴 수는 있어도 틀리지 않으므로, 모든 알고리즘 설계의 출발점이자 정확성 검증의 기준이 된다.
    • 중첩 반복문(i 고정, j = i+1부터)은 모든 쌍을 만드는 완전 탐색의 대표 패턴이며, 비교 횟수는 n(n-1)/2번, O(n²)이다.
    • 문자열은 length()와 charAt(i)로 배열처럼 순회하고, 내용 비교는 반드시 equals로 한다 (==는 객체 비교!).
    • 회문 판별은 left·right 두 포인터를 양 끝에서 가운데로 좁히며 비교한다 — 길이 L에 최대 L/2번, O(L).
    • HashMap은 "키 → 값" 저장소로, getOrDefault(key, 0) + 1 패턴이면 문자·단어 빈도를 순회 한 번에 센다. 결과 순회는 entrySet.
    • HashSet은 중복 없는 집합으로, add의 반환값(이미 있으면 false)으로 중복을 한 번의 순회에 찾는다.
    • 해시는 공간 O(n)을 내주고 시간을 O(n²) → 평균 O(n)으로 줄이는 교환이다. 대신 저장 순서를 기억하지 않는다.

완전 탐색과 문자열·해시 처리

Brute Force, Strings, and Hashing

알고리즘 기초 초급 Java 17+

"가능한 모든 경우를 다 확인한다" — 가장 단순하지만 가장 확실한 문제 해결 전략, 완전 탐색을 배웁니다. 문자열을 한 글자씩 순회하고, 회문을 판별하고, 단어의 빈도를 세는 과정에서 완전 탐색의 대표 패턴인 중첩 반복문을 익힙니다. 그리고 같은 문제를 HashMap과 HashSet으로 다시 풀어, O(n²)의 완전 탐색이 어떻게 O(n)으로 줄어드는지 직접 확인합니다.

이 강의의 목차

    01강의 소개

    문제를 만났을 때 아무 아이디어도 떠오르지 않는다면, 가장 먼저 던져야 할 질문이 있습니다. "가능한 모든 경우를 하나씩 다 확인하면 어떻게 될까?" 이렇게 모든 경우를 빠짐없이 검사하는 전략을 완전 탐색(brute force)이라고 부릅니다. 완전 탐색은 느릴 수는 있어도 틀리지 않습니다 — 그래서 모든 알고리즘 설계의 출발점이 됩니다.

    이번 강의에서는 완전 탐색을 문자열 데이터에 적용합니다. 문자열을 한 글자씩 순회하는 charAt, 문자열을 올바르게 비교하는 equals, 앞뒤가 똑같은 회문(팰린드롬) 판별, 그리고 완전 탐색의 대표 패턴인 중첩 반복문으로 모든 쌍 비교하기를 차례로 배웁니다. 후반부에는 같은 문제를 HashMap과 HashSet으로 다시 풀어, 비교 횟수가 n(n-1)/2번에서 n번으로 줄어드는 것을 1강에서 배운 연산 카운터로 직접 셉니다. 마지막에는 게시글의 단어 빈도, 중복 단어, 최다 등장 단어를 분석하는 단어 분석 프로그램을 완성합니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 완전 탐색이 무엇인지 설명하고, 중첩 반복문으로 모든 쌍을 비교하는 코드를 작성할 수 있다.
    • 학생은 charAt과 length()로 문자열을 한 글자씩 순회하고, equals로 문자열을 올바르게 비교할 수 있다.
    • 학생은 left·right 포인터를 이용해 회문(팰린드롬)을 판별하는 메서드를 작성할 수 있다.
    • 학생은 HashMap의 getOrDefault로 문자·단어의 빈도를 세고, entrySet으로 결과를 순회할 수 있다.
    • 학생은 HashSet의 add 반환값을 이용해 중복 데이터를 한 번의 순회로 찾을 수 있다.
    • 학생은 완전 탐색 O(n²)과 해시 O(n)의 비교 횟수를 카운터로 세어 표로 비교할 수 있다.

    04실제 문제 상황

    여러분이 학과 커뮤니티 게시판의 운영을 맡게 되었다고 상상해 봅시다. 최근 도배성 게시글이 늘어서, 운영진은 게시글에 같은 단어가 반복해서 등장하는지, 어떤 단어가 가장 많이 쓰였는지를 자동으로 분석하고 싶어 합니다. 처음에는 단어 수가 수십 개라 "모든 단어 쌍을 비교"하는 프로그램으로 충분했습니다. 그런데 인기 게시글은 댓글까지 합치면 단어가 수만 개나 되고, 분석 시간이 눈에 띄게 길어졌습니다. 선배가 힌트를 줍니다. "모든 쌍을 비교하면 n²이야. 해시를 쓰면 n에 끝나." n²과 n의 차이가 무엇인지는 1강에서 배웠습니다 — 이제 그 차이를 만들어 내는 방법을 배울 차례입니다.

    모든 경우를 확인하는 완전 탐색은 언제나 옳다. 그런데 더 적게 확인하고도 같은 답을 얻을 수는 없을까?

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 작은 데이터로 문제를 손으로 풀어 봅니다. 단어 5개가 적힌 카드가 있습니다: [사과, 포도, 사과, 배, 포도]. 이 중에서 중복된 단어를 찾아봅시다.

    방법 A — 모든 쌍을 비교하기 (완전 탐색)

    STEP 1

    첫 번째 카드 "사과"를 들고, 뒤에 있는 카드들과 차례로 비교합니다. 사과↔포도(다름), 사과↔사과(같음! 중복 발견), 사과↔배(다름), 사과↔포도(다름).

    질문: 첫 번째 카드 하나를 확인하는 데 비교를 몇 번 했나요?

    4번입니다. 자기 자신을 제외한 나머지 카드 수, 즉 n - 1번입니다. 카드가 100장이라면 첫 카드에만 99번의 비교가 필요합니다.

    STEP 2

    두 번째 카드 "포도"는 그 뒤의 3장과 비교합니다(포도↔사과, 포도↔배, 포도↔포도: 중복!). 세 번째 카드는 2장과, 네 번째 카드는 1장과 비교합니다. 앞 카드와의 비교는 이미 했으므로 다시 하지 않습니다.

    질문: 총 비교 횟수는 몇 번인가요? 카드가 100장이라면요?

    4 + 3 + 2 + 1 = 10번입니다. 일반화하면 (n-1) + (n-2) + … + 1 = n(n-1)/2번. 카드가 100장이면 100 × 99 ÷ 2 = 4,950번입니다. n이 10배가 되면 비교는 약 100배 — 1강에서 배운 O(n²)의 증가 방식입니다.

    방법 B — 명단에 적어 가며 한 번만 훑기

    STEP 3

    이번에는 빈 종이(명단)를 준비하고 카드를 한 장씩 봅니다. "사과" → 명단에 없음, 적는다. "포도" → 없음, 적는다. "사과" → 명단에 이미 있음! 중복. "배" → 없음, 적는다. "포도" → 이미 있음! 중복. 끝.

    질문: 카드를 몇 번 확인했나요? 이 방법의 핵심 아이디어는 무엇인가요?

    카드 수만큼, 딱 5번입니다. 핵심은 "지금까지 본 것"을 기억해 두는 것입니다. 기억(명단) 덕분에 과거의 카드와 일일이 다시 비교할 필요가 없어집니다. 이 명단 역할을 컴퓨터에서 하는 것이 바로 HashSet입니다.

    STEP 4

    두 방법을 비교해 봅시다. 찾아낸 중복은 [사과, 포도]로 같습니다. 하지만 확인 횟수는 방법 A가 10번, 방법 B가 5번입니다.

    질문: 단어가 100,000개라면 두 방법의 확인 횟수는 각각 얼마일까요?

    방법 A는 100,000 × 99,999 ÷ 2 ≈ 50억 번, 방법 B는 100,000번입니다. 약 5만 배 차이입니다. 단, 방법 B는 명단이라는 추가 메모리를 씁니다 — "메모리를 조금 쓰고 시간을 크게 아끼는" 교환이 일어난 것입니다. 이 교환은 복잡도 섹션에서 다시 정리합니다.

    06핵심 개념

    완전 탐색(Brute Force)이란?

    완전 탐색은 가능한 모든 경우를 빠짐없이 확인하는 문제 해결 전략입니다. "후보를 하나도 놓치지 않는다"는 성질 덕분에, 구현이 올바르다면 답이 틀릴 수 없습니다. 2강의 조건 검색(배열을 처음부터 끝까지 확인)도 사실 완전 탐색의 한 형태였습니다. 문제는 속도입니다 — "모든 경우"의 수가 크면 그만큼 오래 걸립니다. 그래서 알고리즘 설계는 보통 이렇게 진행됩니다: ① 완전 탐색으로 일단 정확한 답을 얻는다 → ② 더 적게 확인하는 방법을 찾는다. 오늘 강의가 정확히 이 두 단계를 밟습니다.

    중첩 반복문 — "모든 쌍"을 만드는 기계

    완전 탐색에서 가장 자주 쓰는 도구가 중첩 반복문(반복문 안의 반복문)입니다. 바깥 반복문이 기준 i를 정하면, 안쪽 반복문이 비교 상대 j를 훑습니다. 같은 쌍을 두 번 비교하지 않도록 안쪽을 j = i + 1부터 시작하는 것이 관례입니다.

    패턴코드 형태반복 횟수Big-O
    단일 반복문for (i = 0; i < n; i++)n번O(n)
    중첩 반복문 (모든 쌍)for (i...) for (j = i + 1...)n(n-1)/2번O(n²)

    n=10이면 45번, n=1,000이면 499,500번, n=100,000이면 약 50억 번 — 중첩 반복문은 n이 커질수록 빠르게 무거워집니다. 참고로 이 "i를 고정하고 j를 훑는" 구조는 다음 강의(4강)에서 배울 선택 정렬·버블 정렬의 뼈대이기도 합니다.

    문자열 순회 — length()와 charAt(i)

    문자열은 "문자들이 순서대로 늘어선 데이터"라는 점에서 배열과 매우 닮았습니다. 배열 순회 패턴을 그대로 옮기되, 문법이 조금 다릅니다.

    하고 싶은 일배열(int[])문자열(String)
    길이 구하기arr.lengthstr.length() — 메서드라서 괄호 필요
    i번째 요소 꺼내기arr[i]str.charAt(i) — 결과는 char
    단어로 쪼개기-str.split(" ") — 결과는 String[]

    문자열 비교 — 반드시 equals!

    문자(char)는 숫자처럼 ==로 비교합니다. 하지만 문자열(String)은 객체라서, ==는 "내용이 같은가"가 아니라 "같은 객체인가(같은 메모리를 가리키는가)"를 묻습니다. 내용 비교는 반드시 a.equals(b)를 사용해야 합니다. split으로 만들어진 단어들은 전부 새 객체이므로, == 비교는 내용이 같아도 false가 됩니다 — 오늘 오류 카드(12번 섹션)에서 실제로 이 사고를 재현해 봅니다.

    회문(팰린드롬) 판별

    회문은 앞으로 읽어도 뒤로 읽어도 같은 문자열입니다: level, noon, 기러기, 토마토. 판별 알고리즘은 양 끝에서 가운데로 좁혀 가는 두 포인터를 사용합니다. 왼쪽 포인터 left와 오른쪽 포인터 right가 가리키는 문자를 비교하고, 같으면 한 칸씩 안쪽으로 이동, 다르면 그 즉시 "회문 아님"으로 끝냅니다. 문자열 길이가 L이면 비교는 최대 L/2번 — 이것도 "확인해야 할 모든 쌍을 확인하는" 작은 완전 탐색입니다.

    빈도 계산과 HashMap

    2강에서 점수 빈도를 셀 때는 count[점수]++처럼 정수를 배열 인덱스로 썼습니다. 그런데 "apple"이라는 단어는 배열 인덱스가 될 수 없습니다. 이럴 때 쓰는 자료구조가 HashMap입니다 — 키(key) → 값(value) 쌍을 저장하는 표라서, "단어 → 등장 횟수"를 자연스럽게 담을 수 있습니다.

    • map.put(key, value) — 키에 값을 저장(이미 있으면 덮어쓰기)
    • map.get(key) — 키의 값을 꺼냄. 키가 없으면 null!
    • map.getOrDefault(key, 0) — 키가 없으면 null 대신 기본값 0을 돌려줌
    • map.containsKey(key) — 키가 있는지 확인
    • map.entrySet() — (키, 값) 쌍 전체를 순회할 때 사용

    빈도 계산의 핵심 한 줄은 다음과 같습니다. "지금까지의 횟수(없으면 0)에 1을 더해 다시 저장한다."

    freq.put(word, freq.getOrDefault(word, 0) + 1);

    중복 확인과 HashSet

    HashSet은 "값의 집합"입니다. 같은 값을 두 번 담을 수 없고, add가 그 사실을 알려 줍니다: 처음 넣는 값이면 true, 이미 있던 값이면 false를 반환합니다. 그래서 손 풀이의 "명단에 적어 가며 훑기"가 코드 세 줄이 됩니다 — seen.add(word)가 false를 돌려주는 순간이 곧 중복 발견입니다.

    해시는 왜 빠른가?

    HashMap과 HashSet의 "Hash"는 해시 함수에서 온 이름입니다. 해시 함수는 "apple" 같은 값을 받아 저장 위치(번호)를 계산합니다. 덕분에 "apple이 있나?"라는 질문에 전체를 뒤지지 않고 계산된 위치만 확인하면 됩니다 — 1강 응용 예제에서 "번호 = 인덱스 + 1" 규칙으로 O(1) 접근을 했던 것과 같은 원리를, 해시 함수가 어떤 값에 대해서도 만들어 주는 셈입니다. 그래서 추가·확인이 평균 O(1)이고, n개를 순회하며 확인해도 전체가 평균 O(n)입니다.

    비교 항목완전 탐색 (이중 반복문)해시 (HashSet·HashMap)
    중복 확인 방법모든 쌍을 직접 비교"본 것"을 집합에 기억
    확인 횟수 (n=10)45번10번
    확인 횟수 (n=100,000)약 50억 번100,000번

    07단계별 동작 과정

    손으로 풀었던 중복 검사를 시각화로 다시 봅니다. 1부는 이중 반복문(모든 쌍 비교), 2부는 같은 데이터를 HashSet으로 처리합니다. 다음 단계 ▶ 버튼으로 한 단계씩 진행하며 비교 횟수 카운터를 관찰하세요. 기준 단어 i는 파란색(현재), 비교 상대 j는 앰버색(비교 중), 중복으로 확정된 단어는 초록색(확정)으로 표시됩니다.

    마지막 단계에서 확인할 수 있듯, 단어 5개에 대해 이중 반복문은 10번, HashSet은 5번의 확인으로 같은 중복 [사과, 포도]를 찾아냅니다. 같은 답, 다른 일의 양 — 1강의 "반복문 vs 공식"에서 본 구도가 자료구조의 힘으로 다시 나타납니다.

    08의사코드

    코드를 쓰기 전에, 시각화에서 본 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo 방법 A — 이중 반복문으로 중복 찾기 
    알고리즘 FindDuplicatesByPairs(words)
    i를 0부터 n-1까지 반복:
        j를 i+1부터 n-1까지 반복:
            words[i]와 words[j]를 비교한다     // 핵심 연산 (n(n-1)/2번)
            같으면 words[i]를 중복 목록에 기록한다
    중복 목록을 반환한다
    Pseudo 방법 B — HashSet으로 중복 찾기 
    알고리즘 FindDuplicatesByHashSet(words)
    seen ← 빈 집합
    words의 각 단어 word에 대해 반복:
        word가 seen에 이미 있으면:            // 핵심 연산 (n번)
            word를 중복 목록에 기록한다
        아니면:
            word를 seen에 추가한다
    중복 목록을 반환한다
    Pseudo 회문 판별 — 양 끝 포인터 
    알고리즘 IsPalindrome(word)
    left ← 0
    right ← word의 길이 - 1
    left가 right보다 작은 동안 반복:
        word[left]와 word[right]가 다르면:   // 핵심 연산 (최대 L/2번)
            "회문 아님"을 반환한다
        left ← left + 1
        right ← right - 1
    "회문"을 반환한다

    방법 A의 절차에는 고리(loop) 안에 또 고리가 있고 — 이것이 O(n²)의 모양입니다. 방법 B는 고리가 하나뿐이지만, 대신 집합이라는 기억 장치가 추가됐습니다. 시간을 줄이는 대가로 공간을 쓰는 이 교환을 코드로 확인하러 갑시다.

    public class Step3CountOneWord {
    public static void main(String[] args) {
        String sentence = "apple banana apple orange banana apple";
        String[] words = sentence.split(" ");
        String target = "apple";

        int count = 0;          // target이 등장한 횟수
        int compareCount = 0;   // 비교 연산 실행 횟수 (1강의 카운터 기법)

        // 단어 배열을 한 번 순회하며 target과 비교한다 (단일 루프)
        for (int i = 0; i < words.length; i++) {

            if (words[i].equals(target)) {  // 문자열 비교는 반드시 equals!
                count++;
            }
        }

        System.out.println("단어 \"" + target + "\"의 등장 횟수 = " + count);
        System.out.println("비교 연산 횟수 = " + compareCount + " (단어 수 n = " + words.length + ")");
    }
}

    10완성 Java 코드

    지금까지의 조각을 모아 "같은 문제, 두 가지 알고리즘" 비교 프로그램을 완성합니다. 직접 구현한 이중 반복문(방법 A)과 HashSet(방법 B)으로 각각 중복 단어를 찾아 결과가 같은지 검증하고, 확인 횟수를 비교합니다. 마지막에는 HashMap의 getOrDefault로 모든 단어의 빈도를 단 한 번의 순회로 계산합니다.

    Java WordAnalysisComplete.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;

public class WordAnalysisComplete {

    /** 방법 A: 이중 반복문(완전 탐색)으로 중복 단어 목록을 찾는다. 비교는 n(n-1)/2번. */
    static List<String> findDuplicatesByPairs(String[] words) {
        List<String> duplicates = new ArrayList<>();
        int compareCount = 0;

        for (int i = 0; i < words.length; i++) {
            for (int j = i + 1; j < words.length; j++) {
                compareCount++;                       // 핵심 연산: 문자열 비교
                if (words[i].equals(words[j]) && !duplicates.contains(words[i])) {
                    duplicates.add(words[i]);         // 처음 확인된 중복만 기록
                }
            }
        }

        System.out.println("  [방법 A: 이중 반복문] 비교 횟수 = " + compareCount);
        return duplicates;
    }

    /** 방법 B: HashSet으로 중복 단어 목록을 찾는다. 집합 검사는 n번. */
    static List<String> findDuplicatesByHashSet(String[] words) {
        List<String> duplicates = new ArrayList<>();
        HashSet<String> seen = new HashSet<>();       // 지금까지 본 단어들의 집합
        int checkCount = 0;

        for (String word : words) {
            checkCount++;                             // 핵심 연산: 집합 검사(add)
            if (!seen.add(word)) {                    // add가 false = 이미 있던 단어 = 중복!
                if (!duplicates.contains(word)) {
                    duplicates.add(word);
                }
            }
        }

        System.out.println("  [방법 B: HashSet]     검사 횟수 = " + checkCount);
        return duplicates;
    }

    /** 단어 빈도: HashMap으로 각 단어의 등장 횟수를 센다. 순회는 n번. */
    static Map<String, Integer> countFrequencies(String[] words) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            // 처음 보는 단어면 0에서, 이미 본 단어면 지금까지의 횟수에서 1을 더한다
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    public static void main(String[] args) {
        String sentence = "apple banana apple orange banana apple kiwi orange plum kiwi";
        String[] words = sentence.split(" ");
        int n = words.length;

        System.out.println("문장: " + sentence);
        System.out.println("단어 수 n = " + n);
        System.out.println();

        System.out.println("== 1. 중복 단어 찾기: 완전 탐색 vs HashSet ==");
        List<String> dupA = findDuplicatesByPairs(words);
        List<String> dupB = findDuplicatesByHashSet(words);
        System.out.println("  방법 A 결과: " + dupA);
        System.out.println("  방법 B 결과: " + dupB);
        System.out.println("  두 방법의 결과 일치 = " + dupA.equals(dupB));
        System.out.println();

        System.out.println("== 2. 단어 빈도 (HashMap) ==");
        Map<String, Integer> freq = countFrequencies(words);
        // HashMap 자체는 순서를 보장하지 않으므로, 첫 등장 순서대로 출력한다
        HashSet<String> printed = new HashSet<>();
        for (String word : words) {
            if (printed.add(word)) {
                System.out.println("  " + word + " : " + freq.get(word) + "회");
            }
        }
        System.out.println();

        System.out.println("n = " + n + "일 때: 완전 탐색은 " + (n * (n - 1) / 2)
                + "번, 해시는 " + n + "번. n이 커질수록 차이는 극적으로 벌어진다.");
    }
}

    11실행 과정 추적

    이번에는 문자열 순회의 대표 문제, 회문 판별의 내부를 추적합니다. left·right 포인터가 매 회차 어느 위치의 어떤 문자를 비교하는지 표로 출력해, 의사코드(8번 섹션)의 절차와 정확히 일치하는지 확인합니다.

    Java PalindromeTrace.java 
    public class PalindromeTrace {

    /** 회문 판별: 양 끝(left, right)에서 가운데로 좁혀 가며 문자 쌍을 비교한다. */
    static boolean isPalindrome(String word) {
        int left = 0;
        int right = word.length() - 1;

        System.out.println("[추적] \"" + word + "\" 회문 판별");
        System.out.println("left | right | charAt(left) | charAt(right) | 일치");
        System.out.println("-----+-------+--------------+---------------+-----");

        while (left < right) {
            char leftChar = word.charAt(left);
            char rightChar = word.charAt(right);
            boolean same = (leftChar == rightChar);   // 문자(char) 비교는 ==

            System.out.printf("%4d | %5d | %12c | %13c | %s%n",
                    left, right, leftChar, rightChar, same ? "O" : "X");

            if (!same) {
                return false;   // 한 쌍이라도 다르면 그 즉시 회문이 아니다
            }
            left++;             // 왼쪽 포인터는 오른쪽으로
            right--;            // 오른쪽 포인터는 왼쪽으로
        }
        return true;            // 포인터가 만나거나 엇갈리면 회문이다
    }

    public static void main(String[] args) {
        String[] tests = {"level", "banana", "noon", "기러기"};

        for (String word : tests) {
            boolean result = isPalindrome(word);
            System.out.println("=> \"" + word + "\" 은(는) 회문인가? " + result);
            System.out.println();
        }
    }
}

    13복잡도 및 특성 분석

    입력 크기

    오늘은 입력 크기가 두 종류입니다. 단어 관련 알고리즘은 단어 수 n, 회문 판별은 문자열 길이 L을 기준으로 일의 양을 표현합니다.

    주요 연산

    이중 반복문의 핵심 연산은 문자열 비교 equals, 해시 방식의 핵심 연산은 집합 검사 add·맵 갱신 put, 회문 판별의 핵심 연산은 문자 비교 charAt(left) == charAt(right)입니다.

    시간 복잡도

    알고리즘최선평균최악Big-O
    중복 확인 — 이중 반복문n(n-1)/2번n(n-1)/2번n(n-1)/2번O(n²)
    중복 확인 — HashSetn번n번n번 (검사 1회가 드물게 느려질 수 있음)평균 O(n)
    단어 빈도 — HashMapn번n번n번평균 O(n)
    회문 판별 — 두 포인터1번 (첫 쌍이 다름)-L/2번 (회문일 때)O(L)

    이중 반복문은 중복을 일찍 찾아도 모든 쌍을 끝까지 확인하므로 최선과 최악이 같습니다. 반면 회문 판별은 1강의 조기 중단처럼, 회문이 아닐수록 빨리 끝나는 특이한 구조입니다. 해시의 검사 1회는 "평균 O(1)"입니다 — 아주 드물게 느려질 수 있지만, 실무에서는 평균으로 생각해도 충분합니다.

    공간 복잡도

    • 이중 반복문: 카운터와 인덱스 변수 몇 개 — O(1)
    • HashSet·HashMap: 서로 다른 단어를 모두 저장 — O(n)

    즉 해시는 공간 O(n)을 내주고 시간을 O(n²) → O(n)으로 사는 교환입니다. 메모리가 넉넉한 요즘 환경에서는 대부분 남는 장사지만, "빠름에는 공짜가 없다"는 사실은 기억해 두세요.

    알고리즘 특성

    • 완전 탐색은 정확성의 기준점: 새 알고리즘(해시)을 도입할 때 느리지만 확실한 완전 탐색과 결과를 비교하면(dupA.equals(dupB)) 버그를 빨리 잡을 수 있습니다.
    • 작은 n에는 완전 탐색도 충분: n이 수십~수백이면 O(n²)도 순식간입니다. 코드가 단순한 완전 탐색이 오히려 좋은 선택일 수 있습니다.
    • 해시는 순서가 없다: HashMap·HashSet은 넣은 순서를 잃어버립니다. 순서가 필요하면 원본 배열을 다시 순회하거나 별도 목록으로 순서를 기억해야 합니다.
    • 중첩 반복문 패턴은 재등장한다: "i를 고정하고 j를 훑는" 구조는 4강의 선택 정렬·버블 정렬에서 그대로 다시 만납니다.

    • 회문 판별: 11번 섹션과 같은 두 포인터 알고리즘 — 아이디 길이 L에 대해 O(L)
    Java NoticeAnalysisApplication.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class NoticeAnalysisApplication {

    /** 단어 빈도를 세면서, 처음 만난 단어를 등장 순서대로 order 목록에 기록한다. */
    static Map<String, Integer> countFrequencies(String[] words, List<String> order) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            if (!freq.containsKey(word)) {
                order.add(word);   // 처음 보는 단어의 등장 순서를 기억한다
            }
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    /** 빈도 상위 topN 단어: "최댓값 찾기"(2강 패턴)를 topN번 반복한다. */
    static List<String> topWords(Map<String, Integer> freq, List<String> order, int topN) {
        List<String> result = new ArrayList<>();
        while (result.size() < topN && result.size() < order.size()) {
            String best = null;
            for (String word : order) {
                if (result.contains(word)) {
                    continue;                      // 이미 뽑은 단어는 건너뛴다
                }
                if (best == null || freq.get(word) > freq.get(best)) {
                    best = word;                   // 남은 단어 중 최다 빈도를 기록
                }
            }
            result.add(best);
        }
        return result;
    }

    /** 회문 판별 (PalindromeTrace와 같은 알고리즘, 추적 출력만 없음) */
    static boolean isPalindrome(String word) {
        int left = 0;
        int right = word.length() - 1;
        while (left < right) {
            if (word.charAt(left) != word.charAt(right)) {
                return false;
            }
            left++;
            right--;
        }
        return true;
    }

    public static void main(String[] args) {
        String notice = "시험 일정 안내 시험 범위 안내 시험 일정 준비 안내 제출 마감 안내";
        String[] words = notice.split(" ");

        System.out.println("공지사항: " + notice);
        System.out.println("단어 수: " + words.length);
        System.out.println();

        List<String> order = new ArrayList<>();
        Map<String, Integer> freq = countFrequencies(words, order);

        System.out.println("== 단어 빈도 (첫 등장 순서) ==");
        for (String word : order) {
            System.out.println("  " + word + " : " + freq.get(word) + "회");
        }

        // entrySet 순회로 전체 등장 횟수를 다시 세어 검증한다
        int total = 0;
        for (Map.Entry<String, Integer> entry : freq.entrySet()) {
            total += entry.getValue();
        }
        System.out.println("  (검증) entrySet 순회로 합산한 전체 단어 수 = " + total);
        System.out.println();

        System.out.println("== 빈도 상위 3개 단어 ==");
        List<String> top3 = topWords(freq, order, 3);
        for (int rank = 0; rank < top3.size(); rank++) {
            String word = top3.get(rank);
            System.out.println("  " + (rank + 1) + "위: " + word + " (" + freq.get(word) + "회)");
        }
        System.out.println();

        System.out.println("== 회문 아이디 검출 ==");
        String[] memberIds = {"ana", "minsu", "level", "kiwi", "noon"};
        for (String id : memberIds) {
            if (isPalindrome(id)) {
                System.out.println("  " + id + " → 회문 아이디입니다!");
            } else {
                System.out.println("  " + id + " → 회문이 아닙니다.");
            }
        }
    }
}

    여러분은 커뮤니티 운영팀의 신입 개발자입니다. 운영팀은 도배성 게시글을 걸러 내기 위해 게시글의 단어 사용 패턴을 보고 싶어 합니다. 구체적으로는 게시글에 어떤 단어가 몇 번씩 나오는지, 두 번 이상 반복된 단어는 무엇인지, 그리고 가장 많이 등장한 단어가 무엇인지를 한 번에 보여 주는 도구가 필요합니다. 단어 수만 개짜리 게시글도 분석해야 하므로, 모든 계산은 오늘 배운 HashMap·HashSet 기반의 O(n) 방식으로 구현하기로 했습니다. 이 도구의 이름은 WordLens — 게시글을 단어 단위로 들여다보는 돋보기입니다.

    프로그램 목표

    게시글 문자열을 단어로 분리한 뒤, ① 단어별 빈도 ② 두 번 이상 등장한 단어 목록 ③ 가장 많이 등장한 단어를 출력하는 콘솔 프로그램을 완성합니다.

    필수 요구사항

    1. splitWords(String post) — 게시글을 split(" ")으로 잘라 단어 배열을 반환한다. (제공됨)
    2. countFrequencies(String[] words) — HashMap과 getOrDefault로 각 단어의 등장 횟수를 센다.
    3. findDuplicates(String[] words) — HashSet의 add 반환값으로 두 번 이상 등장한 단어 목록을 첫 등장 순서대로 만든다. 같은 단어를 목록에 두 번 넣지 않는다.
    4. findMostFrequent(String[] words, Map<String, Integer> freq) — 2강의 최댓값 찾기 패턴으로 가장 많이 등장한 단어를 찾는다.
    5. 단어 빈도는 첫 등장 순서대로, 단어마다 한 번씩만 출력한다.
    6. 세 메서드 모두 배열을 한 번씩만 순회해야 한다 (이중 반복문 금지, O(n) 유지).

    Java WordFrequencySolution.java 
    import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class WordFrequencySolution {

    /** 1단계: 문장을 공백 기준으로 잘라 단어 배열을 만든다. */
    static String[] splitWords(String post) {
        return post.split(" ");
    }

    /** 2단계: HashMap으로 각 단어의 등장 횟수를 센다. O(n) */
    static Map<String, Integer> countFrequencies(String[] words) {
        Map<String, Integer> freq = new HashMap<>();
        for (String word : words) {
            // 처음 보는 단어면 0에서, 이미 본 단어면 지금까지의 횟수에서 1을 더한다
            freq.put(word, freq.getOrDefault(word, 0) + 1);
        }
        return freq;
    }

    /** 3단계: 두 번 이상 등장한 단어 목록을 첫 등장 순서대로 만든다. O(n) */
    static List<String> findDuplicates(String[] words) {
        List<String> duplicates = new ArrayList<>();
        Set<String> seen = new HashSet<>();
        for (String word : words) {
            if (!seen.add(word)) {                 // add가 false = 이미 본 단어 = 중복
                if (!duplicates.contains(word)) {  // 같은 단어를 두 번 넣지 않는다
                    duplicates.add(word);
                }
            }
        }
        return duplicates;
    }

    /** 4단계: 가장 많이 등장한 단어를 찾는다. (2강의 최댓값 찾기 패턴) O(n) */
    static String findMostFrequent(String[] words, Map<String, Integer> freq) {
        String best = null;
        for (String word : words) {
            if (best == null || freq.get(word) > freq.get(best)) {
                best = word;   // 더 자주 등장한 단어를 만나면 갈아 끼운다
            }
        }
        return best;
    }

    public static void main(String[] args) {
        String post = "자바 공부 시작 자바 문법 공부 자바 프로젝트 시작";
        String[] words = splitWords(post);

        System.out.println("게시글: " + post);
        System.out.println("단어 수: " + words.length);
        System.out.println();

        Map<String, Integer> freq = countFrequencies(words);

        System.out.println("== 단어 빈도 ==");
        Set<String> printed = new HashSet<>();
        for (String word : words) {
            if (printed.add(word)) {   // 첫 등장 순서대로 한 번씩만 출력
                System.out.println("  " + word + " : " + freq.getOrDefault(word, 0) + "회");
            }
        }
        System.out.println();

        System.out.println("== 두 번 이상 등장한 단어 ==");
        System.out.println("  " + findDuplicates(words));
        System.out.println();

        String most = findMostFrequent(words, freq);
        System.out.println("== 가장 많이 등장한 단어 ==");
        System.out.println("  " + most + " (" + (most == null ? 0 : freq.getOrDefault(most, 0)) + "회)");
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. countFrequencies의 핵심은 freq.put(word, freq.getOrDefault(word, 0) + 1) 한 줄입니다 — "없으면 0에서 시작"이 오류 카드 2의 NullPointerException을 막아 줍니다.
    2. findDuplicates의 핵심은 !seen.add(word)입니다 — add의 반환값 하나로 "확인"과 "기록"이 동시에 끝나므로 순회 한 번이면 충분합니다.
    3. findMostFrequent는 2강의 최댓값 찾기와 같은 구조입니다. 비교 대상이 "값 자체"가 아니라 "맵에서 꺼낸 빈도"라는 점만 다릅니다. best == null 처리 덕분에 단어 1개짜리 경계 조건도 안전합니다.
    4. 출력의 printed.add(word) 패턴은 "한 번만 출력"을 집합으로 구현한 것 — 중복 확인과 같은 아이디어를 출력 제어에 재활용했습니다.

    복잡도 분석

    • 빈도 계산 O(n), 중복 목록 O(n), 최다 단어 O(n), 출력 O(n) — 전체 평균 O(n).
    • 공간은 맵·집합에 서로 다른 단어를 저장하므로 O(n) — 이중 반복문 버전(시간 O(n²), 공간 O(1))과 정확히 반대의 교환입니다.
    • 같은 작업을 이중 반복문으로 하면 n=100,000일 때 약 50억 번의 비교가 필요합니다 — 제한 조건이 "이중 반복문 금지"인 이유입니다.

    자주 발생하는 오류

    • freq.get(word) + 1로 써서 첫 단어에서 NullPointerException이 나는 경우 (오류 카드 2).
    • findDuplicates에서 duplicates.contains 확인을 빼먹어 "자바"가 목록에 두 번 들어가는 경우 (자바는 3번 등장하므로 중복 감지가 2번 일어납니다).
    • findMostFrequent에서 best를 ""로 초기화하고 freq.get(best)를 호출해 NullPointerException이 나는 경우 — null 초기화 + null 검사가 안전합니다.
    • 단어 비교나 동률 처리에서 ==를 사용한 경우 — 항상 equals!

    다른 해결 방법

    중복 목록을 duplicates.contains(리스트 순회) 대신 두 번째 HashSet으로 확인하면 그 부분도 평균 O(1)이 됩니다. 빈도를 유지하면서 순서도 기억하는 LinkedHashMap을 쓰면 출력용 printed 집합이 필요 없어집니다. 또한 실무에서는 freq.merge(word, 1, Integer::sum)이나 stream 집계도 쓰이지만, 내부에서 일어나는 일은 오늘 직접 구현한 "getOrDefault + 1"과 같습니다 — 원리를 알고 쓰는 것이 중요합니다.

    18확인 퀴즈

    19오늘의 핵심 정리

    • 완전 탐색은 가능한 모든 경우를 확인하는 전략이다 — 느릴 수는 있어도 틀리지 않으므로, 모든 알고리즘 설계의 출발점이자 정확성 검증의 기준이 된다.
    • 중첩 반복문(i 고정, j = i+1부터)은 모든 쌍을 만드는 완전 탐색의 대표 패턴이며, 비교 횟수는 n(n-1)/2번, O(n²)이다.
    • 문자열은 length()와 charAt(i)로 배열처럼 순회하고, 내용 비교는 반드시 equals로 한다 (==는 객체 비교!).
    • 회문 판별은 left·right 두 포인터를 양 끝에서 가운데로 좁히며 비교한다 — 길이 L에 최대 L/2번, O(L).
    • HashMap은 "키 → 값" 저장소로, getOrDefault(key, 0) + 1 패턴이면 문자·단어 빈도를 순회 한 번에 센다. 결과 순회는 entrySet.
    • HashSet은 중복 없는 집합으로, add의 반환값(이미 있으면 false)으로 중복을 한 번의 순회에 찾는다.
    • 해시는 공간 O(n)을 내주고 시간을 O(n²) → 평균 O(n)으로 줄이는 교환이다. 대신 저장 순서를 기억하지 않는다.

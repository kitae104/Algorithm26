스택과 큐를 활용한 작업 처리

Task Processing with Stacks and Queues

자료구조 초급 Java 17+

데이터를 "어떤 순서로 꺼내느냐"는 규칙 하나가 자료구조를 결정합니다. 이번 강의에서는 나중에 넣은 것을 먼저 꺼내는 스택(LIFO)과 먼저 넣은 것을 먼저 꺼내는 큐(FIFO)를 배열로 직접 구현하고, 괄호 짝 검사와 고객 대기열 처리 같은 실제 작업에 적용합니다.

이 강의의 목차

    01강의 소개

    지금까지 우리는 배열에 데이터를 담고(2강), 순회하고(2·3강), 정렬하고(4강), 탐색했습니다(5강). 그런데 실제 프로그램에는 "무엇을 저장하느냐"만큼이나 "어떤 순서로 넣고 꺼내느냐"가 중요한 작업이 많습니다. 문서 편집기의 실행 취소(Ctrl+Z)는 가장 최근 작업부터 되돌리고, 프린터 대기열은 먼저 보낸 문서부터 인쇄합니다.

    이 두 가지 "꺼내는 순서 규칙"이 바로 오늘의 주인공입니다. 나중에 넣은 것을 먼저 꺼내는 스택(Stack, LIFO)과 먼저 넣은 것을 먼저 꺼내는 큐(Queue, FIFO)를 2강에서 배운 배열 위에 직접 구현합니다. 스택으로는 괄호 짝 검사기를, 큐로는 주문·고객 대기열 처리를 만들고, 마지막에는 실행 취소와 대기열 기능을 모두 갖춘 미니 작업 관리기를 완성합니다. 표준 라이브러리 ArrayDeque와, "먼저 온 순서" 대신 "중요한 순서"로 꺼내는 우선순위 큐(PriorityQueue)도 맛보기로 소개합니다.

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 배열과 top 변수로 push, pop, peek, isEmpty를 가진 스택을 구현할 수 있다.

    • 학생은 빈 스택·빈 큐에서 꺼내려는 시도를 검사 코드로 안전하게 처리할 수 있다.
    • 학생은 직접 구현한 스택·큐와 ArrayDeque, PriorityQueue의 용도 차이를 설명할 수 있다.

    04실제 문제 상황

    여러분이 작은 메모 앱을 만드는 개발팀에 합류했다고 상상해 봅시다. 첫 출근 날 세 가지 기능 요청이 기다립니다 — 사용자 입력을 "가장 최근 것부터" 되돌리는 실행 취소(Ctrl+Z), 문의 고객을 "먼저 등록한 순서대로" 응대하는 고객 문의 대기열, 그리고 팀장이 얹은 괄호 짝이 안 맞으면 경고해 주는 기능까지. 세 기능 모두 배열만으로 짜려니 "어디에 넣고 어디서 꺼낼지"가 매번 헷갈립니다. 필요한 것은 꺼내는 순서를 규칙으로 보장하는 데이터 보관함입니다.

    오늘의 핵심 질문

    데이터를 보관했다가 꺼낼 때, "나중에 넣은 것부터"와 "먼저 넣은 것부터" — 두 규칙을 각각 어떤 구조로 구현하고, 어떤 작업에 어느 쪽을 골라야 할까?

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 작은 데이터로 두 가지 작업을 손으로 해 봅니다. 먼저 괄호 검사입니다. 문자열 "([()])"의 괄호 짝이 맞는지, 종이에 괄호를 접시 쌓듯 쌓아 가며 확인해 봅시다.

    작업 1 — 괄호 짝 검사를 손으로

    STEP 1

    왼쪽부터 한 글자씩 읽습니다. 여는 괄호를 만나면 접시 더미 위에 올려놓습니다. '(' → 더미: (. '[' → 더미: ( [. '(' → 더미: ( [ (.

    질문: 왜 여는 괄호를 "위에 쌓아" 두는 걸까요?

    닫는 괄호가 나타났을 때 "가장 최근에 열린 괄호"와 짝을 맞춰야 하기 때문입니다. "([()])"에서 첫 ')'의 짝은 처음의 '('가 아니라 가장 나중에 열린 세 번째 '('입니다. "가장 최근 것"이 항상 맨 위에 있도록 쌓아 두면, 비교할 대상을 꺼내는 일이 "맨 위 접시 들기"만큼 쉬워집니다.

    STEP 2

    네 번째 글자 ')'는 닫는 괄호입니다. 더미 맨 위의 '('를 내려서 짝인지 확인합니다. '('와 ')'는 짝 → 통과. 더미: ( [. 다섯 번째 ']'도 맨 위 '['와 짝 → 통과. 더미: (. 여섯 번째 ')'도 맨 위 '('와 짝 → 통과. 더미: (비어 있음).

    질문: 문자열을 다 읽었을 때 더미가 비어 있다는 것은 무엇을 뜻하나요?

    열린 괄호가 모두 짝을 만나 닫혔다는 뜻입니다. 그래서 "([()])"는 유효합니다. 반대로 "((("처럼 더미에 여는 괄호가 남아 있으면, 끝내 닫히지 못한 괄호가 있다는 뜻이므로 무효입니다.

    STEP 3

    실패하는 경우도 손으로 확인해 봅시다. "())"를 같은 방법으로 검사해 보세요.

    질문: "())"는 몇 번째 글자에서, 왜 실패하나요?

    '(' 쌓기 → ')'가 맨 위 '('와 짝 → 더미가 비었습니다. 그런데 세 번째 ')'가 왔을 때 더미가 비어 있어 내릴 접시가 없습니다. 짝 없는 닫는 괄호 — 즉시 무효 판정입니다. 코드로 옮길 때 이 "빈 더미에서 꺼내려는 시도"를 반드시 검사해야 한다는 것을 기억해 두세요.

    방금 사용한 접시 더미가 바로 스택입니다. 올려놓기가 push, 내리기가 pop — 항상 맨 위에서만 넣고 꺼냈습니다.

    작업 2 — 대기열 처리를 손으로

    STEP 4

    이번에는 카페 주문 줄입니다. 김하늘, 이준호가 차례로 줄을 섭니다. 한 명을 처리한 뒤 박서연이 도착합니다. 줄: 이준호, 박서연.

    질문: 방금 처리된 사람은 누구이고, 박서연은 줄의 어디에 섰나요?

    처리된 사람은 가장 먼저 온 김하늘이고, 박서연은 줄의 맨 뒤에 섰습니다. 넣는 곳(맨 뒤)과 꺼내는 곳(맨 앞)이 서로 다른 쪽 끝이라는 것 — 이것이 스택과의 결정적 차이입니다. 이 구조가 큐이고, 줄 서기가 enqueue, 맨 앞 사람 처리가 dequeue입니다.

    STEP 5

    같은 데이터로 두 규칙을 비교해 봅시다. 김하늘 → 이준호 → 박서연 순서로 넣고, 셋을 모두 꺼냅니다.

    질문: 스택으로 꺼내면 어떤 순서, 큐로 꺼내면 어떤 순서인가요?

    스택(LIFO): 박서연 → 이준호 → 김하늘 (나중에 넣은 사람부터). 큐(FIFO): 김하늘 → 이준호 → 박서연 (먼저 넣은 사람부터). 저장하는 데이터는 같아도 꺼내는 규칙이 결과 순서를 완전히 바꿉니다. 실행 취소에는 스택이, 대기열에는 큐가 맞는 이유입니다.

    06핵심 개념

    자료구조 = 데이터 + 규칙

    자료구조는 데이터를 담는 그릇과, 그 그릇을 다루는 규칙의 묶음입니다. 스택과 큐는 저장 공간으로 똑같이 배열을 쓸 수 있습니다. 다른 것은 규칙뿐입니다 — 어디에 넣고, 어디서 꺼내는가. 규칙을 좁게 제한한 대가로, 남은 연산들은 전부 O(1)로 빨라지고 코드의 의도가 분명해집니다.

    스택 (Stack) — LIFO

    스택은 한쪽 끝(맨 위, top)에서만 넣고 꺼내는 구조입니다. 나중에 들어간 데이터가 먼저 나오므로 LIFO(Last-In, First-Out, 후입선출)라고 부릅니다. 접시 더미, 브라우저 뒤로 가기, 실행 취소, 그리고 7강에서 배울 메서드 호출 스택이 모두 스택입니다.

    연산하는 일배열 구현에서는시간
    push(v)맨 위에 v를 올린다top을 1 올리고 stack[top] = vO(1)
    pop()맨 위 값을 꺼내 제거한다stack[top]을 읽고 top을 1 내림O(1)
    peek()맨 위 값을 보기만 한다stack[top] 읽기 (top 유지)O(1)
    isEmpty()비었는지 확인한다top == -1 인지 검사O(1)

    top은 "맨 위 칸의 인덱스"입니다. 비어 있을 때는 가리킬 칸이 없으므로 top = -1을 "비어 있음"의 약속으로 정합니다. 쌓인 개수는 언제나 top + 1입니다.

    큐 (Queue) — FIFO

    큐는 뒤(rear)로 넣고 앞(front)에서 꺼내는 구조입니다. 먼저 들어간 데이터가 먼저 나오므로 FIFO(First-In, First-Out, 선입선출)라고 부릅니다. 카페 주문 줄, 프린터 대기열, 고객센터 상담 순번, 그리고 8·9강에서 배울 레벨 순회·BFS가 모두 큐를 사용합니다.

    연산하는 일배열 구현에서는시간
    enqueue(v)맨 뒤에 v를 세운다queue[rear] = v 후 rear를 1 올림O(1)
    dequeue()맨 앞 값을 꺼내 제거한다queue[front]를 읽고 front를 1 올림O(1)
    peek()맨 앞 값을 보기만 한다queue[front] 읽기 (front 유지)O(1)
    isEmpty()비었는지 확인한다front == rear 인지 검사O(1)

    front는 "다음에 꺼낼 자리", rear는 "다음에 넣을 자리"입니다. 두 값이 같으면 꺼낼 것이 없다는 뜻 — front == rear가 "비어 있음"의 약속이고, 대기 중인 개수는 rear - front입니다.

    스택 vs 큐 — 한눈에 비교

    구분스택큐
    규칙LIFO (후입선출)FIFO (선입선출)
    넣는 곳맨 위 (top)맨 뒤 (rear)
    꺼내는 곳맨 위 (top) — 같은 쪽맨 앞 (front) — 반대쪽
    상태 변수top 하나 (-1이면 빈 스택)front, rear 둘 (같으면 빈 큐)
    대표 용도실행 취소, 괄호 검사, 호출 스택(7강)대기열, 작업 순서 처리, BFS(9강)

    표준 라이브러리는? — Deque와 ArrayDeque (비교 소개)

    실무 Java에서는 스택과 큐 둘 다 java.util.Deque 인터페이스의 구현체 ArrayDeque를 주로 씁니다. Deque(덱)는 양쪽 끝에서 넣고 꺼낼 수 있는 구조라 한쪽만 쓰면 스택, 반대쪽으로 흘리면 큐가 됩니다.

    • 스택처럼: push(v) / pop() / peek()
    • 큐처럼: offer(v)(뒤에 넣기) / poll()(앞에서 꺼내기) / peek()
    • pop()은 비어 있으면 예외를 던지고, poll()은 null을 반환합니다.
    • 옛날 클래스 java.util.Stack도 있지만, 불필요한 동기화 비용 때문에 공식 문서도 ArrayDeque 사용을 권장합니다.

    오늘은 동작 원리를 이해하기 위해 배열로 직접 구현하고, 완성 코드에서 직접 구현과 ArrayDeque의 결과가 같은지 비교만 합니다.

    우선순위 큐 (PriorityQueue) 기초 — 세 번째 규칙 맛보기

    "먼저 온 순서"도 "나중에 온 순서"도 아닌 "중요한 순서"로 꺼내야 할 때가 있습니다. 응급실은 도착 순서가 아니라 위급한 환자부터 진료합니다. java.util.PriorityQueue는 offer로 넣고 poll로 꺼내는 모양은 큐와 같지만, poll이 항상 우선순위가 가장 높은 값을 돌려줍니다. 내부적으로 힙(heap)이라는 구조를 써서 넣고 꺼내기가 각각 O(log n)입니다. 오늘은 응용 예제에서 맛만 보고, 10강 그리디와 12강 최단 경로에서 핵심 도구로 다시 만납니다.

    시각화 2 — 큐로 주문 대기열 처리

    enqueue는 항상 뒤(rear)에, dequeue는 항상 앞(front)에서 일어납니다. 중간에 새 손님이 와도(enqueue) 처리 순서는 온 순서 그대로임을 확인하세요.

    두 시각화 모두 각 단계에서 연산 횟수를 함께 셉니다. 문자·손님 하나당 push/pop 또는 enqueue/dequeue가 최대 1번씩 — 데이터가 n개면 전체 작업이 O(n)이라는 것을 눈으로 확인할 수 있습니다.

    08의사코드

    코드를 쓰기 전에, 배열 위의 두 규칙과 괄호 검사 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo 배열 스택의 네 가지 연산 
    준비: 배열 stack, top ← -1          // top = 맨 위 칸의 인덱스, -1이면 빈 스택

push(v):
    top ← top + 1                    // 맨 위 자리를 한 칸 올리고
    stack[top] ← v                   // 그 자리에 넣는다

pop():
    top = -1 이면 "빈 스택 오류"      // 꺼내기 전에 반드시 검사!
    v ← stack[top]                   // 맨 위 값을 읽고
    top ← top - 1                    // 맨 위 자리를 한 칸 내린다
    v를 반환한다

peek():
    top = -1 이면 "빈 스택 오류"
    stack[top]을 반환한다             // top은 그대로 둔다

isEmpty():
    top = -1 인지를 반환한다
    Pseudo 배열 큐의 네 가지 연산 
    준비: 배열 queue, front ← 0, rear ← 0
      // front = 다음에 꺼낼 자리, rear = 다음에 넣을 자리, 같으면 빈 큐

enqueue(v):
    queue[rear] ← v                  // 맨 뒤 자리에 넣고
    rear ← rear + 1                  // 다음에 넣을 자리를 한 칸 뒤로

dequeue():
    front = rear 이면 "빈 큐 오류"    // 꺼내기 전에 반드시 검사!
    v ← queue[front]                 // 맨 앞 값을 읽고
    front ← front + 1                // 다음에 꺼낼 자리를 한 칸 뒤로
    v를 반환한다

peek():
    front = rear 이면 "빈 큐 오류"
    queue[front]를 반환한다           // front는 그대로 둔다

isEmpty():
    front = rear 인지를 반환한다

    구현 3단계 — pop과 peek, 그리고 예외 처리

    꺼내는 연산을 추가합니다. pop은 맨 위 값을 읽고 top을 한 칸 내리고, peek는 읽기만 하고 top을 그대로 둡니다. 중요한 것은 빈 스택 검사입니다 — top이 -1인데 stack[top]을 읽으면 프로그램이 예외로 죽습니다. 손 풀이 STEP 3의 "빈 더미에서 접시 내리기" 상황을 isEmpty() 검사로 막습니다.

    Java Step3StackPopPeek.java 
    public class Step3StackPopPeek {

    static char[] stack = new char[8];
    static int top = -1;

    /** 비었는지 검사: pop과 peek 전에 반드시 필요하다 */
    static boolean isEmpty() {
        return top == -1;
    }

    static void push(char value) {
        top++;
        stack[top] = value;
    }

    /** peek: 맨 위 값을 "보기만" 한다. top은 그대로 유지된다. */
    static char peek() {
        if (isEmpty()) {
            System.out.println("경고: 빈 스택은 peek할 수 없습니다.");
            return '?';
        }
        return stack[top];
    }

    /** pop: 맨 위 값을 꺼내고 top을 한 칸 내린다. */
    static char pop() {
        if (isEmpty()) {
            System.out.println("경고: 빈 스택은 pop할 수 없습니다.");
            return '?';
        }
        char value = stack[top];
        top--;
        return value;
    }

    public static void main(String[] args) {
        push('(');
        push('[');
        System.out.println("push 2번 후 개수 = " + (top + 1));

        System.out.println("peek() = " + peek() + " (top은 그대로 " + top + ")");
        System.out.println("pop()  = " + pop() + " (pop 후 top = " + top + ")");
        System.out.println("pop()  = " + pop() + " (pop 후 top = " + top + ")");
        System.out.println("비어 있는가? = " + isEmpty());

        // 비어 있는데 또 pop하면? isEmpty 검사 덕분에 프로그램이 죽지 않는다
        System.out.println("pop()  = " + pop());
    }
}

    구현 4단계 — 스택 응용 완성: 괄호 짝 검사

    이제 스택을 실전에 투입합니다. 3강의 문자열 순회로 한 글자씩 읽으며, 여는 괄호면 push, 닫는 괄호면 pop해서 짝을 비교합니다. 의사코드의 무효 판정 세 갈래가 코드의 return false 두 곳과 마지막 return isEmpty()에 그대로 대응합니다.

    Java Step4BracketCheckLoop.java 
    public class Step4BracketCheckLoop {

    static char[] stack = new char[100];
    static int top = -1;

    static boolean isEmpty() { return top == -1; }
    static void push(char value) { stack[++top] = value; }
    static char pop() { return stack[top--]; }

    /** 여는 괄호 open과 닫는 괄호 close가 서로 짝인지 확인한다 */
    static boolean isPair(char open, char close) {
        return (open == '(' && close == ')')
                || (open == '[' && close == ']')
                || (open == '{' && close == '}');
    }

    /** 괄호 문자열이 유효한지 검사한다 */
    static boolean isValid(String text) {
        top = -1;   // 검사를 시작하기 전에 스택을 비운다

        for (int i = 0; i < text.length(); i++) {
            char ch = text.charAt(i);

            if (ch == '(' || ch == '[' || ch == '{') {
                push(ch);                     // 여는 괄호: 스택에 쌓는다
            } else if (ch == ')' || ch == ']' || ch == '}') {
                if (isEmpty()) {
                    return false;             // 짝이 없는 닫는 괄호
                }
                if (!isPair(pop(), ch)) {
                    return false;             // 종류가 다른 괄호끼리 만남
                }
            }
        }
        // 루프가 끝난 뒤 스택이 비어 있어야 진짜 유효 (여는 괄호가 남으면 무효)
        return isEmpty();
    }

    public static void main(String[] args) {
        String[] tests = {"()", "([])", "{[()]}", "(]", "())", "((("};
        for (String t : tests) {
            System.out.println(t + " -> " + (isValid(t) ? "유효" : "무효"));
        }
    }
}

    ++top과 top-- 를 한 줄로 줄였습니다

    stack[++top] = value는 "top을 먼저 1 올린 뒤 그 자리에 넣기", stack[top--]는 "지금 top 자리를 읽은 뒤 top을 1 내리기"입니다. 2·3단계의 두 줄짜리 push/pop과 완전히 같은 동작을 한 줄로 쓴 것입니다. 순서를 바꿔 stack[top++]로 쓰면 엉뚱한 칸에 넣게 되니 주의하세요.

    구현 5단계 — 큐의 재료와 enqueue

    이번에는 큐입니다. 재료는 배열 하나와 변수 둘 — 다음에 꺼낼 자리 front, 다음에 넣을 자리 rear. 스택은 top 하나로 충분했지만, 큐는 넣는 곳과 꺼내는 곳이 다르므로 둘 다 필요합니다. enqueue는 push와 닮았지만 rear 쪽에서만 일어납니다.

    Java Step5QueueEnqueue.java 
    public class Step5QueueEnqueue {

    static String[] queue = new String[8];   // 대기 이름을 담을 공간 (용량 8)
    static int front = 0;                    // 다음에 꺼낼 자리 (맨 앞)
    static int rear = 0;                     // 다음에 넣을 자리 (맨 뒤)

    /** enqueue: rear 자리에 값을 넣고, rear를 한 칸 뒤로 옮긴다 */
    static void enqueue(String name) {
        queue[rear] = name;
        rear++;
        System.out.println("enqueue \"" + name + "\" -> front = " + front
                + ", rear = " + rear + ", 대기 " + (rear - front) + "명");
    }

    public static void main(String[] args) {
        System.out.println("시작: front = " + front + ", rear = " + rear + " (비어 있음)");

        enqueue("김하늘");
        enqueue("이준호");
        enqueue("박서연");

        // 맨 앞(front)부터 맨 뒤(rear 직전)까지 순서대로 확인한다
        StringBuilder state = new StringBuilder();
        for (int i = front; i < rear; i++) {
            if (i > front) state.append(' ');
            state.append(queue[i]);
        }
        System.out.println("대기열 상태(앞 -> 뒤): " + state);
        System.out.println("맨 앞(front)의 값 = " + queue[front]);
    }
}

    단순 배열 큐의 한계 — 앞 공간의 낭비

    dequeue를 하면 front만 뒤로 이동하고, queue[0], queue[1] 같은 앞 칸은 다시 쓰이지 않습니다. 데이터가 많으면 배열 앞쪽이 계속 버려지는 셈입니다. 실무에서는 인덱스가 끝에 닿으면 처음으로 되돌아가는 원형 큐로 해결하며 (rear = (rear + 1) % 용량), ArrayDeque가 내부적으로 이 방식을 씁니다. 오늘은 원리 이해를 위해 단순 버전을 유지합니다.

    10완성 Java 코드

    지금까지의 조각을 모아 하나의 프로그램으로 완성합니다. 스택과 큐를 각각 독립된 클래스(ArrayCharStack, ArrayStringQueue)로 묶고, 3단계의 "경고 출력" 대신 예외를 던지는 방식으로 바꿔 라이브러리처럼 만들었습니다. 괄호 검사는 직접 구현한 스택과 표준 라이브러리 ArrayDeque 두 방식으로 풀어 결과가 항상 같은지 검증하고, 주문 대기열은 직접 구현한 배열 큐로 처리한 뒤 같은 작업을 ArrayDeque로도 해 봅니다.

    Java StackQueueComplete.java 
    import java.util.ArrayDeque;
import java.util.Deque;

public class StackQueueComplete {

    /** 배열로 직접 구현한 문자 스택 — "자료구조 = 데이터(배열) + 규칙(LIFO)" */
    static class ArrayCharStack {
        private char[] data;
        private int top = -1;

        ArrayCharStack(int capacity) {
            data = new char[capacity];
        }

        boolean isEmpty() {
            return top == -1;
        }

        int size() {
            return top + 1;
        }

        void push(char value) {
            if (top == data.length - 1) {
                throw new IllegalStateException("스택이 가득 찼습니다.");
            }
            data[++top] = value;
        }

        char pop() {
            if (isEmpty()) {
                throw new IllegalStateException("빈 스택에서는 pop할 수 없습니다.");
            }
            return data[top--];
        }

        char peek() {
            if (isEmpty()) {
                throw new IllegalStateException("빈 스택에서는 peek할 수 없습니다.");
            }
            return data[top];
        }
    }

    /** 배열로 직접 구현한 문자열 큐 — "자료구조 = 데이터(배열) + 규칙(FIFO)" */
    static class ArrayStringQueue {
        private String[] data;
        private int front = 0;   // 다음에 꺼낼 자리
        private int rear = 0;    // 다음에 넣을 자리

        ArrayStringQueue(int capacity) {
            data = new String[capacity];
        }

        boolean isEmpty() {
            return front == rear;
        }

        int size() {
            return rear - front;
        }

        void enqueue(String value) {
            if (rear == data.length) {
                throw new IllegalStateException("큐가 가득 찼습니다.");
            }
            data[rear++] = value;
        }

        String dequeue() {
            if (isEmpty()) {
                throw new IllegalStateException("빈 큐에서는 dequeue할 수 없습니다.");
            }
            return data[front++];
        }

        String peek() {
            if (isEmpty()) {
                throw new IllegalStateException("빈 큐에서는 peek할 수 없습니다.");
            }
            return data[front];
        }

        /** 앞(front)부터 뒤(rear 직전)까지의 대기 상태 문자열 */
        String state() {
            if (isEmpty()) {
                return "(비어 있음)";
            }
            StringBuilder sb = new StringBuilder("[");
            for (int i = front; i < rear; i++) {
                if (i > front) sb.append(", ");
                sb.append(data[i]);
            }
            return sb.append("]").toString();
        }
    }

    /** 여는 괄호 open과 닫는 괄호 close가 서로 짝인지 확인한다 */
    static boolean isPair(char open, char close) {
        return (open == '(' && close == ')')
                || (open == '[' && close == ']')
                || (open == '{' && close == '}');
    }

    /** 방법 A: 직접 만든 배열 스택으로 괄호 검사 */
    static boolean isValidWithArrayStack(String text) {
        ArrayCharStack stack = new ArrayCharStack(text.length());
        for (int i = 0; i < text.length(); i++) {
            char ch = text.charAt(i);
            if (ch == '(' || ch == '[' || ch == '{') {
                stack.push(ch);
            } else if (ch == ')' || ch == ']' || ch == '}') {
                if (stack.isEmpty() || !isPair(stack.pop(), ch)) {
                    return false;
                }
            }
        }
        return stack.isEmpty();
    }

    /** 방법 B: 표준 라이브러리 ArrayDeque로 괄호 검사 — 실무 권장 방식 */
    static boolean isValidWithDeque(String text) {
        Deque<Character> stack = new ArrayDeque<>();
        for (int i = 0; i < text.length(); i++) {
            char ch = text.charAt(i);
            if (ch == '(' || ch == '[' || ch == '{') {
                stack.push(ch);                       // 스택처럼 사용: 맨 앞에 쌓는다
            } else if (ch == ')' || ch == ']' || ch == '}') {
                if (stack.isEmpty() || !isPair(stack.pop(), ch)) {
                    return false;
                }
            }
        }
        return stack.isEmpty();
    }

    public static void main(String[] args) {
        System.out.println("== 1) 괄호 유효성 검사: 직접 구현 스택 vs ArrayDeque ==");
        String[] tests = {"()", "{[()]}", "(a+b)*[c]", "(]", "())", "((("};
        for (String t : tests) {
            boolean a = isValidWithArrayStack(t);
            boolean b = isValidWithDeque(t);
            System.out.println(t + " -> " + (a ? "유효" : "무효")
                    + " (두 방식 일치 = " + (a == b) + ")");
        }

        System.out.println();
        System.out.println("== 2) 직접 구현한 배열 큐로 주문 대기열 처리 (FIFO) ==");
        ArrayStringQueue orders = new ArrayStringQueue(8);
        orders.enqueue("김하늘");                       // 뒤(rear)에 넣는다
        orders.enqueue("이준호");
        orders.enqueue("박서연");
        System.out.println("대기열: " + orders.state() + " (대기 " + orders.size() + "명)");
        System.out.println("맨 앞(peek) = " + orders.peek());
        while (!orders.isEmpty()) {
            System.out.println("처리: " + orders.dequeue() + " -> 남은 대기열 " + orders.state());
        }

        System.out.println();
        System.out.println("== 3) 같은 대기열을 표준 라이브러리 ArrayDeque로 (실무 권장) ==");
        Deque<String> queue = new ArrayDeque<>();
        queue.offer("김하늘");                          // 큐처럼 사용: 뒤에 넣는다
        queue.offer("이준호");
        queue.offer("박서연");
        System.out.println("대기열: " + queue);
        while (!queue.isEmpty()) {

        }
        System.out.println("빈 큐에서 poll() = " + queue.poll() + " (null 반환, 예외 없음)");
    }

    괄호 검사가 정말 시각화(7번 섹션)와 똑같이 동작하는지, 문자 하나를 처리할 때마다 (문자, 동작, 스택 상태)를 출력해 확인합니다. 손으로 풀었던 "([()])"와, 실패의 두 갈래인 "(()", "())"를 추적합니다.

    Java BracketCheckTrace.java 
    import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Iterator;

public class BracketCheckTrace {

    static boolean isPair(char open, char close) {
        return (open == '(' && close == ')')
                || (open == '[' && close == ']')
                || (open == '{' && close == '}');
    }

    /** 스택 내용을 바닥 -> 꼭대기 순서의 문자열로 만든다 */
    static String stackState(Deque<Character> stack) {
        if (stack.isEmpty()) {
            return "(비어 있음)";
        }
        // ArrayDeque의 push는 앞쪽에 쌓이므로, 바닥부터 보려면 거꾸로 순회한다
        StringBuilder sb = new StringBuilder();
        Iterator<Character> it = stack.descendingIterator();
        while (it.hasNext()) {
            sb.append(it.next());
            if (it.hasNext()) sb.append(' ');
        }
        return sb.toString();
    }

    /** 한 문자씩 처리하며 (문자, 동작, 스택 상태)를 추적 출력한다 */
    static void trace(String text) {
        System.out.println("입력: \"" + text + "\"");
        Deque<Character> stack = new ArrayDeque<>();
        boolean failed = false;

        for (int i = 0; i < text.length() && !failed; i++) {
            char ch = text.charAt(i);
            String action;

            if (ch == '(' || ch == '[' || ch == '{') {
                stack.push(ch);
                action = "push '" + ch + "'";
            } else if (stack.isEmpty()) {
                action = "실패! 짝이 없는 닫는 괄호";
                failed = true;
            } else {
                char open = stack.pop();
                if (isPair(open, ch)) {
                    action = "pop '" + open + "' (짝 맞음)";
                } else {
                    action = "실패! '" + open + "'와 짝이 아님";
                    failed = true;
                }
            }
            System.out.println("  " + i + "번째 문자 '" + ch + "' : " + action
                    + " -> 스택: " + stackState(stack));
        }

        if (failed) {
            System.out.println("  검사 중단 -> 무효한 괄호");
        } else if (stack.isEmpty()) {
            System.out.println("  검사 종료: 스택이 비어 있음 -> 유효한 괄호");
        } else {
            System.out.println("  검사 종료: 스택에 " + stackState(stack)
                    + " 남음 -> 무효 (여는 괄호가 남음)");
        }
        System.out.println();
    }

    public static void main(String[] args) {
        trace("([()])");   // 성공 사례
        trace("(()");      // 실패 사례 1: 여는 괄호가 남는다
        trace("())");      // 실패 사례 2: 닫는 괄호의 짝이 없다
    }
}

    12잘못된 코드와 오류 찾기

    초보자가 스택·큐에서 자주 만드는 오류 두 가지를 직접 찾아봅시다. 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 빈 스택 검사 없이 pop하는 괄호 검사

    Java BuggyBracketPop.java (오류 있음) 
    public class BuggyBracketPop {

    static char[] stack = new char[100];
    static int top = -1;

    static void push(char value) { stack[++top] = value; }
    static char pop() { return stack[top--]; }

    /** 여는 괄호 open과 닫는 괄호 close가 서로 짝인지 확인한다 */
    static boolean isPair(char open, char close) {
        return (open == '(' && close == ')')
                || (open == '[' && close == ']')
                || (open == '{' && close == '}');
    }

    static boolean isValid(String text) {
        top = -1;
        for (int i = 0; i < text.length(); i++) {
            char ch = text.charAt(i);
            if (ch == '(' || ch == '[' || ch == '{') {
                push(ch);
            } else if (ch == ')' || ch == ']' || ch == '}') {
                if (!isPair(pop(), ch)) {   // 닫는 괄호: 바로 pop해서 비교한다
                    return false;
                }
            }
        }
        return top == -1;
    }

    public static void main(String[] args) {
        System.out.println("() -> " + isValid("()"));
        System.out.println("()) -> " + isValid("())"));
    }
}

    원인: 닫는 괄호를 만났을 때 스택이 비었는지 확인하지 않고 바로 pop()을 호출했습니다. top이 -1인 상태에서 stack[top--]은 stack[-1]을 읽으므로 ArrayIndexOutOfBoundsException이 발생합니다. 손 풀이 STEP 3의 "빈 더미에서 접시 내리기"가 바로 이 상황입니다.

    if (top == -1) {          // 빈 스택 검사가 pop보다 먼저!
        return false;         // 짝 없는 닫는 괄호 → 무효
    }
    if (!isPair(pop(), ch)) {
        return false;

}

    public class BuggyQueueFront {

    static int rear = 0;

    발생하는 문제: 세 명을 처리했는데 전부 같은 사람이고, 대기 인원도 줄지 않습니다.

    1번째 처리: 김하늘
2번째 처리: 김하늘
3번째 처리: 김하늘
남은 대기 인원 = 3

    오류가 나타나는 입력: dequeue를 2번 이상 호출하는 모든 경우. 예외가 나지 않고 조용히 틀린 결과가 나오므로 오류 1보다 발견하기 어렵습니다.

    원인: dequeue()가 queue[front] 값을 돌려주기만 하고 front를 한 칸 뒤로 옮기지 않았습니다. "꺼낸다"는 것은 값 읽기 + 자리 이동, 두 동작의 묶음입니다. 줄 맨 앞 손님이 주문만 하고 비켜 주지 않는 것과 같습니다.

    수정 방법: 값을 읽은 뒤 front를 이동합니다 (빈 큐 검사도 함께).

    static String dequeue() {
    if (front == rear) {
        System.out.println("경고: 빈 큐는 dequeue할 수 없습니다.");
        return "?";
    }
    String value = queue[front];
    front++;                  // 맨 앞 자리를 한 칸 뒤로 — 이 줄이 핵심!
    return value;
}

    수정 후 출력은 김하늘 → 이준호 → 박서연 순서가 되고, 남은 대기 인원은 0명이 됩니다. 스택에서 top--를 빼먹는 실수도 완전히 같은 유형입니다.

    13복잡도 및 특성 분석

    입력 크기

    괄호 검사에서 n은 문자열의 길이, 대기열 처리에서 n은 처리할 데이터(고객·작업)의 수입니다.

    주요 연산

    스택은 push/pop, 큐는 enqueue/dequeue가 핵심 연산입니다. 네 연산 모두 배열 인덱스 한 칸을 읽거나 쓰고 변수 하나를 1 움직일 뿐입니다 — 반복문이 없습니다.

    작업최선평균최악Big-O
    push / pop / peek / isEmpty1번1번1번O(1)
    enqueue / dequeue / peek / isEmpty1번1번1번O(1)
    괄호 검사 (길이 n)1번 비교*-문자당 push/pop 1번씩O(n)
    대기열 n명 전체 처리n번n번n번O(n)

    * 괄호 검사의 최선은 첫 글자가 닫는 괄호인 경우("()"의 짝이 없는 ")(" 등) — 빈 스택 검사에서 즉시 무효로 조기 중단합니다. 1강에서 본 조기 중단 패턴 그대로입니다. 유효한 문자열은 항상 끝까지 읽어야 하므로 n번 처리합니다.

    공간 복잡도

    괄호 검사의 스택은 최악의 경우("((((...") 문자열의 모든 글자를 담을 수 있어야 하므로 O(n), 대기열도 n명이 모두 줄을 서면 O(n)입니다. top, front, rear 같은 관리 변수는 O(1)입니다.

    알고리즘 특성

    • 규칙의 대가로 얻는 속도: "맨 위/맨 앞만 만진다"는 제한 덕분에 모든 기본 연산이 O(1)입니다. 배열 중간 삽입·삭제가 O(n)이었던 것(2강)과 비교해 보세요.
    • 단순 배열 큐의 공간 낭비: front가 지나간 앞 칸은 재사용되지 않습니다. 원형 큐(인덱스를 % 용량으로 순환)로 해결하며, ArrayDeque가 이 방식입니다.
    • 용량의 한계: 배열 기반이므로 가득 차면 push/enqueue가 실패합니다. 완성 코드는 예외를 던지고, ArrayDeque는 내부 배열을 자동으로 키웁니다.
    • 우선순위 큐와의 비교: PriorityQueue는 "중요한 순서"를 보장하는 대신 offer/poll이 O(log n)입니다. 순서 규칙이 복잡해질수록 연산 비용이 커지는 교환 관계입니다.

    15실제 데이터 응용 예제

    문제 상황

    은행 지점의 창구 호출 시스템을 만듭니다. 고객은 접수 번호를 받아 대기열에 등록되고, 창구는 기본적으로 도착 순서대로(FIFO) 한 명씩 호출합니다. 그런데 지점장이 요구를 추가했습니다 — "VIP 고객을 먼저, 같은 등급이면 접수 번호 순으로." 도착 순서가 아니라 우선순위가 기준이 되는 순간, 일반 큐로는 부족해집니다.

    데이터 모델과 자료구조 선택 기준

    • 데이터: 고객 Customer = 이름, 접수 번호(ticketNo), VIP 여부(vip)
    • 방식 A (일반 큐): 도착 순서 = 처리 순서가 규칙일 때 — ArrayDeque, offer/poll O(1)
    • 방식 B (우선순위 큐): "중요한 순서"가 규칙일 때 — PriorityQueue + Comparator(VIP 먼저, 같으면 번호 순), offer/poll O(log n)
    Java BankQueueApplication.java 
    import java.util.ArrayDeque;
import java.util.Comparator;
import java.util.PriorityQueue;
import java.util.Queue;

public class BankQueueApplication {

    /** 은행 고객: 이름, 접수 번호, VIP 여부 */
    static class Customer {
        String name;
        int ticketNo;
        boolean vip;

        Customer(String name, int ticketNo, boolean vip) {
            this.name = name;
            this.ticketNo = ticketNo;
            this.vip = vip;
        }

        @Override
        public String toString() {
            return name + "(" + ticketNo + "번" + (vip ? ", VIP" : "") + ")";
        }
    }

    public static void main(String[] args) {
        Customer[] arrivals = {
                new Customer("김하늘", 1, false),
                new Customer("이준호", 2, false),
                new Customer("박서연", 3, true),
                new Customer("최민재", 4, false),
                new Customer("정다은", 5, true)
        };

        System.out.println("== 방식 A: 일반 큐 — 도착 순서 = 처리 순서 (FIFO) ==");
        Queue<Customer> queue = new ArrayDeque<>();
        for (Customer c : arrivals) {
            queue.offer(c);
            System.out.println("접수: " + c + " -> 대기 " + queue.size() + "명");
        }
        int orderA = 1;
        while (!queue.isEmpty()) {
            System.out.println(orderA + "번째 창구 호출: " + queue.poll());
            orderA++;
        }

        System.out.println();
        System.out.println("== 방식 B: 우선순위 큐 맛보기 — VIP 먼저, 같은 등급은 접수 번호 순 ==");
        PriorityQueue<Customer> priorityQueue = new PriorityQueue<>(
                Comparator.comparing((Customer c) -> !c.vip)   // VIP(false가 앞)부터
                          .thenComparing(c -> c.ticketNo));    // 같은 등급이면 번호 순
        for (Customer c : arrivals) {
            priorityQueue.offer(c);
        }
        int orderB = 1;
        while (!priorityQueue.isEmpty()) {
            System.out.println(orderB + "번째 창구 호출: " + priorityQueue.poll());
            orderB++;
        }

        System.out.println();
        System.out.println("일반 큐는 '들어온 순서', 우선순위 큐는 '중요한 순서'로 꺼낸다. (10강에서 자세히)");
    }
}

    • 방식 A는 도착 순서 1→2→3→4→5 그대로 호출합니다. offer/poll이 각각 O(1), n명 전체 처리는 O(n)입니다.
    • 방식 B는 VIP(박서연 3번, 정다은 5번)를 먼저, 그다음 일반 고객을 번호 순으로 호출합니다. 순서를 정하는 기준은 Comparator.comparing((Customer c) -> !c.vip) — false가 true보다 앞이므로 VIP(!vip == false)가 먼저 나오고, thenComparing이 동률(같은 등급)을 접수 번호로 정렬합니다. 4강의 Comparator가 여기서 다시 쓰였습니다.

    • 같은 문제라도 정책(규칙)이 자료구조를 결정합니다 — 도착 순서면 큐, 되돌리기면 스택, 중요도 순이면 우선순위 큐.

    정답 코드와 해설 확인
    Java TaskManagerSolution.java 
    import java.util.ArrayDeque;
import java.util.Deque;

public class TaskManagerSolution {

    /** 문서 내용 (type한 글자들이 이어 붙는다) */
    static StringBuilder document = new StringBuilder();

    /** 실행 취소용 스택: 가장 최근에 입력한 문자열이 맨 위에 온다 (LIFO) */
    static Deque<String> undoStack = new ArrayDeque<>();

    /** 고객 대기열 큐: 먼저 등록한 고객이 먼저 나간다 (FIFO) */
    static Deque<String> waitQueue = new ArrayDeque<>();

    /** 명령 1: text를 문서 끝에 붙이고, 취소할 수 있도록 스택에 기록한다. */
    static void type(String text) {
        document.append(text);
        undoStack.push(text);           // 가장 최근 입력이 맨 위로
        System.out.println("[type] \"" + text + "\" 입력 -> 문서 = \"" + document + "\"");
    }

    /** 명령 2: 가장 최근에 입력한 내용을 취소한다. */
    static void undo() {
        if (undoStack.isEmpty()) {      // 빈 스택 검사가 반드시 먼저!
            System.out.println("[undo] 취소할 입력이 없습니다");
            return;
        }
        String last = undoStack.pop();  // 가장 최근 입력부터 취소 (LIFO)
        document.delete(document.length() - last.length(), document.length());
        System.out.println("[undo] \"" + last + "\" 입력 취소 -> 문서 = \"" + document + "\"");
    }

    /** 명령 3: 고객을 대기열 뒤에 등록한다. */
    static void enqueue(String name) {
        waitQueue.offer(name);          // 뒤(rear)에 넣는다
        System.out.println("[enqueue] " + name + " 님 등록 -> 대기 " + waitQueue.size() + "명");
    }

    /** 명령 4: 대기열 맨 앞 고객의 응대를 시작한다. */
    static void serve() {
        if (waitQueue.isEmpty()) {      // 빈 큐 검사가 반드시 먼저!
            System.out.println("[serve] 대기 중인 고객이 없습니다");
            return;
        }
        String name = waitQueue.poll(); // 앞(front)에서 꺼낸다 (FIFO)
        System.out.println("[serve] " + name + " 님 응대 시작 -> 남은 대기 " + waitQueue.size() + "명");
    }

    public static void main(String[] args) {
        String[] commands = {
                "type:안녕",
                "type:하세요",
                "enqueue:김하늘",
                "type:!!",
                "undo",
                "enqueue:이준호",
                "serve",
                "serve",
                "serve",
                "undo",
                "undo",
                "undo"
        };

        for (String command : commands) {
            if (command.startsWith("type:")) {
                type(command.substring(5));
            } else if (command.equals("undo")) {
                undo();
            } else if (command.startsWith("enqueue:")) {
                enqueue(command.substring(8));
            } else if (command.equals("serve")) {
                serve();
            }
        }

        System.out.println();
        System.out.println("== 최종 상태 ==");
        System.out.println("문서 내용 = \"" + document + "\"");
        System.out.println("남은 대기 고객 = " + waitQueue.size() + "명 " + waitQueue);
        System.out.println("취소 가능한 입력 = " + undoStack.size() + "개");
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. type은 문서에 append + 스택에 push — "작업을 하면서 되돌릴 기록을 함께 남긴다"는 실행 취소 기능의 기본 패턴입니다.
    2. undo의 핵심은 LIFO입니다 — pop은 항상 가장 최근 입력을 돌려주므로, "!!" → "하세요" → "안녕" 순서(입력의 역순)로 취소됩니다. 지울 범위는 document.length() - last.length()부터 끝까지입니다.
    3. enqueue/serve의 핵심은 FIFO입니다 — offer는 뒤에 넣고 poll은 앞에서 꺼내므로 김하늘(먼저 등록)이 이준호보다 먼저 응대됩니다.
    4. 네 메서드 모두에서 꺼내기 전 빈 검사(isEmpty)가 예외를 막습니다 — 세 번째 serve와 네 번째 undo가 안내 메시지로 안전하게 처리되는 이유입니다.

    복잡도 분석

    • 명령 1개 처리: push/pop/offer/poll 모두 O(1). (undo의 delete는 지우는 길이에 비례하지만, 명령 내용 길이가 상수 수준이므로 O(1)로 봅니다.)
    • 명령이 m개면 전체 O(m) — 명령 수에 정비례하는 선형 프로그램입니다.
    • 공간: 취소 기록과 대기열이 각각 최대 명령 수만큼 자라므로 O(m)입니다.

    자주 발생하는 오류

    • 빈 검사 없이 pop()/poll()부터 호출 — ArrayDeque.pop()은 빈 스택에서 NoSuchElementException을 던집니다 (오류 1 유형).
    • undoStack.push 대신 offer(뒤에 넣기)를 써서 undo가 가장 오래된 입력부터 취소되는 경우 — LIFO가 FIFO로 바뀌는 실수입니다.
    • document.delete의 범위를 0, last.length()로 써서 문서의 앞부분이 지워지는 경우 — 끝에서 지워야 합니다.
    • serve에서 poll한 뒤의 size()가 아니라 poll 전의 크기를 출력해 "남은 대기"가 1 크게 나오는 경우.

    다른 해결 방법

    이번 강의 전반부처럼 배열 + top/front/rear로 스택·큐를 직접 만들어 풀 수도 있습니다 — 동작은 같고, 용량 관리(가득 참 처리)를 직접 해야 한다는 점만 다릅니다. 또 undoStack에 문자열 대신 "문서 전체의 스냅숏"을 저장하는 방법도 있습니다. 구현은 더 단순하지만 문서가 길어질수록 메모리를 많이 쓰는 교환 관계가 있습니다.

    19오늘의 핵심 정리

    • 자료구조 = 데이터 + 규칙. 스택과 큐는 배열 위에 "넣고 꺼내는 규칙"을 얹은 것이다.
    • 스택은 LIFO — 맨 위(top)에서만 push/pop. top = -1이 빈 스택, 개수는 top + 1. 실행 취소, 괄호 검사, 호출 스택에 쓰인다.
    • 큐는 FIFO — 뒤(rear)로 넣고 앞(front)에서 꺼낸다. front == rear가 빈 큐, 개수는 rear - front. 대기열과 순서 보장 작업에 쓰인다.
    • push/pop/enqueue/dequeue는 모두 O(1) — 규칙을 제한한 대가로 얻는 속도다.
    • 꺼내기 전에는 반드시 빈 검사 — 빈 스택 pop, 빈 큐 dequeue는 예외 또는 조용한 오류의 원인이다.
    • 괄호 검사의 핵심: 닫는 괄호의 짝은 가장 최근에 열린 괄호 — 그래서 스택이 정답이다. 무효 판정은 세 갈래(빈 스택 pop, 짝 불일치, 여는 괄호 남음)임을 기억하자.
    • 실무에서는 ArrayDeque를 스택·큐로 쓰고, "중요한 순서"가 필요하면 PriorityQueue(O(log n))를 쓴다 — 10·12강에서 다시 만난다.

트리 구조와 트리 순회

Tree Structures and Tree Traversal

자료구조 중급 Java 17+

컴퓨터의 폴더 구조, 회사 조직도, 토너먼트 대진표 — 세상의 많은 데이터는 일렬이 아니라 위아래 계층으로 되어 있습니다. 이번 강의에서는 계층 구조를 담는 자료구조인 트리를 배웁니다. 노드 클래스를 직접 만들어 트리를 조립하고, 7강의 재귀로 전위·중위·후위 순회를, 6강의 큐로 레벨 순회를 구현합니다. 마지막에는 5강의 "절반 버리기"를 구조로 만든 이진 탐색 트리(BST)의 삽입과 검색까지 완성합니다.

이 강의의 목차

    01강의 소개

    지금까지 배운 배열, 리스트, 스택, 큐는 모두 데이터를 일렬로 담는 구조였습니다. 그런데 "인사팀은 경영지원본부 소속이고, 경영지원본부는 대표이사실 소속이다" 같은 포함 관계·상하 관계는 일렬로는 표현할 수 없습니다. 이런 데이터를 담는 구조가 트리(tree)입니다 — 뿌리(루트)에서 시작해 가지가 갈라져 나가는 나무를 거꾸로 세운 모양입니다.

    이번 강의에서는 먼저 루트·부모·자식·리프·높이 같은 트리 용어를 익히고, 자식이 최대 2개인 이진 트리를 노드 클래스로 직접 조립합니다. 그다음 트리의 모든 노드를 빠짐없이 한 번씩 방문하는 네 가지 순회 (전위·중위·후위·레벨)를 구현합니다. 후반부에는 "작으면 왼쪽, 크면 오른쪽" 규칙을 가진 이진 탐색 트리(BST)에 값을 넣고 찾는 과정을 만들고, 마지막에는 자식 수 제한이 없는 일반 트리로 회사 조직도 프로그램을 완성합니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 루트, 부모·자식, 리프, 높이, 서브트리 용어를 사용해 계층 구조 데이터를 설명할 수 있다.
    • 학생은 값과 왼쪽·오른쪽 참조를 가진 노드 클래스를 정의하고, 참조 연결로 이진 트리를 직접 조립할 수 있다.
    • 학생은 전위·중위·후위 순회를 재귀로 구현하고, 주어진 트리의 출력 순서를 손으로 예측할 수 있다.
    • 학생은 큐를 이용한 레벨 순회를 구현하고 재귀 순회와의 방문 순서 차이를 비교할 수 있다.
    • 학생은 이진 탐색 트리의 삽입과 검색을 재귀로 구현하고, 검색 경로를 "절반 버리기"로 설명할 수 있다.
    • 학생은 자식 목록(List)을 가진 일반 트리로 조직도를 표현하고, 재귀로 검색·집계 기능을 작성할 수 있다.

    위아래 관계가 있는 데이터를 어떤 구조로 저장하고, 그 안의 모든 항목을 빠짐없이 한 번씩 방문(순회)하려면 어떻게 해야 할까?

    05사람이 직접 해결해 보기

    코드를 쓰기 전에 종이 위에서 트리를 직접 만들어 봅니다. 숫자 카드 6장 50, 30, 70, 20, 40, 60을 이 순서대로, 규칙 하나만 지키며 붙여 봅시다: "현재 카드보다 작으면 왼쪽 아래, 크거나 같으면 오른쪽 아래".

    카드를 하나씩 붙이기

    STEP 1

    첫 카드 50은 비교할 대상이 없으므로 맨 위에 놓습니다. 이것이 루트입니다. 다음 카드 30은 50보다 작으니 50의 왼쪽 아래에, 70은 50보다 크니 오른쪽 아래에 붙입니다.

    질문: 다음 카드 20은 어디에 붙을까요? 비교를 몇 번 할까요?

    먼저 루트 50과 비교(1번) — 작으니 왼쪽으로. 왼쪽에는 이미 30이 있으니 30과 비교(2번) — 또 작으니 30의 왼쪽 아래에 붙입니다. 비교 2번으로 자리가 정해졌습니다.

    STEP 2

    같은 규칙으로 40과 60까지 붙이면 트리가 완성됩니다.

            50
       /  \
     30    70
    /  \   /
  20   40 60
    질문: 40은 어떤 비교를 거쳐 그 자리에 갔을까요?

    50과 비교 → 작으니 왼쪽. 30과 비교 → 40은 30보다 크니 오른쪽. 30의 오른쪽이 비어 있으므로 거기에 붙습니다. "한 노드와 비교 → 한쪽으로 내려감"의 반복 — 이것이 잠시 후 코드로 만들 BST 삽입입니다.

    완성된 트리 읽기

    STEP 3

    이 트리에서 작은 수부터 순서대로 모든 카드를 읽어 보세요. 어디서부터 시작해야 할까요?

    질문: 어떤 순서로 읽으면 20, 30, 40, 50, 60, 70이 될까요?

    각 노드에서 "왼쪽 전부 → 자기 자신 → 오른쪽 전부" 순서로 읽으면 됩니다. 왼쪽 끝(20)부터: 20 → 30 → 40 → 50 → 60 → 70. 이 읽기 방법이 중위 순회이고, 규칙대로 만든 트리(BST)를 중위 순회하면 항상 오름차순이 나옵니다.

    STEP 4

    이번에는 트리에서 65를 찾아보세요. 루트 50에서 출발합니다.

    질문: 몇 번 비교했고, 아예 쳐다보지도 않은 카드는 몇 장인가요?

    50과 비교(크다 → 오른쪽), 70과 비교(작다 → 왼쪽), 60과 비교(크다 → 오른쪽인데 비어 있음) — 비교 3번 만에 "없다"고 확정합니다. 왼쪽 서브트리의 20, 30, 40 3장은 한 번도 보지 않았습니다. 50과 한 번 비교하는 순간 왼쪽 절반을 통째로 버렸기 때문입니다 — 5강 이진 탐색의 "절반 버리기"가 트리 위에서 일어난 것입니다.

    06핵심 개념

    트리와 트리 용어

    트리는 하나의 루트에서 시작해, 각 노드가 여러 자식 노드를 가리키는 계층 구조입니다. 노드(node)는 데이터를 담는 동그라미, 간선(edge)은 노드 사이의 연결선입니다. 부모에서 자식으로만 갈라져 내려가므로 순환(사이클)이 없고, 루트를 제외한 모든 노드는 부모가 정확히 하나입니다.

    용어뜻위 트리(50,30,70,20,40,60)에서는
    루트(root)부모가 없는 맨 위 노드50
    부모 / 자식간선으로 연결된 위 / 아래 노드30의 부모는 50, 자식은 20과 40
    리프(leaf)자식이 하나도 없는 노드20, 40, 60
    깊이(depth)루트에서 그 노드까지의 간선 수50은 0, 30·70은 1, 20·40·60은 2
    높이(height)루트에서 가장 먼 리프까지의 간선 수2
    서브트리(subtree)어떤 노드를 루트로 하는 부분 트리30을 루트로 하면 {30, 20, 40}

    폴더 구조로 바꿔 말하면: 루트는 최상위 폴더, 자식은 하위 폴더, 리프는 더 하위 폴더가 없는 폴더, 높이는 "가장 깊이 들어간 폴더까지 몇 번 클릭하는가"입니다.

    이진 트리와 일반 트리

    자식 수가 최대 2개(왼쪽·오른쪽)로 제한된 트리를 이진 트리(binary tree)라고 합니다. 자식이 딱 두 자리이므로 노드를 value, left, right 세 필드로 표현할 수 있어 코드가 단순합니다. 반면 조직도처럼 자식 수가 정해져 있지 않으면 자식들을 List에 담는 일반 트리를 씁니다. 이 강의의 앞부분은 이진 트리로, 응용 예제와 최종 문제는 일반 트리로 연습합니다.

    트리 순회 — 모든 노드를 한 번씩 방문하기

    배열은 for 한 줄로 전부 방문할 수 있지만, 트리는 갈림길이 있어서 방문 순서를 정하는 규칙이 필요합니다. 이 규칙이 순회(traversal)입니다. 재귀 순회 세 가지는 "자기 자신을 언제 처리하느냐"만 다릅니다.

    순회방문 순서도구대표 용도위 트리의 결과
    전위(preorder)자신 → 왼쪽 → 오른쪽재귀폴더 구조·조직도 출력 (상위 먼저)50 30 20 40 70 60
    중위(inorder)왼쪽 → 자신 → 오른쪽재귀BST를 오름차순으로 읽기20 30 40 50 60 70
    후위(postorder)왼쪽 → 오른쪽 → 자신재귀폴더 용량 합산·안전한 삭제 (하위 먼저)20 40 30 60 70 50
    레벨(level order)위층부터, 같은 층은 왼쪽부터큐 (6강)층별 출력, 가장 가까운 것부터 탐색50 30 70 20 40 60
    외우는 요령

    전위·중위·후위의 "위(位)"는 자기 자신의 위치입니다. 자신을 맨 앞에서 처리하면 전위, 가운데면 중위, 맨 뒤면 후위. 왼쪽이 오른쪽보다 먼저인 것은 셋 다 같습니다.

    이진 탐색 트리(BST) — 절반 버리기를 구조로 만들다

    이진 탐색 트리는 이진 트리에 규칙 하나를 더한 것입니다: 모든 노드에서, 왼쪽 서브트리의 값은 자신보다 작고 오른쪽 서브트리의 값은 자신보다 크거나 같다. 이 규칙 덕분에 값을 찾을 때 노드 하나와 비교하면 반대쪽 서브트리 전체를 버릴 수 있습니다. 5강 이진 탐색이 "정렬된 배열 + 가운데 비교"였다면, BST는 비교하며 내려갈 길을 미리 구조로 만들어 둔 것입니다. 삽입도 같은 비교 경로를 따라 내려가 빈자리에 붙이면 끝입니다.

    미리 알아 둘 함정

    BST의 성능은 트리의 모양에 달려 있습니다. 정렬된 순서(10, 20, 30, …)로 삽입하면 오른쪽으로만 자라 사실상 연결 리스트가 되고, 탐색이 O(n)으로 떨어집니다. 자세한 내용은 14번 복잡도 섹션에서 다룹니다. 또한 이 강의의 구현은 같은 값을 오른쪽에 넣는 방식으로 중복을 처리합니다.

    07단계별 동작 과정

    삽입 순서 50, 30, 70, 20, 40, 60으로 만든 BST 위에서 중위 순회(왼쪽 → 자신 → 오른쪽)가 진행되는 모습을 단계별로 관찰하세요. 다음 단계 ▶ 버튼으로 한 단계씩 진행할 수 있습니다. 지금 방문 중인 노드는 파란색(현재), 값이 출력된 노드는 초록색(완료)으로 표시되고, 아래 배열에 출력 순서가 쌓입니다.

    방문(파란색)과 출력(초록색)의 시점이 다르다는 것에 주목하세요. 50은 가장 먼저 방문하지만, 왼쪽 서브트리(30, 20, 40)의 출력이 모두 끝난 뒤에야 4번째로 출력됩니다. "새 데이터" 버튼을 누르면 무작위 값 6개로 새 BST를 만들어 같은 순회를 반복합니다 — 어떤 값이든 출력은 항상 오름차순입니다.

    08의사코드

    코드를 쓰기 전에, 손으로 한 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo BST 삽입 (재귀) 
    알고리즘 Insert(node, value)
    만약 node가 비어 있으면(null):
        새 노드를 만들어 반환한다          // 빈자리 도착 = 종료 조건
    만약 value가 node의 값보다 작으면:
        node의 왼쪽  ← Insert(node의 왼쪽, value)
    아니면:
        node의 오른쪽 ← Insert(node의 오른쪽, value)
    node를 그대로 반환한다
    Pseudo 중위 순회 (재귀) 
    알고리즘 Inorder(node)
    만약 node가 비어 있으면(null): 되돌아간다   // 종료 조건
    Inorder(node의 왼쪽)          // 1. 왼쪽 서브트리 전부
    node의 값을 출력한다           // 2. 자기 자신
    Inorder(node의 오른쪽)        // 3. 오른쪽 서브트리 전부

// 전위 순회: 출력을 1번 위치로 옮기면 된다
// 후위 순회: 출력을 3번 아래로 옮기면 된다
    Pseudo 레벨 순회 (큐) 
    알고리즘 LevelOrder(root)
    큐를 만들고 root를 넣는다
    큐가 비지 않은 동안 반복:
        node ← 큐에서 하나 꺼낸다(poll)
        node의 값을 출력한다
        node의 왼쪽 자식이 있으면 큐에 넣는다(offer)
        node의 오른쪽 자식이 있으면 큐에 넣는다(offer)

    재귀 순회는 "아래로 깊이" 내려가고, 큐를 쓰는 레벨 순회는 "옆으로 넓게" 퍼집니다. 이 차이는 9강에서 DFS와 BFS라는 이름으로 다시 만납니다.

    한 번에 완성하지 않고 노드 만들기 → 삽입 판단 한 번 → 재귀 삽입 → 재귀 순회 순서로 확장합니다. 각 단계의 코드는 모두 독립적으로 복사해서 실행할 수 있습니다.

    구현 1단계 — 노드 클래스를 만들고 손으로 연결하기

    트리의 재료는 노드입니다. 값 하나와, 왼쪽·오른쪽 자식을 가리키는 참조 두 개 — 이게 전부입니다. 먼저 노드 3개를 만들어 참조 대입만으로 작은 트리를 조립해 봅니다. 아직 알고리즘은 없습니다.

    Java Step1NodeBasics.java 
    public class Step1NodeBasics {

    /** 트리의 노드: 값 하나와, 왼쪽·오른쪽 자식을 가리키는 참조 두 개 */
    static class Node {
        int value;   // 이 노드가 저장하는 값
        Node left;   // 왼쪽 자식 (없으면 null)
        Node right;  // 오른쪽 자식 (없으면 null)

        Node(int value) {
            this.value = value;
            // left와 right는 자동으로 null — 아직 자식이 없다
        }
    }

    public static void main(String[] args) {
        // 노드 3개를 만들어 손으로 직접 연결한다
        Node root = new Node(50);        // 루트 노드
        Node leftChild = new Node(30);   // 왼쪽 자식이 될 노드
        Node rightChild = new Node(70);  // 오른쪽 자식이 될 노드

        root.left = leftChild;    // 50의 왼쪽에 30을 연결
        root.right = rightChild;  // 50의 오른쪽에 70을 연결

        System.out.println("루트 노드의 값: " + root.value);
        System.out.println("루트의 왼쪽 자식: " + root.left.value);
        System.out.println("루트의 오른쪽 자식: " + root.right.value);

        // 자식이 없는 노드(리프 노드)인지 확인한다
        boolean isLeaf = (leftChild.left == null && leftChild.right == null);
        System.out.println("30은 리프 노드인가? " + isLeaf);
        System.out.println("50은 리프 노드인가? " + (root.left == null && root.right == null));
    }
}

    구현 2단계 — 삽입 판단을 한 번만 해 보기

    손 풀이 STEP 1에서 한 일을 코드로 옮깁니다: 새 값을 현재 노드와 비교해서, 작으면 왼쪽, 크거나 같으면 오른쪽에 붙인다. 일부러 판단을 딱 한 번만 하는 메서드를 만들어, 어디까지 되고 어디서 막히는지 확인합니다.

    Java Step2InsertDecision.java 
    public class Step2InsertDecision {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    /** 한 번의 삽입 판단: 현재 노드와 비교해서 왼쪽 또는 오른쪽에 붙인다 */
    static void insertOneStep(Node current, int newValue) {
        System.out.println("새 값 " + newValue + "을(를) 노드 " + current.value + "과(와) 비교합니다.");

        if (newValue < current.value) {
            System.out.println("  " + newValue + " < " + current.value + " → 왼쪽으로 가야 합니다.");
            if (current.left == null) {
                current.left = new Node(newValue);   // 빈 자리에 새 노드를 연결
                System.out.println("  왼쪽이 비어 있으므로 왼쪽 자식으로 연결했습니다.");
            } else {
                System.out.println("  왼쪽에 이미 " + current.left.value + "이(가) 있습니다. (다음 단계에서 더 내려갑니다)");
            }
        } else {
            System.out.println("  " + newValue + " >= " + current.value + " → 오른쪽으로 가야 합니다.");
            if (current.right == null) {
                current.right = new Node(newValue);
                System.out.println("  오른쪽이 비어 있으므로 오른쪽 자식으로 연결했습니다.");
            } else {
                System.out.println("  오른쪽에 이미 " + current.right.value + "이(가) 있습니다. (다음 단계에서 더 내려갑니다)");
            }
        }
    }

    public static void main(String[] args) {
        Node root = new Node(50);   // 루트만 있는 트리에서 시작

        insertOneStep(root, 30);    // 50과 비교 → 왼쪽에 붙는다
        insertOneStep(root, 70);    // 50과 비교 → 오른쪽에 붙는다
        insertOneStep(root, 20);    // 왼쪽에 이미 30이 있어 한 번의 판단으로는 부족하다!

        System.out.println();
        System.out.println("현재 트리: 루트 " + root.value
                + ", 왼쪽 " + root.left.value + ", 오른쪽 " + root.right.value);
        System.out.println("20은 아직 넣지 못했습니다 → 반복해서 내려가는 구조(재귀)가 필요합니다.");
    }
}

    구현 3단계 — 재귀 삽입 완성

    재귀 삽입 메서드의 약속을 이렇게 정합니다: "node를 루트로 하는 서브트리에 value를 넣고, 그 서브트리의 루트를 돌려준다." 빈자리(null)에 도착하면 새 노드를 만들어 돌려주는 것이 종료 조건입니다. 반환값을 node.left나 node.right에 다시 대입하는 부분이 핵심입니다.

    Java Step3RecursiveInsert.java 
    public class Step3RecursiveInsert {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    /**
     * 재귀 삽입: "node를 루트로 하는 서브트리에 value를 넣고,
     * 완성된 서브트리의 루트를 돌려준다"
     */
    static Node insert(Node node, int value) {
        if (node == null) {
            return new Node(value);          // 빈 자리 도착 → 새 노드가 그 자리의 루트가 된다
        }
        if (value < node.value) {
            node.left = insert(node.left, value);    // 왼쪽 서브트리에 넣고 결과를 다시 연결
        } else {
            node.right = insert(node.right, value);  // 오른쪽 서브트리에 넣고 결과를 다시 연결
        }
        return node;                          // 자기 자신을 그대로 돌려준다
    }

    /** 트리를 왼쪽으로 90도 눕힌 모양으로 출력한다 (오른쪽 자식이 위에 나온다) */
    static void printSideways(Node node, int depth) {
        if (node == null) {
            return;
        }
        printSideways(node.right, depth + 1);
        System.out.println("    ".repeat(depth) + node.value);
        printSideways(node.left, depth + 1);
    }

    public static void main(String[] args) {
        int[] values = {50, 30, 70, 20, 40, 60};

        Node root = null;                     // 빈 트리에서 시작
        for (int value : values) {
            root = insert(root, value);       // 반환값을 반드시 root에 다시 저장!
            System.out.println(value + " 삽입 완료");
        }

        System.out.println();
        System.out.println("완성된 트리 (왼쪽으로 90도 눕힌 모양, 오른쪽 자식이 위):");
        printSideways(root, 0);
    }
}

    구현 4단계 — 중위 순회로 전체 방문

    트리가 완성되었으니 모든 노드를 방문해 봅니다. 중위 순회는 딱 세 줄입니다: 왼쪽 재귀 → 자신 출력 → 오른쪽 재귀. 종료 조건 if (node == null) return;이 없으면 어떻게 되는지는 13번 오류 찾기 섹션에서 확인합니다.

    Java Step4InorderTraversal.java 
    public class Step4InorderTraversal {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    static Node insert(Node node, int value) {
        if (node == null) {
            return new Node(value);
        }
        if (value < node.value) {
            node.left = insert(node.left, value);
        } else {
            node.right = insert(node.right, value);
        }
        return node;
    }

    /** 중위 순회: 왼쪽 서브트리 → 자기 자신 → 오른쪽 서브트리 */
    static void inorder(Node node) {
        if (node == null) {
            return;                    // 종료 조건: 빈 자리에 도착하면 되돌아간다
        }
        inorder(node.left);            // 1. 왼쪽 서브트리를 먼저 전부 방문
        System.out.print(node.value + " ");  // 2. 자기 자신을 출력
        inorder(node.right);           // 3. 오른쪽 서브트리를 방문
    }

    public static void main(String[] args) {
        int[] values = {50, 30, 70, 20, 40, 60};

        Node root = null;
        for (int value : values) {
            root = insert(root, value);
        }

        System.out.println("삽입 순서   : 50 30 70 20 40 60");
        System.out.print("중위 순회 결과: ");
        inorder(root);
        System.out.println();
        System.out.println("→ 중위 순회는 BST의 값을 항상 오름차순으로 출력한다!");
    }
}

    뒤죽박죽 순서(50, 30, 70, …)로 넣었는데 오름차순으로 나왔습니다. 정렬을 한 적이 없는데 정렬된 결과가 나오는 이유는, 삽입할 때마다 "작으면 왼쪽, 크면 오른쪽" 규칙이 자리를 정해 두었기 때문입니다. 7번 섹션의 시각화가 바로 이 코드의 동작입니다.

    10완성 Java 코드

    지금까지의 조각을 모아 완성합니다. 재귀 삽입에 재귀 검색과 순회 4종 세트(전위·중위·후위·레벨)를 더했습니다. 검색은 지나간 노드를 화면에 남겨 "절반 버리기" 경로를 눈으로 확인할 수 있게 했고, 레벨 순회는 6강의 ArrayDeque 큐를 그대로 재사용합니다.

    Java BstComplete.java 
    import java.util.ArrayDeque;
import java.util.Queue;

public class BstComplete {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    /** 재귀 삽입: 서브트리에 값을 넣고 그 서브트리의 루트를 돌려준다 */
    static Node insert(Node node, int value) {
        if (node == null) {
            return new Node(value);
        }
        if (value < node.value) {
            node.left = insert(node.left, value);
        } else {
            node.right = insert(node.right, value);
        }
        return node;
    }

    /** 재귀 검색: 있으면 true. 비교 방향을 화면에 남긴다 */
    static boolean search(Node node, int target) {
        if (node == null) {
            return false;                     // 빈 자리까지 내려왔다 → 없다
        }
        System.out.print(node.value + " ");   // 지금 비교하는 노드
        if (target == node.value) {
            return true;
        }
        if (target < node.value) {
            return search(node.left, target);   // 왼쪽 절반만 확인
        }
        return search(node.right, target);      // 오른쪽 절반만 확인
    }

    /** 전위 순회: 자기 자신 → 왼쪽 → 오른쪽 */
    static void preorder(Node node) {
        if (node == null) return;
        System.out.print(node.value + " ");
        preorder(node.left);
        preorder(node.right);
    }

    /** 중위 순회: 왼쪽 → 자기 자신 → 오른쪽 (BST에서는 오름차순!) */
    static void inorder(Node node) {
        if (node == null) return;
        inorder(node.left);
        System.out.print(node.value + " ");
        inorder(node.right);
    }

    /** 후위 순회: 왼쪽 → 오른쪽 → 자기 자신 */
    static void postorder(Node node) {
        if (node == null) return;
        postorder(node.left);
        postorder(node.right);
        System.out.print(node.value + " ");
    }

    /** 레벨 순회: 큐를 사용해 위에서 아래로, 같은 층은 왼쪽에서 오른쪽으로 */
    static void levelOrder(Node root) {
        if (root == null) return;
        Queue<Node> queue = new ArrayDeque<>();   // 6강에서 배운 큐!
        queue.offer(root);
        while (!queue.isEmpty()) {
            Node node = queue.poll();             // 앞에서 하나 꺼내고
            System.out.print(node.value + " ");
            if (node.left != null) queue.offer(node.left);    // 자식들을 뒤에 넣는다
            if (node.right != null) queue.offer(node.right);
        }
    }

    public static void main(String[] args) {
        int[] values = {50, 30, 70, 20, 40, 60};

        Node root = null;
        for (int value : values) {
            root = insert(root, value);
        }
        System.out.println("삽입 순서: 50 30 70 20 40 60");
        System.out.println();

        System.out.print("전위 순회 (자신→왼쪽→오른쪽): ");
        preorder(root);
        System.out.println();

        System.out.print("중위 순회 (왼쪽→자신→오른쪽): ");
        inorder(root);
        System.out.println();

        System.out.print("후위 순회 (왼쪽→오른쪽→자신): ");
        postorder(root);
        System.out.println();

        System.out.print("레벨 순회 (위→아래, 큐 사용) : ");
        levelOrder(root);
        System.out.println();
        System.out.println();

        System.out.print("40 검색 — 지나간 노드: ");
        boolean found40 = search(root, 40);
        System.out.println("→ " + (found40 ? "발견" : "없음"));

        System.out.print("65 검색 — 지나간 노드: ");
        boolean found65 = search(root, 65);
        System.out.println("→ " + (found65 ? "발견" : "없음"));
    }
}

    11실행 과정 추적

    중위 순회의 재귀가 실제로 어떤 순서로 호출되고 되돌아오는지, 작은 트리(50, 30, 70, 20)로 추적합니다. 들여쓰기 한 칸이 재귀 깊이 한 층 — 7강에서 본 호출 스택이 쌓이는 모양 그대로입니다.

    Java InorderTrace.java 
    public class InorderTrace {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    static Node insert(Node node, int value) {
        if (node == null) {
            return new Node(value);
        }
        if (value < node.value) {
            node.left = insert(node.left, value);
        } else {
            node.right = insert(node.right, value);
        }
        return node;
    }

    static int visitOrder = 0;                    // 몇 번째로 출력되는지 센다
    static StringBuilder result = new StringBuilder();

    /** 중위 순회를 하면서, 재귀 호출의 시작·출력·복귀를 들여쓰기로 보여 준다 */
    static void inorderTrace(Node node, int depth) {
        String indent = "  ".repeat(depth);       // 깊이만큼 들여쓰기
        if (node == null) {
            System.out.println(indent + "빈 자리(null) → 즉시 되돌아감");
            return;
        }
        System.out.println(indent + "호출: inorder(" + node.value + ")");
        inorderTrace(node.left, depth + 1);       // 1. 왼쪽 먼저

        visitOrder++;
        result.append(node.value).append(" ");
        System.out.println(indent + "출력: " + node.value + "  ← " + visitOrder + "번째 출력");

        inorderTrace(node.right, depth + 1);      // 3. 오른쪽은 마지막
        System.out.println(indent + "복귀: inorder(" + node.value + ") 끝");
    }

    public static void main(String[] args) {
        int[] values = {50, 30, 70, 20};          // 작은 트리로 추적한다

        Node root = null;
        for (int value : values) {
            root = insert(root, value);
        }

        System.out.println("트리: 50의 왼쪽에 30, 오른쪽에 70, 30의 왼쪽에 20");
        System.out.println();
        inorderTrace(root, 0);
        System.out.println();
        System.out.println("중위 순회 최종 출력: " + result.toString().trim());
    }
}

    13복잡도 및 특성 분석

    입력 크기

    트리에서는 두 가지 크기가 중요합니다. 노드 수 n과 높이 h입니다. 같은 n이라도 트리 모양에 따라 h는 크게 달라집니다 — 균형이 잘 잡히면 h ≈ log₂n, 한쪽으로만 자라면 h = n − 1입니다.

    주요 연산

    순회의 핵심 연산은 노드 방문(출력), 삽입·검색의 핵심 연산은 값 비교입니다.

    시간 복잡도

    연산균형 잡힌 트리한쪽으로 치우친 트리이유
    순회 (전위·중위·후위·레벨)O(n)O(n)모양과 무관하게 모든 노드를 정확히 1번 방문
    BST 검색O(log n)O(n)비교 1번마다 한 층 내려감 → 최대 h+1번 비교
    BST 삽입O(log n)O(n)검색과 같은 경로를 내려가 빈자리에 연결

    검색·삽입의 일의 양은 정확히 "루트에서 몇 층 내려가는가", 즉 높이 h에 비례합니다. 노드 6개짜리 예제 트리는 높이 2라서 어떤 값도 비교 3번 안에 찾거나 "없음"을 확정했습니다. n이 100만이어도 균형이 잡혀 있으면 약 20번 비교면 충분합니다 — 5강 이진 탐색과 같은 숫자입니다.

    공간 복잡도

    • 트리 자체: 노드 n개 → O(n).
    • 재귀 순회: 호출 스택이 최대 높이 h만큼 쌓임 → O(h). 치우친 트리에서 n이 매우 크면 7강에서 본 StackOverflowError가 날 수 있습니다.
    • 레벨 순회: 큐에 최대 한 층의 노드 수(가장 넓은 층)만큼 쌓임.

    알고리즘 특성

    • 중위 순회 = 오름차순: BST에서만 성립하는 성질입니다. "정렬된 상태를 유지하는 자료구조"로서 BST가 쓰이는 이유입니다.
    • 삽입 순서가 모양을 정한다: 같은 값 집합이라도 50부터 넣으면 균형 트리, 20부터 오름차순으로 넣으면 오른쪽으로만 자라는 막대기가 됩니다. 실무 라이브러리(TreeMap 등)는 스스로 균형을 다시 잡는 트리(레드-블랙 트리)를 씁니다 — 원리는 오늘 배운 BST와 같습니다.
    • 재귀 깊이 = 트리 높이: 순회 재귀의 최대 깊이는 h + 1이므로, 높이가 낮을수록 시간뿐 아니라 스택 메모리도 절약됩니다.

    • 인원 합산: 자신의 인원 + 모든 하위 부서의 합산 결과 — 서브트리 단위 집계
    Java OrgChartApplication.java 
    import java.util.ArrayList;
import java.util.List;

public class OrgChartApplication {

    /** 조직도의 부서: 자식 수가 정해져 있지 않으므로 List로 관리하는 일반 트리 */
    static class Dept {
        String name;
        int headcount;                            // 이 부서에 직접 소속된 인원
        List<Dept> children = new ArrayList<>();  // 하위 부서 목록

        Dept(String name, int headcount) {
            this.name = name;
            this.headcount = headcount;
        }

        void add(Dept child) {
            children.add(child);
        }
    }

    /** 부서 구조를 들여쓰기로 출력한다 (전위 순회: 자신 먼저, 그다음 하위 부서) */
    static void printOrg(Dept dept, int depth) {
        System.out.println("  ".repeat(depth) + dept.name + " (" + dept.headcount + "명)");
        for (Dept child : dept.children) {
            printOrg(child, depth + 1);           // 각 하위 부서에 대해 재귀
        }
    }

    /** 이름으로 부서를 찾는다. 없으면 null */
    static Dept findDept(Dept dept, String name) {
        if (dept.name.equals(name)) {
            return dept;                          // 자기 자신이 찾는 부서다
        }
        for (Dept child : dept.children) {
            Dept found = findDept(child, name);   // 하위 부서에서 재귀로 찾는다
            if (found != null) {
                return found;                     // 찾았으면 즉시 위로 전달
            }
        }
        return null;                              // 이 서브트리에는 없다
    }

    /** 이 부서와 모든 하위 부서의 인원 합계 */
    static int totalHeadcount(Dept dept) {
        int total = dept.headcount;               // 자신의 인원부터
        for (Dept child : dept.children) {
            total += totalHeadcount(child);       // 하위 부서의 합을 더한다
        }
        return total;
    }

    public static void main(String[] args) {
        // 조직도 데이터 만들기
        Dept ceo = new Dept("대표이사실", 2);

        Dept support = new Dept("경영지원본부", 3);
        support.add(new Dept("인사팀", 4));
        support.add(new Dept("재무팀", 5));

        Dept product = new Dept("제품개발본부", 2);
        product.add(new Dept("상품기획팀", 6));
        product.add(new Dept("품질관리팀", 7));

    Java OrgTreeSolution.java 
    import java.util.ArrayList;
import java.util.List;

public class OrgTreeSolution {

    /** 조직도의 부서 노드: 하위 부서가 몇 개든 담을 수 있는 일반 트리 */
    static class Dept {
        String name;
        List<Dept> children = new ArrayList<>();

        Dept(String name) {
            this.name = name;
        }

        void add(Dept child) {
            children.add(child);
        }
    }

    /** 요구사항 1: 전위 순회로 전체 부서를 들여쓰기와 함께 출력한다. */
    static void printOrgChart(Dept dept, int depth) {
        System.out.println("  ".repeat(depth) + dept.name);   // 1. 자기 자신 먼저 (전위)
        for (Dept child : dept.children) {
            printOrgChart(child, depth + 1);                  // 2. 하위 부서는 한 칸 더 들여쓰기
        }
    }

    /** 요구사항 2: 이름이 일치하는 부서를 찾아 반환한다. 없으면 null. */
    static Dept findDept(Dept dept, String name) {
        if (dept.name.equals(name)) {
            return dept;                       // 자기 자신이 정답
        }
        for (Dept child : dept.children) {
            Dept found = findDept(child, name);
            if (found != null) {
                return found;                  // 하위에서 찾았으면 즉시 위로 전달
            }
        }
        return null;                           // 이 서브트리에는 없다
    }

    /** 요구사항 3: 트리의 높이 = 루트에서 가장 먼 부서까지의 간선 수. 리프는 0. */
    static int height(Dept dept) {
        if (dept.children.isEmpty()) {
            return 0;                          // 리프 노드의 높이는 0
        }
        int maxChildHeight = 0;
        for (Dept child : dept.children) {
            int childHeight = height(child);
            if (childHeight > maxChildHeight) {
                maxChildHeight = childHeight;  // 가장 높은 자식을 기억한다
            }
        }
        return maxChildHeight + 1;             // 자식까지 내려가는 간선 1개를 더한다
    }

    /** 요구사항 4: 이 부서를 포함한 전체 부서 수를 반환한다. */
    static int countDepts(Dept dept) {
        int count = 1;                         // 자기 자신
        for (Dept child : dept.children) {
            count += countDepts(child);        // 하위 부서 수를 모두 더한다
        }
        return count;
    }

        dev.add(new Dept("백엔드팀"));
        dev.add(new Dept("데이터팀"));

        sales.add(new Dept("국내영업팀"));
        sales.add(new Dept("해외영업팀"));

        company.add(dev);
        company.add(sales);

        System.out.println();

    1. printOrgChart — 전위 순회의 정의 그대로입니다: 자신 먼저, 자식은 나중에. 출력을 재귀 호출 앞에 두는 위치가 곧 "전위"입니다.
    2. findDept — 자식의 결과를 found 변수로 받아 null이 아닐 때만 반환하는 것이 핵심입니다. 결과 확인 없이 return findDept(child, name);이라고 쓰면 첫 자식 서브트리만 검색하고 끝나 버립니다.
    3. countDepts — "1 + 자식들의 합". 실습 3의 countNodes에서 left/right 두 번의 재귀가 for 반복 속 재귀로 바뀐 것뿐입니다.
    4. height — 자식들의 높이 중 최댓값에 1을 더합니다. 합계가 아니라 최댓값인 이유는, 높이는 "가장 먼 리프까지"의 거리이기 때문입니다. 2강에서 배운 최댓값 찾기 패턴이 재귀 안에 들어간 형태입니다.

    복잡도 분석

    • printOrgChart, countDepts, height: 모든 부서를 정확히 1번 방문 → O(n).
    • findDept: 최선 1번(루트가 정답), 최악 n번(없는 이름) → O(n). 일반 트리에는 BST 같은 정렬 규칙이 없어 절반 버리기가 불가능합니다.
    • 공간: 재귀 깊이 = 조직도 높이 → O(h). 이 데이터에서는 최대 3층입니다.

    자주 발생하는 오류

    • findDept에서 자식의 결과를 확인하지 않고 바로 반환해, 두 번째 이후 본부가 검색되지 않는 경우.
    • height에서 최댓값 대신 +1을 자식마다 누적해 높이가 부서 수처럼 커지는 경우.
    • countDepts에서 자신(1)을 빼먹어 결과가 10이 나오는 경우.
    • printOrgChart에서 출력을 재귀 뒤에 두어(후위) 하위 팀이 본부보다 먼저 나오는 경우.

    다른 해결 방법

    네 기능 모두 6강의 큐(레벨 순회)나 스택을 이용한 반복문 버전으로도 구현할 수 있습니다. 예를 들어 부서 수 세기는 큐에 루트를 넣고, 꺼낼 때마다 세면서 자식들을 다시 넣으면 됩니다. 재귀 버전이 짧고 읽기 쉽지만, 조직도가 수만 층처럼 극단적으로 깊다면 호출 스택 초과를 피할 수 있는 반복문 버전이 안전합니다. 높이 계산은 Math.max(maxChildHeight, childHeight)를 써서 한 줄로 줄일 수도 있습니다.

    19오늘의 핵심 정리

    • 트리는 루트에서 시작해 부모-자식으로 갈라지는 계층 구조다. 리프는 자식이 없는 노드, 높이는 루트에서 가장 먼 리프까지의 간선 수다.
    • 트리는 특별한 문법이 아니라 참조(left/right 또는 children 리스트)를 가진 객체들의 연결이다.
    • 순회는 모든 노드를 한 번씩 방문하는 규칙이다: 전위(자신→왼→오), 중위(왼→자신→오), 후위(왼→오→자신)는 재귀로, 레벨 순회는 6강의 큐로 구현한다.
    • 트리 재귀의 종료 조건은 if (node == null) return; — 첫 줄은 무조건 null 검사를 습관으로 만들자.
    • BST는 "작으면 왼쪽, 크거나 같으면 오른쪽" 규칙으로 5강의 절반 버리기를 구조화한 트리다. 중위 순회하면 항상 오름차순이고, 탐색·삽입은 균형 트리에서 O(log n), 치우친 트리에서 O(n)이다.
    • 재귀 insert의 반환값은 반드시 root나 node.left/node.right에 다시 대입해야 트리가 연결된다.
    • 조직도·폴더 구조 같은 실전 데이터는 자식 목록을 List로 갖는 일반 트리로 표현하고, 검색·집계·높이 계산을 모두 "자신 + 자식들의 결과" 재귀 패턴으로 처리한다.

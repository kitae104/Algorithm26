트리 구조와 트리 순회

Tree Structures and Tree Traversal

자료구조 중급 Java 17+

컴퓨터의 폴더 구조, 회사 조직도, 토너먼트 대진표 — 세상의 많은 데이터는 일렬이 아니라 위아래 계층으로 되어 있습니다. 이번 강의에서는 계층 구조를 담는 자료구조인 트리를 배웁니다. 노드 클래스를 직접 만들어 트리를 조립하고, 7강의 재귀로 전위·중위·후위 순회를, 6강의 큐로 레벨 순회를 구현합니다. 마지막에는 5강의 "절반 버리기"를 구조로 만든 이진 탐색 트리(BST)의 삽입과 검색까지 완성합니다.

이 강의의 목차

    01강의 소개

    • 배열, 리스트, 스택, 큐 = 데이터를 일렬로 담는 구조
    • "인사팀은 경영지원본부 소속, 경영지원본부는 대표이사실 소속" 같은 포함 관계·상하 관계는 일렬로 표현 불가
    • 이런 데이터를 담는 구조 = 트리(tree) — 뿌리(루트)에서 가지가 갈라져 나가는 나무를 거꾸로 세운 모양
    • 루트·부모·자식·리프·높이 같은 트리 용어부터 익히고, 자식 최대 2개인 이진 트리를 노드 클래스로 직접 조립
    • 트리의 모든 노드를 빠짐없이 방문하는 네 가지 순회(전위·중위·후위·레벨) 구현
    • 후반부: "작으면 왼쪽, 크면 오른쪽" 규칙의 이진 탐색 트리(BST) 삽입·검색
    • 마지막: 자식 수 제한 없는 일반 트리로 회사 조직도 프로그램 완성

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 루트, 부모·자식, 리프, 높이, 서브트리 용어를 사용해 계층 구조 데이터를 설명할 수 있다.
    • 학생은 값과 왼쪽·오른쪽 참조를 가진 노드 클래스를 정의하고, 참조 연결로 이진 트리를 직접 조립할 수 있다.
    • 학생은 전위·중위·후위 순회를 재귀로 구현하고, 주어진 트리의 출력 순서를 손으로 예측할 수 있다.
    • 학생은 큐를 이용한 레벨 순회를 구현하고 재귀 순회와의 방문 순서 차이를 비교할 수 있다.
    • 학생은 이진 탐색 트리의 삽입과 검색을 재귀로 구현하고, 검색 경로를 "절반 버리기"로 설명할 수 있다.
    • 학생은 자식 목록(List)을 가진 일반 트리로 조직도를 표현하고, 재귀로 검색·집계 기능을 작성할 수 있다.

    05핵심 개념

    트리와 트리 용어

    • 트리 = 하나의 루트에서 시작해, 각 노드가 여러 자식 노드를 가리키는 계층 구조
    • 노드(node) = 데이터를 담는 동그라미, 간선(edge) = 노드 사이의 연결선
    • 부모에서 자식으로만 갈라져 내려가므로 순환(사이클)이 없음
    • 루트를 제외한 모든 노드는 부모가 정확히 하나

    이 강의 내내 쓰는 예제 트리 — 숫자 50, 30, 70, 20, 40, 60을 순서대로, "현재 노드보다 작으면 왼쪽 아래, 크거나 같으면 오른쪽 아래" 규칙으로 붙여 만든 트리입니다. 

            50
       /  \
     30    70
    /  \   /
  20   40 60
    용어뜻예제 트리(50,30,70,20,40,60)에서는
    루트(root)부모가 없는 맨 위 노드50
    부모 / 자식간선으로 연결된 위 / 아래 노드30의 부모는 50, 자식은 20과 40
    리프(leaf)자식이 하나도 없는 노드20, 40, 60
    깊이(depth)루트에서 그 노드까지의 간선 수50은 0, 30·70은 1, 20·40·60은 2
    높이(height)루트에서 가장 먼 리프까지의 간선 수2
    서브트리(subtree)어떤 노드를 루트로 하는 부분 트리30을 루트로 하면 {30, 20, 40}

    폴더 구조로 바꿔 말하면: 루트는 최상위 폴더, 자식은 하위 폴더, 리프는 더 하위 폴더가 없는 폴더, 높이는 "가장 깊이 들어간 폴더까지 몇 번 클릭하는가".

    이진 트리와 일반 트리

    • 자식 수가 최대 2개(왼쪽·오른쪽)로 제한된 트리 = 이진 트리(binary tree) — 노드를 value, left, right 세 필드로 표현할 수 있어 코드가 단순
    • 조직도처럼 자식 수가 정해져 있지 않으면 자식들을 List에 담는 일반 트리를 사용
    • 이 강의의 앞부분은 이진 트리로, 응용 예제와 최종 문제는 일반 트리로 연습

    트리 순회 — 모든 노드를 한 번씩 방문하기

    • 배열은 for 한 줄로 전부 방문할 수 있지만, 트리는 갈림길이 있어서 방문 순서를 정하는 규칙이 필요 — 이 규칙이 순회(traversal)
    • 재귀 순회 세 가지는 "자기 자신을 언제 처리하느냐"만 다름
    순회방문 순서도구대표 용도예제 트리의 결과
    전위(preorder)자신 → 왼쪽 → 오른쪽재귀폴더 구조·조직도 출력 (상위 먼저)50 30 20 40 70 60
    중위(inorder)왼쪽 → 자신 → 오른쪽재귀BST를 오름차순으로 읽기20 30 40 50 60 70
    후위(postorder)왼쪽 → 오른쪽 → 자신재귀폴더 용량 합산·안전한 삭제 (하위 먼저)20 40 30 60 70 50
    레벨(level order)위층부터, 같은 층은 왼쪽부터큐 (6강)층별 출력, 가장 가까운 것부터 탐색50 30 70 20 40 60
    외우는 요령

    전위·중위·후위의 "위(位)"는 자기 자신의 위치입니다. 자신을 맨 앞에서 처리하면 전위, 가운데면 중위, 맨 뒤면 후위. 왼쪽이 오른쪽보다 먼저인 것은 셋 다 같습니다.

    이진 탐색 트리(BST) — 절반 버리기를 구조로 만들다

    • 이진 탐색 트리 = 이진 트리 + 규칙 하나: 모든 노드에서, 왼쪽 서브트리의 값은 자신보다 작고 오른쪽 서브트리의 값은 자신보다 크거나 같다
    • 이 규칙 덕분에 값을 찾을 때 노드 하나와 비교하면 반대쪽 서브트리 전체를 버릴 수 있음
    • 5강 이진 탐색이 "정렬된 배열 + 가운데 비교"였다면, BST는 비교하며 내려갈 길을 미리 구조로 만들어 둔 것
    • 삽입도 같은 비교 경로를 따라 내려가 빈자리에 붙이면 끝
    미리 알아 둘 함정
    • BST의 성능은 트리의 모양에 달려 있음 — 정렬된 순서(10, 20, 30, …)로 삽입하면 오른쪽으로만 자라 사실상 연결 리스트가 되고, 탐색이 O(n)으로 떨어짐 (자세한 내용은 10번 복잡도 섹션)
    • 이 강의의 구현은 같은 값을 오른쪽에 넣는 방식으로 중복을 처리

    • "새 데이터" 버튼을 누르면 무작위 값 6개로 새 BST를 만들어 같은 순회를 반복 — 어떤 값이든 출력은 항상 오름차순

    07의사코드

    코드를 쓰기 전에, 핵심 개념의 규칙과 시각화에서 본 절차를 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)
    • Insert(…)처럼 알고리즘이 자기 이름을 다시 부르는 줄은 재귀 호출 (7강) — "더 작은 서브트리에 같은 일을 맡긴다"로 읽기
    Pseudo BST 삽입 (재귀) 
    알고리즘 Insert(node, value)
    만약 node가 비어 있으면(null):
        새 노드를 만들어 반환한다          // 빈자리 도착 = 종료 조건
    만약 value가 node의 값보다 작으면:
        node의 왼쪽  ← Insert(node의 왼쪽, value)
    아니면:
        node의 오른쪽 ← Insert(node의 오른쪽, value)
    node를 그대로 반환한다

    코드 설명 — BST 삽입

    • 알고리즘 Insert(node, value) — "node를 루트로 하는 서브트리에 value를 넣고, 넣은 뒤의 서브트리 루트를 돌려준다"는 뜻
    • 만약 node가 비어 있으면(null): 새 노드를 만들어 반환한다 — 내려가다가 빈자리에 도착하면 그곳이 새 값의 자리
      • 재귀가 멈추는 종료 조건 — 이 줄이 없으면 끝없이 내려가려다 오류가 남
      • 트리가 처음부터 비어 있을 때(root가 null)도 이 줄 덕분에 새 노드가 곧바로 루트가 됨
    • 만약 value가 node의 값보다 작으면: node의 왼쪽 ← Insert(node의 왼쪽, value) — 작으면 왼쪽 서브트리에 넣는 일을 맡김
      • 돌아온 결과를 node의 왼쪽에 다시 저장하는 것이 핵심 — 빈자리에서 만든 새 노드가 이 대입으로 부모에 연결됨
    • 아니면: node의 오른쪽 ← Insert(node의 오른쪽, value) — 크거나 같으면 오른쪽 서브트리로 (같은 값은 오른쪽에 넣는 규칙)
    • node를 그대로 반환한다 — 이 노드 자체는 바뀌지 않았으므로 자기 자신을 돌려줌 → 부모의 연결이 그대로 유지됨
      • 예: 예제 트리에 40을 넣으면 50(작다 → 왼쪽) → 30(크다 → 오른쪽) → 빈자리에서 새 노드 40 생성 → 30의 오른쪽에 연결
    Pseudo 중위 순회 (재귀) 
    알고리즘 Inorder(node)
    만약 node가 비어 있으면(null): 되돌아간다   // 종료 조건
    Inorder(node의 왼쪽)          // 1. 왼쪽 서브트리 전부
    node의 값을 출력한다           // 2. 자기 자신
    Inorder(node의 오른쪽)        // 3. 오른쪽 서브트리 전부

// 전위 순회: 출력을 1번 위치로 옮기면 된다
// 후위 순회: 출력을 3번 아래로 옮기면 된다

    코드 설명 — 중위 순회

    • 만약 node가 비어 있으면(null): 되돌아간다 — 빈자리에 도착하면 할 일이 없으므로 바로 돌아감 (종료 조건)
      • 리프의 왼쪽·오른쪽 자식은 항상 비어 있으므로, 재귀는 반드시 이 줄에서 멈추게 됨
    • Inorder(node의 왼쪽) — 자기 값을 출력하기 전에 왼쪽 서브트리를 전부 끝까지 처리
    • node의 값을 출력한다 — 왼쪽이 모두 끝난 뒤에야 자기 자신을 출력
    • Inorder(node의 오른쪽) — 마지막으로 오른쪽 서브트리를 전부 처리
      • BST에서는 왼쪽 = 작은 값, 오른쪽 = 큰 값이므로 이 순서대로 읽으면 오름차순 (예제 트리 → 20 30 40 50 60 70)
    • // 전위 순회 …, // 후위 순회 … — 세 순회는 출력 한 줄의 위치만 다름
      • 출력이 맨 앞(1번 위치) → 전위: 50 30 20 40 70 60
      • 출력이 맨 뒤(3번 아래) → 후위: 20 40 30 60 70 50
    Pseudo 레벨 순회 (큐) 
    알고리즘 LevelOrder(root)
    큐를 만들고 root를 넣는다
    큐가 비지 않은 동안 반복:
        node ← 큐에서 하나 꺼낸다(poll)
        node의 값을 출력한다
        node의 왼쪽 자식이 있으면 큐에 넣는다(offer)
        node의 오른쪽 자식이 있으면 큐에 넣는다(offer)

    코드 설명 — 레벨 순회

    • 큐를 만들고 root를 넣는다 — "앞으로 방문할 노드"를 줄 세워 둘 대기열(큐)을 준비하고, 맨 위의 루트부터 줄에 세움
    • 큐가 비지 않은 동안 반복 — 줄에 기다리는 노드가 남아 있는 한 계속 (재귀 대신 반복문 하나로 동작)
    • node ← 큐에서 하나 꺼낸다(poll) — 줄의 맨 앞 노드를 꺼냄 — 먼저 들어온 노드가 먼저 나옴(FIFO)
    • node의 값을 출력한다 — 꺼낸 노드를 방문
    • node의 왼쪽/오른쪽 자식이 있으면 큐에 넣는다(offer) — 자식들은 줄의 맨 뒤에 세움 (왼쪽 먼저)
      • 자식은 항상 같은 층의 다른 노드들보다 뒤에 서므로, 위층이 모두 끝나야 아래층 차례가 옴
      • 예: 예제 트리 → 큐 [50] → 50 출력, [30, 70] → 30 출력, [70, 20, 40] → 70 출력, [20, 40, 60] → … → 50 30 70 20 40 60

    세 의사코드 정리

    • 재귀 순회는 "아래로 깊이" 내려가고, 큐를 쓰는 레벨 순회는 "옆으로 넓게" 퍼짐
    • 이 차이는 9강에서 DFS와 BFS라는 이름으로 다시 만남

    08실습 코드

    의사코드(07)를 실제 Java 프로그램으로 옮깁니다. 핵심 개념(05)의 노드 구조를 기준으로 삽입·검색·순회 네 기능을 메서드로 나눠 구현했습니다.

    • insert는 07의 BST 삽입 의사코드를 그대로 옮긴 것 — 빈 자리(null)에서 새 노드를 만들어 돌려주는 종료 조건과, 반환값을 node.left/node.right에 다시 대입하는 부분까지 동일합니다.
    • search는 05에서 배운 BST의 "비교 한 번마다 반대쪽 서브트리를 버린다"는 규칙을 재귀로 구현한 것 — 지나간 노드를 화면에 남겨 절반씩 버려지는 경로를 눈으로 확인할 수 있게 했습니다.
    • preorder·inorder·postorder는 07의 중위 순회 의사코드에서 "자기 자신 출력"의 위치만 옮긴 것 — 05 표에서 정리한 방문 순서 그대로입니다.
    • levelOrder는 07의 레벨 순회(큐) 의사코드를 그대로 구현한 것 — 6강의 ArrayDeque 큐를 재사용합니다.
    Java BstComplete.java 
    import java.util.ArrayDeque;
import java.util.Queue;

public class BstComplete {

    static class Node {
        int value;
        Node left;
        Node right;

        Node(int value) {
            this.value = value;
        }
    }

    /** 재귀 삽입: 서브트리에 값을 넣고 그 서브트리의 루트를 돌려준다 */
    static Node insert(Node node, int value) {
        if (node == null) {
            return new Node(value);
        }
        if (value < node.value) {
            node.left = insert(node.left, value);
        } else {
            node.right = insert(node.right, value);
        }
        return node;
    }

    /** 재귀 검색: 있으면 true. 비교 방향을 화면에 남긴다 */
    static boolean search(Node node, int target) {
        if (node == null) {
            return false;                     // 빈 자리까지 내려왔다 → 없다
        }
        System.out.print(node.value + " ");   // 지금 비교하는 노드
        if (target == node.value) {
            return true;
        }
        if (target < node.value) {
            return search(node.left, target);   // 왼쪽 절반만 확인
        }
        return search(node.right, target);      // 오른쪽 절반만 확인
    }

    /** 전위 순회: 자기 자신 → 왼쪽 → 오른쪽 */
    static void preorder(Node node) {
        if (node == null) return;
        System.out.print(node.value + " ");
        preorder(node.left);
        preorder(node.right);
    }

    /** 중위 순회: 왼쪽 → 자기 자신 → 오른쪽 (BST에서는 오름차순!) */
    static void inorder(Node node) {
        if (node == null) return;
        inorder(node.left);
        System.out.print(node.value + " ");
        inorder(node.right);
    }

    /** 후위 순회: 왼쪽 → 오른쪽 → 자기 자신 */
    static void postorder(Node node) {
        if (node == null) return;
        postorder(node.left);
        postorder(node.right);
        System.out.print(node.value + " ");
    }

    /** 레벨 순회: 큐를 사용해 위에서 아래로, 같은 층은 왼쪽에서 오른쪽으로 */
    static void levelOrder(Node root) {
        if (root == null) return;
        Queue<Node> queue = new ArrayDeque<>();   // 6강에서 배운 큐!
        queue.offer(root);
        while (!queue.isEmpty()) {
            Node node = queue.poll();             // 앞에서 하나 꺼내고
            System.out.print(node.value + " ");
            if (node.left != null) queue.offer(node.left);    // 자식들을 뒤에 넣는다
            if (node.right != null) queue.offer(node.right);
        }
    }

    public static void main(String[] args) {
        int[] values = {50, 30, 70, 20, 40, 60};

        Node root = null;
        for (int value : values) {
            root = insert(root, value);
        }
        System.out.println("삽입 순서: 50 30 70 20 40 60");
        System.out.println();

        System.out.print("전위 순회 (자신→왼쪽→오른쪽): ");
        preorder(root);
        System.out.println();

        System.out.print("중위 순회 (왼쪽→자신→오른쪽): ");
        inorder(root);
        System.out.println();

        System.out.print("후위 순회 (왼쪽→오른쪽→자신): ");
        postorder(root);
        System.out.println();

        System.out.print("레벨 순회 (위→아래, 큐 사용) : ");
        levelOrder(root);
        System.out.println();
        System.out.println();

        System.out.print("40 검색 — 지나간 노드: ");
        boolean found40 = search(root, 40);
        System.out.println("→ " + (found40 ? "발견" : "없음"));

        System.out.print("65 검색 — 지나간 노드: ");
        boolean found65 = search(root, 65);
        System.out.println("→ " + (found65 ? "발견" : "없음"));
    }
}

    09잘못된 코드와 오류 찾기

    트리 코드에서 초보자가 가장 자주 만드는 오류 두 가지 — 코드를 먼저 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 삽입 결과를 버려서 트리가 자라지 않음

    10복잡도 및 특성 분석

    복잡도 분석 = "데이터가 많아지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 트리에서는 "몇 개의 노드를 방문하는가"와 "몇 층을 내려가는가"만 세어 봅니다.

    입력 크기 — 무엇이 많아지는가?

    • 노드 수 n — 트리에 담긴 값(부서, 폴더)의 개수
    • 높이 h — 루트에서 가장 먼 리프까지 몇 층인가 (건물의 층수라고 생각하기)
    • 같은 n이라도 모양에 따라 h가 크게 달라짐
      • 양쪽으로 고르게 퍼진 균형 트리: h ≈ log₂n — 노드 100만 개여도 약 20층
      • 한쪽으로만 자란 치우친 트리: h = n − 1 — 노드 100만 개면 약 100만 층 (한 줄로 늘어선 기차)

    주요 연산 — 무엇을 세는가?

    • 프로그램에서 가장 많이 반복되는 한 동작만 세면 충분
    • 순회(전위·중위·후위·레벨): 노드 하나를 방문(출력)하는 한 번
    • BST 검색·삽입: 찾는 값과 노드 값을 비교하는 한 번 — 비교 한 번마다 한 층씩 내려감

    시간 복잡도 — 얼마나 오래 걸리는가?

    연산예제 트리 (노드 6개)노드 100만 개 — 균형노드 100만 개 — 치우침Big-O (균형 / 치우침)
    순회 (전위·중위·후위·레벨)6번 방문100만 번100만 번O(n) / O(n)
    BST 검색최대 3번 비교약 20번최대 약 100만 번O(log n) / O(n)
    BST 삽입최대 3번 비교약 20번최대 약 100만 번O(log n) / O(n)
    • 순회는 모양과 무관하게 O(n): 모든 노드를 정확히 한 번씩 방문 — 출석부를 끝까지 한 번 읽는 것과 같음
    • 검색·삽입은 높이 h에 비례: 비교 한 번마다 한 층 내려가므로 최대 h + 1번 비교
      • 예제 트리는 높이 2 → 어떤 값이든 비교 3번 안에 찾거나 "없음"을 확정 (65 검색: 50 → 70 → 60 → 없음)
    • O(log n)을 쉽게 말하면: 데이터가 2배 늘어도 비교는 1번만 늘어남 — 갈림길마다 절반을 버리므로 5강 이진 탐색과 같은 숫자(100만 개 → 약 20번)
    • 치우치면 O(n): 정렬된 순서(10, 20, 30, …)로 넣으면 오른쪽으로만 자라 사실상 연결 리스트 — 버릴 "반대쪽"이 없어서 하나씩 다 내려가야 함

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 트리 자체: 노드 n개를 저장 → O(n)
    • 재귀 순회·검색·삽입: 호출 스택이 최대 높이 h만큼 쌓임 → O(h)
      • 균형 트리라면 100만 개여도 약 20칸, 치우친 트리라면 약 100만 칸 — 7강에서 본 StackOverflowError가 날 수 있음
    • 레벨 순회: 큐에 최대 가장 넓은 한 층의 노드 수만큼 쌓임
      • 꽉 찬 트리는 맨 아래층에 노드의 약 절반이 몰려 있으므로 최악에는 O(n)
    한 줄 정리 — 트리의 속도는 높이가 정한다
    • 순회는 언제나 n번, 검색·삽입은 높이만큼 — 낮고 넓은 트리는 100만 개도 약 20번, 한 줄로 늘어선 트리는 100만 번

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 정렬된 순서가 필요하면 BST + 중위 순회: BST를 중위 순회하면 항상 오름차순 — "정렬된 상태를 유지하는 자료구조"로 쓰이는 이유 (이 성질은 BST에서만 성립)
    • 삽입 순서가 모양을 정한다: 같은 값이라도 50부터 넣으면 균형 트리, 20부터 오름차순으로 넣으면 오른쪽으로만 자라는 막대기
      • 그래서 실무 라이브러리(TreeMap 등)는 스스로 균형을 다시 잡는 트리(레드-블랙 트리)를 사용 — 원리는 오늘 배운 BST와 같음
    • 재귀 깊이 = 트리 높이: 순회 재귀의 최대 깊이는 h + 1 — 높이가 낮을수록 시간뿐 아니라 스택 메모리도 절약
    • 위층부터 층별로 봐야 하면 레벨 순회(큐), 끝까지 파고들어야 하면 재귀 순회 — 9강의 BFS·DFS로 이어짐

    • 인원 합산: 자신의 인원 + 모든 하위 부서의 합산 결과 — 서브트리 단위 집계

    import java.util.ArrayList;
import java.util.List;

public class OrgChartApplication {

    /** 조직도의 부서: 자식 수가 정해져 있지 않으므로 List로 관리하는 일반 트리 */
    static class Dept {
        String name;
        int headcount;                            // 이 부서에 직접 소속된 인원
        List<Dept> children = new ArrayList<>();  // 하위 부서 목록

        Dept(String name, int headcount) {
            this.name = name;
            this.headcount = headcount;
        }

        void add(Dept child) {
            children.add(child);
        }
    }

    /** 부서 구조를 들여쓰기로 출력한다 (전위 순회: 자신 먼저, 그다음 하위 부서) */
    static void printOrg(Dept dept, int depth) {
        System.out.println("  ".repeat(depth) + dept.name + " (" + dept.headcount + "명)");
        for (Dept child : dept.children) {
            printOrg(child, depth + 1);           // 각 하위 부서에 대해 재귀
        }
    }

    /** 이름으로 부서를 찾는다. 없으면 null */
    static Dept findDept(Dept dept, String name) {
        if (dept.name.equals(name)) {
            return dept;                          // 자기 자신이 찾는 부서다
        }
        for (Dept child : dept.children) {
            Dept found = findDept(child, name);   // 하위 부서에서 재귀로 찾는다
            if (found != null) {
                return found;                     // 찾았으면 즉시 위로 전달
            }
        }
        return null;                              // 이 서브트리에는 없다
    }

    /** 이 부서와 모든 하위 부서의 인원 합계 */
    static int totalHeadcount(Dept dept) {
        int total = dept.headcount;               // 자신의 인원부터
        for (Dept child : dept.children) {
            total += totalHeadcount(child);       // 하위 부서의 합을 더한다
        }
        return total;
    }

    public static void main(String[] args) {
        // 조직도 데이터 만들기
        Dept ceo = new Dept("대표이사실", 2);

        Dept support = new Dept("경영지원본부", 3);
        support.add(new Dept("인사팀", 4));
        support.add(new Dept("재무팀", 5));

        Dept product = new Dept("제품개발본부", 2);
        product.add(new Dept("상품기획팀", 6));
        product.add(new Dept("품질관리팀", 7));

        Dept sales = new Dept("영업마케팅본부", 3);
        sales.add(new Dept("온라인영업팀", 8));
        sales.add(new Dept("오프라인영업팀", 9));
        sales.add(new Dept("마케팅팀", 5));

        ceo.add(support);
        ceo.add(product);
        ceo.add(sales);

        System.out.println("== 조직도 ==");
        printOrg(ceo, 0);

        System.out.println();
        System.out.println("== 부서 검색 ==");
        Dept found = findDept(ceo, "품질관리팀");
        System.out.println("품질관리팀 → " + (found == null ? "없음" : "찾음 (소속 " + found.headcount + "명)"));
        Dept missing = findDept(ceo, "디자인팀");
        System.out.println("디자인팀 → " + (missing == null ? "없음" : "찾음"));

        System.out.println();
        System.out.println("== 인원 합산 ==");
        System.out.println("회사 전체 인원: " + totalHeadcount(ceo) + "명");
        System.out.println("제품개발본부 산하 인원(본부 포함): " + totalHeadcount(product) + "명");
    }
}

    • 이진 트리와의 차이는 반복문 하나뿐: left/right 두 번의 재귀가 for (Dept child : dept.children) 반복 속 재귀로 바뀌었을 뿐, 구조는 같습니다.

static int countNodes(Node node) {
    if (node == null) {
        return 0;
    }
    return 1 + countNodes(node.left) + countNodes(node.right);
}

/** BST의 최댓값: 오른쪽 자식이 없어질 때까지 오른쪽으로만 내려간다 */
static int maxValue(Node node) {
    if (node.right == null) {
        return node.value;
    }
    return maxValue(node.right);
}

    Java OrgTreeSolution.java 
    import java.util.ArrayList;
import java.util.List;

public class OrgTreeSolution {

    /** 조직도의 부서 노드: 하위 부서가 몇 개든 담을 수 있는 일반 트리 */
    static class Dept {
        String name;
        List<Dept> children = new ArrayList<>();

        Dept(String name) {
            this.name = name;
        }

        void add(Dept child) {
            children.add(child);
        }
    }

    /** 요구사항 1: 전위 순회로 전체 부서를 들여쓰기와 함께 출력한다. */
    static void printOrgChart(Dept dept, int depth) {
        System.out.println("  ".repeat(depth) + dept.name);   // 1. 자기 자신 먼저 (전위)
        for (Dept child : dept.children) {
            printOrgChart(child, depth + 1);                  // 2. 하위 부서는 한 칸 더 들여쓰기
        }
    }

    /** 요구사항 2: 이름이 일치하는 부서를 찾아 반환한다. 없으면 null. */
    static Dept findDept(Dept dept, String name) {
        if (dept.name.equals(name)) {
            return dept;                       // 자기 자신이 정답
        }
        for (Dept child : dept.children) {
            Dept found = findDept(child, name);
            if (found != null) {
                return found;                  // 하위에서 찾았으면 즉시 위로 전달
            }
        }
        return null;                           // 이 서브트리에는 없다
    }

    /** 요구사항 3: 트리의 높이 = 루트에서 가장 먼 부서까지의 간선 수. 리프는 0. */
    static int height(Dept dept) {
        if (dept.children.isEmpty()) {
            return 0;                          // 리프 노드의 높이는 0
        }
        int maxChildHeight = 0;
        for (Dept child : dept.children) {
            int childHeight = height(child);
            if (childHeight > maxChildHeight) {
                maxChildHeight = childHeight;  // 가장 높은 자식을 기억한다
            }
        }
        return maxChildHeight + 1;             // 자식까지 내려가는 간선 1개를 더한다
    }

    /** 요구사항 4: 이 부서를 포함한 전체 부서 수를 반환한다. */
    static int countDepts(Dept dept) {
        int count = 1;                         // 자기 자신
        for (Dept child : dept.children) {
            count += countDepts(child);        // 하위 부서 수를 모두 더한다
        }
        return count;
    }

    public static void main(String[] args) {
        // 회사 조직도 데이터 (수정하지 마세요)
        Dept company = new Dept("민들레소프트");

        Dept management = new Dept("경영지원본부");
        management.add(new Dept("인사팀"));
        management.add(new Dept("재무팀"));

        Dept dev = new Dept("개발본부");
        dev.add(new Dept("프론트엔드팀"));
        dev.add(new Dept("백엔드팀"));
        dev.add(new Dept("데이터팀"));

        Dept sales = new Dept("영업본부");
        sales.add(new Dept("국내영업팀"));
        sales.add(new Dept("해외영업팀"));

        company.add(management);
        company.add(dev);
        company.add(sales);

        System.out.println("== 1) 전체 부서 구조 (전위 순회) ==");
        printOrgChart(company, 0);

        System.out.println();
        System.out.println("== 2) 부서 검색 ==");
        Dept found = findDept(company, "백엔드팀");
        System.out.println("\"백엔드팀\" 검색 → " + (found == null ? "없음" : "찾음"));
        Dept missing = findDept(company, "디자인팀");
        System.out.println("\"디자인팀\" 검색 → " + (missing == null ? "없음" : "찾음"));

        System.out.println();
        System.out.println("== 3) 트리 높이 ==");
        System.out.println("높이(루트에서 가장 먼 부서까지의 간선 수): " + height(company));

        System.out.println();
        System.out.println("== 4) 부서 수 ==");
        System.out.println("전체 부서 수: " + countDepts(company));
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. printOrgChart — 전위 순회의 정의 그대로입니다: 자신 먼저, 자식은 나중에. 출력을 재귀 호출 앞에 두는 위치가 곧 "전위"입니다.
    2. findDept — 자식의 결과를 found 변수로 받아 null이 아닐 때만 반환하는 것이 핵심입니다. 결과 확인 없이 return findDept(child, name);이라고 쓰면 첫 자식 서브트리만 검색하고 끝나 버립니다.
    3. countDepts — "1 + 자식들의 합". 실습 3의 countNodes에서 left/right 두 번의 재귀가 for 반복 속 재귀로 바뀐 것뿐입니다.
    4. height — 자식들의 높이 중 최댓값에 1을 더합니다. 합계가 아니라 최댓값인 이유는, 높이는 "가장 먼 리프까지"의 거리이기 때문입니다. 2강에서 배운 최댓값 찾기 패턴이 재귀 안에 들어간 형태입니다.

    복잡도 분석

    • printOrgChart, countDepts, height: 모든 부서를 정확히 1번 방문 → O(n).
    • findDept: 최선 1번(루트가 정답), 최악 n번(없는 이름) → O(n). 일반 트리에는 BST 같은 정렬 규칙이 없어 절반 버리기가 불가능합니다.
    • 공간: 재귀 깊이 = 조직도 높이 → O(h). 이 데이터에서는 최대 3층입니다.

    자주 발생하는 오류

    • findDept에서 자식의 결과를 확인하지 않고 바로 반환해, 두 번째 이후 본부가 검색되지 않는 경우.
    • height에서 최댓값 대신 +1을 자식마다 누적해 높이가 부서 수처럼 커지는 경우.
    • countDepts에서 자신(1)을 빼먹어 결과가 10이 나오는 경우.
    • printOrgChart에서 출력을 재귀 뒤에 두어(후위) 하위 팀이 본부보다 먼저 나오는 경우.

    다른 해결 방법

    네 기능 모두 6강의 큐(레벨 순회)나 스택을 이용한 반복문 버전으로도 구현할 수 있습니다. 예를 들어 부서 수 세기는 큐에 루트를 넣고, 꺼낼 때마다 세면서 자식들을 다시 넣으면 됩니다. 재귀 버전이 짧고 읽기 쉽지만, 조직도가 수만 층처럼 극단적으로 깊다면 호출 스택 초과를 피할 수 있는 반복문 버전이 안전합니다. 높이 계산은 Math.max(maxChildHeight, childHeight)를 써서 한 줄로 줄일 수도 있습니다.

    15오늘의 핵심 정리

    • 트리는 루트에서 시작해 부모-자식으로 갈라지는 계층 구조다. 리프는 자식이 없는 노드, 높이는 루트에서 가장 먼 리프까지의 간선 수다.
    • 트리는 특별한 문법이 아니라 참조(left/right 또는 children 리스트)를 가진 객체들의 연결이다.
    • 순회는 모든 노드를 한 번씩 방문하는 규칙이다: 전위(자신→왼→오), 중위(왼→자신→오), 후위(왼→오→자신)는 재귀로, 레벨 순회는 6강의 큐로 구현한다.
    • 트리 재귀의 종료 조건은 if (node == null) return; — 첫 줄은 무조건 null 검사를 습관으로 만들자.
    • BST는 "작으면 왼쪽, 크거나 같으면 오른쪽" 규칙으로 5강의 절반 버리기를 구조화한 트리다. 중위 순회하면 항상 오름차순이고, 탐색·삽입은 균형 트리에서 O(log n), 치우친 트리에서 O(n)이다.
    • 재귀 insert의 반환값은 반드시 root나 node.left/node.right에 다시 대입해야 트리가 연결된다.
    • 조직도·폴더 구조 같은 실전 데이터는 자식 목록을 List로 갖는 일반 트리로 표현하고, 검색·집계·높이 계산을 모두 "자신 + 자식들의 결과" 재귀 패턴으로 처리한다.

지도 앱은 어떻게 "가장 빠른 길"을 몇 초 만에 찾아낼까요? 이번 강의에서는 9강의 그래프, 10강의 그리디 선택, 11강의 점화식이 하나로 합쳐진 다익스트라(Dijkstra) 알고리즘을 배웁니다. 무가중치 BFS에서 출발해, 가중치가 생기면 왜 BFS가 실패하는지 확인하고, 거리 배열과 완화(relaxation)로 다익스트라를 단계적으로 완성합니다.

      • 그래프 표현(9강) 위에서

      • 점화식 모양의 거리 갱신(11강)으로 거리를 좁힘

    2. 복습 — 무가중치라면 9강의 BFS로 충분하다

    모든 간선의 가중치가 같다면(예: 전부 1) 최단 경로 = 간선 수가 가장 적은 경로이고, 이것은 9강 BFS가 정확히 찾아 줍니다. 캠퍼스 그래프에서 가중치를 무시하고 BFS를 돌려 봅시다.

    Java BfsShortestPath.java 
    import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Queue;

public class BfsShortestPath {

    /** 간선: 도착 정점과 가중치. BFS는 가중치를 무시한다 — 비교 출력에만 사용한다 */
    static class Edge {
        int to;
        int weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    static void addEdge(List<List<Edge>> graph, int u, int v, int weight) {
        graph.get(u).add(new Edge(v, weight));
        graph.get(v).add(new Edge(u, weight));
    }

    /** u-v 간선의 가중치를 찾는다 (경로의 이동 시간 합을 계산할 때 사용) */
    static int findWeight(List<List<Edge>> graph, int u, int v) {
        for (Edge e : graph.get(u)) {
            if (e.to == v) {
                return e.weight;
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        String[] names = {"A", "B", "C", "D", "E", "F"};
        int n = names.length;

        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }
        addEdge(graph, 0, 1, 3);  // A-B
        addEdge(graph, 0, 2, 7);  // A-C
        addEdge(graph, 1, 2, 2);  // B-C
        addEdge(graph, 1, 3, 6);  // B-D
        addEdge(graph, 2, 3, 4);  // C-D
        addEdge(graph, 2, 4, 8);  // C-E
        addEdge(graph, 3, 4, 1);  // D-E
        addEdge(graph, 3, 5, 5);  // D-F
        addEdge(graph, 4, 5, 3);  // E-F

        // 9강에서 배운 BFS 최단 거리: 방문 순서대로 "간선 수"가 확정된다
        int start = 0;
        int[] hops = new int[n];      // 최소 간선 수 (-1 = 아직 방문 안 함)
        int[] prev = new int[n];      // 경로 복원용 직전 정점
        Arrays.fill(hops, -1);
        Arrays.fill(prev, -1);

        Queue<Integer> queue = new ArrayDeque<>();
        hops[start] = 0;
        queue.add(start);

        while (!queue.isEmpty()) {
            int u = queue.poll();
            for (Edge e : graph.get(u)) {
                if (hops[e.to] == -1) {          // 처음 도착한 정점만
                    hops[e.to] = hops[u] + 1;    // 간선 수 = 직전 정점 + 1
                    prev[e.to] = u;
                    queue.add(e.to);
                }
            }
        }

        System.out.println("[BFS] A에서 각 정점까지의 최소 간선 수:");
        for (int v = 0; v < n; v++) {
            System.out.println("  A -> " + names[v] + " : 간선 " + hops[v] + "개");
        }

        // BFS가 찾은 A -> C 경로를 복원하고, 그 경로의 "이동 시간 합"을 계산해 본다
        int target = 2;   // C
        StringBuilder path = new StringBuilder(names[target]);
        int timeSum = 0;
        int v = target;
        while (prev[v] != -1) {
            timeSum += findWeight(graph, prev[v], v);
            v = prev[v];
            path.insert(0, names[v] + " -> ");
        }

        System.out.println();
        System.out.println("BFS가 찾은 A -> C 경로: " + path
                + " (간선 " + hops[target] + "개, 이동 시간 합 " + timeSum + "분)");
        System.out.println("하지만 A -> B -> C 로 가면 3 + 2 = 5분이다!");
        System.out.println("BFS는 간선 수가 가장 적은 경로를 찾을 뿐,");
        System.out.println("가중치(이동 시간)의 합이 최소인 경로는 보장하지 못한다.");
    }
}

  A -> A : 간선 0개

    3. 가중치가 붙는 순간 BFS가 무너진다

    • BFS는 C를 "A에서 간선 1개"로 확정하지만, 그 길은 7분짜리
    • 간선 2개를 건너는 A → B → C는 3 + 2 = 5분으로 더 빠름
    • BFS의 확정 논리는 "먼저 도착한 것이 가장 가깝다"인데, 가중치가 다르면 "먼저 발견"과 "가장 빠름"이 어긋나기 때문
    • 그래서 확정 기준을 간선 수가 아니라 지금까지의 가중치 합으로 바꿔야 함

    4. 거리 배열 — "지금까지 알아낸 최선"의 기록

    • 출발점에서 각 정점까지 지금까지 알아낸 가장 짧은 거리를 배열 dist에 기록
    • 처음에는 출발점만 0이고 나머지는 전부 ∞(모른다)
    • 코드에서는 ∞를 Integer.MAX_VALUE로 표현
    • 여기에 가중치를 더하면 오버플로로 음수가 되므로 ∞인 값에는 절대 덧셈을 하면 안 됨 (실습 코드에서 직접 확인)

    5. 완화(relaxation) — 11강 점화식의 재등장

    정점 u까지의 거리 dist[u]가 확정되었을 때, u의 이웃 v에 대해 "u를 거쳐 가면 더 짧아지는가?"를 검사하고 갱신하는 것이 완화입니다.

    완화 규칙 (오늘의 점화식)
    • dist[v] = min(dist[v], dist[u] + w(u, v))
    • 11강 DP 테이블 갱신 dp[i] = min(dp[i], dp[j] + cost)과 완전히 같은 모양 — "더 좋은 후보를 발견하면 표의 값을 고쳐 쓴다"는 패턴이 그래프 위로 옮겨 온 것뿐

    6. 그리디 확정 — 가장 가까운 미확정 정점은 번복되지 않는다

    • 미확정 정점 중 dist가 가장 작은 정점 u는 그 값이 곧 최종 답
      • 예: A에서 출발해 후보가 B(3분), C(7분)일 때, B는 3분으로 바로 확정해도 됨 — 다른 길로 B에 가려면 C(7분)나 그 너머를 지나야 하므로 3분보다 짧아질 수 없음
    • 이유: u에 다른 경로로 도달하려면 반드시 어떤 미확정 정점 x를 거쳐야 하는데, dist[x] ≥ dist[u]이고 모든 가중치가 0 이상이므로 돌아가는 경로는 절대 dist[u]보다 짧아질 수 없음
    • 10강의 그리디처럼 "한 번 한 선택을 번복하지 않아도 되는" 구조가 성립
    음수 가중치가 있으면 다익스트라를 쓸 수 없다
    • 위 논리는 "가중치 ≥ 0"에 기대고 있음
    • 만약 어떤 간선의 가중치가 음수라면, 멀리 돌아가는 경로가 나중에 합계를 오히려 줄일 수 있어 이미 확정한 거리가 틀릴 수 있음
    • 예: A→B 5, A→C 10, C→B -8이면 다익스트라는 B를 5로 확정하지만 실제 최단은 10 + (-8) = 2
    • 음수 가중치 그래프는 벨만-포드(Bellman-Ford) 같은 다른 알고리즘의 영역 — 오늘은 이름만 기억해 둘 것

    7. 우선순위 큐 복습 — "가장 가까운 정점 뽑기"를 빠르게

    • "미확정 중 최솟값 뽑기"를 매번 배열 전체를 훑어 찾으면 한 번에 O(V)
    • 6강과 10강에서 배운 PriorityQueue는 가장 작은 항목을 O(log V)에 꺼내 주는 자료구조
    • 거리와 정점 번호를 int[]{거리, 정점}으로 묶어 넣고 Comparator.comparingInt(item -> item[0])로 "거리 기준 최소"를 지정하면, poll()이 항상 가장 가까운 후보를 꺼내 줌
    • 단, 같은 정점이 큐에 여러 번 들어갈 수 있으므로(거리가 갱신될 때마다 새로 넣기 때문) 꺼낸 뒤 이미 확정된 정점이면 건너뛰는 처리가 필요 — 실습 코드에서 확인

    8. 경로 복원 — prev 배열

    • 완화로 dist[v]를 갱신하는 순간, "v는 u를 거쳐 왔다"를 prev[v] = u로 기록해 둠
    • 목적지에서 prev를 따라 거꾸로 올라가면 출발점까지의 경로가 복원됨
    • 예: 캠퍼스 그래프에서 F는 E를, E는 D를, D는 B를, B는 A를 거쳐 왔다면 F → E → D → B → A로 거슬러 올라간 뒤 뒤집어 A → B → D → E → F

    06단계별 동작 과정

    04 실제 문제 상황의 캠퍼스 그래프(건물 A~F 6개, 길 9개)에서 A를 출발점으로 다익스트라가 진행되는 모습을 단계별로 확인 — 처음에는 A만 0분, 나머지는 ∞(모름). 다음 단계 ▶ 버튼으로 한 단계씩 진행. 파란색(현재)은 이번 회차에 확정하는 정점, 앰버색(비교 중)은 완화로 거리가 갱신된 정점, 초록색(확정)은 최단 거리가 확정된 정점. 정점 아래 숫자는 현재 dist 값이고, 오른쪽 표에서 같은 값을 함께 볼 수 있음. "새 데이터" 버튼을 누르면 출발 정점이 무작위로 바뀜.

    시각화 마지막 단계에서 확정 순서가 거리가 작은 순서(A 0 → B 3 → C 5 → D 9 → E 10 → F 13)와 일치함을 확인 — BFS가 "간선 수가 적은 층부터" 확정하듯, 다익스트라는 "총 시간이 짧은 정점부터" 확정합니다. 그래서 다익스트라를 가중치 그래프 위의 BFS라고 부르기도 합니다.

    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)
    • ∞는 "아직 모름(무한대)", (u, v, w)는 "u에서 v로 가는 가중치 w인 간선"
    Pseudo 다익스트라 — 배열 버전 
    알고리즘 Dijkstra(graph, start)
    모든 정점 v에 대해 dist[v] ← ∞, visited[v] ← 거짓, prev[v] ← 없음
    dist[start] ← 0

    정점 수만큼 반복:
        u ← 미확정 정점 중 dist가 가장 작은 정점     // 그리디 선택 (10강)
        u가 없으면 반복 종료                         // 남은 정점은 도달 불가
        visited[u] ← 참                              // u의 최단 거리 확정

        u의 모든 간선 (u, v, w)에 대해:
            dist[u] + w < dist[v] 이면:              // 완화 (11강 점화식)
                dist[v] ← dist[u] + w
                prev[v] ← u                          // 경로 복원용 기록

    dist와 prev를 반환한다

    코드 설명 — 배열 버전

    • 모든 정점 v에 대해 dist[v] ← ∞, visited[v] ← 거짓, prev[v] ← 없음 — 준비 단계. 모든 정점의 거리를 "모름(∞)"으로, 확정 여부를 "아직 아님"으로, 직전 정점을 "없음"으로 초기화
    • dist[start] ← 0 — 출발점까지의 거리는 당연히 0 (제자리)
    • 정점 수만큼 반복: — 한 바퀴에 정점 하나씩 확정하므로 최대 V바퀴면 모든 정점이 확정됨
    • u ← 미확정 정점 중 dist가 가장 작은 정점 — 아직 확정되지 않은 정점들 중 가장 가까운 곳을 고름 (그리디 선택)
      • 배열 버전은 이 정점을 찾으려고 dist 배열을 처음부터 끝까지 훑음 — 한 번에 V칸 확인
    • u가 없으면 반복 종료 — 남은 미확정 정점이 전부 ∞라면 출발점에서 갈 방법이 없는 정점들뿐이므로 더 볼 필요가 없음
    • visited[u] ← 참 — u의 거리를 최종 답으로 확정. 이후 다시 뽑히지 않음
    • u의 모든 간선 (u, v, w)에 대해: — 방금 확정한 u에서 한 번에 갈 수 있는 이웃 v를 하나씩 살펴봄
    • dist[u] + w < dist[v] 이면: — "u를 거쳐 v로 가는 길"이 지금까지 알던 v까지의 거리보다 짧은지 검사 (완화)
      • 예: dist[B] = 3, B-C 가중치 2, dist[C] = 7이면 3 + 2 = 5 < 7 → C를 5로 고침
    • dist[v] ← dist[u] + w — 더 짧은 길을 찾았으니 v의 거리를 새 값으로 고쳐 씀
    • prev[v] ← u — "v에는 u를 거쳐 왔다"고 메모. 나중에 이 메모를 거꾸로 따라가 경로를 복원
    • dist와 prev를 반환한다 — 모든 정점까지의 최단 거리(dist)와 경로 복원용 메모(prev)를 돌려줌
    Pseudo 다익스트라 — 우선순위 큐 버전 
    알고리즘 DijkstraPQ(graph, start)
    dist[start] ← 0, 나머지는 ∞
    우선순위 큐 pq에 (0, start)를 넣는다             // 항목 = (거리, 정점)

    pq가 빌 때까지 반복:
        (d, u) ← pq에서 거리가 가장 작은 항목        // O(log V) 꺼내기 (6·10강)
        u가 이미 확정이면 건너뛴다                   // 낡은 항목 무시
        u를 확정한다

        u의 모든 간선 (u, v, w)에 대해:
            d + w < dist[v] 이면:                    // 완화
                dist[v] ← d + w
                prev[v] ← u
                pq에 (dist[v], v)를 넣는다           // 갱신된 새 거리로 넣기

    dist와 prev를 반환한다

    코드 설명 — 우선순위 큐 버전

    • dist[start] ← 0, 나머지는 ∞ — 배열 버전과 같은 준비 단계
    • 우선순위 큐 pq에 (0, start)를 넣는다 — 큐에 "(거리, 정점)" 쌍을 넣음. 처음에는 출발점 하나만 거리 0으로 대기
    • pq가 빌 때까지 반복: — 배열 버전의 "정점 수만큼 반복" 대신, 처리할 후보가 남아 있는 동안 계속 진행
    • (d, u) ← pq에서 거리가 가장 작은 항목 — 우선순위 큐가 가장 가까운 후보를 바로 꺼내 줌
      • 배열을 전부 훑을 필요가 없어 한 번에 O(log V) — 이것이 배열 버전과의 유일한 차이
    • u가 이미 확정이면 건너뛴다 — 같은 정점이 큐에 여러 번 들어 있을 수 있으므로, 이미 확정된 정점의 낡은 항목은 무시
      • 예: C는 처음에 (7, C)로, B를 거친 뒤 (5, C)로 또 들어감 → (5, C)가 먼저 꺼내져 확정되고, 나중에 나온 (7, C)는 버림
    • u를 확정한다 — 큐에서 처음 꺼낸 순간의 거리 d가 u의 최종 답
    • u의 모든 간선 (u, v, w)에 대해: / d + w < dist[v] 이면: — 배열 버전과 똑같은 완화 검사
    • dist[v] ← d + w, prev[v] ← u — 더 짧은 거리로 고쳐 쓰고, 어디서 왔는지 메모
    • pq에 (dist[v], v)를 넣는다 — 갱신된 새 거리로 v를 큐에 다시 넣음. 옛 항목을 지우지 않고 새로 넣기만 하므로 위의 "건너뛰기"가 필요해짐
    • dist와 prev를 반환한다 — 결과는 배열 버전과 완전히 같음

    두 버전 비교

    • 두 버전의 차이는 오직 "미확정 중 최솟값을 어떻게 찾는가"뿐
    • 배열 버전은 매번 전체를 훑고(O(V)), 큐 버전은 우선순위 큐가 대신 찾아 줌(O(log V))
    • 완화 규칙과 확정 논리는 완전히 같음

    08실습 코드

    의사코드(07)의 우선순위 큐 버전을 Java로 옮깁니다. 배열 버전 대신 큐 버전을 구현하는 이유는 — "미확정 정점 중 dist가 가장 작은 정점을 찾는" 그리디 선택을 매번 전체 배열을 훑지 않고(O(V)), PriorityQueue(6·10강)가 O(log V)에 대신 찾아 주기 때문입니다.

    • 완화(relaxation) 규칙 dist[u] + w < dist[v]와 prev[v] ← u 기록은 07 의사코드 두 버전에서 완전히 같음 — 달라지는 것은 다음 정점을 찾는 방법뿐
    • 큐 항목은 int[]{거리, 정점 번호}이고, 거리가 갱신될 때마다 새 항목을 넣기 때문에 같은 정점이 큐에 여러 번 들어갈 수 있음
    • 그래서 꺼낸 뒤 visited로 낡은 항목을 건너뛰는 한 줄이 반드시 필요
    Java DijkstraComplete.java 
    import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.List;
import java.util.PriorityQueue;

public class DijkstraComplete {

    static final int INF = Integer.MAX_VALUE;

    /** 간선 정보: 도착 정점 번호와 가중치(이동 시간) */
    static class Edge {
        int to;
        int weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    /** 다익스트라 결과: 최단 거리 배열 + 경로 복원용 직전 정점 배열 */
    static class Result {
        int[] dist;
        int[] prev;

        Result(int[] dist, int[] prev) {
            this.dist = dist;
            this.prev = prev;
        }
    }

    static void addEdge(List<List<Edge>> graph, int u, int v, int weight) {
        graph.get(u).add(new Edge(v, weight));
        graph.get(v).add(new Edge(u, weight));
    }

    /**
     * 우선순위 큐 버전 다익스트라.
     * 큐 항목은 {거리, 정점 번호} 배열 — 거리가 작은 항목부터 나온다(10강의 PriorityQueue).
     * pickClosest의 O(V) 훑기를 큐의 O(log V) 꺼내기로 바꾼 것이다.
     */
    static Result dijkstra(List<List<Edge>> graph, int start) {
        int n = graph.size();
        int[] dist = new int[n];
        int[] prev = new int[n];
        boolean[] visited = new boolean[n];
        Arrays.fill(dist, INF);
        Arrays.fill(prev, -1);
        dist[start] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(item -> item[0]));
        pq.add(new int[]{0, start});

        while (!pq.isEmpty()) {
            int[] item = pq.poll();      // 미확정 정점 중 거리가 가장 작은 항목
            int d = item[0];
            int u = item[1];
            if (visited[u]) {
                continue;                // 이미 확정된 정점의 낡은 항목은 건너뛴다
            }
            visited[u] = true;           // u까지의 최단 거리 확정

            for (Edge e : graph.get(u)) {
                int newDist = d + e.weight;
                if (newDist < dist[e.to]) {              // 완화 조건
                    dist[e.to] = newDist;
                    prev[e.to] = u;                      // 경로 복원용: 어디서 왔는지 기록
                    pq.add(new int[]{newDist, e.to});    // 갱신된 "새" 거리로 넣는다
                }
            }
        }
        return new Result(dist, prev);
    }

    /** prev 배열을 도착점에서 출발점까지 거슬러 올라가 경로 문자열을 만든다 */
    static String buildPath(int[] prev, String[] names, int end) {
        StringBuilder path = new StringBuilder(names[end]);
        int v = end;
        while (prev[v] != -1) {
            v = prev[v];
            path.insert(0, names[v] + " -> ");
        }
        return path.toString();
    }

    static String show(int d) {
        return d == INF ? "∞" : String.valueOf(d);
    }

    public static void main(String[] args) {
        String[] names = {"A", "B", "C", "D", "E", "F"};
        int n = names.length;

        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }
        addEdge(graph, 0, 1, 3);  // A-B
        addEdge(graph, 0, 2, 7);  // A-C
        addEdge(graph, 1, 2, 2);  // B-C
        addEdge(graph, 1, 3, 6);  // B-D
        addEdge(graph, 2, 3, 4);  // C-D
        addEdge(graph, 2, 4, 8);  // C-E
        addEdge(graph, 3, 4, 1);  // D-E
        addEdge(graph, 3, 5, 5);  // D-F
        addEdge(graph, 4, 5, 3);  // E-F

        int start = 0;
        Result result = dijkstra(graph, start);

        System.out.println("출발 정점: " + names[start]);
        System.out.println("도착 | 최단 거리 | 경로");
        System.out.println("-----+----------+------------------------------");
        for (int v = 0; v < n; v++) {
            System.out.printf("   %s | %8s | %s%n",
                    names[v], show(result.dist[v]), buildPath(result.prev, names, v));
        }
    }
}

    09잘못된 코드와 오류 찾기

    다익스트라에서 초보자가 가장 자주 만드는 오류 두 가지입니다. 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요. 두 코드 모두 컴파일은 되고, 조용히 틀린 답을 냅니다 — 가장 위험한 종류의 오류입니다.

    오류 1 — 확정된 정점을 자꾸 다시 뽑는 선택 함수

    Java BuggyPickClosest.java (오류 있음) 
    import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class BuggyPickClosest {

    static final int INF = Integer.MAX_VALUE;

    static class Edge {
        int to;
        int weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    static void addEdge(List<List<Edge>> graph, int u, int v, int weight) {
        graph.get(u).add(new Edge(v, weight));
        graph.get(v).add(new Edge(u, weight));
    }

    /** 미확정 정점 중 최솟값을 찾으려고 했는데... 무엇이 빠졌을까? */
    static int pickClosest(int[] dist, boolean[] visited) {
        int minVertex = -1;
        int minDist = INF;
        for (int v = 0; v < dist.length; v++) {
            if (dist[v] < minDist) {
                minDist = dist[v];
                minVertex = v;
            }
        }
        return minVertex;
    }

    static String show(int d) {
        return d == INF ? "∞" : String.valueOf(d);
    }

    public static void main(String[] args) {
        String[] names = {"A", "B", "C", "D", "E", "F"};
        int n = names.length;

        List<List<Edge>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }
        addEdge(graph, 0, 1, 3);  // A-B
        addEdge(graph, 0, 2, 7);  // A-C
        addEdge(graph, 1, 2, 2);  // B-C
        addEdge(graph, 1, 3, 6);  // B-D
        addEdge(graph, 2, 3, 4);  // C-D
        addEdge(graph, 2, 4, 8);  // C-E
        addEdge(graph, 3, 4, 1);  // D-E
        addEdge(graph, 3, 5, 5);  // D-F
        addEdge(graph, 4, 5, 3);  // E-F

        int[] dist = new int[n];
        boolean[] visited = new boolean[n];
        Arrays.fill(dist, INF);
        dist[0] = 0;

        for (int round = 1; round <= n; round++) {
            int u = pickClosest(dist, visited);
            if (u == -1) {
                break;
            }
            visited[u] = true;
            for (Edge e : graph.get(u)) {
                if (dist[u] + e.weight < dist[e.to]) {
                    dist[e.to] = dist[u] + e.weight;
                }
            }
        }

        System.out.println("A에서 각 정점까지의 최단 거리:");
        for (int v = 0; v < n; v++) {
            System.out.println("  A -> " + names[v] + " : " + show(dist[v]));
        }
    }
}

        addEdge(graph, 4, 5, 3);  // E-F

        int[] dist = new int[n];
        boolean[] visited = new boolean[n];
        Arrays.fill(dist, INF);
        dist[0] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(item -> item[0]));
        pq.add(new int[]{0, 0});
        visited[0] = true;

        while (!pq.isEmpty()) {
            int[] item = pq.poll();
            int u = item[1];
            for (Edge e : graph.get(u)) {
                if (!visited[e.to]) {              // BFS처럼: 처음 본 정점이면
                    visited[e.to] = true;          // 큐에 넣으면서 바로 확정해 버린다!
                    dist[e.to] = dist[u] + e.weight;
                    pq.add(new int[]{dist[e.to], e.to});
                }
            }
        }

        System.out.println("A에서 각 정점까지의 최단 거리:");
        for (int v = 0; v < n; v++) {
            System.out.println("  A -> " + names[v] + " : " + show(dist[v]));
        }
    }
}

    10복잡도 및 특성 분석

    복잡도 분석 = "지도가 커지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 어려운 수식 대신 "몇 번 뽑고, 몇 번 비교하는가"만 세어 봅니다.

    입력 크기 — 무엇이 많아지는가?

    • 그래프는 크기를 두 개의 숫자로 잼
      • V = 정점(장소) 수 — 건물, 도시, 교차로가 많아질수록 커짐
      • E = 간선(길) 수 — 장소 사이를 잇는 길이 많아질수록 커짐
    • 오늘의 캠퍼스 그래프는 V = 6, E = 9

    주요 연산 — 무엇을 세는가?

    • 다익스트라에서 반복되는 동작은 딱 두 가지
      • 뽑기: 미확정 정점 중 가장 가까운 곳을 고르기 — 정점마다 1번씩, 총 V번
      • 완화: "이 길로 가면 더 짧아지나?" 비교하고 고쳐 쓰기 — 길마다 검사, 무방향 그래프에서는 한 길을 양쪽에서 한 번씩 최대 2번, 총 O(E)번
    • 두 버전의 차이는 "뽑기 한 번이 얼마나 오래 걸리는가"뿐

    시간 복잡도 — 얼마나 오래 걸리는가?

    버전뽑기 1회완화 1회전체 Big-O캠퍼스 (V=6, E=9)큰 지도 (V=10,000, E=50,000)
    배열 버전배열 전체 훑기 O(V)O(1)O(V² + E) ≈ O(V²)수십 번약 1억(10⁸) 번
    우선순위 큐 버전 (DijkstraComplete)큐에서 꺼내기 O(log V)갱신 시 큐에 넣기 O(log V)O((V + E) log V)수십 번약 100만(10⁶) 번
    • 배열 버전을 쉽게 말하면: 매번 "누가 제일 가깝지?"를 명단 전체를 처음부터 끝까지 읽어서 찾음 — V번 뽑기 × V칸 읽기 = V²
    • 큐 버전을 쉽게 말하면: 번호표 기계(우선순위 큐)가 가장 가까운 후보를 바로 내어 줌 — 꺼내고 넣을 때마다 log V만큼의 정리만 하면 됨
    • 작은 지도(캠퍼스처럼 정점 수백 개 이하): 두 버전 모두 순식간 — 코드가 단순한 배열 버전도 충분
    • 크고 길이 듬성한(희소) 지도: 1억 번 vs 100만 번, 약 100배 차이 — 우선순위 큐 버전이 압도적으로 유리

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 지도 자체(인접 리스트): 정점마다 목록 하나 + 길마다 항목 — O(V + E)
    • 기록용 배열 dist·prev·visited: 정점마다 한 칸씩 — O(V)
    • 우선순위 큐: 거리가 갱신될 때마다 새 항목을 넣으므로 최악의 경우 길 수만큼 쌓임 — O(E)
    • 모두 합치면 O(V + E) — 지도 크기에 비례하는 만큼만 씀
    한 줄 정리 — 뽑기를 빠르게 하면 전체가 빨라진다
    • 배열 버전 O(V²) → 우선순위 큐 버전 O((V + E) log V), 메모리는 둘 다 O(V + E) 수준
    • 완화 규칙과 확정 논리는 그대로, "가장 가까운 정점 찾기"만 바꿔서 얻은 속도

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 그리디 + 점화식의 합작품: 확정은 그리디(10강), 거리 고쳐 쓰기는 점화식(11강) — 두 강의의 도구가 한 알고리즘 안에서 함께 일하는 대표 사례
    • 음수 가중치에는 쓸 수 없음: "가장 가까운 미확정 정점은 다시 바뀌지 않는다"는 믿음은 모든 가중치가 0 이상일 때만 성립 — 음수 길이 있으면 벨만-포드 등 다른 알고리즘이 필요
    • BFS는 다익스트라의 특별한 경우: 모든 가중치가 1이면 다익스트라의 확정 순서가 BFS의 방문 순서와 같아짐 — 우선순위 큐가 일반 큐처럼 움직이기 때문
    • 한 번 실행으로 모든 목적지: 출발점 하나에서 모든 정점까지의 최단 거리를 한꺼번에 구함(single-source) — 목적지 하나만 필요하면 그 정점이 확정되는 순간 멈춰도 됨

    데이터 모델과 알고리즘 적용 기준

    • 정점: 도시 8개 (서울, 인천, 대전, 전주, 광주, 대구, 울산, 부산)
    • 간선: 직행 노선 11개, 가중치 = 소요 시간(분), 양방향
    • 알고리즘: 가중치가 모두 양수 + 한 출발점에서 모든 도시 → 다익스트라 (우선순위 큐 버전)
    • 추가 요구: 경로 안내가 필요하므로 prev 배열로 경로 복원, 분 단위를 "n시간 m분"으로 표시
    Java ShortestPathApplication.java 
    import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.List;
import java.util.PriorityQueue;

public class ShortestPathApplication {

    static final int INF = Integer.MAX_VALUE;

    /** 간선 정보: 도착 도시 번호와 이동 시간(분) */
    static class Edge {
        int to;
        int weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    /** 다익스트라 결과: 최단 시간 배열 + 경로 복원용 직전 도시 배열 */
    static class Result {
        int[] dist;
        int[] prev;

        Result(int[] dist, int[] prev) {
            this.dist = dist;
            this.prev = prev;
        }
    }

    static void addRoad(List<List<Edge>> map, int u, int v, int minutes) {
        map.get(u).add(new Edge(v, minutes));
        map.get(v).add(new Edge(u, minutes));
    }

    /** 우선순위 큐 버전 다익스트라 (DijkstraComplete와 같은 구조) */
    static Result dijkstra(List<List<Edge>> map, int start) {
        int n = map.size();
        int[] dist = new int[n];
        int[] prev = new int[n];
        boolean[] visited = new boolean[n];
        Arrays.fill(dist, INF);
        Arrays.fill(prev, -1);
        dist[start] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(item -> item[0]));
        pq.add(new int[]{0, start});

        while (!pq.isEmpty()) {
            int[] item = pq.poll();
            int d = item[0];
            int u = item[1];
            if (visited[u]) {
                continue;
            }
            visited[u] = true;

            for (Edge e : map.get(u)) {
                int newDist = d + e.weight;
                if (newDist < dist[e.to]) {
                    dist[e.to] = newDist;
                    prev[e.to] = u;
                    pq.add(new int[]{newDist, e.to});
                }
            }
        }
        return new Result(dist, prev);
    }

    static String buildPath(int[] prev, String[] names, int end) {
        StringBuilder path = new StringBuilder(names[end]);
        int v = end;
        while (prev[v] != -1) {
            v = prev[v];
            path.insert(0, names[v] + " -> ");
        }
        return path.toString();
    }

    /** 분 단위 시간을 "n시간 m분" 형태로 바꾼다 */
    static String formatMinutes(int minutes) {
        if (minutes == INF) {
            return "도달 불가";
        }
        if (minutes < 60) {
            return minutes + "분";
        }
        if (minutes % 60 == 0) {
            return (minutes / 60) + "시간";
        }
        return (minutes / 60) + "시간 " + (minutes % 60) + "분";
    }

    public static void main(String[] args) {
        // 도시 8개와 고속버스 노선 11개 (이동 시간: 분)
        String[] cities = {"서울", "인천", "대전", "전주", "광주", "대구", "울산", "부산"};
        int n = cities.length;

        List<List<Edge>> map = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            map.add(new ArrayList<>());
        }
        addRoad(map, 0, 1, 40);   // 서울-인천
        addRoad(map, 0, 2, 65);   // 서울-대전
        addRoad(map, 1, 2, 95);   // 인천-대전
        addRoad(map, 2, 3, 50);   // 대전-전주
        addRoad(map, 2, 5, 70);   // 대전-대구
        addRoad(map, 3, 4, 45);   // 전주-광주
        addRoad(map, 3, 5, 85);   // 전주-대구
        addRoad(map, 4, 7, 140);  // 광주-부산
        addRoad(map, 5, 6, 50);   // 대구-울산
        addRoad(map, 5, 7, 65);   // 대구-부산
        addRoad(map, 6, 7, 30);   // 울산-부산

        int start = 0;   // 서울
        Result result = dijkstra(map, start);

        System.out.println("[고속버스 내비게이션] 출발: " + cities[start]);
        System.out.println();
        System.out.println("도착 | 소요 시간     | 추천 경로");
        System.out.println("-----+--------------+------------------------------");
        for (int v = 0; v < n; v++) {
            if (v == start) {
                continue;
            }
            System.out.printf("%s | %-12s | %s%n",
                    cities[v], formatMinutes(result.dist[v]),
                    buildPath(result.prev, cities, v));
        }

        System.out.println();
        System.out.println("가장 오래 걸리는 도시: " + cities[7] + " ("
                + formatMinutes(result.dist[7]) + ")");
        System.out.println("부산행은 광주 경유(65+50+45+140=300분)보다 대구 경유가 100분 빠르다.");
    }
}

    문제 제목 — 동네 길찾기 "PathFinder"

    문제 배경

    여러분은 동네 커뮤니티 앱에 "도보 길찾기" 기능을 만들게 되었습니다. 동네 장소 7곳(집, 카페, 학교, 도서관, 공원, 병원, 체육관) 사이의 길마다 걷는 시간(분)이 조사되어 있고, 이용자가 목적지를 고르면 집에서 그곳까지의 최소 도보 시간과 경로를 보여 줘야 합니다. 주의할 점 두 가지 — 새로 지은 체육관은 진입로가 공사 중이라 연결된 길이 없으므로 이런 목적지는 엉뚱한 숫자 대신 "도달 불가"로 안내해야 하고, 출발지와 목적지가 같은 경우(집 → 집)도 0분으로 자연스럽게 처리되어야 합니다.

    프로그램 목표

    배열 버전 다익스트라로 집에서 모든 장소까지의 최단 시간을 구하고, prev 배열로 경로를 복원하여 "시간 + 경로"를 출력하는 콘솔 프로그램을 완성합니다.

    필수 요구사항

    1. pickClosest(int[] dist, boolean[] visited) — 미확정 장소 중 거리가 가장 작은 번호를 반환한다. 없으면 -1.
    2. dijkstra(List<List<Edge>> map, int start) — 뽑기 → 확정 → 완화를 반복하고, 완화 시 prev를 기록한다.
    3. buildPath(int[] prev, String[] names, int end) — prev를 거슬러 올라가 "집 -> 카페 -> ..." 형태의 문자열을 만든다.
    4. 거리가 INF인 목적지는 경로 대신 "도달 불가"를 출력한다.
    5. 다익스트라 반복은 pickClosest가 -1을 반환하면 조기 종료한다.
    6. 핵심 알고리즘을 라이브러리(예: 외부 그래프 라이브러리)로 대체하지 않고 직접 구현한다.

    Java PathFinderSolution.java 
    import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/**
 * 최종 프로그램 "동네 길찾기 PathFinder" — 정답 코드.
 * 배열 버전 다익스트라 + prev 경로 복원 + 도달 불가 처리.
 */
public class PathFinderSolution {

    static final int INF = Integer.MAX_VALUE;

    /** 간선 정보: 도착 장소 번호와 걷는 시간(분) */
    static class Edge {
        int to;
        int weight;

        Edge(int to, int weight) {
            this.to = to;
            this.weight = weight;
        }
    }

    /** 다익스트라 결과: 최단 시간 배열 + 경로 복원용 직전 장소 배열 */
    static class Result {
        int[] dist;
        int[] prev;

        Result(int[] dist, int[] prev) {
            this.dist = dist;
            this.prev = prev;
        }
    }

    static void addPath(List<List<Edge>> map, int u, int v, int minutes) {
        map.get(u).add(new Edge(v, minutes));
        map.get(v).add(new Edge(u, minutes));
    }

    /** 미확정 장소 중 거리가 가장 작은 장소 번호를 반환한다. 없으면 -1 */
    static int pickClosest(int[] dist, boolean[] visited) {
        int minVertex = -1;
        int minDist = INF;
        for (int v = 0; v < dist.length; v++) {
            if (!visited[v] && dist[v] < minDist) {
                minDist = dist[v];
                minVertex = v;
            }
        }
        return minVertex;
    }

    /** 배열 버전 다익스트라: start에서 모든 장소까지의 최단 시간과 직전 장소를 계산한다 */
    static Result dijkstra(List<List<Edge>> map, int start) {
        int n = map.size();
        int[] dist = new int[n];
        int[] prev = new int[n];
        boolean[] visited = new boolean[n];
        Arrays.fill(dist, INF);
        Arrays.fill(prev, -1);
        dist[start] = 0;

        for (int round = 0; round < n; round++) {
            int u = pickClosest(dist, visited);
            if (u == -1) {
                break;                        // 남은 장소는 모두 도달 불가
            }
            visited[u] = true;                // u까지의 최단 시간 확정

            for (Edge e : map.get(u)) {
                if (dist[u] + e.weight < dist[e.to]) {   // 완화 조건
                    dist[e.to] = dist[u] + e.weight;
                    prev[e.to] = u;                      // 경로 기록
                }
            }
        }
        return new Result(dist, prev);
    }

    /** prev 배열을 거슬러 올라가 "집 -> 카페 -> ..." 형태의 경로 문자열을 만든다 */
    static String buildPath(int[] prev, String[] names, int end) {
        StringBuilder path = new StringBuilder(names[end]);
        int v = end;
        while (prev[v] != -1) {
            v = prev[v];
            path.insert(0, names[v] + " -> ");
        }
        return path.toString();
    }

    public static void main(String[] args) {
        String[] names = {"집", "카페", "학교", "도서관", "공원", "병원", "체육관"};
        int n = names.length;

        List<List<Edge>> map = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            map.add(new ArrayList<>());
        }
        addPath(map, 0, 1, 4);   // 집-카페
        addPath(map, 0, 2, 10);  // 집-학교
        addPath(map, 1, 2, 3);   // 카페-학교
        addPath(map, 1, 3, 8);   // 카페-도서관
        addPath(map, 2, 3, 2);   // 학교-도서관
        addPath(map, 2, 4, 7);   // 학교-공원
        addPath(map, 3, 5, 5);   // 도서관-병원
        addPath(map, 4, 5, 1);   // 공원-병원
        // 체육관(6)은 진입로 공사 중이라 연결된 길이 아직 없다

        int start = 0;   // 집
        Result result = dijkstra(map, start);

        int[] targets = {5, 6, 0};   // 병원, 체육관, 집
        for (int end : targets) {
            if (result.dist[end] == INF) {

            } else {

                        + result.dist[end] + "분, 경로 "
                        + buildPath(result.prev, names, end));
            }
        }
    }

    자주 발생하는 오류

    • pickClosest에서 !visited[v] 누락 → 출발점만 반복해서 뽑힘 (오류 1).
    • dist[u] + e.weight를 INF 검사 없이 아무 정점에나 계산 → 오버플로로 음수 거리. 이 구조에서는 pickClosest가 INF 정점을 반환하지 않으므로 안전하지만, 반복 구조를 바꿀 때는 반드시 다시 확인해야 합니다.
    • 완화 시 prev 기록 누락 → 거리는 정답, 경로는 엉망.
    • buildPath에서 무한 반복 → prev를 -1로 초기화하지 않았거나 출발점 prev를 덮어쓴 경우.

    다른 해결 방법

    pickClosest를 PriorityQueue로 바꾸면 DijkstraComplete와 같은 O((V+E) log V) 버전이 됩니다. 장소가 7개뿐인 이 문제에서는 체감 차이가 없지만, "무엇이 병목이고 언제 개선이 필요한가"를 판단하는 것 자체가 1강부터 연습해 온 복잡도 감각입니다. 경로를 저장하는 다른 방법으로, 정점마다 경로 문자열 전체를 들고 다닐 수도 있지만 메모리가 O(V²)로 늘어나므로 prev 배열 방식이 표준입니다.

    15오늘의 핵심 정리

    • 최단 경로 문제는 간선 수가 아니라 가중치의 합이 최소인 경로를 찾는 문제다. BFS(9강)는 무가중치(모든 가중치 동일)에서만 최단을 보장한다.
    • 거리 배열 dist는 "지금까지 알아낸 최선"이며, 출발점 0, 나머지 ∞(Integer.MAX_VALUE)로 시작한다. ∞에 덧셈을 하면 오버플로로 음수가 되므로 주의한다.
    • 완화(relaxation): dist[v] = min(dist[v], dist[u] + w) — 11강 점화식과 같은 모양의 갱신 규칙.
    • 다익스트라 = 그리디 확정 + 완화 반복. 미확정 중 dist가 가장 작은 정점은 그대로 확정해도 된다(가중치 ≥ 0일 때). 음수 가중치가 있으면 이 논리가 무너져 다익스트라를 쓸 수 없다(벨만-포드의 영역).
    • 뽑기를 배열 훑기로 하면 O(V²), 우선순위 큐(6·10강)로 하면 O((V+E) log V). 큐 버전은 꺼낼 때 확정하고, 이미 확정된 정점의 낡은 항목은 건너뛴다.
    • prev 배열에 "어디서 왔는지"를 기록하면 도착점에서 거꾸로 따라가 경로를 복원할 수 있다.

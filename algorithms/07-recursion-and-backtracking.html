재귀 호출과 백트래킹

Recursion and Backtracking

탐색 중급 Java 17+

반복문은 "몇 번 반복할지"를 코드에 미리 적어야 합니다. 그런데 반복의 깊이가 실행 중에 달라지는 문제라면 어떻게 할까요? 이번 강의에서는 메서드가 자기 자신을 호출하는 재귀와, 재귀 위에 "선택 → 진행 → 취소" 구조를 얹어 모든 경우를 빠짐없이 나열하는 백트래킹을 배웁니다. 6강에서 배운 스택이 호출 스택이라는 이름으로 다시 등장합니다.

이 강의의 목차

    01강의 소개

    3강에서 우리는 완전 탐색을 배웠습니다. 두 글자 조합은 이중 for문, 세 글자 조합은 삼중 for문 — 그런데 "몇 글자인지 실행할 때 정해지는" 문제라면 for문을 몇 겹 써야 할까요? 코드는 실행 중에 자기 몸을 늘릴 수 없습니다. 이 벽을 넘는 도구가 바로 재귀 호출(recursion)입니다.

    이번 강의는 두 부분으로 이루어집니다. 앞부분에서는 팩토리얼(n!)을 예로 종료 조건과 호출 스택이라는 재귀의 두 기둥을 세웁니다. 종료 조건이 없으면 왜 StackOverflowError로 프로그램이 죽는지도 직접 확인합니다. 뒷부분에서는 재귀 위에 선택(choose) → 진행(explore) → 취소(unchoose)라는 백트래킹 패턴을 얹어 부분집합·순열·조합을 빠짐없이 나열하고, 조건에 어긋나는 가지를 미리 잘라내는 가지치기(pruning)까지 적용합니다. 마지막에는 잊어버린 자물쇠 비밀번호의 후보를 모두 생성하는 프로그램을 직접 만듭니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 재귀 메서드에서 종료 조건(base case)과 재귀 단계(recursive step)를 구분하여 설명할 수 있다.
    • 학생은 factorial(4)의 호출과 반환 순서를 호출 스택 그림으로 추적할 수 있다.
    • 학생은 종료 조건이 없거나 도달할 수 없을 때 StackOverflowError가 발생하는 이유를 설명할 수 있다.
    • 학생은 선택-진행-취소 구조의 백트래킹으로 부분집합·순열·조합을 나열하는 Java 코드를 작성할 수 있다.
    • 학생은 조건 검사를 추가해 불필요한 가지를 잘라내는 가지치기를 구현하고 그 효과를 개수로 확인할 수 있다.
    • 학생은 재귀 피보나치의 호출 횟수를 측정해 중복 호출 문제를 설명할 수 있다.

    04실제 문제 상황

    동아리 방 사물함에 다이얼 자물쇠가 걸려 있습니다. 지난 학기 부장이 비밀번호를 정했는데, 기억나는 것은 "버튼은 1, 3, 7, 9 네 개만 사용했다"는 사실뿐입니다. 자리 수도 확실하지 않습니다 — 2자리였던 것 같기도 하고, 3자리였던 것 같기도 합니다. 여러분은 후보 비밀번호를 빠짐없이, 중복 없이 목록으로 뽑아 하나씩 시도해 보기로 했습니다. 2자리라면 3강처럼 이중 for문으로 뽑을 수 있습니다. 그런데 자리 수가 3, 4, 5로 변한다면요? 자리 수 k를 바꿀 때마다 for문을 한 겹씩 더 쓸 수는 없습니다. 반복의 깊이 자체가 입력에 따라 변하는 문제 — 오늘 배울 재귀와 백트래킹이 정확히 이 문제를 풉니다.

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 작은 문제 두 개를 손으로 풀어 봅니다. 첫 번째는 재귀의 감각을 익히는 팩토리얼, 두 번째는 백트래킹의 감각을 익히는 경우의 수 나열입니다.

    문제 1 — 4! (4 팩토리얼)을 정의대로 계산하기

    STEP 1

    팩토리얼의 정의는 n! = n × (n−1)! 입니다. 정의를 그대로 따라가 봅시다. 4! = 4 × 3!. 그런데 3!을 아직 모르므로 계산을 미루고 메모지에 "4 × (3!의 답)"이라고 적어 둡니다. 3! = 3 × 2!, 또 미룹니다. 2! = 2 × 1!, 또 미룹니다.

    질문: 이 "미루기"는 언제까지 계속될까요? 멈추는 곳은 어디인가요?

    1! = 1에서 멈춥니다. 1!은 더 작은 팩토리얼에 기대지 않고 즉시 답할 수 있는, 더는 쪼갤 수 없는 가장 작은 문제입니다. 이것이 바로 재귀의 종료 조건(base case)입니다. 멈추는 곳이 없으면 미루기는 영원히 계속됩니다.

    STEP 2

    1! = 1을 알았으니 이제 미뤄 둔 메모지를 가장 최근 것부터 거꾸로 처리합니다. 2! = 2 × 1 = 2 → 3! = 3 × 2 = 6 → 4! = 4 × 6 = 24.

    질문: 메모지를 "가장 최근 것부터" 처리하는 이 방식, 6강의 어떤 자료구조와 같나요?

    스택(LIFO)입니다. 미룬 계산(4!, 3!, 2!)이 차례로 쌓이고, 마지막에 쌓인 2!부터 거꾸로 풀립니다. 컴퓨터도 똑같이 동작합니다 — 미룬 호출을 호출 스택에 쌓아 두고, 종료 조건에 도달하면 위에서부터 하나씩 꺼내 완성합니다.

    문제 2 — 카드 {1, 2, 3}으로 만들 수 있는 모든 "고르기"를 나열하기

    STEP 3

    카드 세 장 {1, 2, 3}에서 원하는 만큼 골라 만드는 부분집합을 모두 적어 봅시다. 무작정 적으면 빠뜨리기 쉬우니, 카드를 한 장씩 차례로 "넣는다 / 안 넣는다"를 결정합니다. 1을 넣기로 → 2를 넣기로 → 3을 넣기로: {1,2,3}. 이제 마지막 결정만 바꿔서: {1,2}. 3의 두 경우가 끝났으니 한 단계 되돌아가 2의 결정을 바꿉니다: {1,3}, {1}. …

    질문: "한 단계 되돌아가 결정을 바꾼다" — 이 행동이 왜 꼭 필요한가요?

    모든 경우를 빠짐없이 확인하려면, 한 가지를 끝까지 시도한 뒤 마지막 선택을 지우고(취소) 다른 선택지를 시도해야 하기 때문입니다. 이 "되돌아가기"가 바로 백트래킹(backtracking)이라는 이름의 유래입니다. 취소를 잊으면 이전 선택이 종이에 남은 채 다음 경우를 적게 되어 목록이 엉망이 됩니다.

    STEP 4

    결정을 트리로 그려 봅시다. 카드 1에서 2갈래(넣음/안 넣음), 각 갈래에서 카드 2가 또 2갈래, 카드 3이 또 2갈래. 잎(끝)의 개수는 2 × 2 × 2 = 8개: {1,2,3}, {1,2}, {1,3}, {1}, {2,3}, {2}, {3}, {} (빈집합).

    질문: 카드가 10장이면 부분집합은 몇 개일까요? 20장이면요?

    10장이면 2¹⁰ = 1,024개, 20장이면 2²⁰ = 약 105만 개입니다. 원소가 하나 늘 때마다 2배씩 — 지수적으로 늘어납니다. 그래서 백트래킹에서는 조건에 어긋나는 가지를 일찍 잘라내는 가지치기가 중요해집니다.

    06핵심 개념

    재귀 호출이란?

    재귀 호출은 메서드가 자기 자신을 호출하는 것입니다. 핵심 아이디어는 "큰 문제를 같은 구조의 더 작은 문제에 맡기고, 돌아온 답으로 내 답을 완성한다"입니다. factorial(4)는 factorial(3)에게 "3!을 구해 줘"라고 맡기고, 돌아온 6에 4를 곱해 24를 완성합니다.

    재귀의 두 부분 — 이 중 하나라도 없으면 재귀가 아니다

    구성 요소역할팩토리얼에서는
    종료 조건 (base case)더 쪼개지 않고 즉시 답하는 가장 작은 문제. 재귀를 멈추는 브레이크.if (n <= 1) return 1;
    재귀 단계 (recursive step)문제를 더 작게 만들어 자기 자신에게 맡기고, 결과를 조합한다.return n * factorial(n - 1);

    재귀 단계에는 숨은 조건이 하나 더 있습니다: 호출할 때마다 문제가 종료 조건 쪽으로 가까워져야 합니다. factorial(n - 1)은 n이 1씩 줄어 언젠가 종료 조건에 닿지만, 실수로 factorial(n)을 호출하면 문제가 작아지지 않아 영원히 끝나지 않습니다.

    호출 스택과 StackOverflowError

    JVM은 메서드가 호출될 때마다 그 메서드의 매개변수·지역 변수를 담은 스택 프레임을 호출 스택에 push하고, 메서드가 반환되면 pop합니다. 6강에서 배운 LIFO 그대로 — 가장 나중에 호출된 메서드가 가장 먼저 반환됩니다. factorial(4)를 부르면 스택에는 factorial(4) → factorial(3) → factorial(2) → factorial(1)이 차례로 쌓였다가, 위에서부터 1 → 2 → 6 → 24를 반환하며 무너집니다.

    호출 스택의 크기는 유한합니다(기본 설정에서 대략 수천~수만 프레임). 종료 조건이 없거나 도달할 수 없으면 프레임이 무한히 쌓이다가 스택이 넘쳐 StackOverflowError가 발생합니다. 오류 찾기 섹션에서 실제로 터뜨려 봅니다.

    백트래킹 — 선택 · 진행 · 취소

    백트래킹은 재귀로 결정 트리를 내려가며 모든 경우를 나열하되, 한 가지를 끝까지 시도한 뒤에는 반드시 상태를 원래대로 되돌리고 다음 선택지를 시도하는 기법입니다. 모든 백트래킹 코드는 아래 3단계 패턴을 따릅니다.

    단계의미코드 형태
    (1) 선택 choose후보 하나를 골라 현재 상태에 반영한다chosen.add(x), used[i] = true
    (2) 진행 explore다음 결정을 하러 재귀 호출로 내려간다go(index + 1)
    (3) 취소 unchoose돌아오면 선택을 정확히 반대로 되돌린다chosen.remove(...), used[i] = false

    취소가 필요한 이유는 chosen이나 used[]가 모든 재귀 호출이 함께 쓰는 공유 상태이기 때문입니다. 형제 가지를 탐색하러 가기 전에 내가 남긴 흔적을 지우지 않으면, 다음 가지가 오염된 상태에서 출발합니다.

    세 가지 대표 나열 패턴

    패턴각 단계의 결정중복 방지 장치개수 (원소 n개)
    부분집합i번째 원소를 넣는다 / 안 넣는다원소를 index 순서로 결정2ⁿ
    순열아직 안 쓴 원소 중 하나를 다음 자리에 놓는다used[] 방문 배열 (3강의 방문 확인)n!
    조합start 이후의 원소 중 하나를 고른다start 인덱스 (순서 뒤집힌 중복 차단)nCk

    가지치기 (pruning)

    경우의 수가 2ⁿ, n!처럼 폭발하므로, 조건에 어긋나는 것이 확실해진 가지는 끝까지 내려가지 않고 그 자리에서 잘라냅니다. 선택하기 전에 조건을 검사해 continue로 건너뛰는 한 줄이면 됩니다. 잘라낸 가지 아래의 모든 경우가 통째로 생략되므로 효과가 큽니다.

    08의사코드

    코드를 쓰기 전에, 두 알고리즘의 절차를 언어 중립적인 의사코드로 정리합니다.

    Pseudo 재귀 팩토리얼 
    알고리즘 Factorial(n)
    만약 n ≤ 1 이면:                     // 종료 조건 (브레이크)
        1을 반환한다
    smaller ← Factorial(n − 1)           // 더 작은 같은 문제에 맡긴다
    n × smaller 를 반환한다              // 돌아온 답으로 내 답을 완성한다
    Pseudo 부분집합 백트래킹 — 선택·진행·취소 
    알고리즘 Subsets(index)
    만약 index = 원소 개수 이면:          // 종료 조건: 모든 원소를 결정했다
        chosen 을 부분집합 하나로 기록한다
        돌아간다

    // 경우 1: index번째 원소를 넣는 가지
    chosen 에 원소[index] 를 추가한다     // (1) 선택
    Subsets(index + 1) 을 호출한다        // (2) 진행
    chosen 에서 마지막 원소를 제거한다    // (3) 취소 — 상태 복원!

    // 경우 2: index번째 원소를 넣지 않는 가지
    Subsets(index + 1) 을 호출한다

    백트래킹 의사코드에서 (1)과 (3)이 정확히 대칭인 것에 주목하세요. add에는 remove, used[i] = true에는 used[i] = false — 선택에서 한 일을 취소에서 그대로 되돌려야 모든 가지가 깨끗한 상태에서 출발합니다.

    구현 2단계 — 종료 조건 먼저 만들기

    왜 종료 조건부터 쓸까? — 멈추지 않는 재귀의 위험

    재귀 메서드에서 자기 호출을 먼저 쓰고 종료 조건을 "나중에 추가해야지" 하면, 그 사이 실행하는 순간 메서드가 영원히 자기 자신을 호출합니다. 프레임이 무한히 쌓이다가 호출 스택이 넘쳐 StackOverflowError로 죽습니다. 그래서 재귀는 항상 브레이크(종료 조건)를 먼저 달고, 그다음 엔진(자기 호출)을 답니다.

    종료 조건만 있는 뼈대를 만듭니다. 아직 자기 호출이 없으므로 factorial(4)는 임시 값 -1을 돌려줍니다 — 그래도 안전하게 컴파일되고 실행됩니다.

    Java Step2BaseCaseOnly.java 
    public class Step2BaseCaseOnly {

    /** 종료 조건(base case)만 있는 팩토리얼 뼈대. 아직 자기 호출은 없다. */
    static long factorial(int n) {
        if (n <= 1) {      // 종료 조건: 더 이상 쪼갤 수 없는 가장 작은 문제
            return 1;      // 1! = 1 (0! 도 1로 처리)
        }
        // 다음 단계에서 여기에 자기 호출을 추가한다
        return -1;         // "아직 계산하지 못함"을 나타내는 임시 값
    }

    public static void main(String[] args) {
        System.out.println("factorial(0) = " + factorial(0));
        System.out.println("factorial(1) = " + factorial(1));
        System.out.println("factorial(4) = " + factorial(4) + "  <- 아직 -1: 자기 호출이 없어서");
    }
}

    구현 3단계 — 자기 호출을 추가해 재귀 완성

    임시 값 -1 자리에 자기 호출을 넣습니다. 호출과 반환의 순서를 눈으로 보기 위해 출력도 함께 넣었습니다. 호출은 4 → 3 → 2 → 1 순서로 내려가고, 반환은 2 → 3 → 4 순서로 거꾸로 올라오는 것을 확인하세요.

    Java Step3FactorialRecursion.java 
    public class Step3FactorialRecursion {

    /** 완성된 재귀 팩토리얼. 호출과 반환의 순서를 함께 출력한다. */
    static long factorial(int n) {
        System.out.println("호출: factorial(" + n + ")");

        if (n <= 1) {                        // 종료 조건
            System.out.println("종료 조건 도달 -> 1을 반환");
            return 1;
        }

        long smaller = factorial(n - 1);     // 자기 호출: 더 작은 문제를 맡긴다
        long result = n * smaller;           // 돌아온 답으로 내 답을 완성한다

        System.out.println("반환: factorial(" + n + ") = " + n + " x " + smaller + " = " + result);
        return result;
    }

    public static void main(String[] args) {
        long answer = factorial(4);
        System.out.println("최종 결과: 4! = " + answer);
    }
}

    구현 4단계 — 백트래킹 뼈대: 선택 · 진행 · 취소

    이제 재귀에 공유 상태(chosen)를 더해 백트래킹으로 확장합니다. {1, 2, 3}의 부분집합을 나열하는 의사코드를 그대로 옮긴 코드입니다. (1) 선택, (2) 진행, (3) 취소 세 줄이 핵심입니다.

    Java Step4BacktrackingSkeleton.java 
    import java.util.ArrayList;
import java.util.List;

public class Step4BacktrackingSkeleton {

    static int[] numbers = {1, 2, 3};
    static List<Integer> chosen = new ArrayList<>();   // 지금까지의 선택
    static int subsetCount = 0;

    /** index번째 원소를 "넣을지 / 뺄지" 결정한다. 선택 -> 진행 -> 취소 구조. */
    static void subsets(int index) {
        if (index == numbers.length) {          // 종료 조건: 모든 원소를 결정했다
            subsetCount++;
            System.out.println("부분집합 " + subsetCount + ": " + chosen);
            return;
        }

        chosen.add(numbers[index]);             // (1) 선택: 이 원소를 넣는다
        subsets(index + 1);                     // (2) 진행: 다음 원소를 결정하러 간다
        chosen.remove(chosen.size() - 1);       // (3) 취소: 상태를 원래대로 복원한다!

        subsets(index + 1);                     // 이 원소를 넣지 않는 경우도 진행한다
    }

    public static void main(String[] args) {
        System.out.println("{1, 2, 3}의 모든 부분집합:");
        subsets(0);
        System.out.println("총 " + subsetCount + "개 (2 x 2 x 2 = 8)");
    }
}

    10완성 Java 코드

    지금까지의 조각을 모아 완성합니다. 부분집합에 이어 나머지 두 나열 패턴 — 순열(used[] 방문 배열)과 조합(start 인덱스)을 구현합니다. 두 메서드 모두 구현 4단계와 같은 선택·진행·취소 구조이고, 중복 방지 장치만 다릅니다.

    Java PermutationComplete.java 
    public class PermutationComplete {

    static char[] letters = {'a', 'b', 'c'};
    static boolean[] used = new boolean[letters.length];   // 문자 사용(방문) 여부 관리
    static StringBuilder current = new StringBuilder();    // 지금까지 만든 문자열 (공유 상태)
    static int permCount = 0;
    static int comboCount = 0;

    /** 순열: 아직 안 쓴 문자를 하나 골라 붙이고, 재귀가 돌아오면 반드시 되돌린다. */
    static void permutation() {
        if (current.length() == letters.length) {          // 종료 조건: 전부 골랐다
            permCount++;
            System.out.println("  순열 " + permCount + ": " + current);
            return;
        }

        for (int i = 0; i < letters.length; i++) {
            if (used[i]) {
                continue;                                  // 이미 쓴 문자는 건너뛴다
            }
            used[i] = true;                                // (1) 선택
            current.append(letters[i]);
            permutation();                                 // (2) 진행
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 상태 복원
            used[i] = false;
        }
    }

    /** 조합: start 이후의 문자만 고르므로 순서만 다른 중복이 생기지 않는다. */
    static void combination(int start, int k) {
        if (current.length() == k) {                       // 종료 조건: k개를 골랐다
            comboCount++;
            System.out.println("  조합 " + comboCount + ": " + current);
            return;
        }

        for (int i = start; i < letters.length; i++) {
            current.append(letters[i]);                    // 선택
            combination(i + 1, k);                         // 진행: 다음은 i + 1부터만
            current.deleteCharAt(current.length() - 1);    // 취소
        }
    }

    public static void main(String[] args) {
        System.out.println("[1] {a, b, c}의 모든 순열 (3! = 6개)");
        permutation();

        System.out.println();
        System.out.println("[2] {a, b, c}에서 2개를 고르는 조합 (3C2 = 3개)");
        combination(0, 2);
    }
}

    순열과 조합의 결정적 차이
    • 순열은 매번 전체 후보에서 고르되 used[]로 재사용을 막습니다 — ab와 ba를 모두 만듭니다.
    • 조합은 start 이후에서만 고릅니다 — a를 고른 뒤에는 b, c만 볼 수 있으므로 ba처럼 순서만 다른 중복이 아예 생기지 않아 used[]도 필요 없습니다.

    11실행 과정 추적

    완성 코드가 정말 시각화(7번 섹션)와 똑같이 동작하는지, 재귀 깊이만큼 들여쓰기해서 모든 호출·완성·취소를 기록합니다. {a, b, c}에서 길이 2 순열을 만들며, 들여쓰기 깊이 = 호출 스택의 깊이임을 확인하세요.

    Java RecursionTrace.java 
    public class RecursionTrace {

    static char[] letters = {'a', 'b', 'c'};
    static boolean[] used = new boolean[letters.length];
    static StringBuilder current = new StringBuilder();
    static final int K = 2;   // 만들 순열의 길이

    /** 재귀 깊이만큼 들여쓰기해서 호출·완성·취소를 모두 기록한다. */
    static void perm(int depth) {
        String indent = "  ".repeat(depth);   // 깊이 1당 공백 2칸
        System.out.println(indent + "-> perm(현재=\"" + current + "\")");

        if (current.length() == K) {          // 종료 조건
            System.out.println(indent + "  완성! \"" + current + "\"");
            return;
        }

        for (int i = 0; i < letters.length; i++) {
            if (used[i]) continue;
            used[i] = true;                                // 선택
            current.append(letters[i]);
            perm(depth + 1);                               // 진행
            current.deleteCharAt(current.length() - 1);    // 취소
            used[i] = false;
            System.out.println(indent + "<- 취소 " + letters[i] + " (현재=\"" + current + "\")");
        }
    }

    public static void main(String[] args) {
        System.out.println("{a, b, c}에서 길이 2 순열 만들기 — 호출/반환 추적");
        perm(0);
        System.out.println("추적 끝: 들여쓰기 깊이 = 호출 스택의 깊이");
    }
}

    12잘못된 코드와 오류 찾기

    오류 1 — 종료 조건이 없는 재귀

    if (n <= 1) {      // 종료 조건: 여기서 재귀가 멈춘다
        return 1;
    }
    return n * factorial(n - 1);
}

public class BuggySubsetsNoRestore {

    static int[] numbers = {1, 2, 3};
    static List<Integer> chosen = new ArrayList<>();
    static int subsetCount = 0;

    static void subsets(int index) {
        if (index == numbers.length) {
            subsetCount++;
            System.out.println("부분집합 " + subsetCount + ": " + chosen);
            return;
        }

        chosen.add(numbers[index]);   // (1) 선택
        subsets(index + 1);           // (2) 진행
        // (3) 취소를 잊었다! chosen.remove(chosen.size() - 1)가 없다

        subsets(index + 1);           // 넣지 않는 경우
    }

    public static void main(String[] args) {
        System.out.println("{1, 2, 3}의 모든 부분집합:");

    수정 방법: 선택과 정확히 대칭인 취소를 진행 직후에 넣습니다.

    chosen.add(numbers[index]);         // (1) 선택
subsets(index + 1);                 // (2) 진행
chosen.remove(chosen.size() - 1);   // (3) 취소: 선택을 정확히 반대로 되돌린다

subsets(index + 1);                 // 넣지 않는 경우

    수정 후에는 구현 4단계와 같은 올바른 8개가 나옵니다. 선택한 것은 반드시 취소한다 — add에는 remove, used[i] = true에는 used[i] = false를 짝으로 쓰는 습관을 들이세요.

    13복잡도 및 특성 분석

    입력 크기

    팩토리얼에서는 수 n, 나열 문제에서는 원소(후보)의 개수 n이 입력 크기입니다. 재귀의 깊이도 함께 봐야 합니다 — 깊이가 곧 호출 스택 사용량이기 때문입니다.

    주요 연산

    핵심 연산은 재귀 호출(그리고 짝을 이루는 선택·취소)입니다. 나열 알고리즘의 총 일의 양은 대략 "만들어지는 경우의 수 × 하나를 만드는 비용"입니다.

    시간·공간 복잡도

    알고리즘경우의 수시간 복잡도공간(호출 스택 깊이)
    재귀 팩토리얼—O(n) (호출 n번)O(n)
    부분집합 나열2ⁿO(2ⁿ · n)O(n)
    순열 나열n!O(n! · n)O(n)
    조합 나열 (k개)nCkO(nCk · k)O(k)

    반복문 알고리즘의 공간이 O(1)이던 것과 달리, 재귀는 깊이만큼 호출 스택 메모리를 사용합니다. n = 20 부분집합이면 깊이 20이라 안전하지만, 깊이가 수만을 넘는 재귀(예: 배열 100만 개를 원소 하나씩 재귀로 순회)는 정답 로직이라도 StackOverflowError가 날 수 있습니다 — 그럴 때는 반복문이나 6강의 명시적 스택으로 바꿉니다.

    특성 1 — 백트래킹은 "가지치기할 수 있는 완전 탐색"

    2ⁿ, n!은 n이 조금만 커져도 감당할 수 없습니다 (2³⁰ ≈ 10억, 13! ≈ 62억). 백트래킹이 실전에서 쓰이는 이유는 조건에 어긋나는 가지를 조상 단계에서 통째로 잘라낼 수 있기 때문입니다. 최종 프로그램에서 가지치기 한 줄이 몇 개의 경우를 지우는지 직접 세어 봅니다.

    특성 2 — 같은 계산을 반복하는 재귀: 피보나치의 경고

    재귀가 늘 좋은 것은 아닙니다. 피보나치 수를 정의 그대로 재귀로 옮기면 자기 호출이 두 번 일어나는데, 이때 같은 계산이 얼마나 반복되는지 호출 횟수 카운터(1강의 도구)로 측정해 봅시다.

    Java FibonacciBasic.java 
    public class FibonacciBasic {

    static long callCount = 0;   // fibo가 호출된 총 횟수

    /** 기본 재귀 피보나치. 정의를 그대로 옮겼지만 같은 계산을 여러 번 반복한다. */
    static long fibo(int n) {
        callCount++;
        if (n <= 1) {                        // 종료 조건: fibo(0) = 0, fibo(1) = 1
            return n;
        }
        return fibo(n - 1) + fibo(n - 2);    // 자기 호출이 두 번!
    }

    public static void main(String[] args) {
        int[] tests = {10, 20, 30};

        System.out.println("n  | fibo(n) | 호출 횟수");
        System.out.println("---+---------+----------");
        for (int n : tests) {
            callCount = 0;
            long value = fibo(n);
            System.out.printf("%-2d | %-7d | %d%n", n, value, callCount);
        }

        System.out.println();
        System.out.println("n이 10 커질 때마다 호출 횟수가 약 120배씩 폭발한다.");
        System.out.println("원인: fibo(20)을 구할 때 fibo(18)을 2번, fibo(17)을 3번... 같은 계산을 반복하기 때문.");
        System.out.println("해결책은 11강 동적 계획법에서 배운다 (계산 결과를 저장해 재사용).");
    }
}

    15실제 데이터 응용 예제

    문제 상황

    수학여행 버스의 한 줄 좌석 3개에 학생 민준, 서연, 도윤을 배치해야 합니다. 그런데 담임 선생님의 규칙이 하나 있습니다: "민준과 서연은 옆자리에 앉을 수 없다." 가능한 배치를 모두 나열하되, 규칙을 지키는 배치만 골라내야 합니다. 좌석 배치는 순서가 중요하므로 순열 백트래킹이 정확히 맞는 도구이고, 규칙 검사를 가지치기로 넣으면 어긋나는 배치는 끝까지 만들어 보기도 전에 걸러집니다.

    데이터 모델과 알고리즘 적용 기준

    • 데이터: 학생 이름 배열 students, 좌석 배열 seats (seats[i] = i번 좌석의 학생), 방문 배열 used
    • 알고리즘: 좌석 0번부터 차례로 학생을 고르는 순열 백트래킹 — 완성 코드의 permutation()과 같은 구조
    • 가지치기: 학생을 앉히기 전에 바로 왼쪽 좌석과 금지된 짝인지 검사, 어긋나면 continue
    Java SeatingApplication.java 
    public class SeatingApplication {

    static String[] students = {"민준", "서연", "도윤"};
    static String[] seats = new String[students.length];   // seats[i] = i번 좌석의 학생
    static boolean[] used = new boolean[students.length];  // 학생 배치(방문) 여부
    static int totalCount = 0;    // 제약 없는 전체 배치 수
    static int validCount = 0;    // 규칙을 통과한 배치 수
    static int pruneCount = 0;    // 가지치기로 잘라낸 횟수

    /** 규칙: 민준과 서연은 옆자리에 앉을 수 없다. */
    static boolean isForbiddenPair(String a, String b) {
        return (a.equals("민준") && b.equals("서연"))
                || (a.equals("서연") && b.equals("민준"));
    }

    /** [1] 제약 없이 모든 배치를 나열한다 (순열 백트래킹 그대로). */
    static void arrangeAll(int seatIndex) {
        if (seatIndex == seats.length) {           // 종료 조건: 모든 좌석을 채웠다
            totalCount++;
            System.out.println("  배치 " + totalCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;
            used[i] = true;                        // 선택
            seats[seatIndex] = students[i];
            arrangeAll(seatIndex + 1);             // 진행
            used[i] = false;                       // 취소: 상태 복원
            seats[seatIndex] = null;
        }
    }

    /** [2] 같은 구조에 가지치기 검사를 한 번 추가한다. */
    static void arrangeWithRule(int seatIndex) {
        if (seatIndex == seats.length) {
            validCount++;
            System.out.println("  통과 " + validCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;

            // 가지치기: 바로 왼쪽 좌석과 금지된 짝이면 이 가지는 내려가지 않는다
            if (seatIndex > 0 && isForbiddenPair(seats[seatIndex - 1], students[i])) {
                pruneCount++;
                continue;
            }

            used[i] = true;
            seats[seatIndex] = students[i];
            arrangeWithRule(seatIndex + 1);
            used[i] = false;
            seats[seatIndex] = null;
        }
    }

    public static void main(String[] args) {
        System.out.println("[1] 제약 없는 전체 좌석 배치 (3! = 6가지)");
        arrangeAll(0);

        System.out.println();
        System.out.println("[2] 규칙 적용: 민준-서연 옆자리 금지");
        arrangeWithRule(0);

        System.out.println();
        System.out.println("전체 " + totalCount + "가지 중 " + validCount + "가지만 규칙을 통과");
        System.out.println("가지치기 발동 " + pruneCount + "번 — 어긋나는 가지는 끝까지 만들기 전에 잘랐다.");
    }
}

  배치 1: 민준 - 서연 - 도윤
  배치 2: 민준 - 도윤 - 서연

    코드 해설과 복잡도 분석

    • arrangeAll과 arrangeWithRule의 차이는 가지치기 if 한 덩어리뿐입니다. 백트래킹 뼈대를 한 번 익히면, 문제의 규칙은 가지치기 조건으로만 추가됩니다.
    • 가지치기는 선택하기 전에 검사합니다 — 앉혀 놓고 검사하면 취소도 해야 하므로, 아예 앉히지 않고 건너뛰는 쪽이 간결하고 빠릅니다.
    • 취소 단계에서 used[i] = false와 seats[seatIndex] = null — 선택에서 바꾼 두 가지 상태를 모두 되돌리는 것에 주목하세요. 하나만 되돌리면 오류 2와 같은 버그가 됩니다.
    • 복잡도: 전체 나열은 O(n! · n). 학생 3명이면 6가지지만 10명이면 3,628,800가지 — 규칙이 많을수록 가지치기가 일찍 발동해 실제 탐색량은 크게 줄어듭니다.

    16최종 프로그램 작성 문제

    문제 제목 — 자물쇠 비밀번호 후보 생성기

    문제 배경

    실제 문제 상황(4번 섹션)의 자물쇠로 돌아갑시다. 동아리 사물함의 비밀번호는 버튼 1, 3, 7, 9만 사용해 만들어졌고, 같은 버튼을 여러 번 눌러도 됩니다(예: 11, 33). 여러분은 자리 수 k를 입력하면 길이 k의 모든 후보를 사전 순으로 나열하는 프로그램을 만들기로 했습니다. 그런데 전 부장의 증언이 하나 추가되었습니다: "같은 숫자를 연속으로 누른 적은 없어." 이 규칙을 가지치기로 넣으면 시도할 후보를 크게 줄일 수 있습니다. 전체 생성과 가지치기 생성을 모두 구현하고, 가지치기가 몇 개를 걸러 냈는지도 세어 봅시다.

    프로그램 목표

    Java PasswordSolution.java 
    public class PasswordSolution {

    static char[] candidates = {'1', '3', '7', '9'};   // 후보 문자 4개
    static StringBuilder current = new StringBuilder(); // 지금 만드는 중인 비밀번호
    static int allCount = 0;        // 전체 생성 개수
    static int rulePassCount = 0;   // 가지치기 통과 개수
    static boolean printEach = true; // 하나씩 출력할지 여부 (개수만 셀 때는 false)

    /** [과제 1] 길이 k의 모든 비밀번호를 생성한다. (같은 문자를 여러 번 써도 됨) */
    static void generateAll(int k) {
        if (current.length() == k) {                       // 종료 조건: k자리 완성
            allCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            current.append(candidates[i]);                 // (1) 선택
            generateAll(k);                                // (2) 진행
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 상태 복원
        }
    }

    /** [과제 2] 같은 문자가 연속으로 나오는 가지를 잘라내며 생성한다. */
    static void generateNoRepeat(int k) {
        if (current.length() == k) {                       // 종료 조건
            rulePassCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            // 가지치기: 직전 문자와 같으면 이 가지는 내려가 보지 않는다
            if (current.length() > 0
                    && current.charAt(current.length() - 1) == candidates[i]) {
                continue;
            }
            current.append(candidates[i]);                 // 선택
            generateNoRepeat(k);                           // 진행
            current.deleteCharAt(current.length() - 1);    // 취소
        }
    }

    public static void main(String[] args) {
        System.out.println("후보 문자: 1, 3, 7, 9");

        System.out.println();
        System.out.println("[1] 길이 2 — 만들 수 있는 모든 비밀번호");
        printEach = true;
        allCount = 0;
        generateAll(2);
        System.out.println("  총 " + allCount + "개 (이론값 4^2 = 16)");

        System.out.println();
        System.out.println("[2] 길이 2 — 같은 문자 연속 금지 (가지치기)");
        rulePassCount = 0;
        generateNoRepeat(2);
        System.out.println("  총 " + rulePassCount + "개 (이론값 4 x 3 = 12)");

        System.out.println();
        System.out.println("[3] 길이 3 — 개수만 비교");
        printEach = false;
        allCount = 0;
        rulePassCount = 0;
        generateAll(3);
        generateNoRepeat(3);
        System.out.println("  전체 생성: " + allCount + "개 (4^3 = 64)");
        System.out.println("  연속 금지: " + rulePassCount + "개 (4 x 3 x 3 = 36)");
        System.out.println("  가지치기로 " + (allCount - rulePassCount)

    구현 순서와 핵심 알고리즘 적용 부분

    1. generateAll은 부분집합 코드(구현 4단계)와 뼈대가 같습니다. 다른 점은 "넣는다/안 넣는다" 2갈래 대신 후보 4개를 도는 for문이라는 것뿐입니다 — 가지 수가 후보 수(4)인 결정 트리입니다.
    2. 재귀 호출이 generateAll(k)로 k를 그대로 전달하는 것에 주목하세요. 진행 정도는 k가 아니라 current의 길이가 말해 줍니다 — append로 길이가 1 늘어나므로 문제는 종료 조건 쪽으로 확실히 가까워집니다.
    3. generateNoRepeat의 가지치기는 current.length() > 0 검사가 먼저 옵니다. 빈 문자열에서 charAt(-1)을 부르면 예외가 나므로, 경계 조건 검사가 앞이어야 합니다 (테스트 3종의 "경계 조건 k = 1"이 바로 이 지점을 확인합니다).
    4. [3]에서 카운터를 0으로 초기화하고 printEach를 끄는 것 — 상태를 공유하는 프로그램에서는 측정 전에 상태를 초기화하는 습관이 필요합니다.

    복잡도 분석

    • generateAll: 후보 c개, 길이 k → 완성 후보 cᵏ개, 시간 O(cᵏ · k). k = 2면 16개, k = 3이면 64개.
    • generateNoRepeat: 첫 자리 c가지 × 이후 자리마다 (c − 1)가지 → c × (c−1)ᵏ⁻¹개. k = 3이면 4 × 3 × 3 = 36개 — 걸러진 28개의 가지는 재귀 호출 자체가 일어나지 않았습니다.
    • 공간: 호출 스택 깊이 = k → O(k).

    자주 발생하는 오류

    • 종료 조건 없이 for문부터 쓰는 경우 — current가 무한히 길어지다 StackOverflowError (오류 1 유형).
    • deleteCharAt을 빼먹는 경우 — 첫 후보 "11"을 만든 뒤 상태가 복원되지 않아 이후 결과가 전부 오염됩니다 (오류 2 유형).
    • 가지치기에서 current.length() > 0을 빼먹는 경우 — 첫 문자를 붙이기 전에 charAt(-1)로 StringIndexOutOfBoundsException.
    • [3] 실행 전에 카운터를 초기화하지 않아 [1]·[2]의 개수가 합산되는 경우.

    19오늘의 핵심 정리

    • 재귀 호출은 큰 문제를 같은 구조의 더 작은 문제에 맡기는 것 — 종료 조건(브레이크)과 재귀 단계(더 작아지는 자기 호출)가 둘 다 있어야 한다.
    • 메서드 호출은 호출 스택에 프레임으로 쌓이고(6강 스택의 LIFO), 나중에 호출된 것이 먼저 반환된다. 종료 조건이 없으면 StackOverflowError.
    • 백트래킹은 재귀 완전 탐색(3강의 확장)이며, 모든 코드는 선택 → 진행 → 취소 3단계 패턴을 따른다. 선택에서 바꾼 상태는 취소에서 정확히 되돌린다.
    • 나열 3패턴: 부분집합(넣는다/안 넣는다, 2ⁿ), 순열(used[] 방문 관리, n!), 조합(start 인덱스, nCk).
    • 가지치기는 조건에 어긋나는 가지를 선택하기 전에 잘라 탐색량을 줄인다 — 비밀번호 k = 3에서 64개 중 28개를 만들기 전에 걸렀다.
    • 재귀 피보나치의 호출 폭발(fibo(30) = 2,692,537번)은 중복 계산 때문 — 저장해서 재사용하는 해결책은 11강 동적 계획법에서.

    20다음 강의 연결

    다음 강의는 8강. 트리 구조입니다. 트리는 "재귀로 순회하는 구조" — 오늘 배운 재귀가 자료구조를 만나는 곳입니다.

    • 트리의 정의 자체가 재귀적입니다 — "트리 = 루트 + (왼쪽 부분 트리) + (오른쪽 부분 트리)". 오늘의 "같은 구조의 더 작은 문제"가 그대로 적용됩니다.
    • 전위·중위·후위 순회가 모두 재귀 메서드로 구현됩니다. 종료 조건은 "노드가 null이면 돌아간다" — 오늘의 base case 감각이 그대로 쓰입니다.
    • 순회의 호출 스택 깊이 = 트리의 높이 — 오늘 배운 "재귀 깊이 = 스택 사용량"으로 이해합니다.
    • 더 멀리는 9강 그래프 DFS가 오늘의 백트래킹(방문 관리 + 되돌아가기)과 같은 뼈대이고, 11강 DP가 오늘 본 중복 호출 문제를 해결합니다.

재귀 호출과 백트래킹

Recursion and Backtracking

탐색 중급 Java 17+

반복문은 "몇 번 반복할지"를 코드에 미리 적어야 합니다. 그런데 반복의 깊이가 실행 중에 달라지는 문제라면 어떻게 할까요? 이번 강의에서는 메서드가 자기 자신을 호출하는 재귀와, 재귀 위에 "선택 → 진행 → 취소" 구조를 얹어 모든 경우를 빠짐없이 나열하는 백트래킹을 배웁니다. 6강에서 배운 스택이 호출 스택이라는 이름으로 다시 등장합니다.

이 강의의 목차

    01강의 소개

    오늘의 질문: "몇 글자인지 실행할 때 정해지는" 문제, for문을 몇 겹 써야 할까? 답은 바로 재귀 호출(recursion)입니다.

    • 3강 완전 탐색 복습 — 두 글자 조합은 이중 for문, 세 글자 조합은 삼중 for문
    • 그런데 반복 깊이가 실행 중에 정해지는 문제라면? 코드는 실행 중에 자기 몸을 늘릴 수 없음
    • 오늘 강의 구성
      • 앞부분 — 하노이 탑을 재귀로 풀며 종료 조건과 호출 스택이라는 재귀의 두 기둥을 세우고, 종료 조건이 없으면 StackOverflowError로 죽는 것도 직접 확인
      • 뒷부분 — 선택(choose) → 진행(explore) → 취소(unchoose) 백트래킹 패턴을 얹고, 상태 공간 트리를 그려 가며 순열을 빠짐없이 나열한 뒤 가지치기(pruning)까지 적용
      • 마지막 — 잊어버린 자물쇠 비밀번호의 후보를 모두 생성하는 프로그램을 직접 작성

    • 학생은 순열 문제를 상태 공간 트리(노드 = 상태, 간선 = 선택, 리프 = 해)로 그리고, 백트래킹이 이 트리를 깊이 우선으로 훑는 일임을 설명할 수 있다.
    • 학생은 선택-진행-취소 구조의 순열 백트래킹 Java 코드를 작성하고, 재귀 호출 횟수가 트리의 노드 수와 같음을 확인할 수 있다.
    • 학생은 조건 검사를 추가해 불필요한 서브트리를 잘라내는 가지치기를 구현하고 그 효과를 개수로 확인할 수 있다.
    • 학생은 재귀 피보나치의 호출 횟수를 측정해 중복 호출 문제를 설명할 수 있다.

    03실제 문제 상황

    • 동아리 방 사물함 다이얼 자물쇠의 비밀번호는 "버튼은 1, 3, 7, 9 네 개만 사용했다"는 것만 기억날 뿐, 자리 수는 2자리인지 3자리인지도 확실하지 않음
    • 후보 비밀번호를 빠짐없이, 중복 없이 뽑아야 하는데, 자리 수가 2, 3, 4로 바뀔 때마다 for문을 한 겹씩 더 쓸 수는 없음
    • 반복의 깊이 자체가 입력에 따라 변하는 문제 — 오늘 배울 재귀와 백트래킹이 정확히 이 문제를 풀어냄
    • 비밀번호 생성은 오늘 실습할 순열에서 "이미 쓴 문자는 못 쓴다(used[])"는 제한만 빼면 되는 문제 — 걷는 상태 공간 트리의 모양만 다를 뿐 뼈대는 같음

    04핵심 개념

    재귀 호출이란?

    재귀 호출은 메서드가 자기 자신을 호출하는 것 — "큰 문제를 같은 구조의 더 작은 문제에 맡기고 돌아온 답으로 내 답을 완성한다"는 뜻입니다. 하노이 탑에서 원반 3개를 옮기려면, 위의 원반 2개를 먼저 치우고, 가장 큰 원반을 옮기고, 치워 둔 2개를 다시 올리면 됩니다 — "원반 2개 옮기기"는 "원반 3개 옮기기"와 같은 모양의 더 작은 문제이므로 자기 자신에게 맡길 수 있습니다.

    재귀의 두 부분 — 이 중 하나라도 없으면 재귀가 아니다

    구성 요소역할하노이 탑에서는
    종료 조건 (base case)더 쪼개지 않고 즉시 답하는 가장 작은 문제. 재귀를 멈추는 브레이크.if (n == 1) 이면 원반 하나를 바로 옮기고 끝냄
    재귀 단계 (recursive step)문제를 더 작게 만들어 자기 자신에게 맡기고, 결과를 조합한다.hanoi(n - 1, …)로 위의 원반 n-1개를 두 번 맡김 (가장 큰 원반을 옮기기 전과 후)

    재귀 단계에는 숨은 조건이 하나 더 있습니다 — 호출할 때마다 문제가 종료 조건 쪽으로 가까워져야 합니다. hanoi(n - 1, …)은 원반이 매번 하나씩 줄어 언젠가 n == 1에 닿지만, 실수로 hanoi(n, …)을 호출하면 문제가 작아지지 않아 영원히 끝나지 않습니다.

    호출 스택과 StackOverflowError

    • JVM은 메서드가 호출될 때마다 그 메서드의 매개변수·지역 변수를 담은 스택 프레임을 호출 스택에 push하고, 메서드가 반환되면 pop
    • 6강에서 배운 LIFO 그대로 — 가장 나중에 호출된 메서드가 가장 먼저 반환
    • 예: hanoi(3)을 부르면 스택에는 hanoi(3) → hanoi(2) → hanoi(1)이 쌓이고, 맨 위 hanoi(1)이 원반을 옮기고 반환하면 위에서부터 풀림 — 풀린 hanoi(2)는 두 번째 자기 호출로 스택을 다시 쌓음

    호출 스택의 크기는 유한합니다(기본 설정에서 대략 수천~수만 프레임). 종료 조건이 없거나 도달할 수 없으면 프레임이 무한히 쌓이다가 스택이 넘쳐 StackOverflowError가 발생합니다 — 오류 찾기 섹션에서 실제로 터뜨려 봅니다.

    백트래킹 — 선택 · 진행 · 취소

    백트래킹은 재귀로 결정 트리를 내려가며 모든 경우를 나열하되, 한 가지를 끝까지 시도한 뒤에는 반드시 상태를 원래대로 되돌리고 다음 선택지를 시도하는 기법 — 모든 백트래킹 코드는 아래 3단계 패턴을 따릅니다.

    단계의미코드 형태
    (1) 선택 choose후보 하나를 골라 현재 상태에 반영한다chosen.add(x), used[i] = true
    (2) 진행 explore다음 결정을 하러 재귀 호출로 내려간다go(index + 1)
    (3) 취소 unchoose돌아오면 선택을 정확히 반대로 되돌린다chosen.remove(...), used[i] = false

    취소가 필요한 이유는 chosen이나 used[]가 모든 재귀 호출이 함께 쓰는 공유 상태이기 때문 — 형제 가지를 탐색하러 가기 전에 내가 남긴 흔적을 지우지 않으면, 다음 가지가 오염된 상태에서 출발합니다.

    05단계별 동작 과정

    • 세 개의 시각화로 오늘의 핵심을 확인 — 다음 단계 ▶ 버튼으로 한 단계씩 진행
    • 앞의 하나는 재귀의 기본 동작(호출 스택), 뒤의 둘은 순열 문제를 백트래킹으로 푸는 과정 — 곧 작성할 실습 코드와 같은 절차
    • 파란색 테두리 = 현재 실행 중인 프레임/위치, 초록색 = 완료 (캡션 텍스트로도 상태를 설명)

    시각화 1 — 하노이 탑의 호출 스택

    • 규칙: 기둥 A에 쌓인 원반 3개를 기둥 C로 옮기되, 한 번에 원반 하나만 옮기고 큰 원반을 작은 원반 위에 올릴 수 없음 (보조 기둥 B 사용)
    • 원반 3개 = ① 위의 2개를 B로 치움 → ② 가장 큰 원반 3을 C로 옮김 → ③ B의 2개를 C로 옮김 — ①과 ③은 "원반 2개 옮기기"라는 같은 문제를 자기 자신에게 두 번 맡기는 것
    • 원반이 1개가 되면(종료 조건) 더 쪼개지 않고 바로 옮기고 반환 — 그 뒤 반환이 거꾸로 풀리며 다음 단계가 이어짐
    • 새 데이터 버튼으로 원반 수를 바꿔 이동 횟수가 2ⁿ − 1로 늘어나는 것도 확인

    호출 스택이 쌓이고(호출), 종료 조건에서 방향을 바꿔 위에서부터 사라지는(반환) 모습을 관찰하세요 — 이 "미루기 → 거꾸로 처리"가 곧 6강의 스택(LIFO)입니다. 자기 호출이 두 번이라 스택은 "쌓였다 풀렸다"를 반복합니다.

    시각화 2 — {a, b, c} 순열 백트래킹

    • 세 문자 {a, b, c}를 한 줄로 세우는 모든 방법(순열)을 나열 — 자리를 앞에서부터 한 칸씩 채우며, 아직 안 쓴 문자를 하나 골라 붙임
    • 한 가지를 끝까지 시도한 뒤에는 한 단계 되돌아가 마지막 선택을 바꿈 — 이 "되돌아가기"가 백트래킹이라는 이름의 유래
    • current 스택에 선택이 쌓이고, 되돌아올 때 정확히 반대로 빠지는 것과 used 표시가 켜졌다 꺼지는 것을 확인
    • 호출 스택의 깊이는 "지금까지 고른 문자 수 + 1"이라는 것도 확인

    첫 자리 3가지 × 둘째 자리 2가지 × 셋째 자리 1가지 = 6개 — 시각화 마지막 단계에서 abc, acb, bac, bca, cab, cba 순서로 나열됩니다. 시각화 = 잠시 후 작성할 의사코드·코드가 모두 같은 절차입니다.

    시각화 3 — 순열의 상태 공간 트리

    같은 재귀를 이번엔 트리 전체 관점에서 봅니다. 백트래킹이 걷는 길을 미리 다 그려둔 지도가 상태 공간 트리입니다 — 노드 하나는 "지금까지 이렇게 골랐다"는 상태, 간선 하나는 문자를 하나 고르는 선택, 맨 아래 리프는 완성된 해(순열)입니다. 파란 경로는 지금 서 있는 상태, 회색 노드는 탐색을 마치고 돌아온 곳, 초록 노드는 확정된 순열입니다.

    선택(①)은 아래 자식으로 내려가는 일, 취소(③)는 위 부모로 올라오는 일입니다 — 백트래킹은 이 트리를 깊이 우선으로 한 바퀴 훑는 것이고, 노드를 한 번 방문할 때마다 permutation()이 한 번 호출됩니다.

    만약 n = 1 이면:                       // 종료 조건: 원반 1개는 바로 옮긴다
        원반 1 을 from 에서 to 로 옮긴다
        돌아간다

    Hanoi(n − 1, from, via, to) 를 호출한다   // ① 위의 n−1개를 보조 기둥 via 로 치운다
    원반 n 을 from 에서 to 로 옮긴다           // ② 가장 큰 원반을 목적지로 옮긴다
    Hanoi(n − 1, via, to, from) 를 호출한다   // ③ 치워 둔 n−1개를 목적지 위로 옮긴다

    순열 백트래킹 (Permutation Backtracking)

    Pseudo 순열 백트래킹 — 선택·진행·취소 
    알고리즘 Permutation(depth)           // depth = 상태 공간 트리의 깊이 = 호출 스택의 깊이
    nodeCount ← nodeCount + 1              // 트리의 노드(= 호출) 하나를 방문했다

    만약 current 의 길이 = 문자 개수 이면:  // 종료 조건: 리프 노드 — 순열 완성
        current 를 순열 하나로 기록한다
        돌아간다                           // 부모 노드로 복귀

    i 를 0 부터 문자 개수 − 1 까지 반복한다:
        만약 used[i] 가 참이면:            // 이미 쓴 문자는 가지를 만들지 않는다
            다음 i 로 넘어간다

        used[i] ← 참                       // (1) 선택: 자식 노드로 내려갈 준비
        current 끝에 문자[i] 를 붙인다
        Permutation(depth + 1) 을 호출한다 // (2) 진행: 자식 노드 탐색
        current 의 마지막 문자를 지운다    // (3) 취소: 부모 노드의 상태로 복원
        used[i] ← 거짓

    두 의사코드 정리

    • 두 알고리즘 모두 종료 조건을 먼저 검사하고, 그다음에 더 작은 문제로 자기 자신을 호출 — 하노이는 원반이, 순열은 남은 자리가 하나씩 줄어듦
    • 순열 의사코드의 한 호출 = 상태 공간 트리의 노드 하나, used[i] 검사를 통과해 자기 호출까지 가는 한 번의 반복 = 간선 하나
    • (1)과 (3)이 정확히 대칭 — "붙인다"에는 "지운다", used[i] ← 참에는 used[i] ← 거짓
    • 선택에서 한 일을 취소에서 그대로 되돌려야 모든 가지가 깨끗한 상태에서 출발

    • 호출 7번 = 이동 7번 = 2³ − 1 — 원반이 하나 늘 때마다 호출과 이동이 2배 + 1로 늘어남 (09 복잡도에서 계속)
    Java Step3HanoiRecursion.java 
    public class Step3HanoiRecursion {

    static int moveCount = 0;   // 지금까지 옮긴 횟수

    /** 완성된 하노이 탑. 호출 깊이를 들여쓰기로, 원반 이동을 한 줄로 출력한다. */
    static void hanoi(int n, char from, char to, char via, int depth) {
        String indent = "  ".repeat(depth);   // 깊이 = 호출 스택에 쌓인 프레임 수
        System.out.println(indent + "호출: hanoi(" + n + ", " + from + " -> " + to + ")");

        if (n == 1) {                         // 종료 조건: 원반 1개는 바로 옮긴다
            moveCount++;
            System.out.println(indent + "  이동 " + moveCount + ": 원반 1 (" + from + " -> " + to + ")");
            return;
        }

        hanoi(n - 1, from, via, to, depth + 1);   // 1) 위의 n-1개를 보조 기둥 via로 치운다
        moveCount++;
        System.out.println(indent + "  이동 " + moveCount + ": 원반 " + n + " (" + from + " -> " + to + ")");   // 2) 가장 큰 원반을 옮긴다
        hanoi(n - 1, via, to, from, depth + 1);   // 3) 치워 둔 n-1개를 목적지 위로 옮긴다
    }

    public static void main(String[] args) {
        int n = 3;
        System.out.println("원반 " + n + "개: A -> C (보조 B)");
        hanoi(n, 'A', 'C', 'B', 0);
        System.out.println("총 이동 " + moveCount + "번 (2^" + n + " - 1 = " + ((1 << n) - 1) + ")");
    }
}

    실습 코드 2 — 순열 문제를 상태 공간 트리로 풀기

    문제: {a, b, c}를 한 줄로 세우는 모든 방법을 빠짐없이, 중복 없이 나열하라. permutation(depth)는 상태 공간 트리의 노드 하나를 방문하는 메서드이고, 출력의 들여쓰기가 곧 트리의 깊이입니다.

    • current와 used[]가 지금 서 있는 노드의 상태 — 모든 재귀 호출이 함께 쓰는 공유 상태
    • 선택(append, used[i] = true)은 자식 노드로 내려가기 직전의 상태 변경, 취소(deleteCharAt, used[i] = false)는 부모 노드로 올라온 뒤의 상태 복원
    • nodeCount는 호출 횟수 = 방문한 노드 수 — 트리 그림의 노드를 직접 세어 비교해 보세요
    Java PermutationComplete.java 
    public class PermutationComplete {

    static char[] letters = {'a', 'b', 'c'};
    static boolean[] used = new boolean[letters.length];   // 문자 사용(방문) 여부 관리
    static StringBuilder current = new StringBuilder();    // 지금 트리의 어느 노드인지 = 지금까지의 선택
    static int nodeCount = 0;    // 방문한 상태 공간 트리의 노드 수
    static int permCount = 0;    // 완성된 순열(리프) 수

    /** 상태 공간 트리를 깊이 우선으로 훑으며 순열을 만든다. depth = 트리의 깊이 = 호출 스택의 깊이. */
    static void permutation(int depth) {
        nodeCount++;                                       // 이 호출 하나가 트리의 노드 하나
        String indent = "  ".repeat(depth);                // 깊이만큼 들여써서 트리 모양을 만든다

        if (current.length() == letters.length) {          // 종료 조건: 리프(잎) 노드 = 순열 완성
            permCount++;
            System.out.println(indent + current + "   <- 순열 " + permCount);
            return;
        }
        System.out.println(indent + (depth == 0 ? "(시작)" : current.toString()));

        for (int i = 0; i < letters.length; i++) {
            if (used[i]) {
                continue;                                  // 이미 쓴 문자는 가지를 만들지 않는다
            }
            used[i] = true;                                // (1) 선택: 자식 노드로 내려갈 준비
            current.append(letters[i]);
            permutation(depth + 1);                        // (2) 진행: 자식 노드 탐색
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 부모 노드의 상태로 복원
            used[i] = false;
        }
    }

    public static void main(String[] args) {
        System.out.println("{a, b, c}의 상태 공간 트리 (들여쓰기 = 깊이)");
        permutation(0);

        System.out.println();
        System.out.println("방문한 노드(= 재귀 호출 횟수): " + nodeCount + "개");
        System.out.println("그중 리프(순열 완성): " + permCount + "개");
    }
}

    public class BuggyPermutationNoRestore {

    static char[] letters = {'a', 'b', 'c'};
    static boolean[] used = new boolean[letters.length];
    static StringBuilder current = new StringBuilder();
    static int permCount = 0;

    static void permutation() {
        if (current.length() == letters.length) {
            permCount++;
            System.out.println("순열 " + permCount + ": " + current);
            return;
        }

        for (int i = 0; i < letters.length; i++) {
            if (used[i]) continue;
            used[i] = true;                                // (1) 선택
            current.append(letters[i]);
            permutation();                                 // (2) 진행
            current.deleteCharAt(current.length() - 1);
        }
    }

    public static void main(String[] args) {
        System.out.println("{a, b, c}의 모든 순열:");
        permutation();
        System.out.println("총 " + permCount + "개 (기대값 6개)");
    }
}

    09복잡도 및 특성 분석

    복잡도 = "데이터가 많아지면 일이 얼마나 늘어나는가?" 초 단위 시간이 아니라 "몇 번 하는가"만 세어 봅니다.

    시간 복잡도 — 얼마나 오래 걸리는가?

    알고리즘경우(호출)의 수Big-O쉽게 말하면
    하노이 탑이동·호출 2ⁿ − 1번O(2ⁿ)원반 1개 늘면 이동이 2배 + 1 — 64개를 초당 1번 옮기면 약 5,800억 년
    순열 나열리프 n!개 (노드는 약 2.7 × n!개)O(n! · n)n명을 한 줄로 세우는 방법 수 — 상태 공간 트리의 리프 수
    • n = 3: 순열 6개(노드 16개) / n = 4: 24개(노드 65개) / n = 10: 3,628,800개 / n = 20: 약 243경 개
    • 나열은 모든 경우를 다 만들어야 끝남 → 가지치기를 넣을 때만 실제 탐색량이 줄어듦

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 재귀는 호출마다 호출 스택에 한 장씩 쌓임 → 메모리 = 가장 깊이 쌓였을 때의 높이
    • 하노이 탑: 깊이 n → O(n) / 순열: 트리의 깊이 n → O(n) (트리 전체를 저장하지 않고 지금 걷는 한 경로만 스택에 있음)
    • 깊이가 수만을 넘으면 StackOverflowError → 반복문이나 6강의 명시적 스택으로 바꿈
    한 줄 정리 — 코드는 짧지만 경우의 수는 폭발한다
    • 현실적인 한계: 순열은 n ≈ 10 안팎까지 (부분집합도 2ⁿ이라 n ≈ 20이 한계)
    • 메모리는 깊이만큼만 쓰지만, 깊이가 너무 깊으면 스택이 넘침
    • 자기 호출이 두 번씩 일어나는 재귀(아래 피보나치)는 호출 수가 폭발하므로 조심

    재귀의 함정 — 같은 계산을 반복하는 피보나치

    재귀가 늘 좋은 것은 아닙니다. 피보나치 수를 정의 그대로 재귀로 옮기면 자기 호출이 두 번 일어나는데, 이때 같은 계산이 얼마나 반복되는지 호출 횟수 카운터(1강의 도구)로 측정해 봅니다.

    Java FibonacciBasic.java 
    public class FibonacciBasic {

    static long callCount = 0;   // fibo가 호출된 총 횟수

    /** 기본 재귀 피보나치. 정의를 그대로 옮겼지만 같은 계산을 여러 번 반복한다. */
    static long fibo(int n) {
        callCount++;
        if (n <= 1) {                        // 종료 조건: fibo(0) = 0, fibo(1) = 1
            return n;
        }
        return fibo(n - 1) + fibo(n - 2);    // 자기 호출이 두 번!
    }

    public static void main(String[] args) {
        int[] tests = {10, 20, 30};

        System.out.println("n  | fibo(n) | 호출 횟수");
        System.out.println("---+---------+----------");
        for (int n : tests) {
            callCount = 0;
            long value = fibo(n);
            System.out.printf("%-2d | %-7d | %d%n", n, value, callCount);
        }

        System.out.println();
        System.out.println("n이 10 커질 때마다 호출 횟수가 약 120배씩 폭발한다.");
        System.out.println("원인: fibo(20)을 구할 때 fibo(18)을 2번, fibo(17)을 3번... 같은 계산을 반복하기 때문.");
        System.out.println("해결책은 11강 동적 계획법에서 배운다 (계산 결과를 저장해 재사용).");
    }
}

    문제 상황

    • 수학여행 버스의 한 줄 좌석 3개에 학생 민준, 서연, 도윤을 배치해야 함
    • 담임 선생님의 규칙: "민준과 서연은 옆자리에 앉을 수 없다."
    • 가능한 배치를 모두 나열하되, 규칙을 지키는 배치만 골라내야 함
    • 좌석 배치는 순서가 중요하므로 순열 백트래킹이 정확히 맞는 도구이고, 규칙 검사를 가지치기로 넣으면 어긋나는 배치는 끝까지 만들어 보기도 전에 걸러짐

    데이터 모델과 알고리즘 적용 기준

    • 데이터: 학생 이름 배열 students, 좌석 배열 seats (seats[i] = i번 좌석의 학생), 방문 배열 used
    • 알고리즘: 좌석 0번부터 차례로 학생을 고르는 순열 백트래킹 — 실습 코드의 permutation(depth)와 같은 구조 (깊이 = 좌석 번호)
    • 가지치기: 학생을 앉히기 전에 바로 왼쪽 좌석과 금지된 짝인지 검사, 어긋나면 continue — 상태 공간 트리에서 그 가지(서브트리)를 통째로 건너뜀
    Java SeatingApplication.java 
    public class SeatingApplication {

    static String[] students = {"민준", "서연", "도윤"};
    static String[] seats = new String[students.length];   // seats[i] = i번 좌석의 학생
    static boolean[] used = new boolean[students.length];  // 학생 배치(방문) 여부
    static int totalCount = 0;    // 제약 없는 전체 배치 수
    static int validCount = 0;    // 규칙을 통과한 배치 수
    static int pruneCount = 0;    // 가지치기로 잘라낸 횟수

    /** 규칙: 민준과 서연은 옆자리에 앉을 수 없다. */
    static boolean isForbiddenPair(String a, String b) {
        return (a.equals("민준") && b.equals("서연"))
                || (a.equals("서연") && b.equals("민준"));
    }

    /** [1] 제약 없이 모든 배치를 나열한다 (순열 백트래킹 그대로). */
    static void arrangeAll(int seatIndex) {
        if (seatIndex == seats.length) {           // 종료 조건: 모든 좌석을 채웠다
            totalCount++;
            System.out.println("  배치 " + totalCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;
            used[i] = true;                        // 선택
            seats[seatIndex] = students[i];
            arrangeAll(seatIndex + 1);             // 진행
            used[i] = false;                       // 취소: 상태 복원
            seats[seatIndex] = null;
        }
    }

    /** [2] 같은 구조에 가지치기 검사를 한 번 추가한다. */
    static void arrangeWithRule(int seatIndex) {
        if (seatIndex == seats.length) {
            validCount++;
            System.out.println("  통과 " + validCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;

            // 가지치기: 바로 왼쪽 좌석과 금지된 짝이면 이 가지는 내려가지 않는다
            if (seatIndex > 0 && isForbiddenPair(seats[seatIndex - 1], students[i])) {
                pruneCount++;
                continue;
            }

            used[i] = true;
            seats[seatIndex] = students[i];
            arrangeWithRule(seatIndex + 1);
            used[i] = false;
            seats[seatIndex] = null;
        }
    }

    public static void main(String[] args) {
        System.out.println("[1] 제약 없는 전체 좌석 배치 (3! = 6가지)");
        arrangeAll(0);

        System.out.println();
        System.out.println("[2] 규칙 적용: 민준-서연 옆자리 금지");
        arrangeWithRule(0);

        System.out.println();
        System.out.println("전체 " + totalCount + "가지 중 " + validCount + "가지만 규칙을 통과");
        System.out.println("가지치기 발동 " + pruneCount + "번 — 어긋나는 가지는 끝까지 만들기 전에 잘랐다.");
    }
}

    코드 해설과 복잡도 분석

    • arrangeAll과 arrangeWithRule의 차이는 가지치기 if 한 덩어리뿐입니다. 백트래킹 뼈대를 한 번 익히면, 문제의 규칙은 가지치기 조건으로만 추가됩니다.
    • 가지치기는 선택하기 전에 검사합니다 — 앉혀 놓고 검사하면 취소도 해야 하므로, 아예 앉히지 않고 건너뛰는 쪽이 간결하고 빠릅니다.
    • 취소 단계에서 used[i] = false와 seats[seatIndex] = null — 선택에서 바꾼 두 가지 상태를 모두 되돌리는 것에 주목하세요. 하나만 되돌리면 오류 2와 같은 버그가 됩니다.
    • 복잡도: 전체 나열은 O(n! · n). 학생 3명이면 6가지지만 10명이면 3,628,800가지 — 규칙이 많을수록 가지치기가 일찍 발동해 실제 탐색량은 크게 줄어듭니다.

    13최종 프로그램 작성 문제

    과제 안내

    이 문제는 수업 시간이 아니라 수업 후 과제로 진행합니다. 수업에서는 문제 배경과 시작 코드만 짚고 넘어가고, 나머지는 직접 완성해 오세요.

    문제 제목 — 자물쇠 비밀번호 후보 생성기

    문제 배경

    실제 문제 상황(4번 섹션)의 자물쇠로 돌아가면, 비밀번호는 버튼 1, 3, 7, 9만 사용했고 같은 버튼을 여러 번 눌러도 됩니다(예: 11, 33). 여러분은 자리 수 k를 입력하면 길이 k의 모든 후보를 사전 순으로 나열하는 프로그램을 만들기로 했습니다. 그런데 전 부장의 증언이 하나 추가되었습니다: "같은 숫자를 연속으로 누른 적은 없어." 이 규칙을 가지치기로 넣으면 시도할 후보를 크게 줄일 수 있습니다. 전체 생성과 가지치기 생성을 모두 구현하고, 가지치기가 몇 개를 걸러 냈는지도 세어 봅시다.

    프로그램 목표

    길이 k의 비밀번호 후보를 (1) 제약 없이 전부, (2) "같은 문자 연속 금지" 가지치기를 적용해 생성하고, 개수를 이론값과 비교하는 콘솔 프로그램을 완성합니다.

    필수 요구사항

    1. generateAll(int k) — 후보 문자로 만들 수 있는 길이 k의 모든 문자열을 백트래킹으로 생성한다 (같은 문자 반복 허용).
    2. generateNoRepeat(int k) — 같은 문자가 연속으로 나오는 가지를 선택하기 전에 잘라내며 생성한다.
    3. 두 메서드 모두 종료 조건은 "current의 길이가 k"이고, 선택 → 진행 → 취소 구조를 지킨다.
    4. printEach가 true일 때만 후보를 한 줄씩 출력한다 (개수만 셀 때는 false).
    5. 길이 2에서 전체 16개, 연속 금지 12개를 출력하고, 길이 3에서는 개수만 비교한다.

    Java PasswordSolution.java 
    public class PasswordSolution {

    static char[] candidates = {'1', '3', '7', '9'};   // 후보 문자 4개
    static StringBuilder current = new StringBuilder(); // 지금 만드는 중인 비밀번호
    static int allCount = 0;        // 전체 생성 개수
    static int rulePassCount = 0;   // 가지치기 통과 개수
    static boolean printEach = true; // 하나씩 출력할지 여부 (개수만 셀 때는 false)

    /** [과제 1] 길이 k의 모든 비밀번호를 생성한다. (같은 문자를 여러 번 써도 됨) */
    static void generateAll(int k) {
        if (current.length() == k) {                       // 종료 조건: k자리 완성
            allCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            current.append(candidates[i]);                 // (1) 선택
            generateAll(k);                                // (2) 진행
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 상태 복원
        }
    }

    /** [과제 2] 같은 문자가 연속으로 나오는 가지를 잘라내며 생성한다. */
    static void generateNoRepeat(int k) {
        if (current.length() == k) {                       // 종료 조건
            rulePassCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            // 가지치기: 직전 문자와 같으면 이 가지는 내려가 보지 않는다
            if (current.length() > 0
                    && current.charAt(current.length() - 1) == candidates[i]) {
                continue;
            }
            current.append(candidates[i]);                 // 선택
            generateNoRepeat(k);                           // 진행
            current.deleteCharAt(current.length() - 1);    // 취소
        }
    }

    public static void main(String[] args) {
        System.out.println("후보 문자: 1, 3, 7, 9");

        System.out.println();
        System.out.println("[1] 길이 2 — 만들 수 있는 모든 비밀번호");
        printEach = true;
        allCount = 0;
        generateAll(2);
        System.out.println("  총 " + allCount + "개 (이론값 4^2 = 16)");

        System.out.println();
        System.out.println("[2] 길이 2 — 같은 문자 연속 금지 (가지치기)");
        rulePassCount = 0;
        generateNoRepeat(2);
        System.out.println("  총 " + rulePassCount + "개 (이론값 4 x 3 = 12)");

        System.out.println();
        System.out.println("[3] 길이 3 — 개수만 비교");
        printEach = false;
        allCount = 0;
        rulePassCount = 0;
        generateAll(3);
        generateNoRepeat(3);
        System.out.println("  전체 생성: " + allCount + "개 (4^3 = 64)");
        System.out.println("  연속 금지: " + rulePassCount + "개 (4 x 3 x 3 = 36)");
        System.out.println("  가지치기로 " + (allCount - rulePassCount)
                + "개는 만들어 보기도 전에 걸러졌다.");
    }

    구현 순서와 핵심 알고리즘 적용 부분

    1. generateAll은 순열 의사코드(06)와 뼈대가 같습니다 (used[] 검사만 빠진 형태). 다른 점은 "넣는다/안 넣는다" 2갈래 대신 후보 4개를 도는 for문이라는 것뿐입니다 — 가지 수가 후보 수(4)인 결정 트리입니다.
    2. 재귀 호출이 generateAll(k)로 k를 그대로 전달하는 것에 주목하세요. 진행 정도는 k가 아니라 current의 길이가 말해 줍니다 — append로 길이가 1 늘어나므로 문제는 종료 조건 쪽으로 확실히 가까워집니다.
    3. generateNoRepeat의 가지치기는 current.length() > 0 검사가 먼저 옵니다. 빈 문자열에서 charAt(-1)을 부르면 예외가 나므로, 경계 조건 검사가 앞이어야 합니다 (테스트 3종의 "경계 조건 k = 1"이 바로 이 지점을 확인합니다).
    4. [3]에서 카운터를 0으로 초기화하고 printEach를 끄는 것 — 상태를 공유하는 프로그램에서는 측정 전에 상태를 초기화하는 습관이 필요합니다.

    복잡도 분석

    • generateAll: 후보 c개, 길이 k → 완성 후보 cᵏ개, 시간 O(cᵏ · k). k = 2면 16개, k = 3이면 64개.
    • generateNoRepeat: 첫 자리 c가지 × 이후 자리마다 (c − 1)가지 → c × (c−1)ᵏ⁻¹개. k = 3이면 4 × 3 × 3 = 36개 — 걸러진 28개의 가지는 재귀 호출 자체가 일어나지 않았습니다.
    • 공간: 호출 스택 깊이 = k → O(k).

    자주 발생하는 오류

    • 종료 조건 없이 for문부터 쓰는 경우 — current가 무한히 길어지다 StackOverflowError (오류 1 유형).
    • deleteCharAt을 빼먹는 경우 — 첫 후보 "11"을 만든 뒤 상태가 복원되지 않아 이후 결과가 전부 오염됩니다 (오류 2 유형).
    • 가지치기에서 current.length() > 0을 빼먹는 경우 — 첫 문자를 붙이기 전에 charAt(-1)로 StringIndexOutOfBoundsException.
    • [3] 실행 전에 카운터를 초기화하지 않아 [1]·[2]의 개수가 합산되는 경우.

    다른 해결 방법

    StringBuilder 대신 char[] password 배열과 깊이 인덱스 depth를 쓰면 password[depth] = c로 덮어쓰기 때문에 취소 코드가 없어도 됩니다 — 대신 "지금 몇 자리까지 채웠는가"를 depth 매개변수로 전달해야 합니다. 또한 이런 "중복을 허용하는 나열"은 k겹 반복문으로도 가능하지만, k가 실행 중에 바뀌면 코드도 바꿔야 하므로 재귀만이 일반적인 해법입니다.

    14오늘의 핵심 정리

    • 재귀 호출은 큰 문제를 같은 구조의 더 작은 문제에 맡기는 것(하노이 탑: 원반 n개를 n-1개짜리 두 문제로) — 종료 조건(브레이크)과 재귀 단계(더 작아지는 자기 호출)가 둘 다 있어야 한다.
    • 메서드 호출은 호출 스택에 프레임으로 쌓이고(6강 스택의 LIFO), 나중에 호출된 것이 먼저 반환된다. 종료 조건이 없으면 StackOverflowError.
    • 상태 공간 트리는 노드 = 상태, 간선 = 선택, 리프 = 해인 지도 — 백트래킹은 이 트리를 깊이 우선으로 훑는 재귀이며(3강 완전 탐색의 확장), 모든 코드는 선택 → 진행 → 취소 3단계 패턴을 따른다. 선택에서 바꾼 상태는 취소에서 정확히 되돌린다.
    • 순열은 used[]로 이미 쓴 원소를 막으며 n!개의 리프를 만들고, 재귀 호출 횟수는 트리의 노드 수와 같다 ({a, b, c}라면 호출 16번, 순열 6개).
    • 가지치기는 조건에 어긋나는 가지(서브트리)를 선택하기 전에 잘라 탐색량을 줄인다 — 비밀번호 k = 3에서 64개 중 28개를 만들기 전에 걸렀다.
    • 재귀 피보나치의 호출 폭발(fibo(30) = 2,692,537번)은 중복 계산 때문 — 저장해서 재사용하는 해결책은 11강 동적 계획법에서.

재귀 호출과 백트래킹

Recursion and Backtracking

탐색 중급 Java 17+

반복문은 "몇 번 반복할지"를 코드에 미리 적어야 합니다. 그런데 반복의 깊이가 실행 중에 달라지는 문제라면 어떻게 할까요? 이번 강의에서는 메서드가 자기 자신을 호출하는 재귀와, 재귀 위에 "선택 → 진행 → 취소" 구조를 얹어 모든 경우를 빠짐없이 나열하는 백트래킹을 배웁니다. 6강에서 배운 스택이 호출 스택이라는 이름으로 다시 등장합니다.

이 강의의 목차

    01강의 소개

    오늘의 질문: "몇 글자인지 실행할 때 정해지는" 문제, for문을 몇 겹 써야 할까? 답은 바로 재귀 호출(recursion)입니다.

    • 3강 완전 탐색 복습 — 두 글자 조합은 이중 for문, 세 글자 조합은 삼중 for문
    • 그런데 반복 깊이가 실행 중에 정해지는 문제라면? 코드는 실행 중에 자기 몸을 늘릴 수 없음
    • 오늘 강의 구성
      • 앞부분 — 팩토리얼(n!)로 종료 조건과 호출 스택이라는 재귀의 두 기둥을 세우고, 종료 조건이 없으면 StackOverflowError로 죽는 것도 직접 확인
      • 뒷부분 — 선택(choose) → 진행(explore) → 취소(unchoose) 백트래킹 패턴을 얹어 부분집합·순열·조합을 빠짐없이 나열하고, 가지치기(pruning)까지 적용
      • 마지막 — 잊어버린 자물쇠 비밀번호의 후보를 모두 생성하는 프로그램을 직접 작성

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 재귀 메서드에서 종료 조건(base case)과 재귀 단계(recursive step)를 구분하여 설명할 수 있다.
    • 학생은 factorial(4)의 호출과 반환 순서를 호출 스택 그림으로 추적할 수 있다.
    • 학생은 종료 조건이 없거나 도달할 수 없을 때 StackOverflowError가 발생하는 이유를 설명할 수 있다.
    • 학생은 선택-진행-취소 구조의 백트래킹으로 부분집합·순열·조합을 나열하는 Java 코드를 작성할 수 있다.
    • 학생은 조건 검사를 추가해 불필요한 가지를 잘라내는 가지치기를 구현하고 그 효과를 개수로 확인할 수 있다.
    • 학생은 재귀 피보나치의 호출 횟수를 측정해 중복 호출 문제를 설명할 수 있다.

    03실제 문제 상황

    • 동아리 방 사물함 다이얼 자물쇠의 비밀번호는 "버튼은 1, 3, 7, 9 네 개만 사용했다"는 것만 기억날 뿐, 자리 수는 2자리인지 3자리인지도 확실하지 않음
    • 후보 비밀번호를 빠짐없이, 중복 없이 뽑아야 하는데, 자리 수가 2, 3, 4로 바뀔 때마다 for문을 한 겹씩 더 쓸 수는 없음
    • 반복의 깊이 자체가 입력에 따라 변하는 문제 — 오늘 배울 재귀와 백트래킹이 정확히 이 문제를 풀어냄

    반복의 깊이가 실행 중에 정해지는 완전 탐색을, 어떻게 하나의 코드로 구현할까?

    04핵심 개념

    재귀 호출이란?

    재귀 호출은 메서드가 자기 자신을 호출하는 것 — "큰 문제를 같은 구조의 더 작은 문제에 맡기고 돌아온 답으로 내 답을 완성한다"는 뜻입니다. factorial(4)는 factorial(3)에게 "3!을 구해 줘"라고 맡기고, 돌아온 6에 4를 곱해 24를 완성합니다.

    재귀의 두 부분 — 이 중 하나라도 없으면 재귀가 아니다

    구성 요소역할팩토리얼에서는
    종료 조건 (base case)더 쪼개지 않고 즉시 답하는 가장 작은 문제. 재귀를 멈추는 브레이크.if (n <= 1) return 1;
    재귀 단계 (recursive step)문제를 더 작게 만들어 자기 자신에게 맡기고, 결과를 조합한다.return n * factorial(n - 1);

    재귀 단계에는 숨은 조건이 하나 더 있습니다 — 호출할 때마다 문제가 종료 조건 쪽으로 가까워져야 합니다. factorial(n - 1)은 n이 1씩 줄어 언젠가 종료 조건에 닿지만, 실수로 factorial(n)을 호출하면 문제가 작아지지 않아 영원히 끝나지 않습니다.

    호출 스택과 StackOverflowError

    • JVM은 메서드가 호출될 때마다 그 메서드의 매개변수·지역 변수를 담은 스택 프레임을 호출 스택에 push하고, 메서드가 반환되면 pop
    • 6강에서 배운 LIFO 그대로 — 가장 나중에 호출된 메서드가 가장 먼저 반환
    • 예: factorial(4)를 부르면 스택에는 factorial(4) → factorial(3) → factorial(2) → factorial(1)이 차례로 쌓였다가, 위에서부터 1 → 2 → 6 → 24를 반환하며 무너짐

    호출 스택의 크기는 유한합니다(기본 설정에서 대략 수천~수만 프레임). 종료 조건이 없거나 도달할 수 없으면 프레임이 무한히 쌓이다가 스택이 넘쳐 StackOverflowError가 발생합니다 — 오류 찾기 섹션에서 실제로 터뜨려 봅니다.

    백트래킹 — 선택 · 진행 · 취소

    백트래킹은 재귀로 결정 트리를 내려가며 모든 경우를 나열하되, 한 가지를 끝까지 시도한 뒤에는 반드시 상태를 원래대로 되돌리고 다음 선택지를 시도하는 기법 — 모든 백트래킹 코드는 아래 3단계 패턴을 따릅니다.

    단계의미코드 형태
    (1) 선택 choose후보 하나를 골라 현재 상태에 반영한다chosen.add(x), used[i] = true
    (2) 진행 explore다음 결정을 하러 재귀 호출로 내려간다go(index + 1)
    (3) 취소 unchoose돌아오면 선택을 정확히 반대로 되돌린다chosen.remove(...), used[i] = false

    취소가 필요한 이유는 chosen이나 used[]가 모든 재귀 호출이 함께 쓰는 공유 상태이기 때문 — 형제 가지를 탐색하러 가기 전에 내가 남긴 흔적을 지우지 않으면, 다음 가지가 오염된 상태에서 출발합니다.

    세 가지 대표 나열 패턴

    패턴각 단계의 결정중복 방지 장치개수 (원소 n개)
    부분집합i번째 원소를 넣는다 / 안 넣는다원소를 index 순서로 결정2ⁿ
    순열아직 안 쓴 원소 중 하나를 다음 자리에 놓는다used[] 방문 배열 (3강의 방문 확인)n!
    조합start 이후의 원소 중 하나를 고른다start 인덱스 (순서 뒤집힌 중복 차단)nCk

    가지치기 (pruning)

    • 경우의 수가 2ⁿ, n!처럼 폭발하므로, 조건에 어긋나는 것이 확실해진 가지는 끝까지 내려가지 않고 그 자리에서 잘라냄
    • 선택하기 전에 조건을 검사해 continue로 건너뛰는 한 줄이면 충분
    • 잘라낸 가지 아래의 모든 경우가 통째로 생략되므로 효과가 큼

    05단계별 동작 과정

    • 세 개의 시각화로 오늘의 핵심을 확인 — 다음 단계 ▶ 버튼으로 한 단계씩 진행
    • 파란색 테두리 = 현재 실행 중인 프레임/위치, 초록색 = 완료 (캡션 텍스트로도 상태를 설명)

    시각화 1 — factorial(4)의 호출 스택

    • 4! = 4 × 3! — 3!을 아직 모르므로 계산을 미루고, 3! = 3 × 2! → 2! = 2 × 1!로 계속 미룸
    • 1! = 1(종료 조건)에서 멈춘 뒤, 미뤄 둔 계산을 가장 최근 것부터 거꾸로 처리: 2 → 6 → 24

    프레임이 아래에서 위로 쌓이고(호출), 종료 조건에서 방향을 바꿔 위에서부터 사라지는(반환) 모습을 관찰하세요 — 이 "미루기 → 거꾸로 처리"가 곧 6강의 스택(LIFO)입니다.

    시각화 2 — {1, 2, 3} 부분집합 백트래킹

    • 카드 세 장 {1, 2, 3}의 모든 부분집합을 나열 — 원소를 한 장씩 차례로 "넣는다 / 안 넣는다"로 결정하며 결정 트리를 내려감
    • 한 가지를 끝까지 시도한 뒤에는 한 단계 되돌아가 마지막 결정을 바꿈 — 이 "되돌아가기"가 백트래킹이라는 이름의 유래
    • chosen 스택에 선택이 쌓이고, 되돌아올 때 정확히 반대로 빠지는 것을 확인
    • 호출 스택의 깊이가 결정한 원소 개수와 같다는 것도 확인

    원소마다 2갈래이므로 부분집합은 2 × 2 × 2 = 8개 — 시각화 마지막 단계에서 {1,2,3}, {1,2}, {1,3}, {1}, {2,3}, {2}, {3}, {} 순서로 나열됩니다. 시각화 = 잠시 후 작성할 의사코드·코드가 모두 같은 절차입니다.

    시각화 3 — {1, 2, 3} 부분집합의 결정 트리

    같은 재귀를 이번엔 트리 전체 관점에서 봅니다. 미리 다 그려둔 트리 위를 재귀가 어떻게 훑고 지나가는지 관찰하세요 — 파란 경로는 지금 내려가 있는 가지, 초록 노드는 이미 확정된 부분집합입니다.

    06의사코드

    코드를 쓰기 전에, 두 알고리즘의 절차를 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄(만약 … 이면:) 안에 포함된 작업", // 뒤는 설명(주석)
    • Factorial(n − 1)처럼 알고리즘이 자기 이름을 다시 부르는 줄이 재귀 호출 — 그 줄에서 멈춰 답이 돌아올 때까지 기다린 뒤 다음 줄로 넘어감

    재귀 팩토리얼 (Recursive Factorial)

    Pseudo 재귀 팩토리얼 
    알고리즘 Factorial(n)
    만약 n ≤ 1 이면:                     // 종료 조건 (브레이크)
        1을 반환한다
    smaller ← Factorial(n − 1)           // 더 작은 같은 문제에 맡긴다
    n × smaller 를 반환한다              // 돌아온 답으로 내 답을 완성한다

    부분집합 백트래킹 (Subset Backtracking)

    Pseudo 부분집합 백트래킹 — 선택·진행·취소 
    알고리즘 Subsets(index)
    만약 index = 원소 개수 이면:          // 종료 조건: 모든 원소를 결정했다
        chosen 을 부분집합 하나로 기록한다
        돌아간다

    // 경우 1: index번째 원소를 넣는 가지
    chosen 에 원소[index] 를 추가한다     // (1) 선택
    Subsets(index + 1) 을 호출한다        // (2) 진행
    chosen 에서 마지막 원소를 제거한다    // (3) 취소 — 상태 복원!

    // 경우 2: index번째 원소를 넣지 않는 가지
    Subsets(index + 1) 을 호출한다        // 넣은 것이 없으니 취소도 없다

    두 의사코드 정리

    • 두 알고리즘 모두 종료 조건을 먼저 검사하고, 그다음에 더 작은 문제로 자기 자신을 호출
    • 백트래킹 의사코드에서 (1)과 (3)이 정확히 대칭 — add에는 remove, used[i] = true에는 used[i] = false
    • 선택에서 한 일을 취소에서 그대로 되돌려야 모든 가지가 깨끗한 상태에서 출발

    07실습 코드

    의사코드(06)를 Java로 옮깁니다. 부분집합에 이어 나머지 두 나열 패턴 — 순열(used[] 방문 배열)과 조합(start 인덱스)을 구현한 프로그램입니다.

    • permutation·combination 모두 04 핵심 개념·06 의사코드의 선택(choose) → 진행(explore) → 취소(unchoose) 3단계 구조를 그대로 메서드로 옮긴 것
    • permutation의 used[]는 04에서 배운 방문 배열 중복 방지 장치를, combination의 start는 인덱스로 순서를 고정하는 중복 방지 장치를 코드로 옮긴 것 — 둘의 차이가 곧 순열과 조합의 차이
    • 두 메서드 모두 선택·취소가 정확히 대칭이라는 점(append ↔ deleteCharAt, used[i]=true ↔ used[i]=false)에 주목하세요
    Java PermutationComplete.java 
    public class PermutationComplete {

    static char[] letters = {'a', 'b', 'c'};
    static boolean[] used = new boolean[letters.length];   // 문자 사용(방문) 여부 관리
    static StringBuilder current = new StringBuilder();    // 지금까지 만든 문자열 (공유 상태)
    static int permCount = 0;
    static int comboCount = 0;

    /** 순열: 아직 안 쓴 문자를 하나 골라 붙이고, 재귀가 돌아오면 반드시 되돌린다. */
    static void permutation() {
        if (current.length() == letters.length) {          // 종료 조건: 전부 골랐다
            permCount++;
            System.out.println("  순열 " + permCount + ": " + current);
            return;
        }

        for (int i = 0; i < letters.length; i++) {
            if (used[i]) {
                continue;                                  // 이미 쓴 문자는 건너뛴다
            }
            used[i] = true;                                // (1) 선택
            current.append(letters[i]);
            permutation();                                 // (2) 진행
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 상태 복원
            used[i] = false;
        }
    }

    /** 조합: start 이후의 문자만 고르므로 순서만 다른 중복이 생기지 않는다. */
    static void combination(int start, int k) {
        if (current.length() == k) {                       // 종료 조건: k개를 골랐다
            comboCount++;
            System.out.println("  조합 " + comboCount + ": " + current);
            return;
        }

        for (int i = start; i < letters.length; i++) {
            current.append(letters[i]);                    // 선택
            combination(i + 1, k);                         // 진행: 다음은 i + 1부터만
            current.deleteCharAt(current.length() - 1);    // 취소
        }
    }

    public static void main(String[] args) {
        System.out.println("[1] {a, b, c}의 모든 순열 (3! = 6개)");
        permutation();

        System.out.println();
        System.out.println("[2] {a, b, c}에서 2개를 고르는 조합 (3C2 = 3개)");
        combination(0, 2);
    }
}

    • 순열은 매번 전체 후보에서 고르되 used[]로 재사용을 막습니다 — ab와 ba를 모두 만듭니다.
    • 조합은 start 이후에서만 고릅니다 — a를 고른 뒤에는 b, c만 볼 수 있으므로 ba처럼 순서만 다른 중복이 아예 생기지 않아 used[]도 필요 없습니다.

    08잘못된 코드와 오류 찾기

    재귀와 백트래킹에서 초보자가 가장 자주 만드는 오류 두 가지 — 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 종료 조건이 없는 재귀

    Java BuggyFactorialNoBase.java (오류 있음) 
    public class BuggyFactorialNoBase {

    /** 팩토리얼을 재귀로 구한다 */
    static long factorial(int n) {
        return n * factorial(n - 1);
    }

    public static void main(String[] args) {
        System.out.println("4! 계산을 시작합니다.");
        System.out.println("4! = " + factorial(4));
    }
}
    발생하는 문제와 수정 방법 확인
    • 발생하는 문제: 컴파일은 정상적으로 되지만, 실행하면 답이 나오지 않고 프로그램이 죽음
    4! 계산을 시작합니다.
Exception in thread "main" java.lang.StackOverflowError
	at BuggyFactorialNoBase.factorial(BuggyFactorialNoBase.java:5)
	at BuggyFactorialNoBase.factorial(BuggyFactorialNoBase.java:5)
	at BuggyFactorialNoBase.factorial(BuggyFactorialNoBase.java:5)
    • 같은 at BuggyFactorialNoBase.factorial 줄이 스택 깊이만큼 수천 줄 반복해서 출력됨
    • 오류가 나타나는 입력: 모든 입력 — factorial(4)든 factorial(1)이든 반드시 죽음
    • 원인: 멈추는 조건이 없으므로 factorial(4) → factorial(3) → … → factorial(0) → factorial(-1) → … 호출이 영원히 이어짐 — 호출마다 스택 프레임이 하나씩 쌓이는데 호출 스택의 크기는 유한하므로, 결국 스택이 넘쳐 StackOverflowError가 발생 — 오류 메시지에 같은 줄이 끝없이 반복되는 것이 "재귀가 멈추지 않았다"는 결정적 증거
    • 수정 방법: 자기 호출보다 먼저 종료 조건을 검사
    static long factorial(int n) {
    if (n <= 1) {      // 종료 조건: 여기서 재귀가 멈춘다
        return 1;
    }
    return n * factorial(n - 1);
}

    수정 후 출력: 4! = 24. 재귀를 쓸 때는 항상 "종료 조건이 있는가?"와 "매 호출마다 종료 조건에 가까워지는가?" 두 가지를 확인하세요.

    Java BuggySubsetsNoRestore.java (오류 있음) 
    import java.util.ArrayList;
import java.util.List;

public class BuggySubsetsNoRestore {

    static int[] numbers = {1, 2, 3};
    static List<Integer> chosen = new ArrayList<>();
    static int subsetCount = 0;

    static void subsets(int index) {
        if (index == numbers.length) {
            subsetCount++;
            System.out.println("부분집합 " + subsetCount + ": " + chosen);

        subsets(index + 1);           // 넣지 않는 경우

        System.out.println("{1, 2, 3}의 모든 부분집합:");

    }
}

    • 수정 방법: 선택과 정확히 대칭인 취소를 진행 직후에 넣음
    chosen.add(numbers[index]);         // (1) 선택
subsets(index + 1);                 // (2) 진행
chosen.remove(chosen.size() - 1);   // (3) 취소: 선택을 정확히 반대로 되돌린다

subsets(index + 1);                 // 넣지 않는 경우

    수정 후에는 의사코드(06)대로 서로 다른 부분집합 8개가 올바르게 나옵니다. 선택한 것은 반드시 취소한다 — add에는 remove, used[i] = true에는 used[i] = false를 짝으로 쓰는 습관을 들이세요.

    09복잡도 및 특성 분석

    복잡도 분석 = "데이터가 많아지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 재귀에서는 "몇 번 호출하는가"와 "얼마나 깊이 쌓이는가" 두 가지만 세어 봅니다.

    입력 크기 — 무엇이 많아지는가?

    • 팩토리얼: 구하려는 수 n — n이 클수록 곱할 수가 많아짐
    • 부분집합·순열·조합 나열: 원소(후보)의 개수 n — 카드가 한 장 늘 때마다 만들 경우가 늘어남
    • 재귀에서는 깊이(호출이 몇 겹까지 쌓이는가)도 함께 봄 — 깊이가 곧 호출 스택 메모리 사용량

    주요 연산 — 무엇을 세는가?

    • 가장 많이 반복되는 동작 = 재귀 호출 한 번 (그리고 짝을 이루는 선택·취소)
    • 나열 문제의 총 일의 양은 대략 "만들어지는 경우의 수 × 하나를 만드는 비용"
      • 경우 하나를 기록·출력하려면 원소를 최대 n개 적어야 하므로 "하나를 만드는 비용"은 약 n

    시간 복잡도 — 얼마나 오래 걸리는가?

    알고리즘만드는 경우(호출)의 수n = 3일 때n = 10일 때n = 20일 때Big-O
    재귀 팩토리얼호출 n번3번10번20번O(n)
    부분집합 나열2ⁿ개8개1,024개약 105만 개O(2ⁿ · n)
    순열 나열n!개6개3,628,800개약 243경 개O(n! · n)
    조합 나열 (k = 2개 고르기)nCk개3개45개190개O(nCk · k)
    • O(n)을 쉽게 말하면: 팩토리얼은 n에서 1까지 한 칸씩 내려가며 한 번씩만 호출 — 계단을 한 칸씩 내려가는 것과 같음
    • O(2ⁿ)을 쉽게 말하면: 원소가 1개 늘 때마다 경우가 2배 — 종이를 한 번 접을 때마다 두께가 2배가 되는 것과 같음 (10장 1,024개 → 20장 약 105만 개)
    • O(n!)을 쉽게 말하면: n명을 한 줄로 세우는 방법 수 — 첫 자리 n명, 둘째 자리 n−1명, … 을 모두 곱하므로 2ⁿ보다도 훨씬 빨리 커짐
    • 나열은 모든 경우를 다 만들어야 끝나므로 운이 좋든 나쁘든(최선·최악) 횟수가 같음 — 가지치기를 넣을 때만 실제 탐색량이 줄어듦
    • 감당할 수 있는 한계가 금방 옴: 2³⁰ ≈ 10억, 13! ≈ 62억

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 재귀는 호출될 때마다 호출 스택에 프레임(메모지)이 한 장씩 쌓임 — 쓰는 메모리 = 가장 깊이 쌓였을 때의 높이
    • 재귀 팩토리얼: factorial(n) → … → factorial(1)까지 n장이 쌓임 — O(n)
    • 부분집합·순열: 원소 하나를 결정할 때마다 한 겹 내려가므로 깊이 n — O(n) (chosen·used[]도 n칸)
    • 조합 (k개 고르기): k개를 고르면 멈추므로 깊이 k — O(k)
    • 경우의 수는 폭발해도 한 번에 쌓이는 높이는 n 정도 — 결과를 모두 저장하지 않고 하나씩 출력하기 때문
    • 주의: 반복문 알고리즘의 공간이 O(1)이던 것과 달리 재귀는 깊이만큼 메모리를 씀 — n = 20 부분집합(깊이 20)은 안전하지만, 배열 100만 개를 원소 하나씩 재귀로 훑는 것처럼 깊이가 수만을 넘으면 정답 로직이라도 StackOverflowError → 그럴 때는 반복문이나 6강의 명시적 스택으로 바꿈
    한 줄 정리 — 코드는 짧지만 경우의 수는 폭발한다
    • 백트래킹은 몇 줄의 코드로 2ⁿ, n!개를 빠짐없이 만들지만, n이 조금만 커져도 감당할 수 없음
    • 메모리는 깊이만큼(O(n))만 쓰므로 적지만, 깊이가 너무 깊으면 스택이 넘친다는 것은 기억

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 반복의 깊이가 실행 중에 정해질 때 → 재귀·백트래킹: 자리 수가 2, 3, 4로 바뀌어도 for문을 더 쓰지 않고 같은 코드 하나로 해결
    • 경우가 너무 많을 때 → 가지치기: 백트래킹은 "가지치기할 수 있는 완전 탐색" — 조건에 어긋나는 가지를 위쪽 단계에서 통째로 잘라내면 그 아래 경우를 전부 건너뜀 (최종 프로그램에서 몇 개가 지워지는지 직접 세어 봄)
    • n이 작을 때만 전체 나열: 부분집합은 n = 20 안팎, 순열은 n = 10 안팎까지가 현실적인 한계
    • 같은 계산을 반복하는 재귀는 조심: 아래 피보나치처럼 자기 호출이 두 번씩 일어나면 호출 수가 폭발함

    재귀의 함정 — 같은 계산을 반복하는 피보나치

    재귀가 늘 좋은 것은 아닙니다. 피보나치 수를 정의 그대로 재귀로 옮기면 자기 호출이 두 번 일어나는데, 이때 같은 계산이 얼마나 반복되는지 호출 횟수 카운터(1강의 도구)로 측정해 봅니다.

    Java FibonacciBasic.java 
    public class FibonacciBasic {

    static long callCount = 0;   // fibo가 호출된 총 횟수

    /** 기본 재귀 피보나치. 정의를 그대로 옮겼지만 같은 계산을 여러 번 반복한다. */
    static long fibo(int n) {
        callCount++;
        if (n <= 1) {                        // 종료 조건: fibo(0) = 0, fibo(1) = 1
            return n;
        }
        return fibo(n - 1) + fibo(n - 2);    // 자기 호출이 두 번!
    }

    public static void main(String[] args) {
        int[] tests = {10, 20, 30};

        System.out.println("n  | fibo(n) | 호출 횟수");
        System.out.println("---+---------+----------");
        for (int n : tests) {
            callCount = 0;
            long value = fibo(n);
            System.out.printf("%-2d | %-7d | %d%n", n, value, callCount);
        }

        System.out.println();
        System.out.println("n이 10 커질 때마다 호출 횟수가 약 120배씩 폭발한다.");
        System.out.println("원인: fibo(20)을 구할 때 fibo(18)을 2번, fibo(17)을 3번... 같은 계산을 반복하기 때문.");
        System.out.println("해결책은 11강 동적 계획법에서 배운다 (계산 결과를 저장해 재사용).");
    }
}

---+---------+----------

    10실제 데이터 응용 예제

    문제 상황

    • 수학여행 버스의 한 줄 좌석 3개에 학생 민준, 서연, 도윤을 배치해야 함
    • 담임 선생님의 규칙: "민준과 서연은 옆자리에 앉을 수 없다."
    • 가능한 배치를 모두 나열하되, 규칙을 지키는 배치만 골라내야 함
    • 좌석 배치는 순서가 중요하므로 순열 백트래킹이 정확히 맞는 도구이고, 규칙 검사를 가지치기로 넣으면 어긋나는 배치는 끝까지 만들어 보기도 전에 걸러짐

    데이터 모델과 알고리즘 적용 기준

    • 데이터: 학생 이름 배열 students, 좌석 배열 seats (seats[i] = i번 좌석의 학생), 방문 배열 used
    • 알고리즘: 좌석 0번부터 차례로 학생을 고르는 순열 백트래킹 — 실습 코드의 permutation()과 같은 구조
    • 가지치기: 학생을 앉히기 전에 바로 왼쪽 좌석과 금지된 짝인지 검사, 어긋나면 continue
    Java SeatingApplication.java 
    public class SeatingApplication {

    static String[] students = {"민준", "서연", "도윤"};
    static String[] seats = new String[students.length];   // seats[i] = i번 좌석의 학생
    static boolean[] used = new boolean[students.length];  // 학생 배치(방문) 여부
    static int totalCount = 0;    // 제약 없는 전체 배치 수
    static int validCount = 0;    // 규칙을 통과한 배치 수
    static int pruneCount = 0;    // 가지치기로 잘라낸 횟수

    /** 규칙: 민준과 서연은 옆자리에 앉을 수 없다. */
    static boolean isForbiddenPair(String a, String b) {
        return (a.equals("민준") && b.equals("서연"))
                || (a.equals("서연") && b.equals("민준"));
    }

    /** [1] 제약 없이 모든 배치를 나열한다 (순열 백트래킹 그대로). */
    static void arrangeAll(int seatIndex) {
        if (seatIndex == seats.length) {           // 종료 조건: 모든 좌석을 채웠다
            totalCount++;
            System.out.println("  배치 " + totalCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;
            used[i] = true;                        // 선택
            seats[seatIndex] = students[i];
            arrangeAll(seatIndex + 1);             // 진행
            used[i] = false;                       // 취소: 상태 복원
            seats[seatIndex] = null;
        }
    }

    /** [2] 같은 구조에 가지치기 검사를 한 번 추가한다. */
    static void arrangeWithRule(int seatIndex) {
        if (seatIndex == seats.length) {
            validCount++;
            System.out.println("  통과 " + validCount + ": " + String.join(" - ", seats));
            return;
        }

        for (int i = 0; i < students.length; i++) {
            if (used[i]) continue;

            // 가지치기: 바로 왼쪽 좌석과 금지된 짝이면 이 가지는 내려가지 않는다
            if (seatIndex > 0 && isForbiddenPair(seats[seatIndex - 1], students[i])) {
                pruneCount++;
                continue;
            }

            used[i] = true;
            seats[seatIndex] = students[i];
            arrangeWithRule(seatIndex + 1);
            used[i] = false;
            seats[seatIndex] = null;
        }
    }

        arrangeAll(0);

        System.out.println();

        arrangeWithRule(0);

        System.out.println();

    }

    • arrangeAll과 arrangeWithRule의 차이는 가지치기 if 한 덩어리뿐입니다. 백트래킹 뼈대를 한 번 익히면, 문제의 규칙은 가지치기 조건으로만 추가됩니다.
    • 가지치기는 선택하기 전에 검사합니다 — 앉혀 놓고 검사하면 취소도 해야 하므로, 아예 앉히지 않고 건너뛰는 쪽이 간결하고 빠릅니다.

    public class PasswordSolution {

    static char[] candidates = {'1', '3', '7', '9'};   // 후보 문자 4개
    static StringBuilder current = new StringBuilder(); // 지금 만드는 중인 비밀번호
    static int allCount = 0;        // 전체 생성 개수
    static int rulePassCount = 0;   // 가지치기 통과 개수
    static boolean printEach = true; // 하나씩 출력할지 여부 (개수만 셀 때는 false)

    /** [과제 1] 길이 k의 모든 비밀번호를 생성한다. (같은 문자를 여러 번 써도 됨) */
    static void generateAll(int k) {
        if (current.length() == k) {                       // 종료 조건: k자리 완성
            allCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            current.append(candidates[i]);                 // (1) 선택
            generateAll(k);                                // (2) 진행
            current.deleteCharAt(current.length() - 1);    // (3) 취소: 상태 복원
        }
    }

    /** [과제 2] 같은 문자가 연속으로 나오는 가지를 잘라내며 생성한다. */
    static void generateNoRepeat(int k) {
        if (current.length() == k) {                       // 종료 조건
            rulePassCount++;
            if (printEach) {
                System.out.println("  " + current);
            }
            return;
        }

        for (int i = 0; i < candidates.length; i++) {
            // 가지치기: 직전 문자와 같으면 이 가지는 내려가 보지 않는다
            if (current.length() > 0
                    && current.charAt(current.length() - 1) == candidates[i]) {
                continue;
            }
            current.append(candidates[i]);                 // 선택
            generateNoRepeat(k);                           // 진행
            current.deleteCharAt(current.length() - 1);    // 취소
        }
    }

        System.out.println("후보 문자: 1, 3, 7, 9");

        System.out.println();
        System.out.println("[1] 길이 2 — 만들 수 있는 모든 비밀번호");
        printEach = true;
        allCount = 0;
        generateAll(2);
        System.out.println("  총 " + allCount + "개 (이론값 4^2 = 16)");

        System.out.println();
        System.out.println("[2] 길이 2 — 같은 문자 연속 금지 (가지치기)");
        rulePassCount = 0;
        generateNoRepeat(2);
        System.out.println("  총 " + rulePassCount + "개 (이론값 4 x 3 = 12)");

        System.out.println();
        System.out.println("[3] 길이 3 — 개수만 비교");
        printEach = false;
        allCount = 0;
        rulePassCount = 0;
        generateAll(3);
        generateNoRepeat(3);
        System.out.println("  전체 생성: " + allCount + "개 (4^3 = 64)");
        System.out.println("  연속 금지: " + rulePassCount + "개 (4 x 3 x 3 = 36)");
        System.out.println("  가지치기로 " + (allCount - rulePassCount)
                + "개는 만들어 보기도 전에 걸러졌다.");
    }

    구현 순서와 핵심 알고리즘 적용 부분

    1. generateAll은 부분집합 의사코드(06)와 뼈대가 같습니다. 다른 점은 "넣는다/안 넣는다" 2갈래 대신 후보 4개를 도는 for문이라는 것뿐입니다 — 가지 수가 후보 수(4)인 결정 트리입니다.
    2. 재귀 호출이 generateAll(k)로 k를 그대로 전달하는 것에 주목하세요. 진행 정도는 k가 아니라 current의 길이가 말해 줍니다 — append로 길이가 1 늘어나므로 문제는 종료 조건 쪽으로 확실히 가까워집니다.
    3. generateNoRepeat의 가지치기는 current.length() > 0 검사가 먼저 옵니다. 빈 문자열에서 charAt(-1)을 부르면 예외가 나므로, 경계 조건 검사가 앞이어야 합니다 (테스트 3종의 "경계 조건 k = 1"이 바로 이 지점을 확인합니다).
    4. [3]에서 카운터를 0으로 초기화하고 printEach를 끄는 것 — 상태를 공유하는 프로그램에서는 측정 전에 상태를 초기화하는 습관이 필요합니다.

    복잡도 분석

    • generateAll: 후보 c개, 길이 k → 완성 후보 cᵏ개, 시간 O(cᵏ · k). k = 2면 16개, k = 3이면 64개.
    • generateNoRepeat: 첫 자리 c가지 × 이후 자리마다 (c − 1)가지 → c × (c−1)ᵏ⁻¹개. k = 3이면 4 × 3 × 3 = 36개 — 걸러진 28개의 가지는 재귀 호출 자체가 일어나지 않았습니다.
    • 공간: 호출 스택 깊이 = k → O(k).

    자주 발생하는 오류

    • 종료 조건 없이 for문부터 쓰는 경우 — current가 무한히 길어지다 StackOverflowError (오류 1 유형).
    • deleteCharAt을 빼먹는 경우 — 첫 후보 "11"을 만든 뒤 상태가 복원되지 않아 이후 결과가 전부 오염됩니다 (오류 2 유형).
    • 가지치기에서 current.length() > 0을 빼먹는 경우 — 첫 문자를 붙이기 전에 charAt(-1)로 StringIndexOutOfBoundsException.
    • [3] 실행 전에 카운터를 초기화하지 않아 [1]·[2]의 개수가 합산되는 경우.

    다른 해결 방법

    StringBuilder 대신 char[] password 배열과 깊이 인덱스 depth를 쓰면 password[depth] = c로 덮어쓰기 때문에 취소 코드가 없어도 됩니다 — 대신 "지금 몇 자리까지 채웠는가"를 depth 매개변수로 전달해야 합니다. 또한 이런 "중복을 허용하는 나열"은 k겹 반복문으로도 가능하지만, k가 실행 중에 바뀌면 코드도 바꿔야 하므로 재귀만이 일반적인 해법입니다.

    14오늘의 핵심 정리

    • 재귀 호출은 큰 문제를 같은 구조의 더 작은 문제에 맡기는 것 — 종료 조건(브레이크)과 재귀 단계(더 작아지는 자기 호출)가 둘 다 있어야 한다.
    • 메서드 호출은 호출 스택에 프레임으로 쌓이고(6강 스택의 LIFO), 나중에 호출된 것이 먼저 반환된다. 종료 조건이 없으면 StackOverflowError.
    • 백트래킹은 재귀 완전 탐색(3강의 확장)이며, 모든 코드는 선택 → 진행 → 취소 3단계 패턴을 따른다. 선택에서 바꾼 상태는 취소에서 정확히 되돌린다.
    • 나열 3패턴: 부분집합(넣는다/안 넣는다, 2ⁿ), 순열(used[] 방문 관리, n!), 조합(start 인덱스, nCk).
    • 가지치기는 조건에 어긋나는 가지를 선택하기 전에 잘라 탐색량을 줄인다 — 비밀번호 k = 3에서 64개 중 28개를 만들기 전에 걸렀다.
    • 재귀 피보나치의 호출 폭발(fibo(30) = 2,692,537번)은 중복 계산 때문 — 저장해서 재사용하는 해결책은 11강 동적 계획법에서.

    15다음 강의 연결

    다음 강의는 8강. 트리 구조입니다. 트리는 "재귀로 순회하는 구조" — 오늘 배운 재귀가 자료구조를 만나는 곳입니다.

    • 트리의 정의 자체가 재귀적입니다 — "트리 = 루트 + (왼쪽 부분 트리) + (오른쪽 부분 트리)". 오늘의 "같은 구조의 더 작은 문제"가 그대로 적용됩니다.
    • 전위·중위·후위 순회가 모두 재귀 메서드로 구현됩니다. 종료 조건은 "노드가 null이면 돌아간다" — 오늘의 base case 감각이 그대로 쓰입니다.
    • 순회의 호출 스택 깊이 = 트리의 높이 — 오늘 배운 "재귀 깊이 = 스택 사용량"으로 이해합니다.
    • 더 멀리는 9강 그래프 DFS가 오늘의 백트래킹(방문 관리 + 되돌아가기)과 같은 뼈대이고, 11강 DP가 오늘 본 중복 호출 문제를 해결합니다.

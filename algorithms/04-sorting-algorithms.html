정렬 알고리즘과 객체 정렬

Sorting Algorithms and Object Sorting

정렬 초급 Java 17+

뒤죽박죽인 데이터를 순서대로 늘어놓는 것 — 정렬은 컴퓨터가 하는 일 중 가장 오래되고 가장 자주 하는 일입니다. 이번 강의에서는 2강의 "최솟값 찾기"와 3강의 "중첩 반복문"을 조립해 선택 정렬을 직접 만들고, 같은 원리의 변형인 버블 정렬·삽입 정렬까지 구현합니다. 마지막에는 Comparator로 "가격순, 평점순, 다중 기준"처럼 기준을 갈아 끼우는 객체 정렬을 배웁니다.

이 강의의 목차

    01강의 소개

    쇼핑몰의 "낮은 가격순" 버튼, 성적표의 석차, 파일 탐색기의 이름순 목록 — 전부 정렬(sorting)의 결과물입니다. 정렬은 그 자체로도 쓸모 있지만, 더 중요한 이유가 있습니다. 데이터가 정렬되어 있어야만 쓸 수 있는 더 빠른 알고리즘들이 있기 때문입니다. 당장 다음 강의의 이진 탐색이 그렇습니다.

    이번 강의는 두 부분으로 이루어집니다. 앞부분에서는 숫자 배열을 선택 정렬로 정렬하는 과정을 "최솟값 찾기 → 한 회전으로 한 자리 확정 → 반복으로 전체 정렬" 순서로 조립하고, 같은 O(n²) 가족인 버블 정렬과 삽입 정렬을 비교합니다. 뒷부분에서는 숫자가 아닌 객체(상품, 학생 같은 데이터)를 Comparable과 Comparator로 정렬하는 방법을 배우고, "평점 내림차순, 동점이면 이름순" 같은 다중 기준 정렬까지 구현합니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 임시 변수를 사용해 배열의 두 칸을 교환(swap)하는 코드를 작성할 수 있다.
    • 학생은 선택 정렬을 "최솟값 위치 찾기 → 교환 → 반복"의 단계로 나누어 직접 구현할 수 있다.
    • 학생은 버블 정렬과 삽입 정렬의 동작을 설명하고, 세 정렬의 비교·교환 횟수를 카운터로 측정할 수 있다.
    • 학생은 세 정렬의 시간 복잡도가 O(n²)인 이유를 비교 횟수 n(n-1)/2와 연결해 설명할 수 있다.
    • 학생은 Comparator를 작성해 객체 배열을 원하는 기준(오름차순·내림차순·다중 기준)으로 정렬할 수 있다.
    • 학생은 안정 정렬이 무엇인지 설명하고, 같은 값의 순서가 유지되는지 확인할 수 있다.

    여러분은 작은 온라인 쇼핑몰의 개발을 맡았습니다. 상품 목록은 등록 순서대로만 표시되는데, 사용자 설문에서 가장 많이 나온 요청이 "낮은 가격순으로 보고 싶어요"였습니다. 상품 가격 데이터는 등록 순서대로 [26, 15, 38, 12, 21](단위: 천 원)처럼 뒤죽박죽입니다. 게다가 기획자는 "가격순 말고도 평점 높은 순, 평점이 같으면 이름 가나다순도 필요해요"라고 요구합니다. 숫자 정렬 하나 만들면 끝인 줄 알았는데, 기준이 계속 늘어납니다. 오늘은 정렬 알고리즘을 직접 만들고, 기준을 갈아 끼울 수 있는 구조까지 완성합니다.

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 가격표 카드 5장을 책상에 늘어놓고 손으로 정렬해 봅시다. 카드는 [26, 15, 38, 12, 21] 순서로 놓여 있습니다. 사람이 자연스럽게 쓰는 방법 중 하나는 이것입니다: "전체에서 가장 싼 카드를 찾아 맨 앞에 놓는다. 남은 카드에서 또 가장 싼 것을 찾아 그다음에 놓는다." 이 방법이 바로 선택 정렬입니다.

    STEP 1

    다섯 장 전체 [26, 15, 38, 12, 21]에서 가장 싼 카드를 찾습니다. 26 → 15(더 싸다) → 38 → 12(더 싸다) → 21. 최솟값은 12입니다. 12를 맨 앞 카드 26과 자리를 바꿉니다. → [12, 15, 38, 26, 21]

    질문: 최솟값 12를 찾기 위해 비교를 몇 번 했나요?

    4번입니다. 첫 카드 26을 후보로 잡고, 나머지 4장(15, 38, 12, 21)과 한 번씩 비교했습니다. 카드가 n장이면 첫 회전의 비교는 n-1번 — 2강의 최솟값 찾기와 정확히 같습니다.

    STEP 2

    맨 앞의 12는 이제 확정입니다. 다시 볼 필요가 없습니다. 남은 [15, 38, 26, 21]에서 최솟값을 찾습니다 — 15입니다. 그런데 15는 이미 남은 구간의 맨 앞에 있습니다.

    질문: 최솟값이 이미 제자리에 있으면 어떻게 해야 할까요?

    아무것도 하지 않으면 됩니다. 교환은 필요 없고, 15를 그대로 확정하면 됩니다. 코드에서는 if (minIndex != i) 검사로 불필요한 교환을 건너뜁니다. 비교는 했지만(3번) 교환은 0번 — 비교와 교환은 서로 다른 연산입니다.

    STEP 3

    남은 [38, 26, 21]에서 최솟값 21을 찾아(비교 2번) 38과 교환합니다. → 전체는 [12, 15, 21, 26, 38]. 이제 남은 카드는 [26, 38] 두 장 — 비교 1번, 26이 이미 제자리라 교환은 없습니다.

    질문: 마지막 남은 카드 38은 왜 비교하지 않아도 될까요?

    앞의 4자리가 모두 "남은 것 중 최솟값"으로 채워졌으므로, 마지막 한 장은 자동으로 가장 큰 값입니다. 그래서 코드의 바깥 반복문은 i < length - 1까지만 돕니다 — n장의 카드에 회전은 n-1번이면 충분합니다.

    STEP 4

    정렬 완료: [12, 15, 21, 26, 38]. 전체 과정을 되돌아봅시다.

    질문: 비교는 총 몇 번 했나요? 카드가 n장이라면 몇 번일까요?

    4 + 3 + 2 + 1 = 10번입니다. 카드가 n장이면 (n-1) + (n-2) + … + 1 = n(n-1)/2번 — 3강의 "모든 쌍 비교"와 같은 개수입니다. n이 10배가 되면 비교는 약 100배가 되는 O(n²)의 정체가 여기 있습니다.

    06핵심 개념

    정렬이란?

    정렬은 데이터를 정해진 기준에 따라 순서대로 재배치하는 것입니다. 기준은 "작은 것부터"(오름차순)일 수도, "큰 것부터"(내림차순)일 수도, "평점 높은 순, 동점이면 이름순"처럼 복합적일 수도 있습니다. 정렬이 중요한 진짜 이유는 정렬된 데이터에서만 가능한 빠른 알고리즘이 많기 때문입니다 — 5강의 이진 탐색, 10강의 그리디가 대표적입니다.

    교환(swap)과 임시 변수

    정렬의 가장 작은 부품은 두 칸의 값을 맞바꾸는 교환입니다. 두 값을 직접 덮어쓰면 한쪽 값이 사라지므로, 반드시 임시 변수가 필요합니다. 

    int temp = arr[i];   // 1) 한쪽 값을 임시 보관
arr[i] = arr[j];     // 2) 덮어쓰기
arr[j] = temp;       // 3) 보관해 둔 값을 넣기

    오늘 배우는 세 가지 정렬

    세 정렬 모두 "비교하고 자리를 바꾼다"는 같은 재료를 쓰지만, 전략이 다릅니다.

    정렬한 줄 전략한 회전이 끝나면
    선택 정렬남은 구간의 최솟값을 찾아 구간 맨 앞과 교환앞쪽에 최솟값 하나가 확정
    버블 정렬이웃끼리 비교해 어긋나면 교환하며 오른쪽으로 진행뒤쪽에 최댓값 하나가 확정
    삽입 정렬새 값을 왼쪽의 정렬된 영역의 알맞은 자리에 끼워 넣기왼쪽 정렬 영역이 한 칸 확장

    안정 정렬 (stable sort)

    안정 정렬은 기준값이 같은 원소들의 원래 순서를 유지하는 정렬입니다. 예를 들어 가격이 똑같이 23,000원인 상품 A와 B가 A → B 순서로 입력되었다면, 가격순 정렬 후에도 A → B 순서여야 안정 정렬입니다. 버블·삽입 정렬은 안정이고, 선택 정렬은 멀리 있는 값과 교환하는 과정에서 순서가 뒤집힐 수 있어 불안정합니다. "가격순으로 정렬하되, 같은 가격은 인기순 유지" 같은 요구사항에서 안정성이 실무 이슈가 됩니다.

    객체 정렬 — Comparable과 Comparator

    숫자는 <로 비교하면 되지만, Product 같은 객체는 "무엇을 기준으로 앞뒤를 정하는지"를 코드로 알려 줘야 합니다. Java는 두 가지 방법을 제공합니다.

    방법작성 위치용도
    Comparable클래스 안의 compareTo(other)그 클래스의 기본 정렬 기준 1개 (예: 상품은 기본 가격순)
    Comparator클래스 밖의 compare(a, b)바꿔 끼우는 기준 여러 개 (평점순, 이름순, 다중 기준…)

    두 메서드의 반환값 규약은 같습니다. 음수면 a가 앞, 0이면 같음, 양수면 a가 뒤입니다. 정렬 코드 안에서 comp.compare(a, b) > 0은 "a가 b보다 뒤에 와야 한다 = 지금 순서가 어긋났다"로 읽으면 됩니다. 이 규약 덕분에 정렬 알고리즘 코드는 그대로 두고 기준만 교체할 수 있습니다.

    Arrays.sort()는 오늘 어디에 쓰나?

    Java의 Arrays.sort()는 잘 만들어진 라이브러리 정렬이고, 실무에서는 이것을 씁니다. 하지만 오늘의 목표는 정렬의 내부 동작을 이해하는 것이므로 핵심 구현은 반드시 직접 작성하고, Arrays.sort()는 내 구현의 결과가 맞는지 검증하는 용도로만 사용합니다(최종 문제의 해설 참고).

    07단계별 동작 과정

    선택 정렬이 가격 배열 [26, 15, 38, 12, 21]을 정렬하는 모습을 한 단계씩 확인해 봅시다. 다음 단계 ▶ 버튼으로 진행하세요. 비교 중인 칸은 앰버색(비교 중), 지금까지의 최솟값 후보는 보라색(최솟값 후보), 자리가 확정된 칸은 초록색(확정)이며 각 칸 아래에 상태 글자가 함께 표시됩니다.

    마지막 단계의 카운터를 보세요 — 원소 5개에 비교 10번(= 4+3+2+1), 교환은 2번입니다. 비교 횟수는 데이터 내용과 무관하게 항상 n(n-1)/2번이라는 점이 선택 정렬의 특징입니다.

    같은 데이터, 다른 전략 — 삽입 정렬

    이번에는 같은 배열을 삽입 정렬이 어떻게 처리하는지 봅시다. 왼쪽의 초록색 영역(정렬된 영역)이 한 칸씩 넓어지고, 파란색 칸(끼워 넣을 값 key)이 자기 자리를 찾아 들어가는 모습에 주목하세요.

    삽입 정렬은 key보다 작은 값을 만나는 순간 비교를 멈춥니다. 그래서 거의 정렬된 데이터에서는 비교가 확 줄어듭니다 — 11번 완성 코드의 실험에서 숫자로 확인합니다.

    08의사코드

    손으로 한 절차와 시각화의 움직임을 언어 중립적인 의사코드로 정리합니다.

    Pseudo 선택 정렬 
    알고리즘 SelectionSort(arr)
    n ← arr의 길이
    i를 0부터 n-2까지 반복:                 // 채울 자리
        minIndex ← i                        // 남은 구간의 최솟값 "위치" 후보
        j를 i+1부터 n-1까지 반복:           // 남은 구간 훑기
            arr[j] < arr[minIndex] 이면:    // 핵심 연산: 비교
                minIndex ← j
        minIndex ≠ i 이면:
            arr[i]와 arr[minIndex]를 교환   // 핵심 연산: 교환
    // 반복이 끝나면 arr는 오름차순
    Pseudo 삽입 정렬 
    알고리즘 InsertionSort(arr)
    n ← arr의 길이
    i를 1부터 n-1까지 반복:                 // arr[0..i-1]은 이미 정렬됨
        key ← arr[i]                        // 이번에 끼워 넣을 값
        j ← i - 1
        j ≥ 0 이고 arr[j] > key 인 동안:    // key보다 큰 값은
            arr[j+1] ← arr[j]               // 한 칸 뒤로 민다 (이동)
            j ← j - 1
        arr[j+1] ← key                      // 빈 자리에 key 넣기

    선택 정렬은 "찾아서 교환", 삽입 정렬은 "밀어서 끼워 넣기"입니다. 두 의사코드 모두 반복문 안에 반복문이 있는 중첩 구조라는 점 — O(n²)의 근원 — 은 같습니다.

    09점진적 Java 구현

    선택 정렬을 한 번에 쓰지 않고, 데이터 준비 → 비교와 교환 → 한 회전(최솟값 찾기 + 자리 확정) → 반복으로 전체 정렬 순서로 조립합니다. 각 단계의 코드는 모두 독립적으로 복사해서 실행할 수 있습니다.

    구현 1단계 — 입력 데이터 준비

    정렬할 상품 가격 5개를 준비하고, 정렬 전 상태를 눈으로 확인합니다.

    Java Step1PriceData.java 
    public class Step1PriceData {
    public static void main(String[] args) {
        // 상품 5개의 가격 (단위: 천 원) — 오늘 정렬할 입력 데이터
        int[] prices = {26, 15, 38, 12, 21};

        System.out.println("상품 개수: " + prices.length);

        // 정렬 전 상태를 [26, 15, 38, 12, 21] 형태로 출력한다
        System.out.print("정렬 전 가격: [");
        for (int i = 0; i < prices.length; i++) {
            System.out.print(prices[i]);
            if (i < prices.length - 1) {
                System.out.print(", ");
            }
        }
        System.out.println("]");
    }
}

    구현 2단계 — 핵심 연산: 비교와 교환

    정렬의 두 가지 핵심 연산을 반복문 없이 딱 한 번만 수행합니다. 비교(앞이 뒤보다 큰가?)와 교환(임시 변수로 맞바꾸기)입니다. swap 메서드는 오늘 강의 전체에서 계속 재사용됩니다.

    Java Step2CompareSwap.java 
    public class Step2CompareSwap {

    /** 배열의 i번 칸과 j번 칸의 값을 맞바꾼다. 임시 변수가 반드시 필요하다. */
    static void swap(int[] arr, int i, int j) {
        int temp = arr[i];   // 1) 한쪽 값을 임시 변수에 보관하고
        arr[i] = arr[j];     // 2) i번 칸에 j번 값을 덮어쓴 뒤
        arr[j] = temp;       // 3) 보관해 둔 값을 j번 칸에 넣는다
    }

    public static void main(String[] args) {
        int[] prices = {26, 15, 38, 12, 21};

        System.out.println("교환 전: prices[0] = " + prices[0]
                + ", prices[1] = " + prices[1]);

        // 비교: 앞의 값이 뒤의 값보다 크면 오름차순에 어긋난다
        if (prices[0] > prices[1]) {
            System.out.println("prices[0] > prices[1] 이므로 두 값을 교환합니다.");
            swap(prices, 0, 1);
        }

        System.out.println("교환 후: prices[0] = " + prices[0]
                + ", prices[1] = " + prices[1]);
    }
}

    구현 3단계 — 한 회전: 최솟값 위치 찾기 + 자리 확정

    2강의 최솟값 찾기를 가져오되, 값 대신 위치(minIndex)를 기억하도록 바꿉니다. 찾은 최솟값을 0번 칸과 교환하면 — 손 풀이의 STEP 1과 똑같이 — 한 회전으로 한 자리가 확정됩니다.

    Java Step3FirstPass.java 
    public class Step3FirstPass {

    static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }

    /** 배열 상태를 [26, 15, 38, 12, 21] 형태의 문자열로 만든다. */

        StringBuilder sb = new StringBuilder("[");

            if (i < arr.length - 1) {

    public static void main(String[] args) {

        int minIndex = 0;

            if (prices[j] < prices[minIndex]) {
                minIndex = j;

            }
        }

                + " → 0번 칸과 교환합니다.");
        swap(prices, 0, minIndex);

        System.out.println("1회차 종료: " + toText(prices));
        System.out.println("0번 칸(" + prices[0] + ")은 이제 확정 — 다시 볼 필요가 없습니다.");

    구현 4단계 — 반복으로 전체 정렬 + 연산 카운터

    3단계의 "한 회전"을 바깥 반복문으로 감싸 시작 위치 i를 0, 1, 2, …로 옮기면 선택 정렬 완성입니다. 3단계에서 0과 1이던 자리가 i와 i + 1로 바뀐 것에 주목하세요. 1강의 연산 카운터로 비교·교환 횟수도 함께 셉니다.

    Java Step4SelectionSort.java 
    public class Step4SelectionSort {

    static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }

    static String toText(int[] arr) {
        StringBuilder sb = new StringBuilder("[");
        for (int i = 0; i < arr.length; i++) {
            sb.append(arr[i]);
            if (i < arr.length - 1) {
                sb.append(", ");
            }
        }
        return sb.append("]").toString();
    }

    public static void main(String[] args) {
        int[] prices = {26, 15, 38, 12, 21};
        int compareCount = 0;   // 1강의 연산 카운터 — 비교가 일어날 때마다 +1
        int swapCount = 0;      // 교환이 일어날 때마다 +1

        System.out.println("정렬 전: " + toText(prices));

        // 바깥 반복문: 기준 위치 i를 0부터 끝-1까지 옮긴다 (3강의 중첩 반복문 구조)
        for (int i = 0; i < prices.length - 1; i++) {
            int minIndex = i;   // 남은 구간 [i..끝]의 최솟값 위치

            // 안쪽 반복문: i 오른쪽에서 더 작은 값을 찾는다 (Step3의 한 회차)
            for (int j = i + 1; j < prices.length; j++) {
                compareCount++;
                if (prices[j] < prices[minIndex]) {
                    minIndex = j;
                }
            }

            // 최솟값이 이미 제자리(i)에 있으면 교환하지 않는다
            if (minIndex != i) {
                swap(prices, i, minIndex);
                swapCount++;
            }
        }

        System.out.println("정렬 후: " + toText(prices));
        System.out.println("비교 횟수 = " + compareCount + ", 교환 횟수 = " + swapCount);
    }
}

    비교 10번 = 4 + 3 + 2 + 1 = n(n-1)/2 — 손 풀이(STEP 4)와 시각화의 카운터와 정확히 일치합니다. 교환은 2번뿐입니다(12↔26, 21↔38). 선택 정렬은 비교는 많지만 교환은 회전당 최대 1번입니다.

    10완성 Java 코드

    선택 정렬을 조립했으니, 같은 재료(비교·교환·중첩 반복문)로 만드는 버블 정렬과 삽입 정렬을 더해 세 정렬 비교 프로그램을 완성합니다. 1강의 Measurement 패턴처럼 결과와 연산 횟수를 SortResult에 담아, 무작위·이미 정렬됨·역순 세 종류의 입력으로 실험합니다.

    Java SortingThreeComplete.java 
    import java.util.Arrays;

public class SortingThreeComplete {

    /** 한 번의 정렬 결과와 연산 횟수를 담는 기록 클래스 (1강 Measurement 패턴) */
    static class SortResult {
        int[] sorted;      // 정렬된 배열
        long compares;     // 비교 횟수
        long swapsOrMoves; // 교환 횟수(선택·버블) 또는 이동 횟수(삽입)

        SortResult(int[] sorted, long compares, long swapsOrMoves) {
            this.sorted = sorted;
            this.compares = compares;
            this.swapsOrMoves = swapsOrMoves;
        }
    }

    /** 선택 정렬: 남은 구간의 최솟값을 찾아 앞으로 보낸다. */
    static SortResult selectionSort(int[] input) {
        int[] arr = Arrays.copyOf(input, input.length); // 원본 보존
        long compares = 0;
        long swaps = 0;

        for (int i = 0; i < arr.length - 1; i++) {
            int minIndex = i;
            for (int j = i + 1; j < arr.length; j++) {
                compares++;
                if (arr[j] < arr[minIndex]) {
                    minIndex = j;
                }
            }
            if (minIndex != i) {
                int temp = arr[i];
                arr[i] = arr[minIndex];
                arr[minIndex] = temp;
                swaps++;
            }
        }
        return new SortResult(arr, compares, swaps);
    }

    /** 버블 정렬: 이웃끼리 비교·교환하며 큰 값을 뒤로 밀어낸다. 교환이 없으면 조기 종료. */
    static SortResult bubbleSort(int[] input) {
        int[] arr = Arrays.copyOf(input, input.length);
        long compares = 0;
        long swaps = 0;

        for (int i = 0; i < arr.length - 1; i++) {
            boolean swapped = false;
            // 뒤쪽 i개는 이미 확정되었으므로 범위에서 제외한다
            for (int j = 0; j < arr.length - 1 - i; j++) {
                compares++;
                if (arr[j] > arr[j + 1]) {
                    int temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                    swaps++;
                    swapped = true;
                }
            }
            if (!swapped) {
                break; // 한 바퀴 동안 교환이 없었다 = 이미 정렬 완료
            }
        }
        return new SortResult(arr, compares, swaps);
    }

    /** 삽입 정렬: 왼쪽의 정렬된 영역에 새 값을 알맞은 자리에 끼워 넣는다. */
    static SortResult insertionSort(int[] input) {
        int[] arr = Arrays.copyOf(input, input.length);
        long compares = 0;
        long moves = 0;

        for (int i = 1; i < arr.length; i++) {
            int key = arr[i];   // 이번에 끼워 넣을 값
            int j = i - 1;
            while (j >= 0) {
                compares++;
                if (arr[j] > key) {
                    arr[j + 1] = arr[j]; // 한 칸 뒤로 민다 (이동)
                    moves++;
                    j--;
                } else {
                    break; // 더 작은 값을 만나면 그 자리가 key의 자리
                }
            }
            arr[j + 1] = key;
        }
        return new SortResult(arr, compares, moves);
    }

    static void printTable(String title, int[] data) {
        System.out.println("== " + title + ": " + Arrays.toString(data) + " ==");
        System.out.println("알고리즘  | 비교 횟수 | 교환·이동 | 정렬 결과");

        SortResult sel = selectionSort(data);
        SortResult bub = bubbleSort(data);
        SortResult ins = insertionSort(data);

        System.out.printf("선택 정렬 | %-8d | %-8d | %s%n",
                sel.compares, sel.swapsOrMoves, Arrays.toString(sel.sorted));
        System.out.printf("버블 정렬 | %-8d | %-8d | %s%n",
                bub.compares, bub.swapsOrMoves, Arrays.toString(bub.sorted));
        System.out.printf("삽입 정렬 | %-8d | %-8d | %s%n",
                ins.compares, ins.swapsOrMoves, Arrays.toString(ins.sorted));
        System.out.println();
    }

    public static void main(String[] args) {
        int[] random = {26, 15, 38, 12, 21, 30, 8, 19};   // 무작위 데이터
        int[] sorted = {8, 12, 15, 19, 21, 26, 30, 38};   // 이미 정렬된 데이터 (최선)
        int[] reversed = {38, 30, 26, 21, 19, 15, 12, 8}; // 역순 데이터 (최악)

        printTable("무작위 데이터", random);
        printTable("이미 정렬된 데이터", sorted);
        printTable("역순 데이터", reversed);

        System.out.println("관찰: 비교 횟수의 '모양'은 세 정렬 모두 O(n^2)이지만,");
        System.out.println("      이미 정렬된 입력에서 버블(조기 종료)과 삽입은 n-1번 비교로 끝난다.");
    }
}

    /** 두 칸의 값을 맞바꾸려고 했지만, 임시 변수를 빠뜨렸다. */
    static void swap(int[] arr, int i, int j) {
        arr[i] = arr[j];   // 이 순간 arr[i]의 원래 값이 사라진다!
        arr[j] = arr[i];   // 이미 덮어써진 값을 다시 넣을 뿐이다
    }

    static String toText(int[] arr) {
        StringBuilder sb = new StringBuilder("[");
        for (int i = 0; i < arr.length; i++) {
            sb.append(arr[i]);
            if (i < arr.length - 1) {
                sb.append(", ");
            }
        }
        return sb.append("]").toString();
    }

    public static void main(String[] args) {
        int[] prices = {26, 15, 38, 12, 21};

        System.out.println("정렬 전: " + toText(prices));

        // 선택 정렬 — 구조는 Step4SelectionSort와 완전히 같다
        for (int i = 0; i < prices.length - 1; i++) {
            int minIndex = i;
            for (int j = i + 1; j < prices.length; j++) {
                if (prices[j] < prices[minIndex]) {
                    minIndex = j;
                }
            }
            if (minIndex != i) {
                swap(prices, i, minIndex);
            }
        }

        System.out.println("정렬 후: " + toText(prices));
    }
}

    int temp = arr[i];
    arr[i] = arr[j];
    arr[j] = temp;
}

    13복잡도 및 특성 분석

    입력 크기와 주요 연산

    입력 크기 n은 정렬할 원소의 개수입니다. 주요 연산은 비교(두 값의 크기 판단)와 교환·이동(자리 바꾸기)입니다. 10번 섹션의 실험(n=8)에서 잰 숫자가 아래 표의 근거입니다.

    시간 복잡도

    알고리즘최선 (이미 정렬됨)평균최악 (역순)안정성
    선택 정렬O(n²) — 비교는 항상 n(n-1)/2O(n²)O(n²)불안정
    버블 정렬 (조기 종료)O(n) — 한 바퀴에 교환 0이면 끝O(n²)O(n²)안정

    실험값과 맞춰 봅시다. n=8일 때 n(n-1)/2 = 28 — 선택 정렬의 비교는 세 입력 모두에서 28번, 역순 입력에서는 세 정렬 모두 28번이었고, 이미 정렬된 입력에서 버블·삽입의 비교는 n-1 = 7번이었습니다. 표와 실험이 정확히 일치합니다.

    공간 복잡도

    세 정렬 모두 배열 안에서 자리만 바꾸는 제자리 정렬(in-place)입니다. 임시 변수 몇 개만 쓰므로 공간 복잡도 O(1)입니다. (완성 코드의 Arrays.copyOf는 실험을 위한 원본 보존용이지 알고리즘의 일부가 아닙니다.)

    알고리즘 특성

    • 선택 정렬: 비교는 많지만 교환은 회전당 최대 1번(전체 최대 n-1번). 교환 비용이 아주 클 때 유리합니다.
    • 버블 정렬: 가장 단순하지만 교환이 많습니다(역순 n=8에서 28번). swapped 플래그 덕분에 정렬된 입력을 O(n)에 감지합니다.
    • 삽입 정렬: 거의 정렬된 데이터에 가장 강합니다. 실제로 Java의 라이브러리 정렬도 작은 구간에는 삽입 정렬을 씁니다.
    • 공통 한계: 평균 O(n²)이므로 n이 수십만이 되면 감당하기 어렵습니다. 더 빠른 O(n log n) 정렬(병합·퀵)은 7강의 재귀를 배운 뒤에 만날 수 있습니다.

    14실제 데이터 응용 예제

    문제 상황

    이제 4번 섹션의 쇼핑몰 문제로 돌아갑니다. 상품은 숫자가 아니라 이름·가격·평점을 가진 객체입니다. "가격 오름차순", "평점 내림차순(동점이면 이름순)", "이름순" — 기준이 세 가지인데, 정렬 알고리즘을 세 번 만들 수는 없습니다. 정렬 코드는 하나만 두고, 비교 기준(Comparator)만 갈아 끼우는 구조를 만듭니다. 이번에는 그 정렬 코드조차 직접 만들지 않고, JDK가 제공하는 Arrays.sort()를 그대로 씁니다.

    데이터 모델과 알고리즘 적용 기준

    • 데이터: Product 클래스 (이름 name, 가격 price, 평점 rating)
    • 기본 기준(Comparable): 상품의 기본 정렬은 가격 오름차순 — 클래스 안 compareTo에 정의
    • 교체 기준(Comparator): 평점 내림차순+이름순, 이름순 — 클래스 밖에서 만들어 정렬 메서드에 전달
    • 정렬 알고리즘: 9~11번 섹션에서 직접 구현한 삽입 정렬 대신, JDK 표준 라이브러리의 Arrays.sort(T[], Comparator)를 사용 — 내부의 TimSort는 안정 정렬이므로 동점 상품의 입력 순서가 그대로 유지됩니다
    Java ProductSortApplication.java 
    import java.util.Arrays;
import java.util.Comparator;

public class ProductSortApplication {

    /** 상품: 이름, 가격, 평점. 기본 정렬 기준(가격 오름차순)을 Comparable로 정의한다. */
    static class Product implements Comparable<Product> {
        String name;
        int price;      // 원
        double rating;  // 0.0 ~ 5.0

        Product(String name, int price, double rating) {
            this.name = name;
            this.price = price;
            this.rating = rating;
        }

        /** 기본 정렬 기준: 가격 오름차순. 음수=this가 앞, 0=같음, 양수=this가 뒤. */
        @Override
        public int compareTo(Product other) {
            return Integer.compare(this.price, other.price);
        }

        @Override
        public String toString() {
            return name + " (" + price + "원, 평점 " + rating + ")";
        }
    }

    static void printAll(String title, Product[] items) {
        System.out.println("[" + title + "]");
        for (int i = 0; i < items.length; i++) {
            System.out.println("  " + (i + 1) + ". " + items[i]);
        }
        System.out.println();
    }

    public static void main(String[] args) {
        Product[] products = {
            new Product("보조 배터리", 29000, 4.6),
            new Product("무선 이어폰", 79000, 4.6),
            new Product("스마트폰 거치대", 12000, 4.3),
            new Product("차량용 충전기", 18000, 4.1),
            new Product("블루투스 스피커", 45000, 4.3)
        };

        printAll("정렬 전 (입력 순서)", products);

        // 1) Comparable이 정의한 기본 기준(가격 오름차순)으로 정렬
        Product[] byPrice = Arrays.copyOf(products, products.length);
        Arrays.sort(byPrice, Comparator.naturalOrder());
        printAll("가격 오름차순 — Comparable의 compareTo 사용", byPrice);

        // 2) Comparator로 기준 교체: 평점 내림차순, 동점이면 이름 오름차순
        Comparator<Product> byRatingDesc =
                Comparator.comparingDouble((Product p) -> p.rating)
                          .reversed()
                          .thenComparing(p -> p.name);
        Product[] byRating = Arrays.copyOf(products, products.length);
        Arrays.sort(byRating, byRatingDesc);
        printAll("평점 내림차순, 동점 시 이름순 — Comparator 사용", byRating);

        // 3) 같은 정렬 메서드에 또 다른 기준: 이름 오름차순
        Product[] byName = Arrays.copyOf(products, products.length);
        Arrays.sort(byName, Comparator.comparing(p -> p.name));
        printAll("이름 오름차순 — Comparator 사용", byName);

        System.out.println("Arrays.sort 호출은 세 번 다 똑같습니다. 바뀐 것은 Comparator뿐입니다.");
    }
}

    15람다·스트림 수정 문제

    지금까지 쓴 코드를 같은 결과를 내는 다른 문법으로 고쳐 보는 문제입니다. 필요한 문법은 추가 정보의 람다식 문서에 모두 있습니다. 먼저 스스로 고쳐 본 뒤 정답을 펼치세요.

    기준을 바꿔도 정렬 알고리즘은 그대로다

    Comparator를 어떻게 쓰든 삽입 정렬은 최악 O(n²) 그대로입니다. 비교 횟수도 한 번 줄지 않습니다. 4강의 성과는 정렬 알고리즘 자체이고, 람다는 그 알고리즘에 기준을 갈아 끼우기 쉽게 만들 뿐입니다.

    수정 문제 ① — 부호를 따지는 비교를 "무엇으로 비교할지"로

    ProductSorterSolution.java의 기준 두 개입니다. 둘 다 중괄호와 return을 쓰고 있고, 내림차순은 a와 b의 순서를 뒤집어 표현했습니다. 이 방식은 읽는 사람이 부호를 머릿속에서 따져 봐야 의미가 드러납니다.

    Java ProductSorterSolution.java — 지금 코드 
    /** 기준 1: 가격 오름차순 */
static final Comparator<Product> PRICE_ASC = (a, b) -> {
    return Integer.compare(a.price, b.price);
};

/** 기준 2: 평점 내림차순 — 인자 순서를 바꾸면 방향이 뒤집힌다 */
static final Comparator<Product> RATING_DESC = (a, b) -> {
    return Double.compare(b.rating, a.rating);
};

    요구사항

    • 중괄호와 return을 없앨 것
    • 내림차순을 b, a 순서 뒤집기가 아닌 방법으로 표현할 것
    • 줄일 수 있는 곳은 메서드 참조까지 줄여 볼 것
    • 정렬 결과는 지금과 완전히 같아야 함
    • 힌트 — 표준 인터페이스와 메서드 참조
    정답과 해설 보기 — 수정 문제 ①
    Java ModernizeSolution.java — 정답 (3단계로 줄이기) 
    // 1단계: 중괄호와 return을 걷어낸다 (몸통이 식 하나면 함께 생략된다)
Comparator<Product> priceAsc = (a, b) -> Integer.compare(a.price, b.price);

// 2단계: "무엇으로 비교할지"만 주는 형태로
Comparator<Product> priceAsc2 = Comparator.comparingInt(p -> p.price);

// 3단계: 내림차순은 뒤집어 말한다 — 부호를 따질 일이 없어진다
Comparator<Product> ratingDesc =
        Comparator.comparingDouble((Product p) -> p.rating).reversed();

    (Product p)처럼 타입을 직접 적은 이유가 있습니다. Comparator.comparingDouble(...)만 보고는 컴파일러가 p가 무엇인지 알 수 없기 때문입니다. 대입받는 변수에 Comparator<Product>라고 적혀 있어도 .reversed()를 이어 붙이는 순간 추론 근거가 끊깁니다.

    여기서 얻은 것은 줄 수가 아닙니다. RATING_DESC는 "왜 b가 앞에 있지?"를 생각해야 뜻이 보이지만, comparingDouble(...).reversed()는 "평점으로 비교하고 뒤집는다"가 그대로 읽힙니다.

    수정 문제 ② — if 분기로 쓴 다중 기준을 thenComparing으로

    기준 3은 "평점 내림차순, 동점이면 이름 오름차순"입니다. 지금은 두 규칙이 compare 안에 뒤섞여 있어 if를 읽고 나서야 구조가 보입니다.

    Java ProductSorterSolution.java — 지금 코드

static final Comparator<Product> RATING_DESC_THEN_NAME = (a, b) -> {
    int byRating = Double.compare(b.rating, a.rating);
    if (byRating != 0) {
        return byRating;      // 평점이 다르면 평점으로 결정
    }
    return a.name.compareTo(b.name); // 동점일 때만 이름으로 결정
};

    • 안정 정렬이 깨지지 않아야 함 — 가격이 같은 23000원 두 상품이 입력 순서(무선 마우스 → 모니터 받침대)를 유지하는지 확인할 것

            return name + " (" + price + "원, 평점 " + rating + ")";
        }
    }

    /** 기준 1: 가격 오름차순 */
    static final Comparator<Product> PRICE_ASC = (a, b) -> {
        return Integer.compare(a.price, b.price);
    };

    /** 기준 2: 평점 내림차순 — 인자 순서를 바꾸면 방향이 뒤집힌다 */
    static final Comparator<Product> RATING_DESC = (a, b) -> {
        return Double.compare(b.rating, a.rating);
    };

    /** 기준 3: 평점 내림차순, 동점이면 이름 오름차순 (다중 기준) */
    static final Comparator<Product> RATING_DESC_THEN_NAME = (a, b) -> {
        int byRating = Double.compare(b.rating, a.rating);
        if (byRating != 0) {
            return byRating;      // 평점이 다르면 평점으로 결정
        }
        return a.name.compareTo(b.name); // 동점일 때만 이름으로 결정
    };

    /** 직접 구현한 삽입 정렬 — 안정 정렬이므로 같은 값의 입력 순서가 유지된다. */
    static void insertionSort(Product[] arr, Comparator<Product> comp) {
        for (int i = 1; i < arr.length; i++) {
            Product key = arr[i];
            int j = i - 1;
            // 주의: > 0 이어야 안정 정렬이다 (>= 0으로 쓰면 같은 값의 순서가 뒤집힌다)
            while (j >= 0 && comp.compare(arr[j], key) > 0) {
                arr[j + 1] = arr[j];
                j--;
            }
            arr[j + 1] = key;
        }
    }

    static void printAll(String title, Product[] items) {
        System.out.println("[" + title + "]");
        for (int i = 0; i < items.length; i++) {
            System.out.println("  " + (i + 1) + ". " + items[i]);
        }
        System.out.println();
    }

    /** 비교 검증용: 같은 기준으로 Arrays.sort한 결과와 일치하는지 확인한다. */
    static boolean matchesLibrarySort(Product[] mine, Product[] original,
                                      Comparator<Product> comp) {
        Product[] expected = Arrays.copyOf(original, original.length);
        Arrays.sort(expected, comp); // 검증용으로만 사용 (구현 대체 금지!)
        return Arrays.equals(mine, expected);
    }

    public static void main(String[] args) {
        Product[] products = {
            new Product("무선 마우스", 23000, 4.5),
            new Product("기계식 키보드", 89000, 4.8),
            new Product("USB 허브", 15000, 4.2),
            new Product("모니터 받침대", 23000, 4.7),
            new Product("노트북 파우치", 18000, 4.5),
            new Product("웹캠", 54000, 4.2)
        };

        printAll("정렬 전 (입력 순서)", products);

        Product[] byPrice = Arrays.copyOf(products, products.length);
        insertionSort(byPrice, PRICE_ASC);
        printAll("1) 가격 오름차순", byPrice);

        Product[] byRating = Arrays.copyOf(products, products.length);
        insertionSort(byRating, RATING_DESC);
        printAll("2) 평점 내림차순 (단일 기준)", byRating);

        Product[] byMulti = Arrays.copyOf(products, products.length);
        insertionSort(byMulti, RATING_DESC_THEN_NAME);
        printAll("3) 평점 내림차순 + 동점 시 이름순 (다중 기준)", byMulti);

        System.out.println("안정성 확인: 가격이 같은 23000원 상품 두 개가");
        System.out.println("  입력 순서(무선 마우스 → 모니터 받침대)를 유지했습니다.");
        System.out.println();
        System.out.println("Arrays.sort 결과와 일치(검증): "
                + (matchesLibrarySort(byPrice, products, PRICE_ASC)
                && matchesLibrarySort(byRating, products, RATING_DESC)
                && matchesLibrarySort(byMulti, products, RATING_DESC_THEN_NAME)));
    }

    19오늘의 핵심 정리

    • 선택 정렬 = 2강의 최솟값 찾기(값 대신 위치 기억) + 3강의 중첩 반복문. 한 회전마다 앞쪽에 한 자리가 확정된다.
    • 교환(swap)에는 임시 변수가 필수다 — 없으면 값이 복제되어 데이터가 파괴된다.
    • 선택·버블·삽입 정렬은 모두 평균 O(n²) (비교 약 n(n-1)/2번). 단, 이미 정렬된 입력에서 버블(조기 종료)과 삽입은 O(n)으로 끝난다.
    • 안정 정렬은 같은 값의 입력 순서를 유지한다 — 버블·삽입은 안정, 선택은 불안정.
    • 객체 정렬은 비교 기준을 코드와 분리한다 — 기본 기준은 Comparable.compareTo, 교체 기준은 Comparator.compare. 반환값 규약은 음수(앞)/0(같음)/양수(뒤).
    • 다중 기준은 "1차 기준이 동점(0)일 때만 2차 기준"으로 조립한다.
    • Arrays.sort()는 직접 구현을 검증하는 용도로 활용한다 — 결과 대조는 1강부터 이어지는 습관이다.

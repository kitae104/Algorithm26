이 강의의 목차

    01강의 소개

    12개 강의의 도구(배열, 해시, 정렬, 이진 탐색, 스택, 큐, 재귀, 트리, 그래프, 그리디, DP, 다익스트라)가 쌓였지만, 실제 문제는 "삽입 정렬을 구현하시오"처럼 오지 않습니다.

    • 실제로는 "상품을 빨리 찾게 해 주세요. 카테고리별 재고 현황도 보고 싶어요."처럼, 도구 이름이 하나도 등장하지 않는 요구사항으로 옵니다
    • 이번 강의의 목표
      • 요구사항 문장에서 신호를 읽어 어떤 도구를 꺼낼지 스스로 결정
      • 결정한 도구들을 하나의 프로그램으로 결합
    • 소재: 콘솔 상품 관리·분석 프로그램 — 데이터 모델 설계 → 정렬 → 이진 탐색 → HashMap 집계 → 잘못된 입력 방어까지 단계별로 완성
    • 마지막에는 같은 설계를 새 데이터에 적용하는 최종 프로젝트 재고 관리 시스템 "StockMaster"를 직접 완성

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 요구사항 문장에서 데이터(명사)와 기능(동사)을 찾아 데이터 클래스를 설계할 수 있다.
    • 학생은 요구사항의 신호를 결정 기준 표와 연결해 알맞은 자료구조·알고리즘을 선택하고 이유를 설명할 수 있다.
    • 학생은 정렬(Comparator) → 이진 탐색 → HashMap 집계를 하나의 파이프라인으로 결합한 프로그램을 작성할 수 있다.
    • 학생은 try-catch와 범위 검증으로 잘못된 사용자 입력을 방어해 프로그램이 중단되지 않게 만들 수 있다.
    • 학생은 결합된 프로그램의 단계별 시간 복잡도를 분석하고 병목 단계를 지목할 수 있다.
    • 학생은 같은 설계를 다른 도메인 데이터(도서 관리 등)에 재활용할 수 있다.

    도구를 고를 때는 세 가지 질문을 순서대로 던지세요.

    • 질문 1 — 무엇을 가장 자주 하는가? 검색이 잦으면 검색이 싼 구조(정렬+이진 탐색, HashMap)를, 삽입·삭제가 잦으면 그 연산이 싼 구조를 고릅니다.
    • 질문 2 — 데이터에 규칙이 있는가? 고유 키가 있으면 해시나 정렬+이진 탐색이 가능하고, 이미 정렬돼 있다면 정렬 비용을 아낄 수 있습니다.
    • 질문 3 — 어떤 비정상 입력이 오는가? 사용자 입력이 있다면 형식 → 범위 → 존재 순서의 검증과 예외 처리가 반드시 설계에 포함되어야 합니다.

    개념 3 — 우리 프로그램의 결정 과정

    요구사항들린 신호결정
    코드로 바로 검색"고유 번호 + 자주 찾는다"코드 순 정렬(4강) 후 이진 탐색(5강) — 정렬은 시작할 때 1번, 검색은 매번 O(log n)
    카테고리별 현황"이름(키)별로 세기·누적"HashMap(3강) 집계 — 한 바퀴 순회로 O(n)
    재고 부족 알림"조건에 맞는 것 골라내기"리스트 조건 검색(2강) — O(n)
    잘못된 입력에도 계속 동작"사용자 입력 = 신뢰 불가"try-catch + 범위 검증 — 형식·범위·존재 3단계 방어

    이렇게 결정된 처리 순서가 곧 프로그램의 파이프라인입니다: 데이터 로드 → 코드 순 정렬 → 검색 요청 처리(예외 방어) → 카테고리 집계 → 재고 경고. 정렬을 맨 앞에 두는 이유는 뒤의 모든 이진 탐색이 정렬을 전제로 하기 때문입니다.

    HashMap이 있는데 왜 정렬+이진 탐색도 쓰나요?
    • 코드 → 상품 검색만 보면 HashMap<Integer, Product>도 평균 O(1)로 훌륭한 선택
    • 하지만 이 프로그램은 코드 순 목록 출력도 요구하므로 어차피 정렬이 필요
    • 정렬된 리스트가 있으면 이진 탐색은 추가 메모리 없이 따라옴
    • "범위 검색(코드 2000번대만)" 같은 확장에도 정렬된 리스트가 유리
    • 같은 요구라도 함께 있는 다른 요구에 따라 최선의 도구가 달라진다 — 이것이 설계

    잡화점 상품 8종(입고 순서 코드: 2005, 1003, 3010, 1007, 2002, 3001, 1010, 2008)으로 파이프라인 전체가 움직이는 모습을 단계별로 확인해 봅시다 — 코드 순 삽입 정렬 → 2005번 이진 탐색 → 카테고리(전자·생활·잡화)별 집계.

    • 다음 단계 ▶ 버튼으로 한 단계씩 진행
    • 정렬: 카드를 한 장씩 집어, 이미 정리된 앞부분의 알맞은 자리에 끼워 넣음 (4강 삽입 정렬)
    • 탐색: 정렬된 목록의 가운데부터 보고 절반씩 버림 (5강 이진 탐색) — 8개면 최대 4번, 1,000개여도 약 10번 (2¹⁰ = 1024)
    • 집계: 카테고리 이름표(키)마다 개수와 가격 × 재고를 누적 (3강 HashMap) — 한 바퀴 순회로 끝남
    • 정렬 중 끼워 넣는 카드와 탐색 중 확인하는 칸은 파란색(현재) 또는 앰버색(비교), 확정된 부분은 초록색(완료)으로 표시
    • "새 데이터" 버튼을 누르면 입고 순서와 검색 대상이 바뀜
    • 시각화의 정렬 단계는 07 실습 코드의 insertionSort, 탐색 단계는 binarySearchByCode, 집계 단계는 printReport와 정확히 같은 절차
    • examples/java/13-algorithm-project/ProductManagerTrace.java를 직접 실행해, 각 회차의 상태가 이 시각화와 일치하는지 비교해 볼 것

    06의사코드

    코드를 쓰기 전에, 결정한 파이프라인을 언어 중립적인 의사코드로 정리합니다.

    • 의사코드 = 특정 언어 문법 대신 우리말에 가까운 문장으로 알고리즘의 순서를 적은 것
    • 읽는 법: x ← 값은 "x에 값을 저장한다", 들여쓰기는 "바로 위 줄 안에 포함된 작업", // 뒤는 설명(주석)
    • 알고리즘 이름(입력)은 하나의 메서드, 다른 알고리즘 이름을 부르는 줄(HandleRequest(...))은 그 메서드를 호출하는 것
    • 시도: … 변환 실패 시:는 Java의 try … catch — 시도 중 문제가 생기면 곧장 "실패 시" 쪽으로 건너뜀

    상품 관리 파이프라인 (ProductManager)

    Pseudo 전체 파이프라인 — ProductManager 
    알고리즘 ProductManager(products, requests)
    products를 코드 오름차순으로 삽입 정렬한다      // 4강 — 시작할 때 1번만
    requests의 각 요청 r에 대해 반복:               // 정렬은 다시 하지 않고 재사용
        HandleRequest(products, r)                  // 5강 + 예외 방어
    카테고리별 상품 수와 재고 자산을 HashMap으로 집계한다   // 3강 — 한 바퀴 순회
    재고가 기준(5개) 미만인 상품을 골라 경고한다     // 2강 — 조건 검색

    요청 1건 처리 (HandleRequest)

    Pseudo 요청 1건 처리 — HandleRequest 
    알고리즘 HandleRequest(sorted, rawInput)
    시도:                                           // 실패하면 남은 줄을 건너뜀 (try)
        code ← rawInput을 정수로 변환               // 1) 형식 검증 — 실패하면 아래 "변환 실패"로
        만약 code ≤ 0 이면:                          // 2) 범위 검증
            "1 이상의 정수여야 합니다" 출력하고 종료
        result ← BinarySearch(sorted, code)          // 3) 존재 확인 — O(log n)
        만약 result가 없음이면: "미등록 코드" 출력
        아니면: result의 요약 출력
    변환 실패 시:                                   // Java의 catch
        "숫자가 아닙니다" 출력                        // 프로그램은 멈추지 않고 계속된다

    두 의사코드 정리

    • 이 프로그램의 뼈대는 새 알고리즘이 아니라 배운 알고리즘들의 연결 순서
    • "정렬이 이진 탐색보다 먼저"라는 순서 하나가 프로그램 전체의 정확성을 좌우
    • 입력 검증도 순서가 있음: 형식 → 범위 → 존재 — 숫자로 바뀌어야 크기를 비교할 수 있고, 올바른 코드여야 찾아볼 의미가 있음

    07실습 코드

    의사코드(06)를 실제 Java 프로그램으로 옮깁니다. 요구사항 하나당 메서드 하나씩을 대응시켜 데이터 모델 → 정렬 → 검색 → 집계 네 기능을 갖춘 프로그램으로 정리했습니다.

    • insertionSort는 04 핵심 개념 2의 정렬(4강)을 Comparator와 함께 옮긴 것, binarySearchByCode는 이진 탐색(5강)을 그대로 메서드로 옮긴 것
    • printReport는 HashMap 집계(3강)와 조건 검색(2강)을 한 메서드 안에서 순서대로 수행
    • 새로 추가되는 것은 handleSearchRequest 하나 — 문자열 입력을 형식(숫자인가) → 범위(양수인가) → 존재(등록된 코드인가) 3단계로 검증하며, 06 의사코드의 예외 방어 구조를 그대로 옮겨 어떤 잘못된 입력에도 프로그램이 멈추지 않게 함
    • 검색 요청 시나리오에는 정상 코드 2건, 미등록 코드, 숫자 아닌 입력, 음수를 모두 넣음

    import java.util.ArrayList;

/**

 * "잘못된 입력 방어(예외 처리)"를 더해 하나의 프로그램으로 통합한다.

 */
public class ProductManagerComplete {

    /** 상품 1개의 정보를 담는 데이터 클래스 */
    static class Product {
        int code;
        String name;
        String category;
        int price;
        int stock;

        Product(int code, String name, String category, int price, int stock) {
            this.code = code;
            this.name = name;
            this.category = category;
            this.price = price;
            this.stock = stock;
        }

        String summary() {
            return "[" + code + "] " + name + " | " + category
                    + " | " + price + "원 | 재고 " + stock + "개";
        }
    }

    /** 입고 순서 그대로의 상품 8개 */
    static List<Product> loadProducts() {
        List<Product> products = new ArrayList<>();
        products.add(new Product(2005, "유선 키보드", "전자", 23000, 12));
        products.add(new Product(1003, "무선 마우스", "전자", 18000, 25));
        products.add(new Product(3010, "머그컵", "생활", 7000, 2));
        products.add(new Product(1007, "마우스 패드", "잡화", 4000, 18));
        products.add(new Product(2002, "USB 메모리", "전자", 9000, 5));
        products.add(new Product(3001, "텀블러", "생활", 12000, 30));
        products.add(new Product(1010, "노트북 파우치", "잡화", 15000, 3));
        products.add(new Product(2008, "웹캠", "전자", 45000, 4));
        return products;
    }

    /** 삽입 정렬(4강) — Comparator로 기준을 갈아 끼운다 */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** 이진 탐색(5강) — 코드 오름차순 정렬이 전제 조건 */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);
            }
            if (midCode < targetCode) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return null;
    }

    /**
     * 검색 요청 1건 처리 — 잘못된 입력을 예외 처리로 방어한다.
     * 사용자가 입력한 문자열은 숫자가 아닐 수도, 음수일 수도, 없는 코드일 수도 있다.
     */
    static void handleSearchRequest(List<Product> sorted, String rawInput) {
        System.out.println("검색 요청 \"" + rawInput + "\"");
        try {
            int code = Integer.parseInt(rawInput.trim()); // 숫자가 아니면 NumberFormatException
            if (code <= 0) {
                System.out.println("  → 오류: 상품 코드는 1 이상의 정수여야 합니다.");
                return;
            }
            Product found = binarySearchByCode(sorted, code);
            if (found != null) {
                System.out.println("  → " + found.summary());
            } else {
                System.out.println("  → 코드 " + code + " 상품 없음 (미등록 코드)");
            }
        } catch (NumberFormatException e) {
            // 프로그램을 멈추지 않고, 문제를 알린 뒤 다음 요청으로 넘어간다
            System.out.println("  → 오류: \"" + rawInput + "\"은(는) 숫자가 아닙니다.");
        }
    }

    /** 카테고리별 집계(3강 HashMap) + 재고 경고(2강 조건 검색) */
    static void printReport(List<Product> products) {
        Map<String, Integer> countByCategory = new HashMap<>();
        Map<String, Long> valueByCategory = new HashMap<>();
        List<String> categoryOrder = new ArrayList<>(); // 출력 순서 고정용

        for (Product p : products) {
            if (!countByCategory.containsKey(p.category)) {
                categoryOrder.add(p.category);
                countByCategory.put(p.category, 0);
                valueByCategory.put(p.category, 0L);
            }
            countByCategory.put(p.category, countByCategory.get(p.category) + 1);
            valueByCategory.put(p.category,
                    valueByCategory.get(p.category) + (long) p.price * p.stock);
        }

        System.out.println("== 3. 카테고리별 집계 ==");
        long totalValue = 0;
        for (String category : categoryOrder) {
            long value = valueByCategory.get(category);
            totalValue += value;
            System.out.println("  " + category + " : 상품 " + countByCategory.get(category)
                    + "종 | 재고 자산 " + value + "원");
        }
        System.out.println("  전체 재고 자산: " + totalValue + "원");

        System.out.println();
        System.out.println("== 4. 재고 부족 경고 (5개 미만) ==");
        int warningCount = 0;
        for (Product p : products) {
            if (p.stock < 5) {
                warningCount++;
                System.out.println("  " + p.summary());
            }
        }
        System.out.println("  경고 대상: " + warningCount + "종");
    }

    public static void main(String[] args) {
        // 1) 데이터 로드 (Step1)
        List<Product> products = loadProducts();
        System.out.println("== 1. 상품 " + products.size() + "종 로드 → 코드 순 정렬 ==");

        // 2) 코드 오름차순 정렬 (Step2) — 이후 모든 검색의 기반
        insertionSort(products, (a, b) -> a.code - b.code);
        for (Product p : products) {
            System.out.println("  " + p.summary());
        }

        System.out.println();
        System.out.println("== 2. 검색 요청 처리 (이진 탐색 + 예외 처리) ==");
        // 실제 서비스라면 Scanner로 받을 입력 — 여기서는 시나리오로 고정한다
        String[] requests = {"2005", "3010", "1500", "20A5", "-7"};
        for (String request : requests) {
            handleSearchRequest(products, request);
        }

        System.out.println();
        // 3) + 4) 집계와 경고 (Step4)
        printReport(products);
    }
}

    08잘못된 코드와 오류 찾기

    알고리즘을 결합할 때 가장 자주 나는 오류 두 가지입니다. 먼저 코드를 읽고 무엇이 잘못됐는지 생각한 뒤 해설을 여세요.

    오류 1 — 정렬하지 않은 리스트에 이진 탐색

    • 원인: 리스트가 입고 순서 그대로(2005, 1003, 3010, …)라서 이진 탐색의 전제 조건인 "정렬된 상태"가 깨져 있습니다. 첫 비교에서 가운데(인덱스 3)의 1007을 보고 "2005보다 작으니 왼쪽 절반은 버리자"고 판단하는 순간, 왼쪽에 있던 진짜 2005가 함께 버려집니다. 절반 버리기는 정렬을 믿고 하는 판단이기 때문입니다.

    • 수정 방법: 이진 탐색 전에 반드시 코드 순으로 정렬합니다.

Product found = binarySearchByCode(products, 2005);

    for (String request : requests) {
    try {
        int code = Integer.parseInt(request);
        System.out.println("코드 " + code + " 검색을 시작합니다.");

    09복잡도 및 특성 분석

    복잡도 분석 = "상품과 검색 요청이 많아지면 일이 얼마나 늘어나는가?"를 따져 보는 것. 파이프라인은 여러 단계라서, 단계마다 몇 번 확인하는지 세고 그중 가장 느린 단계를 찾습니다.

    입력 크기 — 무엇이 많아지는가?

    • 상품 수 n (예제에서는 8개) — 상품이 늘면 정렬·집계·경고의 일이 늘어남
    • 검색 요청 수 q (예제에서는 5건) — 요청이 늘면 이진 탐색을 부르는 횟수가 늘어남
    • 카테고리 수 k (예제에서는 3개: 전자·잡화·생활) — HashMap에 적어 둘 이름표 수

    주요 연산 — 무엇을 세는가?

    • 단계마다 가장 많이 반복되는 한 동작만 세면 충분
    • 정렬: 두 상품의 코드를 비교하는 comparator.compare 한 번 (그리고 한 칸 밀기)
    • 검색: 가운데 상품의 코드와 찾는 코드를 비교하는 한 번
    • 집계: HashMap에 확인·기록하는 get·put 한 번
    • 경고: "재고가 5개 미만인가?"를 묻는 한 번

    시간 복잡도 — 얼마나 오래 걸리는가?

    파이프라인 단계확인 횟수상품 8개일 때상품 1만 개일 때Big-O
    1. 데이터 로드상품마다 1번: n번8번1만 번O(n)
    2. 코드 순 정렬 (삽입 정렬)최악 n(n-1)/2번 비교 — 시작할 때 1번만최대 28번최대 약 5천만 번O(n²)
    3. 검색 1건 (이진 탐색)절반씩 버리며 최대 약 log₂n + 1번최대 4번최대 14번O(log n)
    4. 카테고리 집계 (HashMap)상품마다 1번: n번8번1만 번평균 O(n)
    5. 재고 경고 (조건 검색)상품마다 1번: n번8번1만 번O(n)
    • O(n²)을 쉽게 말하면: 상품이 10배 늘면 정렬 일은 약 100배 — 뒤죽박죽 카드 더미를 한 장씩 앞쪽 정리된 카드 사이에 끼워 넣는 것과 같음 (카드가 많을수록 새 카드가 지나쳐야 할 카드도 많아짐)
      • 이미 거의 정렬되어 있으면 카드마다 비교 1번으로 끝나 O(n) — 최악일 때만 n(n-1)/2번
    • O(log n)을 쉽게 말하면: 상품이 2배가 되어도 검색은 1번만 늘어남 — 두꺼운 사전을 가운데부터 펼쳐 앞뒤 절반을 버리는 것과 같음
    • O(n)을 쉽게 말하면: 상품이 10배 늘면 일도 10배만 늘어남 — 장부를 위에서부터 한 번 훑어 내려가는 것과 같음
    • 검색 요청 q건 전체: 이진 탐색은 요청마다 반복되므로 q × log n
      • 예: 상품 1,000개, 요청 1만 건 — 매번 처음부터 순차 탐색하면 최대 1,000만 번, 이진 탐색이면 최대 약 10만 번(요청당 최대 10번)
    • HashMap 앞의 "평균": 아주 드물게 한 번의 확인이 느려질 수 있지만, 실제로는 거의 항상 한 번에 끝난다고 생각해도 충분

    공간 복잡도 — 메모리를 얼마나 더 쓰는가?

    • 상품 목록 자체: 상품 수만큼 — O(n) (원래 있어야 하는 데이터)
    • 삽입 정렬: 목록 안에서 자리만 바꿈(제자리 정렬) — 상품이 늘어도 추가 메모리는 그대로, O(1)
    • 이진 탐색: 변수 low·mid·high 세 개뿐 — O(1)
    • 카테고리 집계: 카테고리마다 HashMap 칸 하나 + 순서 목록 — 카테고리 수만큼, O(k) (예제는 3칸)
    한 줄 정리 — 정렬은 한 번 먼저, 검색은 매번 빠르게
    • 정렬 비용(O(n²))을 시작할 때 한 번 내면, 이후 모든 검색이 O(log n) — 프로그램 전체 속도는 가장 느린 단계(정렬)가 정함

    알고리즘 특성 — 언제 무엇을 쓰는가?

    • 검색이 잦으면 "정렬 + 이진 탐색": 정렬은 선불 비용, 검색 이득은 매번 — 요청(q)이 많을수록 유리
    • 느린 단계만 바꾸면 됨: 이 프로그램의 병목은 삽입 정렬 O(n²). 상품이 수만 개로 늘면 O(n log n) 정렬(병합 정렬 계열)로 교체 — 모듈을 나눠 두었기에 insertionSort 메서드만 바꾸면 됨
    • 순서가 정확성을 정함: 정렬 없이 이진 탐색을 하면 예외 없이 조용히 틀린 답 (08 오류 1)
    • 예외 처리는 속도가 아니라 정확성의 문제: try-catch는 확인 횟수를 거의 늘리지 않지만, 없으면 "빠르지만 언제든 꺼지는" 프로그램 — 1강의 원칙 그대로 정확성(견고함) 먼저, 효율성 다음

    /** 상품 1개의 정보를 담는 데이터 클래스 */

    /** 이진 탐색(5강) — low·high를 직접 옮기는 알고리즘이라 반복문 그대로 둔다 */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);
            }
            if (midCode < targetCode) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return null;
    }

    /** 검색 요청 1건 처리 — 잘못된 입력을 예외 처리로 방어한다 */
    static void handleSearchRequest(List<Product> sorted, String rawInput) {
        System.out.println("검색 요청 \"" + rawInput + "\"");
        try {
            int code = Integer.parseInt(rawInput.trim());
            if (code <= 0) {
                System.out.println("  → 오류: 상품 코드는 1 이상의 정수여야 합니다.");
                return;

            Product found = binarySearchByCode(sorted, code);
            if (found != null) {
                System.out.println("  → " + found.summary());
            } else {
                System.out.println("  → 코드 " + code + " 상품 없음 (미등록 코드)");
            }
        } catch (NumberFormatException e) {
            System.out.println("  → 오류: \"" + rawInput + "\"은(는) 숫자가 아닙니다.");
        }
    }

    /** 재고 자산 = 가격 × 재고의 합 (long으로 누적) */
    static long assetValue(List<Product> products) {
        return products.stream()
                .map(p -> (long) p.price * p.stock)
                .reduce(0L, (acc, v) -> acc + v);
    }

    static void printReport(List<Product> products) {
        Map<String, List<Product>> byCategory = products.stream()
                .collect(Collectors.groupingBy(p -> p.category));
        List<String> categoryOrder = products.stream()   // 출력 순서 고정용
                .map(p -> p.category)
                .distinct()
                .toList();

            List<Product> group = byCategory.get(category);
            System.out.println("  " + category + " : 상품 " + group.size()
                    + "종 | 재고 자산 " + assetValue(group) + "원");
        });
        System.out.println("  전체 재고 자산: " + assetValue(products) + "원");

        System.out.println();
        System.out.println("== 4. 재고 부족 경고 (5개 미만) ==");
        List<Product> lowStock = products.stream()
                .filter(p -> p.stock < 5)
                .toList();
        lowStock.forEach(p -> System.out.println("  " + p.summary()));
        System.out.println("  경고 대상: " + lowStock.size() + "종");
    }

    public static void main(String[] args) {
        List<Product> products = loadProducts();
        System.out.println("== 1. 상품 " + products.size() + "종 로드 → 코드 순 정렬 ==");

                .sorted(Comparator.comparingInt(p -> p.code))

        sorted.forEach(p -> System.out.println("  " + p.summary()));

    /** 도서 1권의 정보 — Product와 구조가 같다 (고유 번호, 이름, 분류, 수량) */
    static class Book {

            this.genre = genre;
            this.copies = copies;

        books.add(new Book(5023, "이펙티브 자바", "IT", 2));

    public static void main(String[] args) {
        List<Book> books = loadBooks();
        Comparator<Book> byId = Comparator.comparingInt(b -> b.id);

        // 결정 1: 검색이 잦다 → 등록 번호 순 정렬 + 이진 탐색 (이번엔 라이브러리로)
        books.sort(byId);

            System.out.println("  " + b.summary());

        System.out.println();
        System.out.println("== 도서 검색 (이진 탐색 + 예외 처리) ==");

        for (String request : requests) {

                int id = Integer.parseInt(request.trim());
                Book probe = new Book(id, "", "", 0);   // 비교에만 쓰는 탐색용 키 객체

                if (index >= 0) {
                    System.out.println("  → " + books.get(index).summary());

        List<String> genreOrder = new ArrayList<>();
        for (Book b : books) {
            if (!countByGenre.containsKey(b.genre)) {
                genreOrder.add(b.genre);
                countByGenre.put(b.genre, 0);
            }
            countByGenre.put(b.genre, countByGenre.get(b.genre) + 1);
        }
        for (String genre : genreOrder) {
            System.out.println("  " + genre + " : " + countByGenre.get(genre) + "종");
        }

        System.out.println();

        for (Book b : books) {
            if (b.copies <= 1) {
                System.out.println("  " + b.summary());
            }
        }

        System.out.println();
        System.out.println("도메인이 상품 → 도서로 바뀌어도, 요구사항 패턴이 같으면 같은 설계를 재사용할 수 있다.");
    }
}

    코드 해설과 복잡도 분석

    • 도서 6권이 정렬된 뒤 번호 2205는 단 1번의 비교로 찾았습니다 — 정렬된 6개의 정확히 가운데(인덱스 2)에 있었기 때문입니다. 이진 탐색의 최선의 경우입니다.
    • 없는 번호 9999는 3번 비교로 "없음"을 확정했습니다 (최악의 경우, ⌈log₂ 6⌉ = 3).
    • 복잡도: List.sort(Comparator)는 TimSort로 O(n log n) 1번 (4강에서 직접 구현한 삽입 정렬의 O(n²)보다 데이터가 많아질수록 유리), 검색은 Collections.binarySearch로 여전히 O(log n)/건, 집계는 O(n)입니다.
    • 라이브러리 사용법: Collections.binarySearch는 비교에 쓸 "탐색용 키 객체"가 필요합니다. 그래서 id만 채운 임시 Book(probe)을 만들어 넘깁니다 — 실무에서도 자주 쓰는 패턴입니다.
    • 핵심 교훈: 도메인(상품·도서·회원·주문)이 바뀌어도 "요구사항 신호 → 도구 선택"의 결정 과정은 재사용됩니다. 여러분이 익힌 것은 상품 관리 프로그램이 아니라 설계 절차입니다.

    정답 코드와 해설 확인
    Java StockMasterSolution.java 
    import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 최종 프로그램 문제 — 편의점 재고 관리 시스템 "StockMaster" 정답 코드.
 * 파이프라인: 데이터 로드 → 코드 순 정렬(4강) → 검색 요청 처리(5강 + 예외 방어)
 *            → 카테고리 집계(3강) → 재고 경고(2강)
 */
public class StockMasterSolution {

    /** 상품 1개의 정보를 담는 데이터 클래스 */
    static class Product {
        int code;
        String name;
        String category;
        int price;
        int stock;

        Product(int code, String name, String category, int price, int stock) {
            this.code = code;
            this.name = name;
            this.category = category;
            this.price = price;
            this.stock = stock;
        }

        String summary() {
            return "[" + code + "] " + name + " | " + category
                    + " | " + price + "원 | 재고 " + stock + "개";
        }
    }

    /** 편의점 상품 8종 */
    static List<Product> loadProducts() {
        List<Product> products = new ArrayList<>();
        products.add(new Product(5501, "블루투스 스피커", "전자", 52000, 6));
        products.add(new Product(1203, "게이밍 마우스", "전자", 35000, 2));
        products.add(new Product(7010, "보온 도시락", "생활", 21000, 15));
        products.add(new Product(3305, "무선 충전기", "전자", 28000, 9));
        products.add(new Product(2101, "여행용 파우치", "잡화", 13000, 4));
        products.add(new Product(8804, "스테인리스 텀블러", "생활", 16000, 22));
        products.add(new Product(4409, "휴대용 선풍기", "생활", 19000, 3));
        products.add(new Product(6607, "가죽 키링", "잡화", 8000, 11));
        return products;
    }

    /** [요구사항 1] 삽입 정렬 — 기준은 Comparator로 받는다 (4강) */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));   // key보다 뒤에 와야 하는 원소를 뒤로 민다
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** [요구사항 2] 이진 탐색 — 찾으면 Product, 없으면 null (5강) */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);
            }
            if (midCode < targetCode) {
                low = mid + 1;    // 왼쪽 절반 버리기
            } else {
                high = mid - 1;   // 오른쪽 절반 버리기
            }
        }
        return null;
    }

    /** [요구사항 3] 검색 요청 1건 처리 — 잘못된 입력에도 멈추지 않는다 */
    static void handleSearchRequest(List<Product> sorted, String rawInput) {
        System.out.println("검색 요청 \"" + rawInput + "\"");
        try {
            int code = Integer.parseInt(rawInput.trim());
            if (code <= 0) {
                System.out.println("  → 오류: 상품 코드는 1 이상의 정수여야 합니다.");
                return;
            }
            Product found = binarySearchByCode(sorted, code);
            if (found != null) {
                System.out.println("  → " + found.summary());
            } else {
                System.out.println("  → 코드 " + code + " 상품 없음 (미등록 코드)");
            }
        } catch (NumberFormatException e) {
            System.out.println("  → 오류: \"" + rawInput + "\"은(는) 숫자가 아닙니다.");
        }
    }

    /** [요구사항 4] 카테고리별 상품 수와 재고 자산(가격 × 재고 합계) 집계 (3강) */
    static void printCategoryReport(List<Product> products) {
        Map<String, Integer> countByCategory = new HashMap<>();
        Map<String, Long> valueByCategory = new HashMap<>();
        List<String> categoryOrder = new ArrayList<>();   // 처음 등장한 순서 = 출력 순서

        for (Product p : products) {
            if (!countByCategory.containsKey(p.category)) {
                categoryOrder.add(p.category);
                countByCategory.put(p.category, 0);
                valueByCategory.put(p.category, 0L);
            }
            countByCategory.put(p.category, countByCategory.get(p.category) + 1);
            valueByCategory.put(p.category,
                    valueByCategory.get(p.category) + (long) p.price * p.stock);
        }

        System.out.println("== 3. 카테고리별 집계 ==");
        long totalValue = 0;
        for (String category : categoryOrder) {
            long value = valueByCategory.get(category);
            totalValue += value;
            System.out.println("  " + category + " : 상품 " + countByCategory.get(category)
                    + "종 | 재고 자산 " + value + "원");
        }
        System.out.println("  전체 재고 자산: " + totalValue + "원");
    }

    /** [요구사항 5] 재고 부족 경고 — 재고 5개 미만 상품 출력 (2강) */
    static void printLowStockWarning(List<Product> products) {
        System.out.println("== 4. 재고 부족 경고 (5개 미만) ==");
        int warningCount = 0;
        for (Product p : products) {
            if (p.stock < 5) {
                warningCount++;
                System.out.println("  " + p.summary());
            }
        }
        System.out.println("  경고 대상: " + warningCount + "종");
    }

    public static void main(String[] args) {
        List<Product> products = loadProducts();

        System.out.println("== 1. 상품 " + products.size() + "종 로드 → 코드 순 정렬 ==");
        insertionSort(products, (a, b) -> a.code - b.code);
        for (Product p : products) {
            System.out.println("  " + p.summary());
        }

        System.out.println();
        System.out.println("== 2. 검색 요청 처리 (이진 탐색 + 예외 처리) ==");
        String[] requests = {"5501", "1203", "9999", "12O3", "-100"};
        for (String request : requests) {
            handleSearchRequest(products, request);
        }

        System.out.println();
        printCategoryReport(products);

        System.out.println();
        printLowStockWarning(products);
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. insertionSort (TODO 1): 4강의 삽입 정렬에 Comparator를 결합했습니다. comparator.compare(list.get(j), key) > 0이 "앞 원소가 key보다 뒤에 와야 한다"는 뜻 — 이 조건이 참인 동안 한 칸씩 밀고, 거짓이 되는 순간 그 자리에 삽입합니다.
    2. binarySearchByCode (TODO 2): 5강의 이진 탐색 그대로입니다. low <= high가 반복 조건이라는 것(등호 포함!)과, 버릴 때 mid + 1 / mid - 1로 mid 자신을 제외하는 것이 핵심입니다.
    3. handleSearchRequest (TODO 3): 검증 3단계의 순서가 중요합니다. 형식(parseInt) → 범위(양수) → 존재(이진 탐색). 형식 검증을 통과해야 숫자 비교가 가능하므로 이 순서는 뒤바꿀 수 없습니다. "-100"은 parseInt에 성공하므로 catch가 아니라 범위 검사에서 걸립니다.
    4. printCategoryReport (TODO 4): HashMap 두 개(개수·자산)와 등장 순서 리스트 하나를 함께 관리합니다. 자산 누적은 (long) p.price * p.stock — int 곱셈 오버플로를 막는 캐스팅은 1강에서 배운 함정 대비책입니다.
    5. printLowStockWarning (TODO 5): 2강의 조건 검색에 카운터를 더한 구조입니다.

    복잡도 분석

    • 정렬 O(n²) 1번 + 검색 O(log n) × 5건 + 집계 O(n) + 경고 O(n). n=8이므로 전체 수십 번의 연산.
    • 상품이 10,000개로 늘면 병목은 삽입 정렬(약 5천만 번 비교)입니다. 이때는 O(n log n) 정렬로 교체하되, 나머지 파이프라인은 그대로 둡니다 — 모듈 분리의 이득입니다.
    • 공간은 상품 리스트 O(n) + 집계 구조 O(k), 정렬·탐색 자체는 O(1)입니다.

    자주 발생하는 오류

    • 정렬 전에 binarySearchByCode를 호출해 있는 상품을 "없음"으로 판정 (오류 1 참고).
    • while (low < high)로 써서 마지막 남은 한 칸을 검사하지 않아, 양 끝 경계 코드(1203, 8804)를 놓치는 경우.
    • try-catch 없이 제출해 "12O3"에서 프로그램이 죽는 경우 (오류 2 참고).
    • 범위 검증(code <= 0)을 catch 블록 안에 두는 경우 — "-100"은 예외를 던지지 않으므로 검증이 실행되지 않습니다.
    • 자산 집계를 int로 해서 상품 수·가격이 커지면 오버플로가 나는 경우.

    다른 해결 방법

    검색만 놓고 보면 HashMap<Integer, Product>로 평균 O(1) 검색이 가능합니다. 다만 이 문제는 "코드 순 목록 출력"이 함께 요구되어 정렬이 어차피 필요하므로, 정렬 리스트 + 이진 탐색이 추가 메모리 없이 두 요구를 모두 해결합니다. 상품 추가·삭제가 잦은 시스템이라면 8강의 이진 탐색 트리(균형 트리)가 "정렬 유지 + O(log n) 검색·삽입"을 동시에 주는 대안이 됩니다.

    15오늘의 핵심 정리

    • 실전 문제는 도구 이름 없이 요구사항 문장으로 온다. 명사에서 데이터 모델을, 동사에서 기능을, 신호 문장에서 자료구조·알고리즘을 찾는다.
    • 도구 선택의 세 질문: 무엇을 가장 자주 하는가 · 데이터에 규칙이 있는가 · 어떤 비정상 입력이 오는가.
    • 알고리즘은 파이프라인으로 결합된다: 정렬(선불 비용 1번) → 이진 탐색(매번 O(log n)) → HashMap 집계(O(n)) → 조건 검색(O(n)). 순서가 정확성을 좌우한다 — 정렬 없는 이진 탐색은 조용히 틀린다.
    • 사용자 입력은 신뢰할 수 없다. 형식 → 범위 → 존재 순서로 검증하고, try-catch로 프로그램이 중단되지 않게 방어한다.
    • 결합 프로그램의 성능은 병목 단계가 정한다. 모듈을 분리해 두면 병목만 교체할 수 있다.
    • 도메인이 바뀌어도 결정 과정은 재사용된다 — 여러분이 얻은 것은 코드가 아니라 설계 절차다.

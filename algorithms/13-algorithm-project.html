마지막 강의에서는 새 알고리즘을 배우지 않습니다. 대신 지금까지 배운 12개 강의의 도구를 앞에 펼쳐 놓고, "이 요구사항에는 어떤 자료구조와 알고리즘을 꺼낼 것인가"를 결정하는 훈련을 합니다. 실제 요구사항을 분석해 정렬(4강) → 이진 탐색(5강) → 해시 집계(3강) → 예외 처리를 하나의 파이프라인으로 결합한 콘솔 상품 관리·분석 프로그램을 완성합니다.

이 강의의 목차

    01강의 소개

    12개 강의를 거치며 여러분의 도구 상자에는 배열, 해시, 정렬, 이진 탐색, 스택, 큐, 재귀, 트리, 그래프, 그리디, DP, 다익스트라가 쌓였습니다. 그런데 실무와 코딩 테스트의 문제는 "삽입 정렬을 구현하시오"처럼 오지 않습니다. "상품을 빨리 찾게 해 주세요. 카테고리별 재고 현황도 보고 싶어요."처럼, 도구 이름이 하나도 등장하지 않는 요구사항으로 옵니다.

    이번 강의의 목표는 요구사항 문장에서 신호를 읽어 어떤 도구를 꺼낼지 스스로 결정하고, 결정한 도구들을 하나의 프로그램으로 결합하는 것입니다. 소재는 콘솔 상품 관리·분석 프로그램 — 데이터 모델 설계부터 정렬, 이진 탐색, HashMap 집계, 잘못된 입력 방어까지 단계별로 쌓아 올립니다. 마지막에는 같은 설계를 새 데이터에 적용하는 최종 프로젝트 재고 관리 시스템 "StockMaster"를 직접 완성합니다.

    02학습 목표

    이 강의를 마치면 다음을 할 수 있습니다.

    • 학생은 요구사항 문장에서 데이터(명사)와 기능(동사)을 찾아 데이터 클래스를 설계할 수 있다.
    • 학생은 요구사항의 신호를 결정 기준 표와 연결해 알맞은 자료구조·알고리즘을 선택하고 이유를 설명할 수 있다.
    • 학생은 정렬(Comparator) → 이진 탐색 → HashMap 집계를 하나의 파이프라인으로 결합한 프로그램을 작성할 수 있다.
    • 학생은 try-catch와 범위 검증으로 잘못된 사용자 입력을 방어해 프로그램이 중단되지 않게 만들 수 있다.
    • 학생은 결합된 프로그램의 단계별 시간 복잡도를 분석하고 병목 단계를 지목할 수 있다.
    • 학생은 같은 설계를 다른 도메인 데이터(도서 관리 등)에 재활용할 수 있다.

    도구 이름이 없는 요구사항 문장에서, 어떤 신호를 읽고 어떤 자료구조·알고리즘을 선택할 것인가?

    05사람이 직접 해결해 보기

    코드를 쓰기 전에, 상품 정보를 적은 카드 8장으로 사장님의 요구를 손으로 처리해 봅니다. 카드에는 코드·이름·카테고리·가격·재고가 적혀 있고, 입고된 순서대로 섞여 있습니다: 2005, 1003, 3010, 1007, 2002, 3001, 1010, 2008.

    요구 1 — "코드를 대면 바로 찾아 주세요"

    STEP 1

    섞인 카드 더미에서 2005번을 찾으려면 한 장씩 넘겨 봐야 합니다. 그래서 먼저 카드를 책상에 펼치고, 왼쪽부터 코드 순서대로 다시 꽂아 정리합니다. 두 번째 카드부터 한 장씩 집어, 이미 정리된 부분의 알맞은 자리에 끼워 넣습니다.

    질문: 방금 한 "집어서 알맞은 자리에 끼워 넣기"는 몇 강의 어떤 알고리즘인가요?

    4강의 삽입 정렬입니다. 앞부분을 정렬된 상태로 유지하며, 새 카드보다 큰 카드를 한 칸씩 뒤로 밀고 빈 자리에 끼워 넣는 과정이 그대로 코드가 됩니다.

    STEP 2

    정렬이 끝났으니 이제 2005번을 찾습니다. 처음부터 넘기지 않고 가운데 카드(2002)를 먼저 봅니다. 2005보다 작으니 왼쪽 절반은 볼 필요가 없습니다. 남은 오른쪽에서 다시 가운데를 보고… 세 번 만에 2005를 찾았습니다.

    질문: 카드가 1,000장이라면 이 방법으로 최대 몇 번 만에 찾을까요?

    약 10번입니다 (2¹⁰ = 1024). 5강 이진 탐색의 절반 버리기 덕분에 데이터가 2배가 되어도 확인 횟수는 1번만 늘어납니다 — O(log n). 단, 정렬되어 있을 때만 쓸 수 있다는 전제가 STEP 1과 연결됩니다.

    요구 2 — "카테고리별 현황을 보여 주세요"

    STEP 3

    책상 한쪽에 "전자", "생활", "잡화"라고 적은 메모지 3장을 붙이고, 카드를 한 장씩 보며 해당 메모지 아래에 바를 정(正)자로 개수를 세고 가격 × 재고를 더해 적습니다. 카드를 한 바퀴만 돌면 집계가 끝납니다.

    질문: "메모지 이름표 → 적어 둔 숫자"에 해당하는 자료구조는 무엇인가요?

    3강의 HashMap입니다. 카테고리 이름이 키(key), 개수·누적 금액이 값(value)입니다. 이름표를 찾는 데 걸리는 시간이 평균 O(1)이라, 전체 집계는 카드 수에 비례하는 O(n)입니다.

    요구 3 — "잘못 입력해도 꺼지면 안 돼요"

    STEP 4

    아르바이트생이 "20A5번 찾아 주세요"라고 말합니다. 여러분은 당황해서 일을 멈추는 대신, "그런 코드는 없어요. 다시 확인해 주세요"라고 답하고 다음 요청을 계속 받습니다.

    질문: 프로그램이 사람처럼 "멈추지 않고 알려 주게" 만드는 Java 도구는 무엇인가요?

    예외 처리(try-catch)입니다. Integer.parseInt("20A5")는 NumberFormatException을 던지는데, 이를 catch에서 받아 안내 메시지를 출력하면 프로그램은 죽지 않고 다음 요청으로 넘어갑니다. 검증 순서는 형식(숫자인가) → 범위(양수인가) → 존재(등록된 코드인가)입니다.

    • 질문 1 — 무엇을 가장 자주 하는가? 검색이 잦으면 검색이 싼 구조(정렬+이진 탐색, HashMap)를, 삽입·삭제가 잦으면 그 연산이 싼 구조를 고릅니다.
    • 질문 2 — 데이터에 규칙이 있는가? 고유 키가 있으면 해시나 정렬+이진 탐색이 가능하고, 이미 정렬돼 있다면 정렬 비용을 아낄 수 있습니다.
    • 질문 3 — 어떤 비정상 입력이 오는가? 사용자 입력이 있다면 형식 → 범위 → 존재 순서의 검증과 예외 처리가 반드시 설계에 포함되어야 합니다.

    개념 3 — 우리 프로그램의 결정 과정

    요구사항들린 신호결정
    코드로 바로 검색"고유 번호 + 자주 찾는다"코드 순 정렬(4강) 후 이진 탐색(5강) — 정렬은 시작할 때 1번, 검색은 매번 O(log n)
    카테고리별 현황"이름(키)별로 세기·누적"HashMap(3강) 집계 — 한 바퀴 순회로 O(n)
    재고 부족 알림"조건에 맞는 것 골라내기"리스트 조건 검색(2강) — O(n)
    잘못된 입력에도 계속 동작"사용자 입력 = 신뢰 불가"try-catch + 범위 검증 — 형식·범위·존재 3단계 방어

    이렇게 결정된 처리 순서가 곧 프로그램의 파이프라인입니다: 데이터 로드 → 코드 순 정렬 → 검색 요청 처리(예외 방어) → 카테고리 집계 → 재고 경고. 정렬을 맨 앞에 두는 이유는, 뒤의 모든 이진 탐색이 정렬을 전제로 하기 때문입니다.

    HashMap이 있는데 왜 정렬+이진 탐색도 쓰나요?

    코드 → 상품 검색만 보면 HashMap<Integer, Product>도 평균 O(1)로 훌륭한 선택입니다. 하지만 이 프로그램은 코드 순 목록 출력도 요구하므로 어차피 정렬이 필요하고, 정렬된 리스트가 있으면 이진 탐색은 추가 메모리 없이 따라옵니다. "범위 검색(코드 2000번대만)" 같은 확장에도 정렬된 리스트가 유리합니다. 같은 요구라도 함께 있는 다른 요구에 따라 최선의 도구가 달라진다 — 이것이 설계입니다.

    07단계별 동작 과정

    파이프라인 전체가 실제 상품 데이터로 움직이는 모습을 단계별로 확인해 봅시다. 다음 단계 ▶ 버튼으로 한 단계씩 진행하세요. 정렬 중 끼워 넣는 카드와 탐색 중 확인하는 칸은 파란색(현재) 또는 앰버색(비교), 확정된 부분은 초록색(완료)으로 표시됩니다. "새 데이터" 버튼을 누르면 입고 순서와 검색 대상이 바뀝니다.

        HandleRequest(products, r)                  // 5강 + 예외 방어
    카테고리별 상품 수와 재고 자산을 HashMap으로 집계한다   // 3강 — 한 바퀴 순회
    재고가 기준(5개) 미만인 상품을 골라 경고한다     // 2강 — 조건 검색
    Pseudo 요청 1건 처리 — HandleRequest 
    알고리즘 HandleRequest(sorted, rawInput)
    시도:
        code ← rawInput을 정수로 변환               // 1) 형식 검증 — 실패하면 아래 "변환 실패"로
        만약 code ≤ 0 이면:                          // 2) 범위 검증
            "1 이상의 정수여야 합니다" 출력하고 종료
        result ← BinarySearch(sorted, code)          // 3) 존재 확인 — O(log n)
        만약 result가 없음이면: "미등록 코드" 출력
        아니면: result의 요약 출력
    변환 실패 시:
        "숫자가 아닙니다" 출력                        // 프로그램은 멈추지 않고 계속된다

        products.add(new Product(2008, "웹캠", "전자", 45000, 4));

    /**
     * 삽입 정렬(4강) — 정렬 기준을 Comparator로 받아서
     * "코드 순", "가격 순" 등 어떤 기준으로도 같은 코드를 재사용한다.
     */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);   // 이번에 제자리를 찾아줄 상품
            int j = i - 1;
            // key보다 "뒤에 와야 하는" 상품을 한 칸씩 뒤로 민다
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
            }
            list.set(j + 1, key);        // 비게 된 자리에 key를 넣는다
        }
    }

        List<Product> products = loadProducts();

        // 기준 1: 상품 코드 오름차순 — 이진 탐색(5강)을 쓰기 위한 준비
        insertionSort(products, (a, b) -> a.code - b.code);

        insertionSort(products, (a, b) -> b.price - a.price);
        System.out.println("[정렬 2] 가격 내림차순 — 비싼 상품부터 보고서");
        for (Product p : products) {
            System.out.println("  " + p.summary());
        }
    }

        products.add(new Product(2008, "웹캠", "전자", 45000, 4));
        return products;
    }

    /** 삽입 정렬(4강) — Step2와 같은 코드 */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** 마지막 탐색의 비교 횟수 (1강의 연산 카운터 기법) */
    static int compareCount = 0;

    /**
     * 이진 탐색(5강) — 코드 오름차순으로 정렬된 리스트에서만 동작한다!
     * 찾으면 해당 Product, 없으면 null을 반환한다.
     */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        compareCount = 0;
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;      // 남은 범위의 가운데
            compareCount++;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);      // 발견!
            }
            if (midCode < targetCode) {
                low = mid + 1;               // 왼쪽 절반 버리기
            } else {
                high = mid - 1;              // 오른쪽 절반 버리기
            }
        }
        return null;                          // 범위가 사라짐 = 없음
    }

    public static void main(String[] args) {
        List<Product> products = loadProducts();

        // 이진 탐색의 전제 조건: 반드시 먼저 코드 순으로 정렬한다 (Step2의 도구 재사용)
        insertionSort(products, (a, b) -> a.code - b.code);

        int[] targets = {2005, 3010, 1500};
        for (int code : targets) {
            Product found = binarySearchByCode(products, code);
            if (found != null) {
                System.out.println("코드 " + code + " 검색: " + found.summary()
                        + "  (비교 " + compareCount + "번)");
            } else {
                System.out.println("코드 " + code + " 검색: 없음  (비교 " + compareCount + "번)");
            }
        }

        System.out.println();
        System.out.println("상품 8개에서 최대 비교 4번 — 순차 탐색(최악 8번)의 절반 이하다.");
        System.out.println("상품이 1,000개라면? 이진 탐색 최대 10번 vs 순차 탐색 최대 1,000번.");
    }
}

            valueByCategory.put(p.category,
                    valueByCategory.get(p.category) + (long) p.price * p.stock);
        }

        System.out.println("[카테고리별 집계] — 배열 순회(2강) + HashMap(3강)");
        long totalValue = 0;
        for (String category : categoryOrder) {
            long value = valueByCategory.get(category);
            totalValue += value;
            System.out.println("  " + category + " : 상품 " + countByCategory.get(category)
                    + "종 | 재고 자산 " + value + "원");
        }
        System.out.println("  전체 재고 자산: " + totalValue + "원");

        System.out.println();

        // 조건 검색(2강): 재고가 5개 미만인 상품 = 발주가 필요한 상품
        System.out.println("[재고 부족 경고] — 재고 5개 미만");
        int warningCount = 0;
        for (Product p : products) {
            if (p.stock < 5) {
                warningCount++;
                System.out.println("  " + p.summary());
            }
        }
        System.out.println("  경고 대상: " + warningCount + "종");
    }

    10완성 Java 코드

    네 모듈을 로드 → 정렬 → 검색 요청 처리 → 집계 → 경고 파이프라인으로 연결합니다. 새로 추가되는 것은 handleSearchRequest 하나 — 문자열 입력을 형식(숫자인가) → 범위(양수인가) → 존재(등록된 코드인가) 3단계로 검증하며, 어떤 잘못된 입력에도 프로그램이 멈추지 않게 합니다. 검색 요청 시나리오에는 정상 코드 2건, 미등록 코드, 숫자 아닌 입력, 음수를 모두 넣었습니다.

    Java ProductManagerComplete.java 
    import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 콘솔 상품 관리·분석 프로그램 — 완성판.
 * Step1(데이터 모델) + Step2(정렬) + Step3(이진 탐색) + Step4(집계)에
 * "잘못된 입력 방어(예외 처리)"를 더해 하나의 프로그램으로 통합한다.
 *
 * 처리 파이프라인: 데이터 로드 → 코드 순 정렬 → 검색 요청 처리 → 카테고리 집계 → 재고 경고
 */
public class ProductManagerComplete {

    /** 상품 1개의 정보를 담는 데이터 클래스 */
    static class Product {
        int code;
        String name;
        String category;
        int price;
        int stock;

        Product(int code, String name, String category, int price, int stock) {
            this.code = code;
            this.name = name;
            this.category = category;
            this.price = price;
            this.stock = stock;
        }

        String summary() {
            return "[" + code + "] " + name + " | " + category
                    + " | " + price + "원 | 재고 " + stock + "개";
        }
    }

    /** 입고 순서 그대로의 상품 8개 */
    static List<Product> loadProducts() {
        List<Product> products = new ArrayList<>();
        products.add(new Product(2005, "유선 키보드", "전자", 23000, 12));
        products.add(new Product(1003, "무선 마우스", "전자", 18000, 25));
        products.add(new Product(3010, "머그컵", "생활", 7000, 2));
        products.add(new Product(1007, "마우스 패드", "잡화", 4000, 18));
        products.add(new Product(2002, "USB 메모리", "전자", 9000, 5));
        products.add(new Product(3001, "텀블러", "생활", 12000, 30));
        products.add(new Product(1010, "노트북 파우치", "잡화", 15000, 3));
        products.add(new Product(2008, "웹캠", "전자", 45000, 4));
        return products;
    }

    /** 삽입 정렬(4강) — Comparator로 기준을 갈아 끼운다 */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** 이진 탐색(5강) — 코드 오름차순 정렬이 전제 조건 */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);
            }
            if (midCode < targetCode) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return null;
    }

    /**
     * 검색 요청 1건 처리 — 잘못된 입력을 예외 처리로 방어한다.
     * 사용자가 입력한 문자열은 숫자가 아닐 수도, 음수일 수도, 없는 코드일 수도 있다.
     */
    static void handleSearchRequest(List<Product> sorted, String rawInput) {
        System.out.println("검색 요청 \"" + rawInput + "\"");
        try {
            int code = Integer.parseInt(rawInput.trim()); // 숫자가 아니면 NumberFormatException
            if (code <= 0) {
                System.out.println("  → 오류: 상품 코드는 1 이상의 정수여야 합니다.");
                return;
            }
            Product found = binarySearchByCode(sorted, code);
            if (found != null) {
                System.out.println("  → " + found.summary());
            } else {
                System.out.println("  → 코드 " + code + " 상품 없음 (미등록 코드)");
            }
        } catch (NumberFormatException e) {
            // 프로그램을 멈추지 않고, 문제를 알린 뒤 다음 요청으로 넘어간다
            System.out.println("  → 오류: \"" + rawInput + "\"은(는) 숫자가 아닙니다.");
        }
    }

    /** 카테고리별 집계(3강 HashMap) + 재고 경고(2강 조건 검색) */
    static void printReport(List<Product> products) {
        Map<String, Integer> countByCategory = new HashMap<>();
        Map<String, Long> valueByCategory = new HashMap<>();
        List<String> categoryOrder = new ArrayList<>(); // 출력 순서 고정용

        for (Product p : products) {
            if (!countByCategory.containsKey(p.category)) {
                categoryOrder.add(p.category);
                countByCategory.put(p.category, 0);
                valueByCategory.put(p.category, 0L);
            }
            countByCategory.put(p.category, countByCategory.get(p.category) + 1);
            valueByCategory.put(p.category,
                    valueByCategory.get(p.category) + (long) p.price * p.stock);
        }

        System.out.println("== 3. 카테고리별 집계 ==");
        long totalValue = 0;
        for (String category : categoryOrder) {
            long value = valueByCategory.get(category);
            totalValue += value;
            System.out.println("  " + category + " : 상품 " + countByCategory.get(category)
                    + "종 | 재고 자산 " + value + "원");
        }
        System.out.println("  전체 재고 자산: " + totalValue + "원");

        System.out.println();
        System.out.println("== 4. 재고 부족 경고 (5개 미만) ==");
        int warningCount = 0;
        for (Product p : products) {
            if (p.stock < 5) {
                warningCount++;
                System.out.println("  " + p.summary());
            }
        }
        System.out.println("  경고 대상: " + warningCount + "종");
    }

    public static void main(String[] args) {
        // 1) 데이터 로드 (Step1)
        List<Product> products = loadProducts();
        System.out.println("== 1. 상품 " + products.size() + "종 로드 → 코드 순 정렬 ==");

        // 2) 코드 오름차순 정렬 (Step2) — 이후 모든 검색의 기반
        insertionSort(products, (a, b) -> a.code - b.code);
        for (Product p : products) {
            System.out.println("  " + p.summary());
        }

        System.out.println();
        System.out.println("== 2. 검색 요청 처리 (이진 탐색 + 예외 처리) ==");
        // 실제 서비스라면 Scanner로 받을 입력 — 여기서는 시나리오로 고정한다
        String[] requests = {"2005", "3010", "1500", "20A5", "-7"};
        for (String request : requests) {
            handleSearchRequest(products, request);
        }

        System.out.println();
        // 3) + 4) 집계와 경고 (Step4)
        printReport(products);
    }
}

    import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

/**
 * 처리 과정 추적 — 완성 프로그램의 핵심 두 단계(정렬, 이진 탐색)가
 * 내부에서 어떻게 움직이는지 회차별 상태를 출력한다.
 * 시각화(7번 섹션)와 똑같이 동작하는지 눈으로 확인하는 것이 목적이다.
 */
public class ProductManagerTrace {

    /** 상품 1개의 정보를 담는 데이터 클래스 */
    static class Product {
        int code;
        String name;
        String category;
        int price;

        Product(int code, String name, String category, int price, int stock) {
            this.code = code;
            this.name = name;
            this.category = category;
            this.price = price;
            this.stock = stock;

    static List<Product> loadProducts() {
        List<Product> products = new ArrayList<>();
        products.add(new Product(2005, "유선 키보드", "전자", 23000, 12));
        products.add(new Product(1003, "무선 마우스", "전자", 18000, 25));
        products.add(new Product(3010, "머그컵", "생활", 7000, 2));
        products.add(new Product(1007, "마우스 패드", "잡화", 4000, 18));
        products.add(new Product(2002, "USB 메모리", "전자", 9000, 5));
        products.add(new Product(3001, "텀블러", "생활", 12000, 30));
        products.add(new Product(1010, "노트북 파우치", "잡화", 15000, 3));
        products.add(new Product(2008, "웹캠", "전자", 45000, 4));
        return products;
    }

    /** 리스트의 상품 코드만 한 줄로 만든다 (추적 출력용) */
    static String codeLine(List<Product> list) {
        StringBuilder sb = new StringBuilder("[");
        for (int i = 0; i < list.size(); i++) {
            if (i > 0) sb.append(", ");
            sb.append(list.get(i).code);
        }
        return sb.append("]").toString();
    }

    /** 삽입 정렬 — 회차(i)마다 밀어낸 칸 수와 배열 상태를 출력한다 */
    static void insertionSortTrace(List<Product> list, Comparator<Product> comparator) {
        System.out.println("[1] 삽입 정렬 추적 (기준: 코드 오름차순)");
        System.out.println("  시작       " + codeLine(list));
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            int shiftCount = 0;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
                shiftCount++;
            }
            list.set(j + 1, key);
            System.out.println("  i=" + i + " key=" + key.code
                    + " → " + shiftCount + "칸 밀고 " + (j + 1) + "번 자리에 삽입 "
                    + codeLine(list));
        }
    }

    /** 이진 탐색 — 회차마다 low/mid/high와 판단 결과를 출력한다 */
    static void binarySearchTrace(List<Product> sorted, int targetCode) {
        System.out.println("[2] 이진 탐색 추적 (목표: 코드 " + targetCode + ")");
        int low = 0;
        int high = sorted.size() - 1;
        int round = 0;
        while (low <= high) {
            round++;
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            System.out.print("  " + round + "회차: low=" + low + " high=" + high
                    + " mid=" + mid + " → 코드 " + midCode);
            if (midCode == targetCode) {
                System.out.println(" == " + targetCode + " → 발견! ("
                        + sorted.get(mid).name + ", 비교 " + round + "번)");
                return;
            }
            if (midCode < targetCode) {
                System.out.println(" < " + targetCode + " → 왼쪽 절반 버림 (low=" + (mid + 1) + ")");
                low = mid + 1;
            } else {
                System.out.println(" > " + targetCode + " → 오른쪽 절반 버림 (high=" + (mid - 1) + ")");
                high = mid - 1;
            }
        }
        System.out.println("  범위가 사라짐(low > high) → 코드 " + targetCode + " 없음 (비교 " + round + "번)");
    }

    public static void main(String[] args) {
        List<Product> products = loadProducts();

        insertionSortTrace(products, (a, b) -> a.code - b.code);

        System.out.println();
        binarySearchTrace(products, 2005);   // 있는 코드

        System.out.println();
        binarySearchTrace(products, 1500);   // 없는 코드
    }
}

  3회차: low=2 high=2 mid=2 → 코드 1010 < 1500 → 왼쪽 절반 버림 (low=3)
  범위가 사라짐(low > high) → 코드 1500 없음 (비교 3번)

    정렬 추적의 i=6 회차를 보세요. key 1010이 4칸이나 밀고 들어갑니다 — 삽입 정렬이 O(n²)인 이유가 이 "밀기"에 있습니다. 이진 탐색 추적에서는 8개 중 3번의 비교로 2005를 찾았고, 없는 코드 1500도 3번 만에 "없음"을 확정했습니다. 손 풀이(5번 섹션) = 시각화(7번 섹션) = 코드가 같은 절차임을 확인했습니다.

    static Product binarySearchByCode(List<Product> list, int targetCode) {

    13복잡도 및 특성 분석

    입력 크기

    상품 수 n(예제에서는 8), 검색 요청 수 q(예제에서는 5), 카테고리 수 k(예제에서는 3)를 기준으로 분석합니다.

    단계별 시간 복잡도

    파이프라인 단계주요 연산시간 복잡도실행 횟수
    1. 데이터 로드리스트에 추가O(n)시작할 때 1번
    2. 코드 순 정렬 (삽입 정렬)비교·이동O(n²) (최선 O(n))시작할 때 1번
    3. 검색 요청 처리 (이진 탐색)비교O(log n) / 1건요청마다 — 총 O(q log n)
    4. 카테고리 집계 (HashMap)get·putO(n) (연산당 평균 O(1))보고서마다 1번
    5. 재고 경고 (조건 검색)비교O(n)보고서마다 1번

    결합 프로그램의 특성

    • 정렬 비용은 선불, 탐색 이득은 매번: O(n²) 정렬을 시작할 때 1번 치르면, 이후 모든 검색이 O(log n)이 됩니다. 검색이 잦을수록(q가 클수록) 이 선택이 유리합니다. 매번 순차 탐색하면 총 O(q·n) — n=1,000, q=10,000이면 천만 번 비교입니다.
    • 병목은 가장 느린 단계: 이 프로그램의 병목은 정렬 O(n²)입니다. 상품이 수만 개로 늘면 삽입 정렬 대신 O(n log n) 정렬(병합 정렬 계열)로 교체해야 하며, 모듈을 분리해 둔 덕분에 insertionSort 메서드만 바꾸면 됩니다.
    • 예외 처리는 복잡도가 아니라 정확성의 문제: try-catch는 실행 횟수를 거의 바꾸지 않지만, 이것이 없으면 프로그램은 "빠르지만 언제든 죽는" 상태가 됩니다. 1강의 원칙 그대로 — 정확성(견고함) 먼저, 효율성 다음입니다.

    공간 복잡도

    상품 리스트 O(n) 외에 집계용 HashMap과 순서 리스트가 O(k)를 사용합니다. 정렬은 리스트 안에서 자리만 바꾸므로(제자리 정렬) 추가 공간 O(1), 이진 탐색도 변수 세 개(low·mid·high)만 쓰므로 O(1)입니다.

    Java ProductManagerApplication.java 
    import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 같은 설계를 다른 도메인에 재활용하기 — 학교 도서실 도서 관리.
 * "고유 번호가 있는 데이터 + 검색이 잦음 + 분류별 집계"라는 요구사항 패턴이 같으므로,
 * 상품 관리에서 내린 결정(정렬 → 이진 탐색, HashMap 집계)을 그대로 다시 쓴다.
 * 바뀐 것은 데이터 클래스(Product → Book)뿐이다.
 */
public class ProductManagerApplication {

    /** 도서 1권의 정보 — Product와 구조가 같다 (고유 번호, 이름, 분류, 수량) */
    static class Book {
        int id;          // 등록 번호 (고유한 값 — 검색의 기준)
        String title;    // 제목
        String genre;    // 장르 (분류의 기준)
        int copies;      // 대출 가능 권수 (경고의 기준)

        Book(int id, String title, String genre, int copies) {
            this.id = id;
            this.title = title;
            this.genre = genre;
            this.copies = copies;
        }

        String summary() {
            return "[" + id + "] " + title + " | " + genre + " | 대출 가능 " + copies + "권";
        }
    }

    /** 기증받은 순서 그대로의 도서 6권 */
    static List<Book> loadBooks() {
        List<Book> books = new ArrayList<>();
        books.add(new Book(5023, "이펙티브 자바", "IT", 2));
        books.add(new Book(1101, "데미안", "소설", 1));
        books.add(new Book(3402, "코스모스", "과학", 4));
        books.add(new Book(2205, "1984", "소설", 0));
        books.add(new Book(4310, "클린 코드", "IT", 3));
        books.add(new Book(1508, "어린 왕자", "소설", 5));
        return books;
    }

    /** 삽입 정렬(4강) — 상품 관리와 같은 알고리즘, 타입만 Book */
    static void insertionSort(List<Book> list, Comparator<Book> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Book key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** 이진 탐색(5강) — 등록 번호 오름차순 정렬이 전제 조건 */
    static Book binarySearchById(List<Book> sorted, int targetId) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midId = sorted.get(mid).id;
            if (midId == targetId) {
                return sorted.get(mid);
            }
            if (midId < targetId) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return null;
    }

    public static void main(String[] args) {

        // 결정 1: 검색이 잦다 → 등록 번호 순 정렬 + 이진 탐색
        insertionSort(books, (a, b) -> a.id - b.id);

        for (Book b : books) {

        String[] requests = {"2205", "9999", "일구팔사"};

            System.out.println("검색 요청 \"" + request + "\"");

                Book found = binarySearchById(books, id);
                if (found != null) {
                    System.out.println("  → " + found.summary());
                } else {
                    System.out.println("  → 번호 " + id + " 도서 없음");
                }

    문제 배경

    지하철역 앞 무인 편의점을 운영하는 스타트업에 여러분이 합류했습니다. 무인 매장이라 관리자가 상주하지 않기 때문에, 본사에서 콘솔 프로그램으로 재고를 관리합니다. 지금은 엑셀 파일을 눈으로 훑는 방식이라, 상품 하나를 찾는 데도 한참 걸리고 재고가 바닥난 것을 손님 항의 전화로 알게 되는 일까지 있었습니다. 팀장이 여러분에게 첫 업무를 맡겼습니다. "이번 강의에서 만든 상품 관리 파이프라인 그대로면 돼요. 단, 우리 매장 상품 데이터로요. 그리고 키오스크에서 별별 입력이 다 들어오니 방어는 확실하게." 여러분은 배운 도구만으로 이 프로그램을 완성해야 합니다.

    4. printCategoryReport(List<Product>) — HashMap으로 카테고리별 상품 수와 재고 자산(가격 × 재고의 합)을 집계하고, 카테고리가 처음 등장한 순서로 출력한 뒤 전체 재고 자산을 출력한다.
    5. printLowStockWarning(List<Product>) — 재고 5개 미만 상품을 모두 출력하고 경고 대상 수를 출력한다.

    Java StockMasterSolution.java 
    import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * 최종 프로그램 문제 — 편의점 재고 관리 시스템 "StockMaster" 정답 코드.
 * 파이프라인: 데이터 로드 → 코드 순 정렬(4강) → 검색 요청 처리(5강 + 예외 방어)
 *            → 카테고리 집계(3강) → 재고 경고(2강)
 */
public class StockMasterSolution {

    /** 상품 1개의 정보를 담는 데이터 클래스 */
    static class Product {
        int code;
        String name;
        String category;
        int price;
        int stock;

        Product(int code, String name, String category, int price, int stock) {
            this.code = code;
            this.name = name;
            this.category = category;
            this.price = price;
            this.stock = stock;
        }

        String summary() {
            return "[" + code + "] " + name + " | " + category
                    + " | " + price + "원 | 재고 " + stock + "개";
        }
    }

    /** 편의점 상품 8종 */
    static List<Product> loadProducts() {
        List<Product> products = new ArrayList<>();
        products.add(new Product(5501, "블루투스 스피커", "전자", 52000, 6));
        products.add(new Product(1203, "게이밍 마우스", "전자", 35000, 2));
        products.add(new Product(7010, "보온 도시락", "생활", 21000, 15));
        products.add(new Product(3305, "무선 충전기", "전자", 28000, 9));
        products.add(new Product(2101, "여행용 파우치", "잡화", 13000, 4));
        products.add(new Product(8804, "스테인리스 텀블러", "생활", 16000, 22));
        products.add(new Product(4409, "휴대용 선풍기", "생활", 19000, 3));
        products.add(new Product(6607, "가죽 키링", "잡화", 8000, 11));
        return products;
    }

    /** [요구사항 1] 삽입 정렬 — 기준은 Comparator로 받는다 (4강) */
    static void insertionSort(List<Product> list, Comparator<Product> comparator) {
        for (int i = 1; i < list.size(); i++) {
            Product key = list.get(i);
            int j = i - 1;
            while (j >= 0 && comparator.compare(list.get(j), key) > 0) {
                list.set(j + 1, list.get(j));   // key보다 뒤에 와야 하는 원소를 뒤로 민다
                j--;
            }
            list.set(j + 1, key);
        }
    }

    /** [요구사항 2] 이진 탐색 — 찾으면 Product, 없으면 null (5강) */
    static Product binarySearchByCode(List<Product> sorted, int targetCode) {
        int low = 0;
        int high = sorted.size() - 1;
        while (low <= high) {
            int mid = (low + high) / 2;
            int midCode = sorted.get(mid).code;
            if (midCode == targetCode) {
                return sorted.get(mid);
            }
            if (midCode < targetCode) {
                low = mid + 1;    // 왼쪽 절반 버리기
            } else {
                high = mid - 1;   // 오른쪽 절반 버리기
            }
        }
        return null;
    }

    /** [요구사항 3] 검색 요청 1건 처리 — 잘못된 입력에도 멈추지 않는다 */
    static void handleSearchRequest(List<Product> sorted, String rawInput) {
        System.out.println("검색 요청 \"" + rawInput + "\"");
        try {
            int code = Integer.parseInt(rawInput.trim());
            if (code <= 0) {
                System.out.println("  → 오류: 상품 코드는 1 이상의 정수여야 합니다.");
                return;
            }
            Product found = binarySearchByCode(sorted, code);
            if (found != null) {
                System.out.println("  → " + found.summary());
            } else {
                System.out.println("  → 코드 " + code + " 상품 없음 (미등록 코드)");
            }
        } catch (NumberFormatException e) {
            System.out.println("  → 오류: \"" + rawInput + "\"은(는) 숫자가 아닙니다.");
        }
    }

    /** [요구사항 4] 카테고리별 상품 수와 재고 자산(가격 × 재고 합계) 집계 (3강) */
    static void printCategoryReport(List<Product> products) {
        Map<String, Integer> countByCategory = new HashMap<>();
        Map<String, Long> valueByCategory = new HashMap<>();
        List<String> categoryOrder = new ArrayList<>();   // 처음 등장한 순서 = 출력 순서

        for (Product p : products) {
            if (!countByCategory.containsKey(p.category)) {
                categoryOrder.add(p.category);
                countByCategory.put(p.category, 0);
                valueByCategory.put(p.category, 0L);
            }
            countByCategory.put(p.category, countByCategory.get(p.category) + 1);
            valueByCategory.put(p.category,
                    valueByCategory.get(p.category) + (long) p.price * p.stock);
        }

        System.out.println("== 3. 카테고리별 집계 ==");
        long totalValue = 0;
        for (String category : categoryOrder) {
            long value = valueByCategory.get(category);
            totalValue += value;
            System.out.println("  " + category + " : 상품 " + countByCategory.get(category)
                    + "종 | 재고 자산 " + value + "원");
        }
        System.out.println("  전체 재고 자산: " + totalValue + "원");
    }

    /** [요구사항 5] 재고 부족 경고 — 재고 5개 미만 상품 출력 (2강) */
    static void printLowStockWarning(List<Product> products) {
        System.out.println("== 4. 재고 부족 경고 (5개 미만) ==");
        int warningCount = 0;
        for (Product p : products) {
            if (p.stock < 5) {
                warningCount++;
                System.out.println("  " + p.summary());
            }
        }
        System.out.println("  경고 대상: " + warningCount + "종");
    }

    public static void main(String[] args) {
        List<Product> products = loadProducts();

        System.out.println("== 1. 상품 " + products.size() + "종 로드 → 코드 순 정렬 ==");
        insertionSort(products, (a, b) -> a.code - b.code);
        for (Product p : products) {
            System.out.println("  " + p.summary());
        }

        System.out.println();
        System.out.println("== 2. 검색 요청 처리 (이진 탐색 + 예외 처리) ==");
        String[] requests = {"5501", "1203", "9999", "12O3", "-100"};
        for (String request : requests) {
            handleSearchRequest(products, request);
        }

        System.out.println();
        printCategoryReport(products);

        System.out.println();
        printLowStockWarning(products);
    }
}

    구현 순서와 핵심 알고리즘 적용 부분

    1. insertionSort (TODO 1): 4강의 삽입 정렬에 Comparator를 결합했습니다. comparator.compare(list.get(j), key) > 0이 "앞 원소가 key보다 뒤에 와야 한다"는 뜻 — 이 조건이 참인 동안 한 칸씩 밀고, 거짓이 되는 순간 그 자리에 삽입합니다.
    2. binarySearchByCode (TODO 2): 5강의 이진 탐색 그대로입니다. low <= high가 반복 조건이라는 것(등호 포함!)과, 버릴 때 mid + 1 / mid - 1로 mid 자신을 제외하는 것이 핵심입니다.
    3. handleSearchRequest (TODO 3): 검증 3단계의 순서가 중요합니다. 형식(parseInt) → 범위(양수) → 존재(이진 탐색). 형식 검증을 통과해야 숫자 비교가 가능하므로 이 순서는 뒤바꿀 수 없습니다. "-100"은 parseInt에 성공하므로 catch가 아니라 범위 검사에서 걸립니다.
    4. printCategoryReport (TODO 4): HashMap 두 개(개수·자산)와 등장 순서 리스트 하나를 함께 관리합니다. 자산 누적은 (long) p.price * p.stock — int 곱셈 오버플로를 막는 캐스팅은 1강에서 배운 함정 대비책입니다.
    5. printLowStockWarning (TODO 5): 2강의 조건 검색에 카운터를 더한 구조입니다.

    복잡도 분석

    • 정렬 O(n²) 1번 + 검색 O(log n) × 5건 + 집계 O(n) + 경고 O(n). n=8이므로 전체 수십 번의 연산.
    • 상품이 10,000개로 늘면 병목은 삽입 정렬(약 5천만 번 비교)입니다. 이때는 O(n log n) 정렬로 교체하되, 나머지 파이프라인은 그대로 둡니다 — 모듈 분리의 이득입니다.
    • 공간은 상품 리스트 O(n) + 집계 구조 O(k), 정렬·탐색 자체는 O(1)입니다.

    자주 발생하는 오류

    • 정렬 전에 binarySearchByCode를 호출해 있는 상품을 "없음"으로 판정 (오류 1 참고).
    • while (low < high)로 써서 마지막 남은 한 칸을 검사하지 않아, 양 끝 경계 코드(1203, 8804)를 놓치는 경우.
    • try-catch 없이 제출해 "12O3"에서 프로그램이 죽는 경우 (오류 2 참고).
    • 범위 검증(code <= 0)을 catch 블록 안에 두는 경우 — "-100"은 예외를 던지지 않으므로 검증이 실행되지 않습니다.
    • 자산 집계를 int로 해서 상품 수·가격이 커지면 오버플로가 나는 경우.

    다른 해결 방법

    검색만 놓고 보면 HashMap<Integer, Product>로 평균 O(1) 검색이 가능합니다. 다만 이 문제는 "코드 순 목록 출력"이 함께 요구되어 정렬이 어차피 필요하므로, 정렬 리스트 + 이진 탐색이 추가 메모리 없이 두 요구를 모두 해결합니다. 상품 추가·삭제가 잦은 시스템이라면 8강의 이진 탐색 트리(균형 트리)가 "정렬 유지 + O(log n) 검색·삽입"을 동시에 주는 대안이 됩니다.

    19오늘의 핵심 정리

    • 실전 문제는 도구 이름 없이 요구사항 문장으로 온다. 명사에서 데이터 모델을, 동사에서 기능을, 신호 문장에서 자료구조·알고리즘을 찾는다.
    • 도구 선택의 세 질문: 무엇을 가장 자주 하는가 · 데이터에 규칙이 있는가 · 어떤 비정상 입력이 오는가.
    • 알고리즘은 파이프라인으로 결합된다: 정렬(선불 비용 1번) → 이진 탐색(매번 O(log n)) → HashMap 집계(O(n)) → 조건 검색(O(n)). 순서가 정확성을 좌우한다 — 정렬 없는 이진 탐색은 조용히 틀린다.
    • 사용자 입력은 신뢰할 수 없다. 형식 → 범위 → 존재 순서로 검증하고, try-catch로 프로그램이 중단되지 않게 방어한다.
    • 결합 프로그램의 성능은 병목 단계가 정한다. 모듈을 분리해 두면 병목만 교체할 수 있다.
    • 도메인이 바뀌어도 결정 과정은 재사용된다 — 여러분이 얻은 것은 코드가 아니라 설계 절차다.

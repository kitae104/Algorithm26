# 시각화 모션 개선과 본문 강조 강화 설계

작성일: 2026-07-30

## 1. 배경

랜딩 페이지와 13개 강의 페이지의 애니메이션이 뻣뻣하고, 강의의 결론부가 시각적으로 드러나지 않는다.
코드를 조사해 확인한 사실은 다음과 같다.

| 사실 | 근거 |
|---|---|
| 프로젝트 전체에 `@keyframes`가 하나도 없다 | `assets/css/*.css` 전수 검색 |
| 이징이 전부 기본 `ease`다 | 전환 선언 9곳 모두 |
| **`AlgoViz.renderStep()`이 매 단계 무대 DOM을 파괴·재생성한다** | `visualization.js:338` `stage.textContent = ""` |
| 그래서 `.viz-cell`의 전환이 발동하지 않는다 | 새 노드는 상태 클래스를 생성 시점에 갖고 태어나므로 전환 시작값이 없다 |
| 랜딩 히어로 막대는 DOM이 유지되어 높이 전환은 실제로 작동한다 | `landing.js:222` `renderFrame()`이 기존 노드를 갱신 |
| 랜딩 히어로는 자동 재생을 멈출 수단이 없다 | `landing.js:241` `setInterval` 무한 반복, 컨트롤 없음 |
| 스크롤 진입 애니메이션이 없다 | `IntersectionObserver`는 목차 활성화에만 쓰인다 (`common.js:187`) |
| 강의 결론부인 "오늘의 핵심 정리"가 아무 장식 없는 `<ul>`이다 | 13개 강의 `#sec-summary` |
| `note-box`가 138곳에 쓰이는데 위계 구분이 약하다 | `--tip` 30곳, `--warn` 18곳, `--danger` 0곳 |
| `inline-array` CSS 40줄이 사용 0건인 죽은 코드다 | `lesson.css:259-298`, 전 프로젝트 검색 결과 0 |
| `viz-legend`는 죽은 코드가 아니다 | `visualization.js:276`이 동적 생성 |

시각화는 13개 강의에 총 16개 있고, `array` 그룹이 지배적(22곳)이다.

## 2. 목표와 비목표

**목표**

- 시각화의 단계 전환을 하드컷에서 의미 있는 모션으로 바꾼다
- 랜딩 히어로를 재설계하고 재생 제어 수단을 제공한다
- 강의의 주요 내용을 훑어보기 쉽게 강조한다

**비목표**

- 강의 본문 텍스트를 새로 쓰지 않는다
- 16개 시각화의 `makeSteps` 알고리즘 코드를 고치지 않는다
- 빌드 도구를 도입하지 않는다

## 3. 결정 사항

세 가지를 사용자와 확정했다.

1. **범위** — 엔진 구조 개선 + 랜딩 히어로 재설계 + 스크롤 진입 + 강조 컴포넌트 전면
2. **모션 성격** — 의미 있는 모션. 모든 움직임이 알고리즘의 사실을 전달하고, 장식용 움직임은 넣지 않는다
3. **강조 방식** — CSS 중심. 강의 HTML은 클래스 삽입만 하고 본문은 건드리지 않는다

## 4. 구현 접근

**채택: 키 기반 셀 재사용 + 교환 자동 감지 FLIP**

`renderStep()`이 DOM을 버리지 않는다. 그룹 시그니처(종류 + 개수)가 이전 단계와 같으면 기존 셀을 재사용해
값·서브라벨·상태 클래스만 diff 갱신한다. 그러면 이미 선언된 전환이 실제로 발동한다.

여기에 **이전 단계와 현재 단계의 값 배열을 비교해 엔진이 값의 이동을 자동 추론**한다.
강의 코드는 한 줄도 고치지 않는다.

감지는 두 종류를 구분해야 한다. 실제 코드를 확인한 결과 둘의 데이터 패턴이 다르기 때문이다.

| 패턴 | 데이터 특징 | 예 |
|---|---|---|
| 교환(swap) | 정확히 두 위치의 값이 서로 맞바뀐다. 값 구성은 그대로 | 4강 선택 정렬 `tmp` 교환 |
| 앞으로 복사(copy-forward) | 인접한 두 위치만 다르고 `next[j+1] === prev[j]`. 값이 복제되므로 **값 구성이 달라진다** | 4강 삽입 정렬 `arr[j+1] = arr[j]` |

삽입 정렬은 `key`를 배열 밖 변수에 들고 있어 shift 단계마다 값이 하나 복제된다.
따라서 교환 감지기로는 잡히지 않고 별도 감지기가 필요하다.
두 패턴 모두 아니면 값만 부드럽게 교차 전환한다 — 이동 모션은 없지만 하드컷보다는 명확히 낫다.

4강 선택 정렬의 `randomArray`는 `arr.indexOf(v) === -1`로 **중복 없는 값**을 보장하므로
교환 감지에 모호함이 없다.

**탈락한 대안**

- *키 기반 재사용만* — 색·위치 전환은 부드러워지지만 자리 교대가 나오지 않는다
- *`makeSteps`에 모션 힌트 추가* — 모션은 가장 정확하지만 16개 시각화의 알고리즘 코드를 손대야 한다.
  `docs/adding-lessons.md`가 "시각화 동작과 실제 코드 동작 일치"를 규칙으로 정해둔 만큼 회귀 위험이 가장 크다

## 5. 작업 영역

### 5.1 모션 토큰 (`assets/css/common.css`)

`:root`에 토큰을 정의하고 모든 전환이 이를 참조한다. 현재는 전부 맨 `ease`라서 사이트 전체에 리듬이 없다.

```
--dur-fast: 140ms;      /* 색·테두리 등 즉각 반응 */
--dur-base: 240ms;      /* 일반 상태 전환 */
--dur-slow: 340ms;      /* 자리 교대(FLIP), 높이 변화 */
--ease-out: cubic-bezier(0.22, 0.61, 0.36, 1);
--ease-settle: cubic-bezier(0.34, 1.26, 0.64, 1);   /* 약한 오버슈트 — 확정의 정착감 */
--ease-in-out: cubic-bezier(0.45, 0.05, 0.55, 0.95);
```

`prefers-reduced-motion` 전역 규칙(`common.css:157`)은 유지하고, 그 블록에서 세 duration 토큰을 `0.01ms`로 덮는다.
토큰을 한곳에서 무력화하므로 개별 선언을 일일이 막을 필요가 없다.

### 5.2 시각화 엔진 (`assets/js/visualization.js`)

- `renderStep()`을 파괴·재생성에서 키 기반 갱신으로 전환한다.
  그룹 시그니처가 같으면 재사용, 다르면 해당 그룹만 재생성한다
- 배열 셀의 키는 그룹 인덱스 + 셀 인덱스로 삼는다
- 교환·shift를 자동 감지해 FLIP을 적용한다
- 스택 push / 큐 enqueue로 새로 들어온 셀은 진입, 빠진 셀은 퇴장 애니메이션을 준다
- 카운터 칩(비교·교환 횟수)은 값이 바뀐 칩만 짧게 강조한다
- 자동 재생 중에는 FLIP 시간이 재생 간격을 넘지 않도록 duration을 간격에 맞춰 줄인다

**공개 API는 바꾸지 않는다.** `AlgoViz.create`, 반환 객체의 `rebuild`·`setInput`,
그리고 step·view group 데이터 형식이 모두 그대로 유지되어 16개 호출부는 무변경이다.

### 5.3 상태 모션 문법 (`assets/css/visualization.css`)

| 상태 | 모션 |
|---|---|
| 비교(compare) | 살짝 들림 — 현재 동작 유지, 이징만 개선 |
| 교환(swap) | 두 셀이 자리 교대 (FLIP translate) |
| 확정(done) | 가벼운 정착 — `--ease-settle` |
| 발견(found) | 한 번의 짧은 맥박 |
| 버림(faded) | 축소 + 페이드 |
| 방문(visited) | 색이 번지듯 통과 |

색 외에 형태·위치 신호를 함께 유지해 `docs/adding-lessons.md`의
"색상만으로 상태 구분 금지" 규칙을 지킨다.

### 5.4 랜딩 히어로 (`index.html`, `assets/js/landing.js`, `assets/css/landing.css`)

- 무대를 넓히고 값 라벨을 막대 상단으로 옮긴다
- 교환 시 두 막대가 자리를 교대한다
- 하단에 회차 진행 타임라인 도트를 둔다
- **▶/⏸ 재생 제어와 🎲 새 데이터 버튼을 추가한다.** 현재 무한 자동 재생을 멈출 수 없는 것은 실제 사용성 문제다
- `prefers-reduced-motion`에서는 자동 재생을 하지 않고 정적 장면 + 설명을 보여준다 (현재 동작 유지).
  단 수동 조작은 이 상태에서도 가능해야 한다

### 5.5 스크롤 진입 (`assets/js/common.js`, CSS)

- `IntersectionObserver`로 섹션·카드가 뷰포트에 들어올 때 1회 페이드 + 상승
- 목차 활성화에 쓰는 기존 패턴(`common.js:187`)을 따르고, `IntersectionObserver` 미지원 시 즉시 표시한다
- 되돌아가도 재생하지 않는다 (관찰 해제)
- `prefers-reduced-motion`이면 관찰을 걸지 않고 즉시 표시한다
- 인쇄 시에는 진입 전 상태가 남지 않도록 `print.css`에서 강제 표시한다

### 5.6 강조 (CSS 중심)

- **핵심 정리 승급** — 13개 강의 `#sec-summary`의 맨 `<ul>`이 결론부인데 가장 안 보인다.
  전용 카드 스타일을 부여한다. 강의 HTML은 `<ul>`에 클래스 1개를 넣는 수정만 한다
- **note-box 재설계** — 138곳. 변형별로 아이콘과 좌측 바 위계를 정리한다.
  사용 0건인 `--danger` 변형은 남겨두되(향후 쓰임) 나머지와 일관되게 맞춘다
- **strong 마킹** — 현재 색만 바뀌는 본문 강조에 미묘한 배경을 준다
- **섹션 헤더 위계** — 번호 배지와 제목의 대비를 높인다
- **읽는 진도 바** — 강의 페이지 상단에 얇은 진행 바를 둔다
- **죽은 CSS 제거** — 사용 0건인 `inline-array` 규칙 40줄을 지운다

### 5.7 제약

- **ES5 유지** — 프로젝트 전체가 `var`·`function`·IIFE이고 빌드 단계가 없다. 이 스타일을 따른다
- **외부 라이브러리 금지** — 현재 의존성은 Pretendard 웹폰트 CDN뿐이다
- **인쇄 호환** — 학생용·교수자용 인쇄가 핵심 기능이다. 강조는 흑백에서도 읽혀야 한다
- **접근성** — 색상만으로 상태를 구분하지 않는다
- **`scripts/validate.mjs` 통과 유지**

## 6. 검증

1. `node scripts/validate.mjs` 통과
2. 16개 시각화를 전부 브라우저로 열어 단계를 넘기며 확인한다.
   단계 수·캡션·카운터가 변경 전과 같아야 한다 (모션만 달라지고 내용은 불변)
3. 자동 재생을 세 가지 속도로 돌려 모션이 간격을 넘지 않는지 확인한다
4. 랜딩 히어로의 재생·일시정지·새 데이터를 조작한다
5. 인쇄 미리보기를 학생용·교수자용 둘 다 확인한다
6. `prefers-reduced-motion: reduce`를 켠 상태에서 전 페이지를 확인한다
7. 라이트·다크 테마 양쪽을 확인한다

## 7. 알려진 한계

교환과 앞으로 복사는 감지하지만, 그 밖의 임의 재배치는 데이터만으로 추론할 수 없다.
그 경우 부드러운 값 교차 전환까지만 적용되고 이동 모션은 나오지 않는다.
현재의 하드컷보다는 명확히 낫지만 완전하지는 않다.

값에 중복이 있는 배열에서 교환을 감지할 때는 모호함이 생길 수 있다.
"정확히 두 위치만 다르고 그 두 값이 서로 맞바뀐 경우"라는 국소 조건만 쓰므로
잘못된 이동 모션이 나올 위험은 없지만, 감지를 놓칠 수는 있다. 놓치면 교차 전환으로 흘러간다.

더 정확한 모션이 필요하다면 나중에 `makeSteps`가 선택적으로 모션 힌트를 넘기는 길을 열 수 있다.
엔진이 힌트가 없을 때 자동 추론으로 흘러가도록 설계하므로 이 확장은 하위 호환된다.

자바 스트림

Java Streams

자바 문법 보충 자료 Java 17+

스트림은 "데이터를 거르고 · 바꾸고 · 모으는 과정을 한 줄기로 잇는" API입니다. 2강에서 세 번 순회하며 구한 합계·평균·최댓값, 3강에서 HashMap으로 센 단어 빈도를 for 반복문 없이 다시 씁니다. 람다식 문서를 먼저 읽어 주세요 — 스트림에 넘기는 것이 전부 람다입니다.

이 문서의 목차

    01왜 필요한가

    2강에서 성적 통계를 만들 때, 이런 요구를 처리했습니다. "60점 이상인 점수만 골라, 5점씩 가산한 뒤, 평균을 구한다." 반복문으로 쓰면 이렇습니다.

    Java 이전 — 반복문 (12줄) 
    int total = 0;
int count = 0;
for (int i = 0; i < scores.length; i++) {
    if (scores[i] >= 60) {          // 거르기
        int adjusted = scores[i] + 5; // 바꾸기
        total += adjusted;            // 모으기
        count++;
    }
}
double average = count == 0 ? 0 : (double) total / count;
    Java 이후 — 스트림 (4줄) 
    double average = Arrays.stream(scores)   // 흘려보낼 원본
        .filter(s -> s >= 60)            // 거르기
        .map(s -> s + 5)                 // 바꾸기
        .average().orElse(0);            // 모으기

    줄 수보다 중요한 차이가 있습니다. 반복문 버전에서 "무엇을 하는가"는 total, count, i, adjusted 네 변수의 움직임을 머릿속에서 따라가야 드러납니다. 스트림 버전은 거르기 → 바꾸기 → 모으기가 그대로 세 줄로 적혀 있습니다. 변수를 하나도 만들지 않았기 때문에 순서를 잘못 세거나 초기화를 빠뜨릴 자리도 없습니다.

    스트림은 알고리즘을 대신해 주지 않는다

    위 코드는 여전히 배열을 한 번 훑습니다 — O(n)입니다. 스트림으로 썼다고 더 빨라지지 않고, 오히려 작은 배열에서는 조금 느립니다. 스트림이 주는 것은 표현이지 복잡도가 아닙니다. 정렬을 O(n log n)으로 만드는 것은 8·11강에서 배운 알고리즘 지식이지 문법이 아닙니다.

    02학습 목표

    이 문서를 읽고 나면 다음을 할 수 있습니다.

    • 학생은 스트림 파이프라인의 세 단계(생성 · 중간 연산 · 최종 연산)를 구분할 수 있다.
    • 학생은 filter, map, sorted, distinct, limit의 역할을 설명할 수 있다.
    • 학생은 collect, count, average, anyMatch, reduce 중 상황에 맞는 최종 연산을 고를 수 있다.
    • 학생은 Collectors.groupingBy와 counting으로 빈도표를 만들 수 있다.
    • 학생은 반복문으로 쓰인 집계·검색 코드를 스트림으로 바꿔 쓸 수 있다.
    • 학생은 스트림이 한 번만 소비된다는 점, 지연 평가된다는 점을 실행 결과로 설명할 수 있다.
    • 학생은 스트림을 쓰지 말아야 할 상황을 판단할 수 있다.

    03파이프라인 구조

    모든 스트림 코드는 예외 없이 세 부분입니다.

    단계하는 일개수예
    ① 생성원본을 스트림으로 만든다정확히 1개Arrays.stream(arr), list.stream()
    ② 중간 연산스트림을 받아 스트림을 돌려준다0개 이상filter, map, sorted
    ③ 최종 연산결과를 꺼낸다. 여기서 실제로 실행된다정확히 1개collect, count, forEach
    중간 연산은 예약표를 쌓을 뿐이다

    filter와 map을 부르는 순간에는 아무 일도 일어나지 않습니다. "이렇게 처리하겠다"는 계획만 붙습니다. 실제 계산은 최종 연산이 호출될 때 원소 하나씩 파이프라인 전체를 통과하며 일어납니다. 이것을 지연 평가라고 합니다. 아래 코드로 직접 확인할 수 있습니다.

    Java LazyEvaluationDemo.java — 지연 평가를 눈으로 보기 
    import java.util.stream.Stream;

public class LazyEvaluationDemo {
    public static void main(String[] args) {
        System.out.println("=== 최종 연산이 없을 때 ===");
        Stream.of(1, 2, 3, 4, 5)
              .filter(n -> { System.out.println("  filter " + n); return n % 2 == 0; })
              .map(n -> { System.out.println("  map " + n); return n * 10; });
        System.out.println("(아무것도 출력되지 않았습니다)");

        System.out.println("\n=== 최종 연산을 붙였을 때 ===");
        int first = Stream.of(1, 2, 3, 4, 5)
              .filter(n -> { System.out.println("  filter " + n); return n % 2 == 0; })
              .map(n -> { System.out.println("  map " + n); return n * 10; })
              .findFirst().orElse(-1);
        System.out.println("결과: " + first);
        // filter 1, filter 2, map 2 까지만 실행되고 멈춥니다.
        // 3, 4, 5는 아예 검사되지 않습니다 — 5강의 '조기 중단'과 같은 원리입니다.
    }
}

    두 번째 실행 결과를 잘 보세요. 원소 1부터 5까지 filter를 모두 돌린 뒤 map으로 넘어가는 것이 아닙니다. 원소 하나가 파이프라인 끝까지 갔다가 다음 원소가 출발합니다. 그래서 findFirst는 답을 찾는 즉시 나머지를 아예 건드리지 않습니다. 5강에서 순차 탐색에 return을 넣어 조기 중단했던 것과 정확히 같은 절약입니다.

    04스트림 만들기

    Java 원본에 따라 만드는 방법이 다르다 
    int[] scores = {88, 72, 95, 64, 79};
List<String> names = List.of("김인하", "이공전", "박알고");
Map<String, Integer> stock = Map.of("사과", 12, "배", 5);

IntStream  a = Arrays.stream(scores);        // 기본형 배열 → IntStream
Stream<String> b = names.stream();           // 컬렉션 → Stream<T>
Stream<String> c = Stream.of("가", "나");     // 값을 직접 나열
IntStream  d = IntStream.range(0, 5);        // 0,1,2,3,4  (끝 미포함)
IntStream  e = IntStream.rangeClosed(1, 5);  // 1,2,3,4,5  (끝 포함)
Stream<Map.Entry<String, Integer>> f = stock.entrySet().stream();   // 맵은 entrySet부터
    IntStream과 Stream<Integer>는 다르다

    Arrays.stream(int[])은 IntStream을 돌려줍니다. IntStream에는 sum(), average(), max()가 바로 있습니다 — 정수라는 것을 알기 때문입니다. 반면 Stream<Integer>에는 sum()이 없습니다. 객체 스트림에서 숫자 연산이 필요하면 mapToInt(...)로 넘어가야 합니다. 박싱 비용도 여기서 갈립니다.

    05중간 연산

    연산받는 것하는 일13강의 무엇에 해당하나
    filterPredicate조건에 맞는 것만 통과2강 조건 검색, 5강 순차 탐색
    mapFunction원소를 다른 값으로 바꿈2강 가산점 적용

    Java 순서가 결과와 비용을 바꾼다 
    // ⚠ 1000개를 전부 정렬한 뒤 3개만 남긴다 — 정렬 비용 O(n log n)
List<Product> slow = products.stream()
        .sorted(Comparator.comparingInt(p -> p.price))
        .filter(p -> p.rating >= 4.5)
        .limit(3)
        .toList();

// ✓ 먼저 걸러서 정렬 대상 자체를 줄인다
List<Product> fast = products.stream()
        .filter(p -> p.rating >= 4.5)     // 남는 게 20개라면
        .sorted(Comparator.comparingInt(p -> p.price))   // 20개만 정렬한다
        .limit(3)
        .toList();

    거르기를 먼저, 정렬을 나중에. 1강에서 "같은 결과라도 일의 양은 다를 수 있다"고 배운 것이 그대로 적용됩니다. 스트림은 이런 순서를 알아서 바꿔 주지 않습니다 — 적은 대로 실행합니다.

    06최종 연산

    연산돌려주는 것쓰는 자리
    toList()List<T> (수정 불가)결과 목록이 필요할 때
    collect(...)지정한 자료구조Set·Map·그룹으로 모을 때
    count()long2강 조건 개수 세기
    sum() · average() · max()숫자 / Optional2강 합계·평균·최댓값
    anyMatch · allMatch · noneMatchboolean"하나라도 있나?" 판정 (조기 중단)
    findFirst()Optional<T>5강 순차 탐색의 첫 결과
    reduce(...)누적 결과직접 정의한 누적 규칙
    forEach(...)없음출력 등 소비만 할 때
    Optional이 나오는 이유

    빈 배열의 최댓값은 존재하지 않습니다. 2강에서는 data[0]을 후보로 삼았기 때문에 빈 배열이면 예외가 났습니다. max()가 Optional을 돌려주는 것은 "없을 수도 있다"를 타입으로 강제하는 것입니다. .orElse(0)이나 .orElseThrow()로 없을 때의 처리를 반드시 적게 만듭니다.

    Java reduce — 누적의 일반형 
    // 1강의 누적 패턴: total = total + v 를 그대로 옮긴 것이 reduce다
int sum = Arrays.stream(scores).reduce(0, (acc, v) -> acc + v);
//                                     ↑초깃값  ↑누적 규칙

// 곱셈으로 바꾸면 팩토리얼 (7강 재귀와 같은 결과)
long fact = IntStream.rangeClosed(1, 10).asLongStream().reduce(1L, (a, b) -> a * b);

// 문자열 잇기 — 다만 문자열은 joining을 쓰는 편이 훨씬 낫다
String joined = names.stream().collect(Collectors.joining(", "));

    07모으기와 그룹핑

    Collectors는 "어떻게 모을 것인가"를 정하는 도구 모음입니다. 3강에서 HashMap으로 손수 만들던 빈도표가 한 줄이 됩니다.

    Java 자주 쓰는 다섯 가지 
    import static java.util.stream.Collectors.*;

// 1) Set으로 — 3강의 HashSet 중복 제거
Set<String> unique = words.stream().collect(toSet());

// 2) Map으로 — 키와 값을 각각 어떻게 뽑을지 지정
Map<String, Integer> priceByName =
        products.stream().collect(toMap(p -> p.name, p -> p.price));

// 3) 그룹핑 — 등급별로 학생을 묶는다
Map<String, List<Student>> byGrade =
        students.stream().collect(groupingBy(s -> grade(s.score)));

// 4) 그룹핑 + 세기 — 3강 단어 빈도표가 이 한 줄이다
Map<String, Long> freq =
        Arrays.stream(words).collect(groupingBy(w -> w, counting()));

// 5) 참/거짓 두 덩어리로 — 합격자와 불합격자를 한 번에
Map<Boolean, List<Integer>> passFail =
        Arrays.stream(scores).boxed().collect(partitioningBy(s -> s >= 60));

    2강과 이어 보기

    summaryStatistics()가 네 번의 O(n) 순회를 한 번으로 줄이지만, 복잡도는 여전히 O(n)입니다. 4 × O(n)도 O(n)이기 때문입니다. 1강에서 "상수 배는 Big-O에서 버린다"고 배운 그 이야기입니다. 실측 시간은 줄지만 증가 모양은 같습니다.

    08강의 코드 바꿔 보기

    ① 2강 — 성적 통계

    Java ScoreStatsComplete — 이전 · 이후 
    // ── 이전: 목적마다 메서드 하나, 순회 하나
static int sum(int[] d)  { int t = 0; for (int v : d) t += v; return t; }
static int max(int[] d)  { int c = d[0]; for (int v : d) if (v > c) c = v; return c; }
static int countAtLeast(int[] d, int th) {
    int n = 0; for (int v : d) if (v >= th) n++; return n;
}
static int[] collectBelow(int[] d, double lim) {   // 개수를 먼저 세고 배열을 다시 채웠다
    int n = 0; for (int v : d) if (v < lim) n++;
    int[] r = new int[n]; int p = 0;
    for (int v : d) if (v < lim) r[p++] = v;
    return r;
}

    Java WordFrequencySolution — 이전 · 이후 
    // ── 이전
static Map<String, Integer> countFrequencies(String[] words) {
    Map<String, Integer> freq = new HashMap<>();
    for (String w : words) {
        freq.put(w, freq.getOrDefault(w, 0) + 1);
    }
    return freq;
}
static String findMostFrequent(String[] words, Map<String, Integer> freq) {
    String best = null;
    for (String w : words) {
        if (best == null || freq.get(w) > freq.get(best)) best = w;
    }
    return best;
}

// ── 이후
Map<String, Long> freq = Arrays.stream(words)

String best = freq.entrySet().stream()

        .map(Map.Entry::getKey)
        .orElse(null);

    09자주 하는 실수

    ① 스트림을 두 번 쓴다

    Java 실행 중 예외가 나는 코드 
    Stream<Integer> s = list.stream();
long a = s.count();
long b = s.filter(n -> n > 10).count();
// IllegalStateException: stream has already been operated upon or closed

    스트림은 컬렉션이 아니라 한 번 흘려보내는 통로입니다. 최종 연산이 끝나면 닫힙니다. 두 번 써야 한다면 list.stream()을 두 번 부르세요. 스트림을 변수에 담아 두는 습관 자체를 피하는 편이 안전합니다.

    ② 최종 연산을 빼먹는다

    list.stream().filter(...).map(...);은 오류 없이 아무 일도 하지 않습니다. 컴파일도 되고 실행도 되는데 결과만 없으므로 찾기 어려운 종류의 버그입니다. 스트림을 썼는데 아무 변화가 없다면 가장 먼저 최종 연산을 확인하세요.

    ③ 람다 안에서 바깥 상태를 바꾼다

    Java 되긴 하지만 쓰면 안 되는 코드 
    // ✗ 리스트에 밀어 넣는 방식 — 병렬로 바꾸는 순간 깨진다
List<Integer> result = new ArrayList<>();
scores.stream().filter(s -> s >= 60).forEach(result::add);

// ✓ 모으는 일은 collect에 맡긴다
List<Integer> result = scores.stream().filter(s -> s >= 60).toList();

    forEach로 밖의 리스트를 채우는 것은 반복문을 어렵게 쓴 것일 뿐입니다. 스트림의 값어치인 "무엇을 하는지가 그대로 읽힌다"도 잃습니다.

    ④ parallelStream()을 습관적으로 쓴다

    병렬 스트림은 스레드를 나눠 쓰므로 준비 비용이 붙습니다. 원소가 수만 개 미만이거나 각 원소의 처리가 가벼우면 대개 더 느립니다. 게다가 위 ③처럼 공유 상태를 건드리는 코드가 있으면 결과가 매번 달라집니다. 측정해 보기 전에는 쓰지 마세요.

    ⑤ 모든 반복문을 스트림으로 바꾼다

    인덱스가 필요한 경우(4강 삽입 정렬의 arr[j + 1] = arr[j]), 중간에 break로 빠져나가며 여러 변수를 함께 갱신하는 경우, 이중 반복문에서 두 인덱스를 동시에 다루는 경우 — 이런 곳은 반복문이 더 명확합니다. 13강의 알고리즘 구현부는 대부분 여기에 해당합니다. 스트림이 잘 맞는 곳은 집계·변환·필터링입니다.

    연습 — 다음 반복문을 스트림 한 줄기로 바꿔 보세요
    Java 문제 — 90점 이상인 학생 이름을 사전순으로 
    List<String> names = new ArrayList<>();
for (Student s : students) {
    if (s.score >= 90) {
        names.add(s.name);
    }
}
Collections.sort(names);

    답 — 세 연산이 그대로 세 줄이 됩니다.

    Java 답 
    List<String> names = students.stream()
        .filter(s -> s.score >= 90)   // if
        .map(s -> s.name)             // add에 넣던 값
        .sorted()                     // Collections.sort
        .toList();

// 주의: toList()가 돌려주는 리스트는 수정할 수 없습니다.
// 나중에 add해야 한다면 .collect(Collectors.toCollection(ArrayList::new)) 를 쓰세요.

    10확인 퀴즈

    실행 순서와 "언제 쓰지 말아야 하는가"를 확인하는 문제들입니다.

    11핵심 정리

    • 스트림 코드는 언제나 생성 → 중간 연산 → 최종 연산 세 부분이다. 최종 연산이 없으면 아무 일도 일어나지 않는다.
    • 중간 연산은 계획만 쌓고, 실행은 최종 연산 때 원소 하나씩 파이프라인 전체를 통과하며 일어난다(지연 평가).
    • filter는 Predicate, map은 Function, sorted는 Comparator를 받는다 — 전부 람다식 문서에서 배운 것들이다.
    • 거르기를 먼저, 정렬을 나중에. 스트림은 순서를 알아서 바꿔 주지 않는다.
    • groupingBy + counting이 3강의 빈도표를, summaryStatistics()가 2강의 네 번 순회를 한 줄로 대신한다.
    • 스트림은 한 번만 소비된다. 두 번 필요하면 stream()을 두 번 부른다.
    • 표현이 바뀔 뿐 복잡도는 그대로다. O(n) 순회는 스트림으로 써도 O(n)이고, 작은 데이터에서는 오히려 조금 느리다.
    • 인덱스 조작·조기 break·다중 변수 갱신이 필요한 알고리즘 구현부는 반복문이 더 명확하다. 스트림은 집계·변환·필터링에 쓴다.

    12다음 단계

    두 문서를 다 읽었다면, 13강 중 아무 강의나 골라 "집계·변환·필터링을 하는 부분만" 스트림으로 바꿔 보세요. 알고리즘의 핵심 구현부(정렬의 교환, 탐색의 범위 축소, DP의 테이블 채우기)는 그대로 두는 것이 좋습니다. 그 부분은 원래 반복문이 가장 잘 맞습니다.

    바꾼 뒤에는 반드시 실행해서 결과가 같은지 확인하세요. 1강에서 두 알고리즘의 결과가 같은지 코드로 검증했던 것과 같은 습관입니다. 특히 HashMap을 거치며 순서가 달라지는 경우를 조심하세요.
